# PPT 生成技能

## Overview

PPT 生成技能通过两个阶段完成：需求澄清 → PPT 生成。

核心能力：

- 通过 `show_form` 工具一次性收集用户关键需求

- 用户提交表单后，立即执行 PPT 生成，无需额外确认

- 支持深度研究或基于文档、上下文生成 PPT

---

## ⚠ 强制约束（最高优先级）

1. 收到 PPT 请求后，**必须首先**进行需求澄清：

- 若终端类型为**即时通讯应用**（如微信、企业微信、飞书等 IM 环境），以**文本表单**形式输出澄清问题

- 否则，**调用** `show_form` 工具展示澄清表单

2. 用户提交表单后，**立即执行深度研究（如需）并调用** `generate_ppt` 生成，**禁止**展示规划方案或等待用户确认

3. 用户提交表单后，**禁止**以任何形式再次向用户提问或请求澄清，必须直接执行生成

4. 用户`user_query`命中英文腾讯云模板意图时，**必须**将 template_id 设为`tencent_cloud_template_en`，并将 PPT 内容语言切换为用户指定的外语（默认英文）。判定条件（满足任一即可）：

- 用户在`user_query`中明确要求用某种外语（英语、日语、韩语等）制作PPT，且要求使用腾讯云模板

- 用户`user_query`本身为某种外语（英语、日语、韩语等），且要求使用腾讯云模板

- 用户 `user_query`包含关键词：`国际版`、`英文版`，且要求使用腾讯云模板

> ⚠️ **全流程语言切换**：当用户 query 本身为英文（或其他外语）时，即使未明确要求英文模板，整个交互流程也必须切换为对应语言：
> 1. **大模型输出**：所有对话回复、说明文字、提示信息全部使用英文（或用户使用的外语）
> 2. **需求澄清**：show_form / IM 文本表单的标题、字段 label、选项文案全部使用英文
> 3. **深度研究**：检索 query 使用英文构造
> 4. **PPT 生成**：context、planning 内容使用英文输出
> 5. **汇总报告**：最终输出的汇总报告使用英文

5. **国际化内容筛选规则**：当第4条被触发，或用户 query 涉及海外/出海场景（包含关键词：`海外`、`出海`、`国际化`、`global`、`overseas`、`international`、`海外市场`、`跨境`、`多地区`、`多语言`）时，第二阶段调研**必须先筛选出国际版文档范围，后续只在该范围内进行检索和内容生成**。

   **国际版文档判定规则**：

   符合以下任一条件的文档视为"国际版文档"：
   - 文档内容专为海外市场编写
   - 文档内容包含关键词：`global`、`international`、`overseas`、`worldwide`、`cross-border`、`海外`、`全球`、`出海`、`国际站`、`国际版`、`海外版`
   - 文档标题为纯英文

   **执行流程**：
   1. 使用 `mcp__lexiang__search_kb_embedding_search` 进行检索
   2. 从检索结果中按上述判定规则筛选出国际版文档
   3. 后续所有内容获取和生成**仅限定在国际版文档范围内**，非国际版文档的结果丢弃
   4. 将筛选后的内容进行深度研究，整理为 context 传给 `generate_ppt`

## 第一阶段：需求澄清

收到 PPT 请求后，根据终端类型选择澄清方式，**一次性**收集所有关键信息：

- **即时通讯应用**（IM 环境）：以文本表单形式输出澄清问题

- **其他终端**：调用 `show_form` 工具展示澄清表单

### 表单字段规范

**表单内容必须参考当前会话上下文动态生成**，包括但不限于：

- 若用户已提及主题，将其作为主题字段的 `default` 值或优先选项

- 若上下文中有文档、背景资料，结合内容推断合适的受众、风格和页数

- 若用户已表达偏好（如"简洁一点"、"面向管理层"），对应字段的 `default` 和选项顺序应体现该偏好

- 表单的选项内容可根据上下文适当调整，使其更贴合当前场景，而非照搬固定模板

表单必须包含以下 4 个核心维度（若触发模板优先规则则为 3 个），可根据上下文补充额外字段（总字段数 ≤ 7）：

| 字段 | caption | kind | 说明 |

|------|---------|------|------|

| 主题 | PPT 主题 | `single-select` | 提供常见主题选项 |

| 受众 | 目标受众 | `single-select` | 如：技术团队、管理层、客户、学生等 |

| 风格 | 演示风格 | `single-select` | 如：专业商务、简洁学术、活泼创意等。**若触发模板优先规则，则省略此字段** |

| 结构 | 页数范围 | `single-select` | 如：精简版（5-8页）、标准版（10-15页）、详细版（20+页） |

**⚠ 模板优先规则**：若 `<user_context>` 中包含 `当前用户使用的 PPT 模板ID`，说明用户已选择了 PPT 模板，此时**必须省略"演示风格"字段**（风格由模板自身决定），表单核心维度缩减为 3 个（主题、受众、结构）。

**⚠ 腾讯云模板默认推荐规则**：当"演示风格"字段未被省略（即未触发模板优先规则）时，需要判断是否将腾讯云模板设为 `default`。内容与腾讯云工作相关时，"演示风格"字段的 `default` 必须设为 `["腾讯云风格"]`。判定条件（满足任一即可）：

- 提及腾讯云产品名称（如 CVM、COS、TDSQL、CLB、CDN、TKE、CBS、VPC、SCF 等）

- 提及腾讯云/CSIG/腾讯云智等组织关键词

- 提及云计算行业术语且上下文暗示腾讯云场景（如"面客材料"、"客户汇报"、"售前"、"PoC"、"产品介绍"等）

- 提及腾讯云行业方案关键词（如"金融云"、"政务云"、"教育云"、"智慧零售"、"工业互联网"等）

- 上下文文档内容涉及腾讯云产品或服务

**⚠ 页数范围选项约束**：页数范围选项**禁止**出现超出实际能力（40页）的具体大区间选项（如"40-50页"、"50-80页"等）。

**所有字段只使用 `single-select` 或 `multi-select` 类型，禁止使用 text/textarea/number。**

**每个字段必须设置 `default` 值，不允许 `default` 为空数组。**

## 第二阶段：执行生成

用户提交表单后，根据对话上下文判断执行路径：

### 判断执行路径

生成 PPT 的参考内容是否充足？

- **内容充足** → 路径 A（直接生成）

- **内容不足或需要补充** → 路径 B（先研究后生成）

> 💡 判断依据：文档被截断、用户未提供文档、用户要求检索更多内容等情况视为"内容不足"

### 路径 A：直接生成

调用 `generate_ppt`：

- `context`：对话中的文档内容或历史上下文

- `planning`：表单收集到的规划信息

- `use_template`：根据规则选择模板

### 路径 B：先研究后生成

按以下步骤顺序执行：

**Step 1：乐享 MCP 知识库语义检索（优先内容来源）**

优先使用乐享 MCP 的 `mcp__lexiang__search_kb_embedding_search` 工具在乐享知识库中进行语义向量检索：

- **前置门禁**：调用 `mcp__lexiang__whoami` 校验 MCP 绑定状态。未绑定/过期时，引导用户通过 `https://lexiangla.com/mcp?company_from=CSIG` 获取 `LEXIANG_TOKEN` 完成绑定，绑定成功后再继续
- 基于表单规划内容构建详细的检索任务 query，调用 `mcp__lexiang__search_kb_embedding_search`
- **调用参数**：`{"filters": {"keyword": "<query>"}, "limit": 10}`
  - ⚠️ **不要传 `_mcp_fields` 正向选择**：该参数 schema 要求**字符串**类型（非数组），且只接受负向排除路径（如 `"-staffs,-entry.html_content"`），正向选择（`@default` / `chunks.content`）会被忽略并可能触发 `/_mcp_fields: must be string` 校验报错。默认返回即包含正文片段，无需指定字段。
- 汇总检索结果，评估内容覆盖度
- **🔗 溯源链接**：每个 chunk 都带 `target_id`，用它拼出乐享页面 URL：`{domain}/pages/{target_id}`（顶级域名需追加 `?company_from=csig`）。标题用 `lexiang_search` 回查 `original_title` 校正。
- **📋 全量素材追踪表（强制）**：每轮检索**立即逐条登记** chunk：`target_id` | 标题 | 命中维度 | 采用/弃用。最终参考清单须如实列全（去重后），禁止只挑几条代表性来源。
- **🔢 正文内联引用（强制）**：报告正文中每处数据/论断/案例都必须标注来源序号 `[n]`，与文末清单双向对应。禁止正文 0 标注。

> 若乐享 MCP 检索内容已充足，可跳过 Step 2 和 Step 3，直接进入 Step 4。
> ⚠️ 若 MCP 未绑定/过期，**必须先引导用户完成配置**，不得跳过直接使用 WebSearch 替代。

**Step 2：WebSearch 全网补充（知识库不足时）**

对乐享知识库未覆盖或信息不足的部分，用 `WebSearch` 进行补充搜索。

**Step 3：WebFetch 抓取详情**

对 WebSearch 返回的高质量页面，用 `WebFetch` 抓取详细内容。

**Step 4：出具深度研究报告并调用 `generate_ppt` 生成 PPT**

将研究内容整理为 **Markdown 格式的深度研究报告**（2000-4000字），报告末尾必须附带所有参考文档链接：

```markdown
# 深度研究报告：{主题}

## 一、核心内容
- 要点1：...（数据来源：XXX [1]）
- 要点2：...

## 二、补充信息
- ...

---

## 参考文档

[1] 文档名称 - URL链接
[2] 文档名称 - URL链接
...
```

> 报告中所有数据引用必须使用 `[序号]` 标注，并在末尾"参考文档"章节列出对应的完整链接（来自乐享知识库的文档链接 + WebFetch 抓取的页面 URL）。
> ⚠️ **必须如实列全**：参考文档须包含全部被采用素材来源（按 `target_id` 去重后），禁止只挑几条代表性来源。乐享来源用 `{domain}/pages/{target_id}` 真链接。

**⚠️ 参考清单交付前硬校验（任一不通过禁止进入 PPT 生成）**：
- [ ] 每条参考都有真实 `target_id`，无「合集/汇总/等/部分」之类占位词
- [ ] 每条链接都是完整可点击 URL，无裸 `target_id`
- [ ] 正文每个 `[n]` 在清单能找到对应条目，反之亦然（双向计数一致）
- [ ] 采用条数 ≥ 实际检索轮次命中数（防止"挑几条充数"）

将报告作为 context 连同规划信息一起传入：

- `context`：Markdown 格式深度研究报告
- `planning`：表单收集到的规划信息
- `use_template`：根据规则选择模板

> 📄 **强制交付物：独立深度研究报告 .md**
> PPT 生成完毕后**必须**额外把深度研究报告写为独立文件 `{方案名}-深度研究报告.md`，通过 `present_files` 展示给用户。
> **🔢 正文必须带内联引用 `[n]`**，与末尾清单编号双向对应。严禁正文 0 标注。

### 轮询策略

调用 `generate_ppt` 后需要轮询等待生成完成：

- **首次查询**：等待 15-20 秒再开始轮询
- **轮询间隔**：30-60 秒
- **整体生成时长**：通常 20-30 分钟
- **状态流转**：`pending` → `running`（多个子阶段）→ `success`
- 从 `generation_result.preview_url` 取链接展示给用户

⚠️ 路径 B 必须按 Step 1→2→3→4 顺序执行

## 完整示例

**用户**：\"帮我做个关于 AI Agent 的 PPT\"

**关键步骤**：

```

1. show_form(fields=[主题, 受众, 风格, 页数范围]) → 用户提交表单

2. 判断内容是否充足

- 充足 → generate_ppt(context=上下文, planning=表单信息, use_template=模板)

- 不足 → Step1: mcp__lexiang__search_kb_embedding_search → Step2: WebSearch补充 → Step3: WebFetch → Step4: generate_ppt(context=整理后内容, planning=表单信息, use_template=模板)

```
