# 客户案例内容模板

本文档定义客户案例页面的标准内容结构和信息组织方式。

---

## 单客户案例页结构

每个客户案例独占一页，重点客户可占 2 页。标准内容结构如下：

### 信息维度

| 维度 | 内容要求 | 示例 |
|------|---------|------|
| 客户背景 | 公司名称、成立时间、核心业务、行业地位 | "杭州宇树科技，成立于2016年，专注高性能四足/人形机器人研发" |
| 客户痛点/目标 | 面临的具体问题和希望达到的目标 | "希望构建云上算力集群，更快应对不同规格机器人的AI模型训练" |
| 腾讯云方案 | 采用的产品、配置、技术路线 | "4~64台8卡H20带RDMA计算集群，支持FP32计算" |
| 量化成效 | **必须有数字**的业务效果 | "性能差距仅20%（H20 vs H100），线性扩展率高达97%" |
| ⭐ 前后对比 | 使用方案前后的关键指标变化 | "训练耗时从48小时降至12小时"、"成本从XX降至XX" |
| ⭐ 测试数据 | 具体的测试条件和结果数据 | GPU卡数、加速模式、batch size、step耗时、加速比等 |
| 关键结论 | 1-2句总结性结论 | "H20在算力差异下性能差距小，3.2T RDMA网络线性扩展优异" |

### ⭐ 量化数据硬性要求

**每个案例必须至少包含以下3项中的2项**：
1. **性能指标**：延迟、吞吐、QPS、训练速度等具体数值
2. **效果对比**：使用前 vs 使用后的关键指标变化（用百分比或绝对值）
3. **成本数据**：成本降低百分比、TCO对比、ROI数据

如果调研报告中找不到量化数据，必须标注 `[具体数据待确认]`，不能使用模糊描述（如"显著提升"、"大幅降低"）代替。

### 布局方式

推荐两种布局：

#### 布局A：上下二分式

```
┌──────────────────────────────────────────────────────┐
│ 页面标题：XX行业客户案例 – [客户名称]                  │
├──────────────────────────────────────────────────────┤
│                                                      │
│  上部区域（40%高度）                                   │
│  • 客户背景：公司简介、成立时间、核心业务              │
│  • 业务需求/痛点：希望解决的问题                       │
│  • 测试/部署信息：模型名称、数据集、配置参数等          │
│                                                      │
│  下部区域（50%高度）                                   │
│  • 方案详情 / 测试结果表格                             │
│  • 量化成效（大字突出）                                │
│  • 关键结论                                           │
│                                                      │
└──────────────────────────────────────────────────────┘
```

#### 布局B：左右二分式

```
┌──────────────────────────────────────────────────────┐
│ 页面标题：XX行业客户案例 – [客户名称]                  │
├──────────────────────────────────────────────────────┤
│                                                      │
│  左栏（40%宽度）          右栏（55%宽度）              │
│                                                      │
│  客户背景                 方案概述                     │
│  (公司简介、              (产品配置、技术参数)          │
│   成立时间、                                          │
│   核心业务)               测试结果/量化成效             │
│                           (表格或关键数字)             │
│  客户痛点/目标                                        │
│  (2-3个要点)              关键结论                     │
│                           (1-2句话)                   │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 设计要点

1. **量化数据必须突出**：关键数字用大字号 + 高亮色展示
2. **表格紧凑**：如有测试数据表格，保持紧凑可读
3. **背景信息简洁**：客户背景用2-3句话概括，不需要写太多
4. **结论明确**：最后的结论要明确、有力，直接回应客户痛点
5. **前后对比必须有**：如调研报告中找不到具体数据，至少给出定性的前后变化，并标注 `[具体数据待确认]`

### ⭐ 重点案例双页展示（可选）

当案例信息非常丰富（如有完整测试数据表格）时，可使用 2 页展示同一案例：

**第一页：背景 + 方案概述**
```
┌──────────────────────────────────────────────────────┐
│ 页面标题：XX行业客户案例 – [客户名称]（1/2）           │
├──────────────────────────────────────────────────────┤
│                                                      │
│  左栏：                    右栏：                      │
│  客户背景                  部署方案                    │
│  (公司简介、行业地位)       (采用的产品组合)             │
│                                                      │
│  客户痛点/目标              技术配置                    │
│  (3-4个核心痛点)           (GPU型号、集群规模、         │
│                            网络配置等)                 │
│                                                      │
└──────────────────────────────────────────────────────┘
```

**第二页：测试数据 + 成效总结**
```
┌──────────────────────────────────────────────────────┐
│ 页面标题：XX行业客户案例 – [客户名称]（2/2）           │
├──────────────────────────────────────────────────────┤
│                                                      │
│  测试数据表格                                         │
│  | GPU型号 | 卡数 | 模式 | Batch Size | Step耗时 |    │
│  | H20     | 8    | FP32 | 128        | 2.3s     |    │
│  | H100    | 8    | FP32 | 128        | 1.8s     |    │
│                                                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐            │
│  │ 关键数字1 │  │ 关键数字2 │  │ 关键数字3 │            │
│  │  97%     │  │  -20%    │  │  3.2T    │            │
│  │ 线性扩展率│  │ 性能差距  │  │ RDMA带宽  │            │
│  └──────────┘  └──────────┘  └──────────┘            │
│                                                      │
│  关键结论：一句话总结                                   │
│                                                      │
└──────────────────────────────────────────────────────┘
```

## 案例墙页结构

汇总所有客户案例的概览页。

### 布局

```
┌──────────────────────────────────────────────────────┐
│ 页面标题：客户案例总览                                 │
├──────────────────────────────────────────────────────┤
│                                                      │
│  ┌────────┐  ┌────────┐  ┌────────┐                  │
│  │ 客户A  │  │ 客户B  │  │ 客户C  │                  │
│  │ 行业   │  │ 行业   │  │ 行业   │                  │
│  │ 一句话  │  │ 一句话  │  │ 一句话  │                  │
│  │ 成效   │  │ 成效   │  │ 成效   │                  │
│  └────────┘  └────────┘  └────────┘                  │
│                                                      │
│  ┌────────┐  ┌────────┐  ┌────────┐                  │
│  │ 客户D  │  │ 客户E  │  │ 客户F  │                  │
│  │ ...    │  │ ...    │  │ ...    │                  │
│  └────────┘  └────────┘  └────────┘                  │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 卡片内容

每个卡片包含：
- **客户名称**：加粗
- **行业标签**：小标签样式（如"机器人"、"自动驾驶"）
- **核心成效**：一句话（如"训练性能差距仅20%，线性扩展率97%"）

### 卡片数量

- 3个案例：1行×3列
- 4-6个案例：2行×3列
- 6+个案例：考虑缩小卡片或分页

---

## 案例信息不足时的处理策略

当调研报告中的案例信息不完整时：

1. **缺少量化数据**：在 planning 中标注"[具体数据待确认]"，告知用户需要补充
2. **缺少客户背景**：在 deep_research 补充调研中追加搜索
3. **案例数量不足**：扩大调研范围到更宽泛的行业，或告知用户建议内部补充
4. **完全没有公开案例**：如实告知用户，建议内部补充或使用匿名化案例
