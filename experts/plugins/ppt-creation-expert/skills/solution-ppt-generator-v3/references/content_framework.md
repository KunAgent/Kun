# 调研 Query 构造指南与内容组织指南

本文档为 Agent 在 Phase 2（调研）和 Phase 3（内容组织）阶段的详细参考。

---

## 一、deep_research Query 构造指南

当用户给出 `{行业}` + `{场景}` + `{腾讯云产品}` 后，Agent 需要构造高质量的 `deep_research` query。

### 构造原则

1. **结构化描述**：query 中明确列出需要调研的维度和期望的信息类型
2. **维度完整**：确保 8 个维度在 1-2 次调研中全部覆盖
3. **具体化**：用具体的产品名、技术术语替代笼统描述
4. **时效性要求**：在 query 中明确要求最近 1-2 年的数据
5. **来源优先级**：强调优先使用官方资料和权威报告

### 第一次调研 Query 模板（主调研）

**覆盖维度**：① 行业趋势、② 产业链全景、③ 痛点与挑战、④ 腾讯云方案、⑧ 客户案例

```
围绕"{行业}{场景}"进行系统性深度调研，需要覆盖以下方面：

1. 行业趋势与市场规模
   - {行业}的全球和中国市场规模（最近1-2年数据），增长率和预测
   - 技术发展阶段划分（从早期到成熟的演进路线）
   - 关键技术路线图和未来发展趋势

2. 产业链全景
   - {行业}的上下游产业链结构（上游供应→行业本体→下游应用）
   - 头部企业/核心玩家（5-8家代表企业），各自核心业务和市场定位
   - 企业的核心业务域中哪些与云计算/AI基础设施相关

3. 痛点与挑战
   - {行业}客户在{场景}场景下面临的核心痛点（期望获取3-6个维度的痛点）
   - 技术瓶颈：算力、数据、网络、存储等方面的具体挑战
   - 业务挑战：成本、效率、安全、合规等方面的问题

4. 腾讯云解决方案
   - 腾讯云在{行业}领域的整体解决方案
   - {腾讯云产品}的核心功能、产品架构、应用场景
   - 腾讯云官方白皮书、技术博客中关于{场景}的方案描述

5. 客户案例
   - 腾讯云在{行业}领域的公开客户合作案例（至少3个）
   - 每个案例需包含：客户名称、合作内容、使用的产品、量化成效（性能提升/成本降低的百分比）
   - 如有测试数据（GPU型号、batch size、训练耗时等），请一并提供

请重点关注最近1-2年的数据和信息，优先使用腾讯云官方资料和行业权威研究报告。
```

### 第二次调研 Query 模板（补充调研）

**覆盖维度**：⑤ 技术细节、⑥ 基础设施能力、⑦ 竞品对比

```
围绕腾讯云{腾讯云产品}在{场景}场景下的技术能力进行深度调研：

1. 技术架构与性能指标
   - {具体产品A}的技术架构设计、核心模块、工作原理
   - {具体产品B}的性能 benchmark 数据（延迟、吞吐、QPS等）
   - 最佳实践和典型部署方案

2. 基础设施能力（需要具体数字）
   - 计算能力：HCC高性能计算集群规格、支持的GPU型号（H100/H20/A100等）及核心参数（显存、FP32/FP16/INT8算力）、单集群最大规模
   - 网络能力：星脉网络架构详情、RDMA网络性能（带宽如3.2Tbps）、交换容量、网络拓扑
   - 存储能力：CFS Turbo/GooseFS/COS各自的性能指标（IOPS、吞吐、延迟）和适用场景对比
   - 通信优化：TCCL集合通信库的优化特性、线性扩展率数据（如64卡/128卡/256卡的扩展效率）

3. 竞品对比（使用真实竞品名称）
   - 腾讯云 vs 阿里云在{场景}场景的方案对比
   - 腾讯云 vs AWS在{场景}场景的能力对比
   - 腾讯云 vs 华为云在{场景}场景的差异化分析
   - 具体产品层面：{腾讯云产品} vs {竞品对应产品}的性能测试数据对比
   - 差异化优势总结（3-5个核心差异点，附带量化指标）

请提供具体的数字和技术参数，用真实竞品名称进行对比，不使用"竞品A/竞品B"。
```

### Query 构造的场景化调整

#### 当用户提供了补充材料时

```
围绕"{行业}{场景}"进行补充调研。

已有材料包含以下内容：
- [材料摘要：概述材料涵盖的主要内容和数据]

请重点补充以下缺失维度：
- [列出材料中未覆盖的维度]
- [列出需要更新的数据（如材料中的数据较旧）]
```

#### 当行业较小众时

```
围绕"{行业}{场景}"及其相关领域进行调研。

由于该领域相对小众，请同时关注以下相关领域的信息作为参照：
- [相近行业1]
- [相近行业2]

调研重点：
- [核心维度列表]
```

#### 非腾讯云方案时

将 query 中的"腾讯云"替换为目标厂商名称，其余框架不变。

## 二、内容组织详细指南

### 板块一：行业趋势与背景（目标 4-6 页内容页）

#### 页面 A：行业概念 + 发展阶段

**信息组织方式**：
```
上半部分：行业核心定义
→ 一句话定义（30字以内，精准概括行业本质）
→ 2-3个关键特征词

下半部分：发展阶段时间线
→ 阶段1（年份区间）：特征描述
→ 阶段2（年份区间）：特征描述
→ 阶段3（年份区间）：特征描述
→ 当前/未来趋势
```

**推荐布局**：水平时间线，每个阶段一个节点

#### 页面 B：核心技术与传统对比

**信息组织方式**：
```
对比维度选择（从调研结果中提取 4-6 个关键维度）：
→ 如：数据输入、学习目标、依赖条件、典型案例...

表格形式：
| 维度 | 传统方案 | 新方案 |
|------|---------|--------|
| ... | ... | ... |
```

**推荐布局**：全宽表格，传统方案灰色调、新方案蓝色调高亮

#### 页面 C：产业链全景 + 头部企业

**信息组织方式**：
```
三栏布局：
左栏-上游：列举上游关键要素（芯片、传感器、电池等）
中栏-行业本体：核心业务域 + 头部企业列表
右栏-下游：应用场景列举

头部企业（5-8家）：
→ 企业名称 + 一句话定位
```

**推荐布局**：三栏等宽，中栏高亮；下方单独列头部企业

#### 页面 D：市场规模与增长趋势

**信息组织方式**：
```
关键数字展示：
→ 当前市场规模（如"2024年全球市场规模 XXX 亿美元"）
→ 年复合增长率（CAGR）
→ 未来预测（如"2028年预计达到 XXX 亿美元"）

图表：
→ 柱状图/折线图展示历年市场规模和增长趋势
→ 标注关键拐点和驱动因素
```

**推荐布局**：左侧关键发现文字 + 右侧图表

### 板块二：需求和挑战（目标 2-3 页内容页）

#### 页面 E：痛点矩阵

**信息组织方式**：
```
从调研结果中提炼 3-6 个核心痛点，每个痛点：
→ 痛点标题（4-6字）
→ 痛点描述（1-2句话）
→ 对应的解决方向暗示（可选）

示例：
痛点1：硬件建设门槛高 → 复用云上多规格算力
痛点2：资源碎片化 → 云上业务调度接入
痛点3：平台利用率有限 → 充分利用云原生能力
```

**推荐布局**：多列卡片（3列或2行×3列），每卡片一个痛点

#### 页面 F：技术挑战分析（可选，内容多时添加）

**信息组织方式**：
```
将技术挑战按类别归纳：
→ 架构挑战：...
→ 数据挑战：...
→ 性能挑战：...
→ 安全挑战：...
```

### 板块三：解决方案（目标 12-20 页内容页，占比最大）

#### 页面 G：整体架构总览

**信息组织方式**：
```
分层架构（自上而下）：
第1层-行业应用层：列举支持的行业场景
第2层-业务框架层：核心业务能力
第3层-框架层：技术框架和引擎
第4层-调度层：容器和集群管理
第5层-基础资源层：计算、存储、网络

每层用不同色块表示，层间有箭头连接
```

**推荐布局**：分层横向布局，每层一行

#### 页面 H：痛点-方案映射 ⭐

**信息组织方式**：
```
将板块二的每个痛点与板块三的能力一一对应：
左列-痛点：直接引用板块二的痛点标题
中间：箭头连接
右列-方案：对应的腾讯云能力/产品

示例：
硬件建设门槛高    →    HCC 高性能计算集群（弹性算力按需使用）
资源规格碎片化    →    多规格 GPU 统一管理（H100/H20/A100）
平台利用率有限    →    云原生容器调度（智能算力调度平台）
```

**推荐布局**：左痛点（红色系）→ 中间箭头 → 右方案（蓝色系）

#### 页面 I-N：核心子能力详解（每页一个，5-7 页）

**信息组织方式**：
```
标准三段式：
1. 能力标题 + 一句话概述
2. 核心要点（3-5个bullet point）
3. 关键数据/技术参数（至少1个量化指标）

可选附加：
→ 方案示意图/流程图
→ 与友商对比数据（用真实友商名称）
→ 配套产品说明
→ 使用场景示例
```

**推荐布局**：
- 纯文字多时：双栏文字
- 有数据时：左文右图（左60% 右40%）
- 有对比时：左右对比（友商 vs 腾讯，用真实名称）

#### 页面 O：能力矩阵汇总

**信息组织方式**：
```
大表格汇总所有能力：
行 = 能力维度（5-8个）
列 = 开源/社区方案 | 腾讯云方案 | 差异/优势

或者用网格卡片形式：
每个能力一个卡片，卡片内包含：标题 + 核心指标 + "腾讯优化"标签
```

**推荐布局**：全宽表格或 2×4 网格卡片

#### 页面 P-S：基础设施能力（2-4 页）⭐

**信息组织方式**：
```
每页聚焦一个基础设施层：

页面P - 计算能力：
→ HCC 高性能计算集群概述
→ GPU 型号与规格（H100/H20/A100的核心参数）
→ 单集群最大规模、弹性扩缩容能力
→ 关键数字突出展示

页面Q - 网络能力：
→ 星脉网络架构图
→ RDMA 网络性能数据（如3.2Tbps、800T交换容量）
→ 网络拓扑和高可用设计

页面R - 存储能力（可选）：
→ CFS Turbo / GooseFS / COS 方案对比
→ 存储性能指标（IOPS、吞吐、延迟）
→ 适用场景推荐

页面S - 通信优化（可选）：
→ TCCL 集合通信库
→ 定制优化模块说明
→ 线性扩展性数据（如"64卡线性扩展率97%"）
```

**推荐布局**：
- 计算能力：GPU规格卡片式（3列大卡片，每卡片一种GPU）
- 网络能力：架构图 + 关键性能数字
- 存储能力：方案对比表格
- 通信优化：流程图 + 性能曲线描述

#### 页面 T：性能对比与测试数据 ⭐

**信息组织方式**：
```
左侧 30%：测试条件说明
→ 测试环境（GPU型号、数量、网络）
→ 测试模型/数据集
→ 测试方法

右侧 70%：对比图表
→ 腾讯云 vs 友商 分组柱状图
→ 每组标注具体数值
→ 标注差异百分比

或者用数据表格形式展示详细测试结果
```

**推荐布局**：左侧测试条件 + 右侧图表/表格，下方可附一行关键结论

#### 页面 U：差异化优势汇总

**信息组织方式**：
```
提炼 3-5 个差异化优势：
优势1：[标题] — [量化指标，如"性能提升30%"]
优势2：[标题] — [量化指标]
优势3：[标题] — [量化指标]
```

**推荐布局**：图标+标题+指标的列表式，或进度条式

### 板块五：附录（目标 1-3 页，可选但推荐）⭐

#### 页面 Z1：技术参数对照表

**信息组织方式**：
```
全宽紧凑表格：
→ 行：各项技术指标/产品功能
→ 列：腾讯云 | 友商A（真实名称）| 友商B（真实名称）
→ 优势项用加粗/高亮标注

或者产品功能清单：
→ 方案涉及的所有腾讯云产品
→ 每个产品的核心功能、适用场景、计费模式
```

**推荐布局**：全宽紧凑表格，斑马纹

#### 页面 Z2：部署架构参考 / 行业数据参考

**信息组织方式**：
```
选项A - 推荐部署架构：
→ 简化的部署架构图
→ 关键组件和连接关系
→ 高可用保障说明（双活、容灾等）

选项B - 行业数据横向对比：
→ 行业主流平台/数据集/标准的对比表

选项C - 联系与下一步：
→ 商务联系方式
→ 推荐的下一步（POC试用、技术交流、方案定制等）
```

**推荐布局**：根据内容选择架构图布局或表格布局
