# 福帮手超级合伙人专家团

这是 `fbsir-super-partner-group@1.3.0` 的 WorkBuddy 专家团审核包源目录，用于人工审核、静态校验和本地等效联调。它不是已经安装到用户 WorkBuddy 里的运行态证明。

## 这个包能做什么

- 为企业经营者提供“下一步怎么做”的结果卡，而不是只输出分析文字。
- 让唐老、老孙、老朱、老沙、小白按职能协作，并由主理人统一收口。
- 首值先直接交付结果卡和唯一下一步；当宿主已显式暴露服务跟进链路时，再用福帮手服务链路补充场景包建议、行动卡和后续任务。
- 在当前 WorkBuddy 宿主中，对项目、文件、记忆、产物索引和多智能体协作能力做有边界的使用。

## 当前边界

- 本目录是源码包和审核包来源，不等于正式安装态。
- 连接器主干仍保持 `1.2.9`，本包只增加超级合伙人需要的可选字段。
- 默认首值执行 `no-connector first value`；连接器、MCP 和服务侧链路只属于后首值增强或受控联调面。
- 国内 WorkBuddy 是主验证宿主；国际 WorkBuddy AI 只做映射说明。
- 本机宿主版本只代表本机当前安装事实；服务侧自然流量和当前用户群继续按多版本观测矩阵区分，不绑定单一版本。
- 用户可见技能入口保持单入口：`super-partner-core`。
- `super-partner-entry`、`lebao-unlock`、`genius-partner-builder`、`fbs-connector-health` 是包内合同、路由或诊断能力，不作为并列的用户入口宣传。

## 术语说明

- `my-experts`：WorkBuddy 的“我的专家”本地等效测试入口。它可以证明本地包能被加载和调用，但不能证明官方市场已经上架。
- `runtime`：真实宿主运行过程，例如安装、可见、被调用、会话记录和持久化证据。
- `same-binding`：同一次业务链路里的同一绑定关系。它只用来避免把不同样本混在一起，不是用户需要理解的产品术语。
- `remote COS`：官方远端分发和正式专家团 UI 的证据面。本地文件或缓存不能替代它。
- `gate`：门禁检查。它只说明某一类证据是否足够，不能自动扩大成“已经上线”或“业务闭环完成”。

## 提交包材料

人工审核时优先看这些文件：

- `.workbuddy-plugin/plugin.json`：WorkBuddy 专家团元数据、成员、分类、首问和展示说明。
- `agents/*.md`：主理人与成员的角色、边界和输出合同。
- `skills/super-partner-core/SKILL.md`：团队协作、首值、后首值增强和收口规则。
- `settings.json`：团队成员启用与协作配置。
- `marketplace-entry.json`：市场提交边界与信任说明。
- `LICENSE`：与插件清单一致的许可文件。

不随提交包分发的材料包括开发调试命令、审计过程报告、本地测试截图、临时诊断报告和宿主本机路径。这些内容可以作为外部工作记录保存，但不能作为本包的官方运行态或自然业务闭环证明。

## 当前宿主使用边界

- `memory` 和 `app/memory` 只作为上下文线索，不自动当作当前事实。
- `artifact-index` 可以帮助找到结果卡、报告和审核包，但文件存在不等于用户已经接受。
- 插件、会话、任务和项目能帮助继续工作，但不能单独证明自然业务闭环。
- `projects` 可以把一个经营议题组织成项目单元，但项目存在不等于交付完成。
- 文件和云盘式交付面可以承载成果，但仍需要所有者、状态、下一步和审核边界。

## UI 证据边界

请分开记录三类证据：

1. `remote_cos_ui_surface`：官方专家团 UI 和正式分发的权威证据面。
2. `local_my_experts_equivalent_path`：本地“我的专家”等效测试路径，用于验证入口、路由、成员行为、连接器调用和证据回读。
3. `review_package_artifact`：审核 zip、文档、截图索引和测试说明，只证明提审材料可复核。

本地 `my-experts` 测试通过，可以作为审核包本地等效测试通过；它不能被写成官方市场已上架、远端 UI 已渲染或自然业务闭环已完成。
