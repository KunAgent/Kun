# GEO诊断报告 - 评分规则与质量标准

---

## AIVO评分模型

四维等权重评分，总分 = 各维度score × weight之和。

| 维度 code | 中文名 | 权重 | 说明 |
|-----------|--------|------|------|
| AI_SEARCH_VISIBILITY | AI搜索可见性 | 0.25 | AI搜索中品牌提及率 |
| INFRA_COMPLETENESS | 基建完善度 | 0.25 | 官网/自媒体/权威媒体建设 |
| COMPETITIVE_ADVANTAGE | 竞争优势 | 0.25 | 相对竞品的差异化优势 |
| SENTIMENT_HEALTH | 舆情健康度 | 0.25 | 正面/负面舆情比例与趋势 |

评级：≥90优秀 / ≥75良好 / ≥60一般 / <60较差

## 输出裁剪规则

> 裁剪规则仅用于 **HTML报告展示**，不影响 prompts.md 中的生成数量要求（如自媒体至少10条）。
> AI生成时按prompts.md数量输出完整数据，HTML渲染时按裁剪规则截取展示。

| 字段 | 上限 | 理由 |
|------|------|------|
| questionDetails | 5条 | 概览足够 |
| competitors | 5条 | 前5竞品（v4.0优化，原数据已限制5个） |
| INFRA_EVAL.items | 3条/类 | 概览足够 |
| SENTIMENT.issues | 5条 | 关键问题 |
| suggestions | priority前5条 | 聚焦优先 |
| quickWins | 3条 | 快速赢利 |

## 解读质量检查

输出前逐项检查：

- [ ] 9章节均有数据（缺章节标注⚠️）
- [ ] 四维评分均有score+comment，totalScore=各维度score×weight之和
- [ ] overallMentioned = sum(platformResults[*].mentioned)
- [ ] 评级颜色匹配分数范围（≥90优秀 / ≥75良好 / ≥60一般 / <60较差）
- [ ] 每个风险至少配一条建议
- [ ] 建议具体到"做什么→预期效果"
- [ ] 进度条width=score%，提及率1位小数
- [ ] 裁剪规则已应用，章节编号01-09对齐前端

## 反模式

| ❌ 反模式 | ✅ 正确做法 |
|----------|------------|
| "品牌表现很差" | "舆情健康度58分，低于行业基准65分" |
| "建议加强品牌建设" | "[P0] 增加通义千问平台内容覆盖 → 预计提升可见性8分" |
| 列出所有竞品详情 | 展示前5竞品，说"详情"看更多 |
| 编造不存在的数据 | 缺章节时标注"⚠️ 数据缺失" |
| 只说问题不给方案 | 每个风险配一条建议行动 |

## 异常处理

| 异常 | 处理 |
|------|------|
| JSON解析失败 | 重试1次，仍失败标注⚠️跳过 |
| 字段缺失 | 合理默认值填充+标注⚠️ |
| 序数据空 | 标注"前序数据缺失"，基于可用数据执行 |
| 虚拟收录结果异常(全100%/全0%) | 重试1次 |
| WebSearch不可用 | 自动降级为纯虚拟模式 |
| 搜索超时/无结果 | 重试1次，换搜索引擎 |

## 模型适配指导

| 模型系列 | JSON可靠性 | 适配要点 |
|----------|-----------|----------|
| GPT-4o / o1 | 高 | 原生支持，无需特殊处理 |
| Claude 3.5+ | 高 | 偶尔包裹代码块，需strip |
| Gemini 2.0+ | 中 | 倾向在JSON前后加解释文字，需截取 |
| DeepSeek V3 | 中 | 偶尔输出不完整JSON，需重试 |
| Qwen 2.5+ | 中高 | 长JSON可能截断，建议分步执行 |

**通用JSON提取规则**：
1. 尝试直接 JSON.parse(fullOutput)
2. 失败则正则提取第一个 { 到最后一个 } 之间的内容
3. 仍失败则strip代码块标记后重试
4. 最终失败则重试该阶段（最多1次）

## SENTIMENT兼容性

后端SENTIMENT数据可能存储在 stages.SENTIMENT["2"] 下（而非根级）。
解读时先检查根级字段，若无则从 "2" key 取值。
