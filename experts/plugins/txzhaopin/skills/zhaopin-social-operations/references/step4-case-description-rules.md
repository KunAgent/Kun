## 🔍「粗筛做了什么」生成规则

从 profile 里取**实际用到的维度**，用一段话口语化告诉用户这一轮做了什么。**不要罗列条目**。

候选维度（在 profile 里出现才提，没出现就不写）：

| profile 字段 | 对应措辞参考 |
|---|---|
| `must.locations` + `supportNoExpectCity` | 城市过滤（含/不含期望为空的候选） |
| `must.workYears` | 工作年限区间 |
| `must.minDegree` | 学历门槛 |
| `must.schoolLevels` | 学校层次 |
| `must.companies` | 公司硬性要求（搜索端已兜底，所有结果都必然命中这些公司之一） |
| `bonus.tier1_companies` | 大厂背景加权（哪些公司） |
| `bonus.skill_keywords` / `domain_keywords` | 技能/领域加权（哪些关键词） |
| `bonus.position_keywords` / `seniority_keywords` | 职位名/职级加权 |

## ⚠️「精读要重点评估什么」生成规则

从 profile 里挑 **2-3 个最能体现本次 case 特色**的维度，用一段话说清楚精读要盯什么。**像对用户汇报一样口语化**，不要罗列条目，不要堆技术词。

常见 case 参考（按画像特征选 2-3 个，不要全堆上）：

| 画像特征 | 精读要盯什么 |
|---|---|
| 具体技术栈（如 Flutter/RLHF/Shader） | 真实深度：简历列了 ≠ 主导过，要看项目描述 |
| 强调大厂经历 | 最近不是大厂 ≠ 早年没待过，要翻全部工作经历 |
| 提到顶会/论文/比赛 | 粗筛完全拿不到，要确认一作/发表期刊/比赛名次 |
| 高级/专家/资深职级 | title 里写 ≠ 真的 P7+，要看晋升路径和带团队规模 |
| 强调项目/产品 | 具体量级（启动耗时、DAU、GMV 等）要读项目明细 |
| 复合能力（跨端/TA 等） | 需读项目职责判断多端协同或跨工种经验 |
| 低年限候选人（≤3 年） | 看是否有快速晋升/核心模块负责等成长信号 |
| 岗位标签泛（算法/运营/产品） | 警惕方向偏离风险，要在项目描述里确认实际做的是什么 |

## Few-shot 示例（1 个典型场景）

**场景：广州客户端（1-5年，大厂+跨端经验优先）**

```
🔍 粗筛做了什么
这一轮按广州（含期望城市为空的候选）+ 1-5 年 + 本科及以上做了硬性过滤，然后按一线大厂背景（字节/腾讯/小米/华为等）、跨端技能（Flutter/RN）、iOS/Android 核心技能和高级职级做了加权排序。

⚠️ 精读要重点评估什么
重点要看候选人是否真的主导过 Flutter 或 RN 跨端项目（简历出现技术词不等于主导），大厂经历是否扎实（最近不是大厂不代表早年没待过，需翻全部工作经历），以及性能优化的具体量化成果（启动耗时降多少、内存降多少，这些细节只有项目描述里才有）。
```

## 写作原则小结

1. **口语化**：像对用户汇报，不是列清单
2. **Case-by-case**：根据当前 profile 选维度，不是套固定模板
3. **2-3 句/段**：控制信息密度，用户一眼能看完
4. **聚焦差异**：精读段重点讲"粗筛看不见但精读能看见"的证据（真实深度、量级、晋升路径、论文/比赛等）
