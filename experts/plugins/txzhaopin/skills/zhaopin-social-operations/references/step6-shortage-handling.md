# 阶段 6：不足处理与下一步建议 v6.0.1

## 何时触发

精读命中数 < 10（默认目标 10 人）时触发，向用户说明原因并给出调整建议。

---

## 常见 3 类召回不足原因

- **画像过窄**（表现：候选池 < 30）
  → 搜索合并去重后样本就不够
  → 建议：放宽硬约束（扩城市 / 放年限 / 降学历）

- **搜索词选错/方向偏**（表现：候选池 ≥ 30 但 A+B 档 < 10）
  → 召回量够但 `searchKey` 没打中业务领域
  → 建议：换或加 `searchKey` 同义词，尤其是业务领域词（查 `data/domain-synonyms.json`）

- **硬约束互斥**（表现：excluded 占候选池 > 60%）
  → 大量候选被必筛（如"5 年外企本科+深圳总部"）
  → 建议：识别矛盾约束，与用户商量放宽哪一项

## 向用户展示的完整话术模板

```
## ⚠️ 本次仅推荐 X 份（目标 10 份）

**原因**：画像过窄
3 路搜索合计去重后仅 22 人，候选池规模不足。

**建议调整方向**：

1. 🔓 **放宽公司范围**：当前仅搜索"字节跳动"，建议允许候选人来自头部 TOP 10
   → 预计增加 15-30 个候选

2. 🔓 **扩展核心技能**：当前仅用了"冷启动"，建议扩展为"推荐算法/召回/排序/冷启动/Bandit" OR 组合
   → 预计增加 10-20 个候选

**请问你希望**：
- [A] 先用现有的 X 份简历，稍后再调整
- [B] 按建议 1（放宽公司）重新搜索
- [C] 按建议 2（扩展技能）重新搜索
- [D] 同时应用建议 1 和 2
- [E] 完全由我决定怎么调（告诉我具体修改）
```

## 收藏联动（v6.0 可选附加能力）

⚠️ **默认不主动收藏。** 只有用户**显式**说"收藏"/"收藏前 N 个"/"全部收藏" 时才调用。不要在输出 Top 10 后主动询问。

触发后：
1. 从精读 `results` 里取对应 rid
2. 每个 rid 对应的 `ExtId`（精读详情里的 `extId` 字段）转 int
3. 批量调 `recruit.social-resume.post_api_favorite_favorite_resume`，每次间隔 300-500ms

```bash
mcporter call recruit-mcp CallAPI \
  apiId='recruit.social-resume.post_api_favorite_favorite_resume' \
  params='{"employeeId": <int>}'
```

`favorite_resume` 是幂等的，重复收藏不会报错。完整接口定义见 `interfaces/favorite-resume.md`。
