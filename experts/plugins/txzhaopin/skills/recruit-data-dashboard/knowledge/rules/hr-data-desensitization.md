# HR 数仓数据脱敏识别规则

本规则定义了识别和处理 HR 数仓查询结果中脱敏数据的规范。**始终生效**，无论是否加载了任何 Skill。

## 脱敏值特征

查询结果中部分数据可能因用户权限不足被服务端脱敏处理。常见的脱敏值特征如下：

| 数据类型 | 脱敏后的典型值 | 说明 |
|----------|--------------|------|
| 字符串/文本 | `*`、`***` | 星号占位，常见于姓名、手机号等敏感字段 |
| 数值/整数 | `0` | 人数统计、薪资等字段显示为 0，且与业务逻辑不符 |
| 日期 | `1970-01-01`、`1970年1月1日` | Unix 时间戳零值，表示日期被脱敏 |
| 浮点数 | `0`、`0.0` | 比率、金额等字段异常为 0 |

## 识别方法

判断查询结果中是否存在脱敏数据，可通过以下特征综合判断：

1. **类型不匹配**：数值列出现 `*` 等非数值字符
2. **批量异常零值**：某列大量行的值为 `0`，但业务上不应为 0
3. **同列大量相同异常值**：某列绝大多数行显示相同的异常值
4. **敏感字段出现占位符**：姓名、手机号、身份证号、薪资等字段出现 `*`、`***` 或不合理的 `0`
5. **日期零值**：日期字段显示 `1970-01-01`，本应有值却为 NULL 或空

## 处理规范

### 发现脱敏数据时

1. 在结果表格后、分析洞察前，**主动提示用户**数据中存在疑似脱敏值
2. 明确告知**脱敏会影响统计准确性**（如 COUNT 可能偏小、AVG 可能不准确）
3. 建议用户使用 `data-permission-checker` Skill 深入排查权限原因
4. 对于前端展示场景，应考虑对脱敏值给出适当的 UI 提示（如 tooltip、标注等）

### 注意事项

- **仅在确实发现脱敏特征时才提示**，避免误报
- 不要将正常的 `0` 值或 `NULL` 值都当作脱敏处理
- 结合字段业务含义综合判断，例如"在职人数为0"大概率是脱敏，但"离职人数为0"可能是真实数据
