# 简历订阅操作

为当前登录员工订阅指定的校招简历，订阅后可在招聘平台「我的订阅」列表中跟踪该简历的动态（流程状态变更等）。

---

## 1. 新增简历订阅

- **apiId**: `recruit.campus-resume-search.get_v1_subscribe_add`
- **原始路径**: `GET /v1/subscribe/add`
- **操作类型**: ⚠️ 写操作（会写入订阅关系）
- **说明**: 为当前登录员工订阅指定简历。需要登录态；未登录或 `resumeId` 为 0 时返回错误。订阅成功后返回剩余订阅名额信息。

### 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `resumeId` | string | ✅ | 简历数字 ID（搜索接口返回的 `data.list[].id` 字段的字符串形式），不能为空且不能为 0 |

> ⚠️ **`resumeId` 是数字 `id`，不是 `rid`（UUID）**。与收藏接口一致：搜索接口每条简历同时返回 `id`（数字）和 `rid`（UUID），订阅接口使用 `id`。
> 接口定义中参数类型为 `string`，传入时可将数字 `id` 转为字符串（如 `"${id}"`）；实测传入数字亦可被服务端接受，但推荐使用字符串以贴合接口契约。

### MCP 调用

```bash
mcporter call recruit-mcp CallAPI \
  apiId='recruit.campus-resume-search.get_v1_subscribe_add' \
  params='{"resumeId": "${resumeId}"}'
```

### 返回示例

```json
{
  "message": "",
  "status": 0,
  "data": {
    "total": 5,
    "limit": 50,
    "left": 45
  }
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | integer | 0 表示请求成功，非 0 表示失败（如未登录、resumeId 为 0） |
| `message` | string | 错误描述（成功时为空） |
| `data.total` | integer | 当前用户已订阅的简历总数 |
| `data.limit` | integer | 系统限制的最大订阅数 |
| `data.left` | integer | 剩余可订阅名额 = `limit - total` |

---

## 2. 订阅 vs 收藏 vs 锁定 对比

| 维度 | 订阅 | 收藏 | 锁定 |
|------|------|------|------|
| **功能** | 跟踪简历动态变化 | 标记到个人列表以便查看 | 占住简历供自己走流程 |
| **影响范围** | 仅个人订阅列表 | 仅个人收藏列表 | 改变简历流程状态，影响所有用户 |
| **参数** | `resumeId`（数字 ID） | `resumeId`（数字 ID） | `rid`（UUID 字符串） |
| **名额限制** | ✅ 有上限（返回 `limit`/`left`） | ❌ 无明显上限 | ❌ 无上限（但受 BG 分配规则约束） |
| **可逆性** | 较轻（前端可取消订阅） | 较轻（前端可取消收藏） | 较重，需解锁流程 |
| **对其他用户影响** | 无 | 无 | 其他面试官暂时无法操作该简历 |
| **典型场景** | 跟踪尚未决定的候选人状态变化 | 标记感兴趣的候选人 | 准备发起面试 |

---

## 3. 注意事项

1. **参数类型**：`resumeId` 是搜索结果的数字 `id`，**不是 `rid`（UUID）**。这一点与锁定接口不同，与收藏接口相同
2. **订阅名额有限**：接口返回的 `data.left` 字段表示剩余名额；当 `left = 0` 时再次调用会失败，应先在平台取消部分旧订阅
3. **幂等性**：对同一简历重复调用订阅接口的行为未完全验证，建议先检查是否已订阅；从参数校验可推断：重复订阅可能不会报错，但不会重复扣减名额
4. **权限要求**：需要面试官权限（连接走太湖授权；面试官权限到 hrright.woa.com 申请）
5. **MCP 可用性**：仅「新增订阅」接口在 MCP 上注册。查询订阅列表、取消订阅等接口未在 MCP 注册，无法通过 mcporter 调用
6. **与社招订阅的区别**：本接口仅用于**校招**。社招有独立的订阅接口 `recruit.social-resume.get_api_flow_queue_push_inflow_queue`（简历排队），参数、语义都不同，本技能不涵盖

---

## 4. 完整使用流程示例

```
1. 搜索简历 → 获取候选人列表（含 id 和 rid）
2. 粗读 & 精读 → 评估候选人
3. 对高潜质但暂未决定面试的候选人 → 订阅（跟踪动态）
4. 对确定要面试的候选人 → 收藏 + 锁定
```

### 调用示例

```bash
# 假设搜索返回某候选人 id=123456789
mcporter call recruit-mcp CallAPI \
  apiId='recruit.campus-resume-search.get_v1_subscribe_add' \
  params='{"resumeId": "123456789"}'
```

返回：
```json
{"status": 0, "message": "", "data": {"total": 6, "limit": 50, "left": 44}}
```
