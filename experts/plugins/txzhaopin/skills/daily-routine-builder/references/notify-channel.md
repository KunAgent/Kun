# 通知渠道配置指引（企业微信群机器人 Webhook）

> 定时任务到点跑完，结果默认只输出在**当前 IDE / WorkBuddy 对话窗口**。
> 如果你希望结果**主动推送到企业微信群**（团队周报 / 个人提醒群），需要配一个**群机器人 Webhook**。
> 本文件供 agent 在配置定时任务时引导用户拿到 webhook URL。

---

## 一、为什么要配通知渠道

> 🔴 **本 skill 硬性规则**：**所有定时任务一律必须配 webhook**（不区分任务性质）。下表说明原因。

| 不配 webhook | 配了 webhook |
|---|---|
| 结果只在 IDE 对话窗口出现，**必须当时人在 IDE 前才看得到** | 结果自动推到企微群，手机也能收到 |
| 错过了就得翻历史对话 | 群里留存，团队可见 |
| 人不在电脑前 = 任务白跑 | 任意任务都能随时随地收到 |

> 🔴 **关键事实**：定时任务依赖客户端进程在前台运行，但**即使在前台，结果也只是新对话气泡**——人不在电脑前就看不到。所以本 skill 把 webhook 定为**所有任务的强制前置**：拿不到 webhook 就先记参数、不创建任务，绝不降级成"只在对话窗口看"。

---

## 二、怎么拿企业微信群机器人 Webhook（30 秒）

引导用户按以下步骤操作（agent 不能代办，必须用户在企微里手动建）：

```
1. 打开企业微信，进入要接收消息的群聊（建议专门建一个"我的定时任务"群，或用现有团队群）
2. 点群右上角「…」→「群机器人」→「添加机器人」→「新创建一个机器人」
3. 给机器人起个名字（如"招聘流程周报Bot"）→ 创建
4. 创建后会显示一个 Webhook 地址，形如：
   https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
5. 复制这个完整 URL，粘贴给我即可
```

> ⚠️ 这个 URL 含 `key=` 是**敏感凭证**——拿到它的人都能往你群里发消息。
> - 不要贴到公开仓库 / 截图外发
> - agent 收到后只把它写进 automation 的 prompt 占位符，**不要回显到对话**、不要写进任何日志

## 三、Webhook 在定时任务里怎么用

配置定时任务时，如果用户提供了 webhook，agent 在生成 prompt 时**追加一段推送指令**：

```
> 【结果推送】通过自检门（§3.5）后，用 curl 把内容 POST 到企业微信群机器人：
>
>   curl -s '<用户提供的 webhook URL>' \
>     -H 'Content-Type: application/json' \
>     -d '{"msgtype":"markdown_v2","markdown_v2":{"content":"<把上面报告转成 markdown，长度控制在 4096 字节内>"}}'
>
> 推送成功（errcode=0）后在对话里简短确认"✅ 已推送到企微群"；推送失败重试 1 次仍失败则把报告原文留在对话里并提示用户手动转发。
```

> 企业微信群机器人消息体硬限制：**单条 ≤ 4096 字节**。报告过长时让 agent 自动截断或只推"聚焦清单"摘要 + 一句"详情见 IDE 对话"。

### 3.4 markdown vs markdown_v2 怎么选

企业微信群机器人有两种 markdown 消息类型，**招聘报告优先用 `markdown_v2`**：

| 类型 | `msgtype` | 支持表格 | 支持颜色字 | 适用 |
|---|---|---|---|---|
| 旧版 | `markdown` | ❌ 不支持表格 | ✅ `<font color=...>` | 纯文字提醒、需要红/绿色字强调 |
| 新版 | `markdown_v2` | ✅ **支持表格** | ❌ 不支持 font color | **招聘进度表 / 漏斗 / 待办清单等带表格的报告** |

> 🔴 **招聘类报告几乎都含表格**（进度对标表、面试待办表、漏斗转化表），所以本 skill 招聘班次模板**统一用 `markdown_v2`**。报告里用标准 Markdown 表格语法（`| 列1 | 列2 |`），企微会渲染成真表格。
>
> ⚠️ 二者**不能混用**：`msgtype` 写 `markdown_v2`，外层 key 也必须是 `markdown_v2`（不是 `markdown`）。状态用 emoji 灯（🟢🟡🔴）替代颜色字，避免依赖旧版 font color。

### 3.5 推送前自检门（CRITICAL · 防推半成品）

> **来源教训**：多板块报告（如招聘三班次的搜推+进度+面试待办）里，只要有一块数据没拉到就推送，群里会出现"半张表 + 一堆 ⚠️"，比不推还难看。所以**推送前必须过一道自检门**。

**自检规则（写进任务 prompt，不依赖任何外部脚本）**：

```
【推送前自检门】生成报告后、curl 推送前，先自检：
  - 本次任务启用的每个板块，是否都产出了"真实内容"（不是 ⚠️ 占位/报错行）？
  - 全部产出 → 通过自检，执行 curl 推送
  - 有板块只剩 ⚠️ 占位 → 不通过：本次【不推群】，只把已完成部分留在对话里，
    并提示"部分板块（XX）暂不可用，本次未推送，下一班次自动重试"
```

| 场景 | 自检结果 | 动作 |
|---|---|---|
| 三块都有真实内容 | ✅ 通过 | 推群 |
| 两块正常 + 一块 ⚠️（如进度查不到） | ❌ 不通过 | 不推群，留对话，下次重试 |
| 单块任务（如只配了面试待办）该块正常 | ✅ 通过 | 推群 |
| 全部失败 | ❌ 不通过 | 不推群，对话里报错 + 客服入口 |

> 💡 **设计原则**：自检门是**纯 prompt 内的文字规则**（让 agent 自己判断"我这报告完整吗"），**不引入 cache_helper.py / push_checker.py 之类的外部脚本依赖**——保持本 skill 零脚本耦合、可上架公共市场。
> 单板块失败时遵循"**隔离降级**"：失败块输出 1 行 ⚠️，其余块照常，但整体不推群（推群门槛 = 全部启用块都成功）。

## 四、Agent 配置时的询问话术（标准模板）

配置**任何**定时任务时，**必须**问这一步并拿到 webhook 才能创建（不是二选一，是必填）：

```
📨 创建前还差一步：这个任务跑完的结果要推送到一个企业微信群，请给我一个群机器人 Webhook：
  群右上角「…」→「群机器人」→「添加机器人」→ 复制 Webhook 地址发给我
  （拿到形如 https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=... 的链接贴给我即可）

💡 还没有群？建议专门建一个"我的定时任务"群再加机器人。
   暂时拿不到 webhook 的话，我们先把任务参数记下来，等你拿到地址再一句话创建。
```

- 用户给 URL → 任务 prompt **追加 §三 的推送指令**，URL 填进占位符，正常创建
- 🔴 用户暂时给不出 → **不创建任务**，复述并记下已收集参数，告知"拿到 webhook 再来一句话创建"；**绝不**降级成"只在对话窗口输出"静默建好

## 五、安全与边界

1. **禁止硬编码**：任何模板文件、SKILL.md、reference 里**绝不允许**出现真实 webhook URL / key
2. **禁止回显**：agent 收到用户的 webhook 后，不要在对话里复述完整 URL（可以说"已记录你的群机器人地址"）
3. **存储位置**：webhook 只存在 automation 的 prompt 字段里（本地 TOML），随任务定义走，不单独落盘
4. **过期/泄漏**：用户在企微里删掉机器人 = webhook 立即失效；如怀疑泄漏，到群机器人设置里重置即可
5. **其他渠道**：本指引只覆盖企业微信群机器人；如用户问钉钉 / 飞书 webhook，原理相同（都是 POST JSON），但消息体格式不同，让用户提供对应平台的 webhook + 说明平台，agent 按对应格式拼 curl
