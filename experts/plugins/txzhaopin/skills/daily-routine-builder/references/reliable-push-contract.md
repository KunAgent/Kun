# 多步定时任务·可靠推送契约（v1.0 · 2026-06-17）

> 本文件沉淀「让定时任务跑得稳、推得准、不推半成品」的通用规则，供 agent 在
> **生成多步/多板块定时任务的 prompt 时按需注入**。所有规则都是**纯 prompt 文字**，
> 不引入任何外部脚本依赖（保持 skill 零脚本耦合、可上架公共市场）。
>
> 来源：吸收自 recruiter-super-brain 的三班次自动推送实践，剔除其专用的
> relay 跨班次闭环与 push_checker.py / cache_helper.py 脚本耦合，只保留通用增强。

适用对象：**多步骤 / 多板块**的定时任务（如早班「进度 + 待办」播报、
「漏斗 + 渠道 + 同环比」月报）。单步简单任务（如「提醒喝水」「每日简历搜推」）无需注入本契约。

---

## 一、生成期注入：把下面这段「执行契约」追加进任务 prompt

当一个定时任务包含 **≥2 个会各自取数/产出的板块** 时，agent 在拼 `prompt` 字段时，
在「任务正文 + §通知渠道推送段」之间插入以下契约（按实际板块名替换 `{板块N}`）：

```
【执行契约 · 多步可靠性 · 必须严格遵守】

Step 1｜逐板块执行：依次产出 {板块1}、{板块2}、{板块3} ……
  - 每个板块独立取数，互不阻塞。
  - 单个板块取数失败 → 该板块只输出 1 行降级占位：
    「⚠️ {板块名} 暂不可用：{一句话原因}，下次自动重试」
    其余板块照常产出，绝不因为一块失败就整体中断。

Step 2｜推送前自检门（防推半成品）：
  - 检查本次启用的每个板块，是否都产出了「真实内容」（不是 ⚠️ 占位/报错行）。
  - 全部板块都有真实内容 → 通过自检，进入 Step 3 推送。
  - 有任意板块只剩 ⚠️ 占位 → 不通过：本次【不推群】，只把已完成部分留在对话里，
    并提示「部分板块（{失败块}）暂不可用，本次未推送，下一次触发自动重试」。
  - 单板块任务（只启用一个板块）→ 该块成功即通过。

Step 3｜推送 + 失败重试：
  - 通过自检后才 curl 推送（推送段见任务 prompt 末尾的【结果推送】）。
  - 推送返回 errcode=0 才算成功，在对话里简短确认「✅ 已推送到企微群」。
  - errcode≠0 或网络失败 → 自动重试 1 次；仍失败 → 把报告原文留在对话里，
    提示用户手动转发，并附客服入口。

【红线】任意启用板块未产出真实内容 → 自检必不通过 → 禁止推送。
```

> 💡 这套与 `notify-channel.md §3.5 自检门` 同源，本契约是它的「多步完整版」
> （多了逐板块降级 + 推送重试）。单板块任务沿用 §3.5 简版即可。

## 二、触发时机可靠性：missed（漏跑）的正确话术

> **背景**：WorkBuddy / CodeBuddy 桌面端的定时任务是**本地应用进程内调度**——
> 到点时应用没在前台运行，这一次就会被**跳过（missed）**，不是云端 cron。
> 这是平台机制，skill 改不了，但**可以在两处帮用户规避/感知**。

### 2.1 创建任务时：主动提示「触发时段要开着应用」

agent 在 §三点五配 webhook、复述参数时，对**每天固定早高峰**（如 9:00）的任务，
追加一句善意提示（不阻断创建）：

```
⏰ 小提示：定时任务靠本机 WorkBuddy 应用在「触发那一刻」运行来驱动。
   你设的是 {time}，如果那个点你通常还没开电脑/应用，建议挪到你稳定在线的时段
   （如 9:30 / 10:00），否则那次可能被跳过。要调整时间吗？
```

- 用户要调 → 改 RRULE 的 BYHOUR/BYMINUTE。
- 用户坚持原时间 → 尊重，正常创建（已尽到告知义务）。

### 2.2 任务执行时：用「内容自带日期戳」让用户能识别 missed

在多步任务 prompt 的推送内容里，要求**标题带当天日期 + 班次**，例如
`🌅 6-17 周三 · 早班播报`。这样：
- 用户每天在群里看到日期戳 → 一旦某天没收到，立刻知道「那天 missed 了」。
- 配合 §一 Step 2 的「无内容不推半成品」，群里不会出现误导性的空播报。

> ⚠️ 不要在 prompt 里写「如果今天没数据就别推」这类规则——
> 让自检门（§一 Step 2）自然决定推不推，比硬编码更新可靠。

## 三、与「跨天去重」的关系（搜简历类定时任务专属）

如果任务里含**简历搜索推送**板块，跨天「今天别推昨天那批人」由
搜简历 skill（zhaopin-operations / zhaopin-social-operations）内部的
`scripts/dedup_pushed.py` 负责，**不在本契约范围**。本契约只管
「多板块产出完整性 + 推送可靠性 + missed 感知」。

> 即：去重是搜简历 skill 的职责，可靠推送是 daily-routine-builder 的职责，两者正交。
