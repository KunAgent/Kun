> 本索引列出所有可通过 recruit-mcp 拉取的硬技能参考模型。

## 一、使用前必读

### 1.1 用途
硬技能模型用于环节② **Part 1：四层硬技能画像** 的"通用模型补缺"环节，作为"用户没提到但岗位通常需要"的硬技能参考来源。

### 1.2 补缺规则（关键）
- 模型中权重 **≥ 20%** 且用户需求中**未提及**的维度 → 补入「🟡 优先具备」
- 模型中权重 **10%-20%** 且用户需求中**未提及**的维度 → 补入「🟢 加分项」
- 模型中权重 **< 10%** → 不补充
- **用户已明确提及的维度**：以用户表述为准，不论模型权重多少
- 从模型补充的项必须在 `source` 字段标注 `通用模型参考（{BG}）`

### 1.3 加载策略
- **不叠加**：硬技能模型按 BG 唯一匹配，一次最多命中 1 条
- **仅在岗位类型为后台开发类时尝试匹配**；其他岗位（前端、客户端、产品、设计、运营等）当前**无对应硬技能模型**，直接跳过

### 1.4 失败兜底（强制）
- MCP 拉取失败 → 静默跳过通用模型补缺
- 画像照常输出，仅"🟡 优先具备"和"🟢 加分项"可能少 1-3 条
- ⚠️ 不阻塞环节②的产出，不向用户暴露错误

## 四、MCP 调用快查（粘贴即用）

```
工具：mcp_call_tool
serverName: recruit-mcp
toolName:   CallAPI
arguments:
{
  "apiId": "recruit.recruit-ai-service.get_document",
  "params": { "documentId": "<上表中的 documentId>" }
}
```

**返回路径**: `response.data.data` = markdown 全文。  
**成功判定**: `response.status === 200` AND `response.data.code === "200"` AND `response.data.success === true` AND `response.data.data` 非空字符串。  
**常见失败码**: `50050`（文档不存在）/ `500`（服务异常）— 任一失败信号命中均视为失败，按 SKILL.md 兜底规则静默跳过。
