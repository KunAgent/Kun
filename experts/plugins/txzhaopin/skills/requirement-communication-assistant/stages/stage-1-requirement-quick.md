# 📌 环节①（快速模式）：4 问搞定需求识别

### 职责
只写 `meta` 和 `stage_1_requirement`；不动后续环节。

适合"老岗位续招、需求清楚、想快速出 JD"等场景。  
详细模式见 `stage-1-requirement.md`（多轮挖掘 + 6 项需求识别方法）。

### 与详细模式的区别

| 维度 | 详细模式 | 快速模式（本文件） |
|------|---------|------------------|
| 触发 | 用户选"详细" | 用户选"快速" / 用户说"我赶时间"等 |
| 轮次 | 10-15 轮 | 3-5 轮 |
| 方法 | 6 项识别方法全启用 | 仅保留"潜台词翻译"+"参照人法兜底" |
| 适用 | 第一次招、需求模糊 | 老岗位续招、需求已清楚 |
| 产物质量 | A | B+（够用，不卡画像生成）|

---

## 🚀 Step 1：一次性抛出 4 问

收到用户在起手式报来的"岗位+团队"、且确认走快速模式后，**立即抛出以下 4 问（一条消息全部发出）**：

```
🚀 快速需求识别（一次性回完即可，没有就写"无"）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1. 核心动作
   这个人进来主要做哪几件事？最核心的 1-2 件是什么？

Q2. 关键能力 + 硬门槛
   • 你最看重候选人哪 2-3 项能力？
   • 硬性门槛是什么？（学历 / 工作年限 / 必须懂的技术栈或工具 / 必须有过的行业或项目经验）

Q3. 反面雷区
   什么样的人坚决不要？或历史上踩过的坑？

Q4.（可选）业务方对人的其他描述
   业务方还说过哪些对"人"的描述或期待？
   （常见的比如：要稳定 / 抗压能力强 / 主动性强 / 沟通好 / 学习能力强 / 责任心强 / 要资深的 等）
   原话复述给我即可，我会帮你翻译成具体能力。
   想不起来或没有可以直接跳过。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

答完我帮你整理画像，缺的我来推，不用纠结。
```

---

## 🔍 Step 2：解析用户回答

用户回复可能形态：
- 逐条对应（Q1: …, Q2: …）
- 一段话讲完
- 贴 JD / 聊天记录 / 邮件原文
- 只答了部分（如 Q3 / Q4 答"无"或省略）

LLM 从中提取以下 5 类信息：

| 字段 | 来源 | 缺省处理 |
|------|------|---------|
| 核心动作 | Q1 | 必须；缺则触发追问 |
| 关键能力 | Q2 上半 | 必须；缺则触发追问 |
| 硬门槛 | Q2 下半 | 缺可由 LLM 基于岗位推导 |
| 反面雷区 | Q3 | 允许空 |
| 原话偏好 | Q4 | 允许空 |

---

## 🔄 Step 3：追问规则（最多 1 轮）

### 触发条件（任一命中即追问）

| 缺失项 | 判断标准 | 示例 |
|--------|---------|------|
| Q1 核心动作 | 空白 / 仅复述岗位名 / 无法推导能力 | "做开发"、"做策划"、"就那些事" |
| Q2 关键能力 | 完全没说能力，也没说硬门槛 | "随便招一个"、"看简历再说" |

### 追问模板

```
有一点想再确认下：

{岗位名} 进来后，是负责 {方向 A}、{方向 B}，还是 {方向 C}？
或者你心目中是否有一个理想标杆，他/她身上你最看重哪 2-3 点？

（回完我们就直接出画像）
```

### 不触发追问

- Q3 / Q4 答"无" → ✅ 接受
- Q2 只答能力没答硬门槛 → ✅ 接受（硬门槛由 LLM 基于岗位推导）
- 信息有但不够丰富 → ✅ 接受
- 用户贴了完整 JD/原文，能从中提取足够信息 → ✅ 接受

### 强制规则

1. **最多 1 轮追问**，不能问第 2 轮
2. 追问只问"最缺的那一项"，不能借机多问
3. 1 轮追问后，无论用户答得怎样，必进诊断输出
4. 如果用户没回答追问、直接说"算了你直接出"，按已有信息出画像，不再纠结

---

## 📊 Step 4：诊断输出（轻量版）

```
🎯 需求识别结果（快速模式）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 精准化需求

岗位目的：{这个人进来要做的具体事}
核心动作：{TA 日常工作内容}
关键能力（最看重的）：
   1. {能力1}
   2. {能力2}
   3. {能力3}
硬性门槛：
   • {硬门槛 1}
   • {硬门槛 2}
   {如果用户没说，标"（基于岗位推导，可在画像确认时调整）"}
反面雷区：{Q3 内容，无则"无"}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔁 业务方原话翻译  ← 仅当 Q4 有内容时输出，否则整段省略

| 业务方原话 | 翻译后能力 |
|-----------|-----------|
| {原话1} | {翻译1} |
| {原话2} | {翻译2} |

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 一句结论：{需求清晰度判断 + 是否可进画像生成}

以上需求确认无误吗？回 OK 进环节②（生成画像），或告诉我哪里要改。
```

### 输出注意

- **不展示三维诊断表**（那是详细模式的）
- 翻译表仅在 Q4 有内容时输出，无则整段省略，不留空表
- 如果用户在 Q4 提到敏感原话（如"家境好 / 大厂背景 / 性别 / 年龄"等），按潜台词翻译表处理 + **追加合规风险提示**
- 一句结论尽量积极正向，避免审判语气

## 💾 Step 5：写回 context

```json
{
  "meta": {
    "stage": "① 需求识别（快速）✅ → 待进入 ②",
    "version": "+1"
  },
  "stage_1_requirement": {
    "status": "completed",
    "mode": "quick",
    "skipped_techniques": [
      "症状根因分离",
      "外归因识别",
      "反设法",
      "内部盘活评估",
      "参照人法（除非追问中启用）"
    ],
    "raw_input": "用户原始回复（一段或逐条）",
    "clarified_need": "翻译后精准需求（结构化版）",
    "is_real_need": true,
    "reasoning": "快速模式：未做深度需求质询，按用户输入直接结构化",
    "clarification_log": [
      {
        "round": 1,
        "trigger": "Q1 核心动作过空",
        "my_question": "...",
        "user_answer": "...",
        "insight_gained": "..."
      }
    ],
    "hidden_meaning_translated": {
      "原话举例": "翻译后能力"
    },
    "internal_alternatives_considered": "未评估（快速模式跳过）",
    "confirmed_by": "...",
    "confirmed_at": "..."
  }
}
```

字段说明：
- `mode: "quick"` 必填，方便环节② 识别画像质量等级
- `skipped_techniques` 透明记录跳过了哪些方法，让用户知情
- `clarification_log` 没有追问则空数组 `[]`，有就如实记录 1 条
- `hidden_meaning_translated` 无 Q4 输入则空对象 `{}`

---

## ⚠️ 注意事项

1. **去敏感化措辞**：4 问的 Q4 列举词只用中性偏好（要稳定 / 抗压 / 主动性 / 沟通好 / 学习能力等），不主动列举"家境 / 大厂 / 性别 / 年龄 / 聪明"等敏感词
2. **保留潜台词翻译能力**：用户自己回答中出现敏感原话时，AI 后台仍按潜台词翻译表处理 + 加合规风险提示
3. **不要伪造 clarification_log**：没追问就空数组，有就如实记
4. **不替业务方下结论**：快速模式仍要尊重业务方表述，不代替决策
5. **支持返工**：如果用户拿到画像后说"画像太粗，重做需求识别"，应允许重置 stage_1，引导走详细模式

---

## 🔗 用户主动返工的处理

如果用户在环节② 之后说"需求识别太粗，重做"：
1. 提示："要重做需求识别，建议走详细模式以挖掘更深层需求。确认重做吗？"
2. 用户确认 → 重置 `stage_1_requirement` 和 `stage_2_persona`，引导用户走 `stage-1-requirement.md`（详细模式）
3. 用户拒绝 → 留在画像调整阶段，不重置

---

⛔ **环节①（快速模式）完成后必须停止回复**，展示诊断结果后等用户确认才进入环节②。
