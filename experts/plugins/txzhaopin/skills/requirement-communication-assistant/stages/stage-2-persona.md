# 📌 环节②：人才画像生成 + 胜任力模型

### 职责
读：`stage_1_requirement`；只写 `meta` 和 `stage_2_persona`。
前置：① `completed`（详细模式 `mode: undefined` 或快速模式 `mode: "quick"` 产出均可）。

> 💡 如果检测到 `stage_1_requirement.mode === "quick"`，画像质量等级标 B+，并在 context 的 `stage_2_persona.input_mode` 中记录"基于快速模式需求识别生成"，方便后续追溯。

---

## 概述

环节②输出两个产物：
1. **四层画像**（硬技能/背景/经验类）— 用于简历搜索筛选
2. **软素质胜任力模型**（基于素质词典）— 用于后续面试出题设计

两者一次性展示给用户，一次确认。

### 表达风格（必须遵守）

- 你是**资深招聘顾问**，不是系统报告员
- ❌ 禁止说：匹配到了、读取了、硬规则、套用、直接基于、符合N+M的规则
- ❌ 禁止暴露文件名、匹配逻辑、内部决策过程
- ✅ 用业务语言解释推荐理由：「这个岗位日常要做X，所以Y能力很关键」
- ✅ 所有匹配和参考过程在后台完成，用户只看到专业的推荐结果

## Part 1：四层画像生成（纯硬技能/背景/经验）

> ⚠️ 四层画像**只放硬技能、背景资质、工作经验类**内容。所有软素质（沟通、协作、学习力、抗压等）统一归入 Part 2 胜任力模型。

### 硬技能 vs 软素质 分类判断规则

| 归入四层画像（硬件） | 归入胜任力模型（软素质） |
|---------------------|------------------------|
| 编程语言/技术栈/工具 | 沟通能力/协作/影响力 |
| 行业经验/项目经验 | 学习能力/好奇心/成长性 |
| 学历/学校/专业 | 抗压/韧性/自驱力 |
| 工作年限/职级 | 思维方式（结构化/创新/批判性） |
| 证书/资质 | 领导力/带团队/辅导 |
| 特定领域知识 | 价值观/文化匹配 |
| 作品集/成果产出 | 执行力/责任心/细致度 |

**判断原则**：能通过简历直接验证的 → 硬件；需要面试中观察行为才能判断的 → 软素质。

### 画像生成逻辑（需求驱动 + 通用模型参考）

#### Step 0：硬技能参考模型匹配

> ⚠️ 模型正文不在本地，所有模型内容通过 MCP 拉取。详见 `SKILL.md → 🔌 MCP 文档调用规范`。

**执行流程**：

1. 读取 `{skill_dir}/references/hard-skill-models-index.md`
2. 从环节①信息中提取 BG 关键词和岗位关键词
3. 在索引中按 `触发条件` 做结构化匹配（一次最多命中 1 条）
4. 命中 → 取 documentId，按 SKILL.md 中 MCP 调用四步法拉取文档正文
5. 拉取成功 → 作为参考输入融入画像（按 1.2 补缺规则）
6. **未命中 / 当前岗位类型无对应硬技能模型 / MCP 失败 / 超时 → 静默跳过**

**兜底原则**：
- 跳过通用模型补缺时，画像照常输出，仅"🟡 优先具备"和"🟢 加分项"可能少 1-3 条
- 不向用户暴露匹配状态、拉取状态、用了哪份模型——所有过程后台完成
- 即便整个 Step 0 全失败，环节② 必须能正常产出画像

#### Step 1：生成四层画像

基于环节①的 `clarified_need` 和 `hidden_meaning_translated`，结合匹配到的通用模型（如有），生成四层画像：

| 画像层级 | 生成逻辑 |
|---------|---------|
| 🔴 必须具备 | 用户硬要求中的硬技能 + 从核心动作推导的必备硬技能 |
| 🟡 优先具备 | 用户软要求中的硬技能 + 潜台词翻译后的硬技能 + 通用模型中高权重(≥20%)但用户未提及的维度 |
| 🟢 加分项 | 需求衍生的关联硬技能 + 通用模型中中等权重(10-20%)但用户未提及的维度 |
| ⛔ 反面特征 | 用户明确的硬件类雷区 + 岗位特性推断 |

**通用模型补缺规则**（有匹配到模型时）：
- 模型中权重 ≥20% 的维度，如果用户需求中完全没提到 → 补入"优先具备"
- 模型中权重 10-20% 的维度，如果用户需求中完全没提到 → 补入"加分项"
- 模型中权重 <10% 的维度 → 不补充
- 用户已明确提及的维度，不管模型权重多少，**以用户表述为准**
- 从模型补充的项必须标注 `来源：通用模型参考（{BG}）`

**注意**：
- 用户需求中的软素质类内容（如"要能抗压"、"沟通要好"），**不放画像，转入 Part 2 胜任力模型作为推荐参考**

---

### 四层画像规则（纯硬件版）

| 层级 | 来源 | 用途 |
|------|------|------|
| 🔴 必须具备（Must Have） | 需求识别中的硬技能硬要求 + 核心动作推导 | 筛选简历硬门槛，缺一不可（建议 3–5 个） |
| 🟡 优先具备（Preferred） | 需求识别中的硬技能软要求 + 潜台词翻译 | 有这些的候选人优先安排面试 |
| 🟢 加分项（Nice to Have） | 需求衍生硬技能、岗位常识推断 | 不作为筛选条件 |
| ⛔ 反面特征（Anti-patterns） | 业务方明确的硬件类雷区 + 岗位特性推断 | 一票否决项（不要带偏见） |

## Part 2：软素质胜任力模型生成

> 基于环节①的需求描述，从素质词典中推荐 6-9 项维度 + 强制包含 4 项集团价值观，生成完整胜任力模型。后续用于面试出题设计。

### Step 1：现有模型智能匹配

> ⚠️ 模型正文不在本地，所有模型内容通过 MCP 拉取。详见 `SKILL.md → 🔌 MCP 文档调用规范`。

**执行流程**：

1. 读取 `{skill_dir}/references/existing-models-index.md`
2. 从环节①信息中提取：BG 关键词、岗位关键词
3. 按【逐级叠加】策略筛选 documentId 列表（不是回退）：
   - **公司级（必加载）**：`26` 集团价值观 + `27` 素质词典
   - **BG 级（按命中加载）**：TEG → `19`；WXG → `14`；IEG/天美 → `37`；S3 → `13`（红线，特殊处理）
   - **岗位级（按命中加载）**：天美策划 → `31`；IEG用研 → `33`；TEG专业岗 → `32`
   
   > 📌 本 Skill 仅服务社招场景，不加载校招（41）/ 产培（35）模型。
4. 对所有命中的 documentId 列表，按 SKILL.md 中 MCP 调用四步法**并行调用**
5. 拉取成功 → 以现有模型维度为基础做个性化调整（叠加合并，岗位级覆盖 BG 级覆盖公司级）
6. **任一文档拉取失败 → 跳过该文档，其余照常使用**
7. **全部失败 → 退化为"无现有模型参考"模式**，直接走 Step 2 从素质词典维度兜底列表中推荐

**S3 红线特殊规则**（命中 documentId=13 时）：
- 不进入维度总览表
- 在环节② 输出末尾**单独追加"红线检查"区块**
- 列出每条红线行为 + "需重点关注"标注

**兜底原则**：
- 不向用户暴露匹配状态、拉取状态、用了哪些模型
- 用业务语言说推荐理由："这个岗位日常要做X，所以Y能力关键"

### Step 2：维度推荐

> ⚠️ 词典正文不在本地。如果 Step 1 中已成功拉取 documentId=27（素质词典），直接使用其内容；如果未拉取或拉取失败，按 SKILL.md 中 MCP 调用四步法单独拉取 documentId=27。

**词典内容**：腾讯集团 5 大类 25 项基础素质词典，是软素质胜任力模型推荐的**唯一维度来源**。

**推荐逻辑**：

1. **如果 Step 1 匹配到现有模型**：以现有模型的维度为基础，结合环节①需求描述做微调（增/删/替换）
2. **如果未匹配到**：纯粹基于环节①的岗位信息和需求描述，从词典 25 项中推荐 6-9 项
3. **如果词典也拉取失败（极端情况）**：使用以下兜底维度库（5 大类 25 项概要）做推荐，并在 context 中标注 `dictionary_source: "fallback"`：
   - 成长潜质类（6项）：成就导向、责任心、学习能力、抗压能力、开放度、自我认知能力
   - 思维类（6项）：用户/客户导向、分析洞察、长期主义、风险管理、创新、数据敏锐
   - 协作类（3项）：沟通能力、合作共赢、人际敏锐
   - 执行类（5项）：执行力、持续优化、灵活应变、严谨细致、原则意识
   - 管理类（5项）：凝聚团队、知人善用、指导培养、科学经营、推动变革

**推荐依据**：
- 岗位核心动作（环节①的 `clarified_need` 中的"核心动作"）→ 推断需要什么软素质
- 用户在环节①提到的软性要求（如"要能抗压"、"沟通要好"）→ 直接对应词典维度
- 岗位常识推断（如管理岗 → 推荐"凝聚团队"类；创新岗 → 推荐"创新"类）

**推荐时必须**：
- 每项给出推荐理由（为什么这个岗位需要这项素质）
- 标注权重（核心维度 1.5x / 一般维度 1.0x）
- 只从词典 25 项中选；定义优先**原文引用词典**；如词典未拉到走 fallback 时，定义可由 LLM 基于维度名生成简明定义，并标注 `definition_source: "fallback"`

### Step 3：强制追加集团价值观

> ⚠️ 价值观正文不在本地。如果 Step 1 中已成功拉取 documentId=26（集团价值观），直接使用其内容；如果未拉取或拉取失败，按 SKILL.md 中 MCP 调用四步法单独拉取 documentId=26。

无论推荐了多少项岗位软素质，**最终输出必须固定追加 4 项集团价值观**。即便 documentId=26 拉取失败，也要使用以下内嵌简要描述兜底（不阻塞输出），并在 context 中标注 `values_source: "fallback"`：

| 维度 | 核心要求（兜底简要版） |
|------|---------|
| 思考 | 条理清晰有逻辑，批判性思维，抓主要矛盾 |
| 正直 | 坦诚沟通不撒谎，敢于直言不唯上 |
| 开放 | 接受新事物，积极求解，高效协作 |
| 务实 | 结果导向使命必达，百折不挠，执行有方法 |

**优先使用原则**：documentId=26 拉取成功 → 使用 MCP 返回的完整价值观正文（含正面/负面行为指标）；失败 → 用上表兜底版本。

**最终维度总数** = 6-9 项岗位软素质 + 4 项价值观 = 10-13 项。

### Step 4：生成完整模型

按 `{skill_dir}/references/modeling-output-template.md` 的格式，为每个维度生成：

```markdown
### {序号}、{维度名}

**定义**：{原文引用素质词典}

**考察要点**：
- {要点1}
- {要点2}
- {要点3}

**正面行为指标**：
1. {基于岗位特点的正面行为1}
2. {基于岗位特点的正面行为2}
3. {基于岗位特点的正面行为3}

**负面行为指标**：
1. {基于岗位特点的负面行为1}
2. {基于岗位特点的负面行为2}

**判断标准**：
- ✅ 优秀：{描述}
- ❌ 不足：{描述}
```

**注意**：
- 定义必须原文引用素质词典，不得改写、合并或拆分
- 考察要点和行为指标**必须基于岗位特点定制**（不是通用的）
- 正面/负面行为必须是面试中可观察到的具体行为

### 建模 5 条硬原则

1. **少即是多**：岗位软素质 6-9 项（不含价值观），超过 9 项强制建议砍减
2. **有定义才算数**：每项必须有定义 + 3正面行为 + 2负面行为 + 判断标准
3. **可观察可区分**：维度必须是面试中可观察到的行为差异
4. **岗位相关**：每项能回答"为什么这个岗位需要"
5. **词典优先**：只从词典25项选，定义原文引用

### 模型健康度检查

生成后自动执行以下检查：

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 维度数量 | 岗位维度 6-9 项 | 超过则建议砍减并说明理由 |
| 定义完整性 | 每项有定义+行为+判断标准 | 补缺 |
| 可观察性 | 每项在面试中可考察 | 标注"此项较难面试考察"并建议替代 |
| 重叠度 | 维度间无明显重叠 | 合并或二选一 |
| 岗位相关性 | 每项有岗位理由 | 无理由则标注建议移除 |
| 价值观完整 | 4项价值观齐全 | 补全 |
