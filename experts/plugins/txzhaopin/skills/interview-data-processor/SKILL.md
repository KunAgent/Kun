面试评价数据的**导入、字段映射、清洗、归一化**工具。

## 适用场景

招聘经理上传自己部门的面试评价 Excel，CodeBuddy 帮他做数据清洗和标准化，为后续的能力建模（interview-talent-modeler）准备干净数据。

- 单部门、单职位为主
- 数据量通常几十到几千条
- **仅支持社招和校招数据，不适用于活水（内部转岗）数据**

---

## 用户输入

- **数据文件**：Excel (.xlsx/.xls) 或 CSV
- **职位名称**（可选）：用于数据筛选
- 招聘类型由系统自动识别（社招 / 校招），无需用户指定

---

## 执行方式

### 一键执行（推荐）

所有清洗逻辑（导入→字段映射→归一化→过滤→质量检查）均由脚本完成，不需要 LLM 参与：

```bash
python3 references/scripts/data_clean.py \
  --input interview_data.xlsx \
  --output cleaned_data.json \
  --report quality_report.md
```

**CodeBuddy LLM 的职责**：调用脚本 → 读取输出 → 展示质量报告 → 处理用户交互（选职位等）。

### 脚本处理内容

脚本自动完成以下步骤（详细规则见 `data_clean.py` 源码）：

| 步骤 | 内容 | 说明 |
|------|------|------|
| 1. 导入解析 | 读取 Excel/CSV，自动识别社招/校招/活水 | 取第一个有数据的 Sheet |
| 2. 字段映射 | 原始列名映射到 16 个标准字段 | 8 必选 + 1 次重要 + 7 可选 |
| 3. 归一化 | result→pass/fail/pending，grade→S/A+/A/A-/B，bg→标准简称，dept→第二层组织 | 归一化结果存为独立字段（gradeNorm/resultNorm） |
| 4. 过滤 | 去空行、去无评价、社招去非 7-11 级 | 校招和无法解析职级的保留 |
| 5. 质量检查 | 阻断性检查 + 警告性检查 | 输出 `quality_report.md` |

### 脚本输出

- **`cleaned_data.json`**：标准化后的记录数组
- **`quality_report.md`**：质量报告（含通过/阻断/警告信息）

---

## 质量检查规则

### 阻断性（不通过则终止，不进入建模）

| 检查项 | 阻断条件 |
|--------|---------|
| 有效记录数 | < 60 条 |
| comment 字段 | 100% 缺失 |
| result 字段 | 100% 缺失 |
| grade 字段 | 100% 缺失 |
| round 字段 | 100% 缺失 |
| position 字段 | 100% 缺失 |
| bg 字段 | 100% 缺失 |

### 警告性（提示但不终止）

| 检查项 | 警告条件 |
|--------|---------|
| 活水数据 | 检测到活水面评记录（已自动排除） |
| 有效记录数 | 60-100 条（置信度较低） |
| 通过样本占比 | < 10% 或 > 90%（样本极不均衡） |
| result/grade 归一化率 | < 80% 有效 |
| dept 字段 | 100% 缺失（无法做部门分析） |
| candidateLevel | 社招且 100% 缺失（无法分职级段） |
| 职级段分布 | 某职级段 < 10 条或 = 0 条 |
| BG 数量 | > 1 个 BG（提示确认数据来源） |
| 职位数量 | > 1 个职位（需用户选择目标职位） |
| 招聘类型 | 同时包含社招和校招（分别生成报告） |

| ❌ 不说 | ✅ 说 |
|--------|------|
| 通过率 | **通过样本占比** |

## 完成后引导

数据清洗完成且质量检查通过后，**主动引导用户进入建模阶段**：

```markdown
---

✅ 数据清洗完成！

**整体概况**：{职位} | {BG名} | 有效记录 {N} 条

**按部门×招聘类型分布**：

| 部门 | 招聘类型 | 记录数 | 通过样本占比 | 评级分布 | 职级段 |
|------|---------|--------|------------|---------|--------|
| {部门1} | {类型} | {N} 条 | {X}% | S({n}) A+({n}) A({n}) A-({n}) B({n}) | {职级段分布或"—"} |
| ... | ... | ... | ... | ... | ... |

**建模计划**：共 {M} 份报告（每份 = 1个部门 × 1种招聘类型 × {职位}），逐一生成。
需要现在开始吗？
```

如果用户确认，将清洗后的标准化数据传递给 **interview-talent-modeler** skill。按 **部门 × 招聘类型** 拆分为多个独立任务，逐一生成报告：
- 每份报告 = 1个部门 × 1种招聘类型 × 1个职位
- 社招报告：分 10-11 级和 7-9 级两个职级段
- 校招报告：整体模式，不分职级段
- 跑完一个出一个，不用等全部完成

---

## 注意事项

1. **社招/校招必须明确**：清洗规则不同（社招有职级过滤，校招没有）
2. **comment 是核心**：没有有效评价的记录直接过滤
3. **BG 和 dept 在清洗阶段就标准化**：不要等到建模阶段再处理
4. **不要修改原始数据**：归一化结果存为独立字段（如 gradeNorm、resultNorm），原始值保留在 grade、result 等字段中
