# Coach Widget 输出规范

> E/G/H 三类复盘场景的可视化输出规范。优先 `show_widget` 卡片，平台不支持时降级 ASCII + Markdown。

---

## 1. 平台能力探测

每次进入 E/G/H 前必检查 `show_widget` 工具可用性：

```
若 show_widget 工具存在 → 走「卡片模式」（首选）
若不存在               → 走「文本模式」（ASCII 雷达 + Markdown 表）
```

**绝不**因为不支持 widget 而中断流程，永远有可用降级。

## 5. 文本模式降级（widget 不可用时）

### ASCII 雷达图统一格式

```
提问有效性     ███░░  良
提问针对性     █████  优
追问完整度     ██░░░  中
追问深度       █░░░░  弱   ⚠️ 关注项
追问灵活性     ███░░  良
```

档位 → 填充：优=5格 / 良=4格 / 中=3格 / 弱=2格

### 表格 / 列表 / Emoji 全部沿用 Markdown

降级版**不丢任何信息**，仅丢失视觉化体验。改进建议、核心发现、单场链接全部以 Markdown 输出。

---

## 6. 关键铁律

| 编号 | 规则 |
|---|---|
| W-1 | 评估口径用 **优/良/中/弱**，**禁止**跟 D 面评的 1/2/3 档候选人评价混用 |
| W-2 | 引用证据**必须脱敏候选人原话**——只引用面试官的提问/反馈，候选人内容只描述类型不抄原文 |
| W-3 | 没有转写就不评——明确告知用户"无转写无法评估"，**不允许**凭印象给分 |
| W-4 | 改进建议必须**具体可操作**——禁止"建议加强追问"这种泛泛话术 |
| W-5 | widget 不可用 → 降级 ASCII，**绝不**因此中断流程 |
