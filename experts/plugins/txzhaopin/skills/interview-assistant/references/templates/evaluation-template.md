# 面评输出模板 v2.0

> 基于三档评价体系的面评结构化输出模板。替代 v1.x 的 evaluation-templates.md。

## 面评整体结构

```
1. 总评结论
2. 候选人背景简述
3. 各维度评分 + 档位标签 + 场景证据
4. 红线检查（S3 专用，非 S3 业务跳过）
5. 风险点
6. 综合建议
```

---

## 一、总评结论

**要求**：开门见山，一句话给出结论和核心理由。

**格式**：
```
**总评**：[建议录用 / 不建议录用 / 待定]

[一句话核心理由]
```

**示例**：
- 「**总评**：建议录用。候选人在聪明度和自驱力两个核心维度表现突出，游戏理解深度超出校招平均水平。」
- 「**总评**：不建议录用。候选人离职动机存在疑点，且协作性维度有明确负面证据。」
- 「**总评**：待定。核心维度表现中等，需结合业务面评价综合判断。」

---

## 二、候选人背景简述

**要求**：2-3 句话概括关键背景，不要超过 50 字。

**格式**：
```
候选人 [姓名]，[学历/工作年限/核心经验]。
```

---

## 三、各维度评分

**要求**：逐维度给出评分、档位标签和场景证据。

### 三档评价标准

#### 🔴 1-2 分 — 不推荐档

**写作要求**：
- 必须给出**明确的淘汰原因**
- 至少 **2 个负面行为证据**（具体场景 + 候选人表现）
- 说明**风险点**（如果录用可能带来什么问题）

**格式**：
```
### [维度名称]：[X] 分 — 不推荐

**评价**：[1-2 句话核心判断]

**证据**：
1. [场景描述] → [候选人的具体表现] → [为什么是负面信号]
2. [场景描述] → [候选人的具体表现] → [为什么是负面信号]

**风险**：[如果录用，在这个维度可能带来什么问题]
```

#### 🟡 3 分 — 待定档

**写作要求**：
- 需说明**犹豫原因**
- **正反两方面证据**都要给
- 提供**补充核实建议**

**格式**：
```
### [维度名称]：3 分 — 待定

**评价**：[1-2 句话核心判断]

**正面**：[正面行为证据]
**疑虑**：[负面或不确定的信号]

**建议**：[需要进一步核实的点]
```

#### 🟢 4-5 分 — 推荐档

**写作要求**：
- 突出**核心亮点**
- 至少 **2 个正面行为证据**
- 说明**岗位适配理由**

**格式**：
```
### [维度名称]：[X] 分 — 推荐

**评价**：[1-2 句话核心判断]

**证据**：
1. [场景描述] → [候选人的具体表现] → [为什么是正面信号]
2. [场景描述] → [候选人的具体表现] → [为什么是正面信号]

**适配**：[为什么这个维度的表现适合目标岗位]
```

---

## 四、红线检查（S3 专用）

**仅 S3 业务使用**，非 S3 业务跳过此部分。

**格式**：
```
### 红线检查（业务红线模型）

| 维度 | 检查结果 | 说明 |
|------|---------|------|
| 正直 | ✅ / ⚠️ / ❌ | [具体说明] |
| 务实 | ✅ / ⚠️ / ❌ | [具体说明] |
| 开放 | ✅ / ⚠️ / ❌ | [具体说明] |
| 思考 | ✅ / ⚠️ / ❌ | [具体说明] |

**综合判定**：[通过 / 存在风险 / 不通过]
```

---

## 五、风险点

**要求**：列出所有识别到的风险点，必须具体。

**格式**：
```
### 风险点

1. [具体风险描述]（严重程度：高/中/低）
2. [具体风险描述]（严重程度：高/中/低）

如无明显风险点，写：「无明显风险点。」
```

---

## 六、综合建议

**格式**：
```
### 综合建议

**录用建议**：[建议录用 / 不建议录用 / 待定]
**核心理由**：[2-3 句话]
**后续动作**：[如有需要进一步确认的事项]
```

---

## 评价原则（适用于所有输出）

1. **结论先行**：先给结论，再给理由
2. **证据支撑**：所有判断必须有具体行为事例
3. **禁止空话**：不写「沟通能力强」「综合素质高」
4. **客观中立**：不主动美化候选人
5. **综合判断**：允许灵活结论（如「某维度未达标但综合判定可用」）
6. **语言专业但不官僚**：避免套话和模板式语言

## 禁止项

- ❌ 禁止空话（如「沟通能力强」）
- ❌ 禁止无证据的判断
- ❌ 禁止信息不足时强行输出
- ❌ 禁止美化候选人

---

## 输出版本规范

面评初稿完成后，需生成两个精简版本：

### 系统提交版（≤400 字）

**用途**：录入招聘系统
**格式要求**：
- 字数 ≤ 400 字（中文字符，不含标点空格）
- 结构化格式，可使用分点
- 必须包含：总评结论 + 核心维度评分 + 关键证据 + 录用建议
- 每个维度只保留最关键的 1 个行为证据
- 可使用 Markdown 格式

**结构**：
```
总评：[结论]。[核心理由]。

维度评估：
- [维度1]：[X]分。[关键证据]。
- [维度2]：[X]分。[关键证据]。
- [维度3]：[X]分。[关键证据]。

风险：[如有]。
建议：[录用建议 + 后续动作]。
```

### 总经理微信版（≤200 字）

**用途**：微信发给总经理，快速了解候选人情况
**格式要求**：
- 字数 ≤ 200 字（中文字符，不含标点空格）
- **纯文本连贯叙述**，不用标题、不分点、不用表格
- 不使用 Markdown 格式标记
- 直奔结论，一段话说完
- 核心信息：结论 + 1-2 个关键理由 + 是否推荐

**示例**：
```
候选人张三，XX大学计算机硕士，3年游戏策划经验。面试表现较好，游戏理解深度突出，能从设计层面分析核心玩法和用户体验，独立策划过两款中等规模手游关卡。协作能力良好，有跨职能推动项目经验。但对数值平衡的理解偏理论化，缺乏实际调优经验，需入职后重点培养。整体建议录用。
```

### 格式检查

生成两个版本后，使用 `scripts/format_evaluation.py` 进行格式检查：
- `python format_evaluation.py <file> system` — 检查系统提交版
- `python format_evaluation.py <file> wechat` — 检查微信版
- `python format_evaluation.py <file> all` — 同时检查（文件用 `---` 分隔）
