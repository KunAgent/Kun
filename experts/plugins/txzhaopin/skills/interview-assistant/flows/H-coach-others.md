# 类目 ⑦ 复盘 · 招聘经理评估面试官（H-coach-others）

> **场景**：招聘经理 / HR / BG 招聘负责人想**评估别人（团队下面的面试官）**的最近 N 场（默认 5 场，可调 3-5）面试表现，输出该面试官的多场综合评估 + 给招聘经理的判断结论 + 给被评估人的反馈话术。
>
> **触发词**：分析下王五最近 5 场面试 / 看团队某面试官表现 / 评估面试官 XXX / 我团队的面试官谁面得最好

---

## H-0 · 入口与权限边界（CRITICAL）

| 规则 ID | 内容 |
|---|---|
| H-RULE-1 | 🔴 **权限边界**：当前用户**只能评估**自己负责岗位下的面试官——禁止跨部门偷看 |
| H-RULE-2 | 🔴 **数据来源优先级**：① 调 H-1 流程拉对方转写做新评估 → ② 拉不到时降级用对方已存档的自评数据 → ③ 都不行就**拒绝评估** |
| H-RULE-3 | 🔴 **隐私收口**：评估输出**禁止引用候选人原话**（涉及面试候选人隐私），只能引用面试官的提问/反馈 |
| H-RULE-4 | 🔴 **存档隔离**：A 招聘经理对 B 面试官的评估，存档命名**带 `__by-<A-login>` 后缀**——同一面试官被多人评估时各自结果不互覆盖 |
| H-RULE-5 | 输出**必须**给招聘经理一段「给被评估人的反馈话术草稿」——但**不允许**自动发送，必须用户手动确认才能调 hrclaw-messenger |
| H-RULE-6 | **3-5 场**为推荐区间，>10 场拒绝（token 治理 + 隐私顾虑） |

---

## H-1 · 三阶段流程总览

```
Stage 1 · 探权：当前用户是该面试官的招聘经理吗？
   ↓ 通过
Stage 2 · 列清单：拉该面试官最近 N 场已完成面试（仅限我负责的岗位）
   ↓ 用户决策
Stage 3 · 评估：每场单独评估（循环），最后聚合输出
```

---

## H-2 · Stage 1 · 探权

调 recruit-mcp 验证「当前用户是 X 面试官 Y 个岗位的招聘经理」：

```bash
mcporter recruit-mcp.SearchAPI \
  query="查岗位归属：面试官 <X-login> 在哪些岗位下做过面试，这些岗位的招聘经理是谁"
```

- 接口存在且校验通过 → 进 Stage 2
- 接口缺失 → **降级**：明确告知用户"接口校验暂未实现，请用户**自我承诺**只评估自己负责的面试官"，记录到上报作为风险标记
- 校验失败（不是该岗位招聘经理）→ **拒绝**："你不是 X 面试官的相关招聘经理，无法跨部门评估"

> ⚠️ 接口降级路径上，**必须**让用户显式承诺（不只是 yes/no），把承诺记录写到 hooks 上报字段 `manager_promise=true`。

## H-3 · Stage 2 · 列清单 + 用户决策

### 3.1 拉最近 N 场已完成面试

```bash
mcporter recruit-mcp.SearchAPI \
  query="面试官 <X-login> 最近 5 场已完成面试，限招聘经理为 <当前 login> 的岗位"
```

**接口缺失时的降级链**：
1. 退 1：拉所有 X 面试官最近面试 → 客户端按"我负责的岗位"过滤
2. 退 2：拉 X 面试官的 `coach-archive/` 自评记录 → 用户确认 traceId 列表
3. 退 3：要求用户**手动给 traceId 列表**

### 3.2 输出清单（不读转写）

```
📋 **王五最近 5 场已完成面试**（限你负责的岗位）

  | # | 候选人 | 岗位            | 日期    | 已存档评估？  |
  | 1 | A**    | WXG 后端 P5     | 06-08   | ✅ 王五自评   |
  | 2 | B**    | WXG 后端 P5     | 06-05   | ❌ 未评估     |
  | 3 | C**    | WXG 后端 P5     | 06-02   | ❌ 未评估     |
  | 4 | D**    | WXG 后端 P5     | 05-28   | ✅ 王五自评   |
  | 5 | E**    | WXG 后端 P5     | 05-25   | ❌ 未评估     |

总：5 场可见，3 场未做过任何评估

📋 你想：
  ① 跳过未评估的，仅用已存档数据出概览（最快）
  ② 把 3 场未评估的全部跑一遍评估（预计 ~3 分钟，token 成本中等）
  ③ 选其中 N 场详细评估（推荐 ≤3 场）
```

### 3.3 用户决策处理

| 选项 | 处理 |
|---|---|
| ① | 跳到 H-5 聚合（仅用已存档数据） |
| ② | 进 H-4 循环评估全部未评估场 |
| ③ | 用户给 3 个序号 → H-4 循环 3 场 |
| 用户说"我只给 traceId 自己挑" | 直接进 H-4 用用户给的清单 |

## H-4 · Stage 3 · 单场评估循环（不堆叠 context）

> **关键设计**：每场**独立**调用——`fetch_transcript → LLM 评估 → 存档`，循环 N 次。**禁止**把 N 场转写一并塞 context（爆 token）。

### 4.1 单场子流程

For each traceId in 用户选择的列表：

```
1. fetch_transcript --trace-id <id>          # 退码 3 跳过该场
2. 加载 coach 知识：
     references/coach/bei-framework.md
     references/coach/scoring-rubric.md
3. 投喂转写 + 知识 + 模型路由的维度清单 → LLM 输出 E-3 同结构 JSON
4. 调 save_coach_eval.py 存档：
     --interviewer-login <X-login>
     --evaluator-login <当前用户 login>     # 关键：传招聘经理 login
     --eval-json '...'
   存档文件名带 __by-<招聘经理-login> 后缀（隔离）
5. 进入下一场（用户可看进度条）
```

### 4.2 进度可视化

```
🔄 评估中...
  ✅ B** 那场已完成（06-05）
  🔄 C** 那场进行中（06-02）
  ⏸ E** 那场待评（05-25）
```

### 4.3 转写不可用场处理

某场退码 3 → 该场标记为"无转写无法评估"，**不计入**最后聚合，但在最终输出明示："3 场目标中有 1 场无转写未能评估"。

## H-5 · Stage 3+ · 聚合输出

调 `aggregate_coach.py`（带 evaluator-login 过滤——只看我做过的评估）：

```bash
python3 scripts/aggregate_coach.py \
  --interviewer-login <X-login> \
  --evaluator-login <当前用户 login> \
  --limit 5 \
  --scope all
```

### 5.1 widget 模式

按 `references/coach/widget-spec.md §4` 输出 7 区块卡片：
- 评估摘要
- 总体雷达 vs BG 基线
- 行为规范达标率
- **系统性问题**（多场重复）
- 单场链接列表
- 给招聘经理的判断结论
- 给被评估人的反馈话术

### 5.2 ASCII 降级模式

```markdown

📈 总体表现
  整体：B 级（合格但有提升空间）
  vs BG 基线：略低于 WXG 后端面试官平均水平

🅰️ 行为规范达标率
```

## H-6 · 反馈发送（可选 · 用户手动确认）

用户选「一键发企微 Tips」→ 调 hrclaw-messenger：

⚠️ **必须**遵守：
- 接收人是被评估面试官 X 一人，**不要**抄送多人
- 内容用 H-5 的草稿，**用户可改**之后再发
- 发送前**必须**明示："这条会发到 X 的企微 Tips，确认发送？"
- 发送动作记上报 `coach_others_feedback_sent`

---

## H-7 · 上报（hooks）

```bash
# 评估发起
bash scripts/track.sh --event coach_others_initiated \
  --target-login <X-login> --n-target <场数计划>

# 评估完成
bash scripts/track.sh --event coach_others_completed \
  --target-login <X-login> --n-evaluated <实际场数> \
  --manager-promise <true|false>   # 接口降级时记录

# 反馈发送（用户确认后）
bash scripts/track.sh --event coach_others_feedback_sent \
  --target-login <X-login>
```
