# 能力目录 · capability-catalog

> **用途**：当 agent 的 §-1/§-2 关键词路由**命中失败**、或用户需求**跨多个能力**时，Read 本文件做语义匹配与组合规划。
> **不是常驻必读**——只在兜底（路由四层算法第 3/4 层）时按需加载，省常驻 context。
> **维护约定**：本目录是「导航索引」，只记 能做 / 输入 / 输出 / 关键词 / 可组合点；**字段级细节以各 skill 的 SKILL.md 为准**，本文件过时不影响执行，仅影响发现。

---

## 一、第一层：用户可直接触发的业务 skill（12 个）

> agent 路由时应命中到这一层。每条 = 能做什么 / 需要什么输入 / 产出什么 / 命中关键词 / 输出能否被下游消费。

### 1. interview-assistant（面试全流程）
- **能做**：面试待办查询、面试安排（约/改/取消/查日程）、面试准备（选模型/拉简历详情/评简历/出题）、面评（拉转写+写草稿）、复盘单场(E)、复盘成长(G)、招聘经理评估面试官(H)、面试官画像(I)
- **输入**：候选人姓名 或 RID 或 traceId；部分场景无需输入（如"我的待办"）
- **输出**：待办列表 / 简历详情 / 面评草稿 / 转写文本 / 画像报告（可被下游消费：traceId、候选人列表、简历RID）
- **关键词**：面试、面评、转写、待办、约面、改面、复盘、画像、出题、面试计划
- **可组合**：✅ 输出 traceId / RID / 候选人列表，可喂给其他 skill

### 2. hr-data-router（HR数仓+招聘历史数据分析+看板）
- **能做**：员工/组织/合同/调动/入离职/编制等基础HR数据；招聘漏斗/转化率/伯乐ROI/学校分布/录用结构/完成率/达成率；**数据看板/大盘/dashboard**
- **输入**：查询维度（部门/年份/人群/时间区间）+ 指标
- **输出**：结构化数据表 / 统计结果 /（如需）前端可视化代码（内部编排 data-warehouse-api-codegen + hr-vue-next）
- **关键词**：完成率、达成率、转化率、漏斗、分布、统计、占比、排名、看板、大盘、dashboard、毕业生数据、录用数据、XX部门数据
- **可组合**：✅ 输出数据可作为报告/看板的数据源

### 2b. recruit-data-dashboard（招聘数据查询入口·社招治理级指标）
- **能做**：用户问招聘数/指标的**首选入口**——内置已治理的社招 44 个指标口径（在招需求/各环节面试数与通过率/薪谈/offer/入职/入职率/平均招聘天数等），问句即可拿到精准、可对外汇报/KPI 引用的数，无需懂表与 SQL。**用户问"能查什么(招聘)数 / 你能查哪些指标 / 怎么问数"时，读 `skills/recruit-data-dashboard/references/askable-metrics.md`**——开头是**五种典型场景·推荐问法**（A 我就要个数 / B 对比 / C 漏斗 / D 整体进展 / E 为什么，每种带推荐问法+输出物形态）+ 黄金问数公式 + 省时技巧，之后是按业务环节分组的指标话术清单；按用户语境挑给参考。
- **输入**：自然语言指标问题，或"能查什么数"探索类问题
- **输出**：单值 / 对比表 / 漏斗 / 4 卡总览 / 归因；口径强披露（时间/主体/国家/流程范围/时效）
- **关键词**：能查什么数、能查哪些指标、社招看板、社招漏斗、offer 接受率、在招需求进展、入职率、转化率（社招）、**为什么 XX 降了/大跌、XX 为啥这么低、归因/复盘**（社招指标归因走场景 E，先查真实数据再给假设，🔴 严禁脑补编数）
- **边界**：当前指标库只治理了**社招域**；校招/编制/员工等清单外问题降级到 hr-data-router 走数仓通用查询（口径现场确认），不谎称已封装。
- **与 hr-data-router 关系**：社招指标上重叠，由 agent §-1.6 反问消歧后进入；社招对外汇报/KPI 首选本 skill（口径治理级）。

### 3. recruitment-inquiry-bot（招聘规则制度问答）
- **能做**：回答招聘规则/制度/流程/操作方法类问题（活水冷冻期、伯乐奖金算法、三方协议、Offer审批流等），检索知识库
- **输入**：自然语言问题
- **输出**：知识库检索后的文字答案
- **关键词**：制度、规则、怎么算、怎么操作、多久、什么条件、活水规则、伯乐奖金、流程是什么
- **可组合**：❌ 纯问答终点，无结构化输出可供下游

### 4. zhaopin-operations（校招简历搜索）
- **能做**：校招简历搜索、筛选、推荐
- **输入**：岗位画像 / 搜索条件（学校/专业/经验等）
- **输出**：校招候选人列表（含RID）
- **关键词**：校招搜简历、找校招候选人、校招推荐、搜应届生
- **可组合**：✅ 输出候选人RID列表，可喂给 interview-assistant 拉详情/约面

### 5. zhaopin-social-operations（社招简历搜索）
- **能做**：社招简历搜索（6步流程：画像→检索→并发搜索粗筛→确认→精读→表格输出）
- **输入**：岗位画像 / 工作年限 / 技能等
- **输出**：社招候选人列表（含RID）
- **关键词**：社招简历、社招搜索、找社招候选人、招人、工作年限≥N年
- **可组合**：✅ 输出候选人RID列表，可喂给下游

### 6. recruitment-process-tracker（社招流程进度查询）
- **能做**：查社招流程进度（我负责的/指定招聘经理的，多维过滤+智能洞察）。**注意：社招专用**
- **输入**：（默认查自己）招聘经理 / 候选人 / 岗位 / 部门 / 状态 / 时间区间
- **输出**：流程进度列表 + 偏慢预警
- **关键词**：流程到哪步、进度、我负责的流程、社招进度、卡在哪
- **可组合**：✅ 输出候选人/流程列表

### 7. warming-recruit-manager（校招签约后保温）
- **能做**：校招签约后保温经营SOP（待入职名单、保温话术、毁约风险识别、HRClaw通知导师上级、定时保温播报）。**注意：校招专用**
- **输入**：（默认查自己负责的）待入职候选人
- **输出**：保温名单 / 话术 / 风险评估 / 通知发送结果
- **关键词**：保温、签约后、待入职、毁约风险、稳定签约、保温话术、保温播报
- **可组合**：✅ 输出待入职候选人列表；调用 hrclaw-messenger 发通知

### 8. requirement-communication-assistant（需求识别+画像+JD · 仅社招）
- **能做**：招聘需求三环节链路（真实需求识别 → 人才画像生成含胜任力模型 → JD生成）；需求识别支持**详细模式**（多轮挖掘 10-15 轮）和**快速模式**（4 问一次回完 3-5 轮）
- **适用范围**：⚠️ **仅服务社招**；校招需求不走本 skill
- **输入**：原始招聘需求描述
- **输出**：结构化需求 / 人才画像 / 胜任力模型 / 可发布JD
- **关键词**：我有个招聘需求、新开了HC、要招一个、帮我分析岗位、写JD、生成画像、快速生成画像、我赶时间
- **可组合**：✅ 输出胜任力模型/画像，可喂给 assessment-quality-expert 出题/面试设计

### 9. assessment-quality-expert（甄选方法论+面试设计）
- **能做**：胜任力建模、JD生成、单题出题指导(BEI/案例/LGD)、岗位面试设计方案、题目审核、面评质量审核、测评工具推荐
- **输入**：岗位/胜任力模型/已有面评或题目
- **输出**：胜任力模型 / 面试设计方案 / 题库 / 审核报告
- **关键词**：胜任力建模、面试设计、出题方法、考察维度、面评质量审核、题目审核、用什么标准考察
- **可组合**：✅ 输出面试设计方案，可导出到 interview-assistant

### 10. interview-data-processor（面评数据清洗）
- **能做**：面试评价Excel/CSV的字段映射、清洗、归一化
- **输入**：上传的面试评价 Excel/CSV
- **输出**：标准化面试评价数据
- **关键词**：面试数据、面评数据、数据清洗、处理Excel、导入面试数据、整理面试评价
- **可组合**：✅ 输出标准化数据，是 interview-talent-modeler 的前置输入

### 11. interview-talent-modeler（面评数据建模）
- **能做**：基于清洗后的面评数据提取能力要素，生成岗位能力模型和人才标准
- **输入**：清洗后的面试评价数据（来自 interview-data-processor）
- **输出**：岗位能力模型 / 人才标准
- **关键词**：面试建模、能力模型、人才标准、岗位建模、面评分析、生成招聘标准
- **可组合**：✅ 与 interview-data-processor 强绑定（清洗→建模两步链）

### 12. daily-routine-builder（定时任务 · 横切层）
- **能做**：把任意能力变成"每天/每周/每月自动跑"的定时任务（automation_update调度）
- **输入**：要定时的业务诉求 + 频率/时间
- **输出**：已配置的 automation 任务
- **关键词**：每天、每周、每月、定时、自动、提醒我、scheduled、cron、recurring
- **可组合**：✅ 横切层，可把上面任意 skill 的能力包装成定时任务

## 三、常见跨域组合范例（agent 自动拆步执行）

> 当单个 skill 覆盖不了，按下表拆步。**先告诉用户"我分N步：先X后Y"再执行不是必须**——可直接自动拆步执行，跑完汇总结果。

| 用户需求 | 拆解 | 数据流 |
|---|---|---|
| "查A部门校招漏斗，再推荐几个985候选人" | ① hr-data-router(漏斗) → ② zhaopin-operations(搜简历) | 两步独立，分别产出后合并呈现 |
| "新开个后端HC，帮我把题也出了" | ① requirement-communication-assistant(需求+画像+胜任力) → ② assessment-quality-expert(出题) | 画像/胜任力模型喂给出题 |
| "把这份面评Excel分析出能力模型" | ① interview-data-processor(清洗) → ② interview-talent-modeler(建模) | 清洗数据喂给建模 |
| "搜几个社招候选人然后帮我约面" | ① zhaopin-social-operations(搜) → ② interview-assistant·S(约面) | 候选人RID喂给约面 |
| "每周给我发A部门招聘漏斗" | ① daily-routine-builder(建任务，prompt=查A部门漏斗) | 横切包装，执行时再由agent走hr-data-router |
| "需求沟通完直接发JD给候选人" | ① requirement-communication-assistant(出JD) → 用户自行发送 | JD为终点产物 |

## 四、组合规划算法（agent 兜底时执行）

```
路由四层都没命中单个 skill
    │
    ├─ Step A: Read 本文件，对用户需求做语义匹配
    │         （拆出需求里的"动作动词 + 对象 + 维度"）
    │
    ├─ Step B: 单 skill 能覆盖？
    │         ├─ 能 → 直接路由，结束
    │         └─ 不能 → 进 Step C
    │
    ├─ Step C: 查"组合范例表" + "可组合点"，能否用2+skill串起来？
    │         ├─ 能 → 自动拆步执行（产出A → 喂B → 汇总）
    │         └─ 不能 → 进 Step D
    │
    └─ Step D: 确实无覆盖 → §-0 反问澄清；仍无解 → 坦诚告知能力边界
              🚫 绝不盲目调 MCP API 撞运气
```
