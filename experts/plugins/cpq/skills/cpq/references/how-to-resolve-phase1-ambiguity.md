# Phase 1 歧义解决（阶段 D 子规则）

> **定位**：[how-to-parse-product-list.md](./how-to-parse-product-list.md) 阶段 D 的执行细则。Phase 1 落盘前**必须**按本模板做一次结构化追问。
>
> **设计依据**：决策 3 = C 模式（一次结构化追问 + 默认提案 + 默认值合法范围约束）+ Phase 1 单次执行原则（漏问 = 信息永久丢失）。

---

## 设计目标

| 目标           | 说明                                          |
| -------------- | --------------------------------------------- |
| 一次性问完     | Phase 1 不允许多轮追问；漏问 = 信息永久丢失   |
| 默认提案合理   | 默认值必须是"保守不推进"，不能是"AI 帮你猜了" |
| 用户决策成本低 | 平均回复一次 "go" 即过；只有 A 段必须显式回答 |
| 透明可追溯     | 每个推断标注"推断依据"，让用户判断是否接受    |

---

## 三段式结构

```
Phase 1 解析完成（识别出 N 行产品），请确认下列推断（任意修改后回复 "go"）：

【A 段 · 必须确认（无默认值）】
  - 售卖模式（如有歧义）
  - 多地域取舍（如有歧义）
  - COMPLIANCE 触发（如有命中）
  - OCR 低置信 cell（如有）

【B 段 · 默认提案（不修改即接受）】
  - IMPLICIT_SPEC 推断（默认 = 不推断）
  - 未识别列处置（默认 = 忽略）

【C 段 · 一次性告知（不追问）】
  - 已忽略的 META 列（不阻断，让用户主动喊停）

回复格式：
  - "go" 接受全部默认（A 段必须答）
  - "1=预留实例RI" 仅修改部分项
```

---

## A 段 · 必须确认项

### A.1 售卖模式追问

**触发条件**：

- 任意行 `售卖模式` 列为空
- 且原始输入存在关联信号（"承诺三年" / "三年合同" / "购买周期 36 个月" 等）

**模板**：

```
1. 售卖模式：原始清单出现"承诺三年"但未明确售卖模式。
   ☐ 包年包月 3 年（按月计费 × 36，可灵活退款）
   ☐ 预留实例 RI 3 年（一次性付清，不可退款）
   ☐ 节省计划 SP 3 年承诺（按消费量自动折扣）
   ☐ 包销 3 年（大客户合同，需供应商审核）
   👉 请选一项（不能默认）
```

**默认值合法范围**：❌ 不许默认。原因：

- "承诺三年"在 cn / intl 多个产品上的可选售卖模式不一致
- 凭常识默认（如默认包年包月）违反 §全局禁令第 5 条
- AI 无法判断用户是否有 RI / SP 合同

### A.2 多地域追问

**触发条件**：

- 原始输入含 ≥ 2 个不同地域
- 且用户原始意图不明确（没说"两个都要" / 没说"只要某个"）

**模板**：

```
2. 多地域：清单出现地域 [新加坡, 香港, 法兰克福]，请选：
   ☐ 拆三单（每个地域单独配置单）
   ☐ 笛卡尔积（每地域复制全部产品 → 总行数 × 3）
   ☐ 仅 [新加坡]（其他丢弃）
   ☐ 仅 [新加坡, 香港]（手选两个）
   ☐ 自定义（请告知具体规划）
   👉 请选一项（不能默认）
```

**默认值合法范围**：❌ 不许默认。原因：错选会导致 phase1.md 行数差异极大，下游 Phase 5 写入金额估算偏差几倍。

### A.3 COMPLIANCE 触发追问

**触发条件**：

- 任意 cell 命中 [`data/phase1-token-dict/compliance.md`](./data/phase1-token-dict/compliance.md)（如出现 `等保 2.0` / `GDPR` / `金融云` 等）

**模板**：

```
3. 合规要求：清单出现合规要求 [等保 2.0]。
   该要求会强制改变可选 SPU 集合：
   ☐ 强制使用专属云 / 金融云 SKU（价格高，但通过等保认证）
   ☐ 仅作为备注，按普通 SKU 报价（不通过等保认证，价格低）
   ☐ 跳过此清单（不报价合规相关产品）
   👉 请选一项（不能默认）
```

**默认值合法范围**：❌ 不许默认。原因：合规决策直接决定客户能否使用，错选可能造成法律风险。

### A.4 OCR 低置信 cell 追问

**触发条件**：

- A.0 输入归一化阶段标记的低置信 cell（见 [`how-to-normalize-input.md`](./how-to-normalize-input.md)）

**模板**：

```
4. OCR 识别低置信 cell：
   - 行 3 "规格" 列：识别结果 "标准型 SS5"，可能是：
     ☐ 标准型 S5
     ☐ 标准型 SA5
     ☐ 其他（请告知）
   👉 请选一项或提供原始信息
```

**默认值合法范围**：❌ 不许默认。原因：OCR 错误率高，错填会传到下游搜索关键词。

---

## B 段 · 默认提案项

### B.1 IMPLICIT_SPEC 推断（默认 = 不推断）

**触发条件**：

- 任意行 `推断标记` 列含 `<token>→<目标>`（如 `Ice_Lake→S6`）
- 命中决策 1.2 标准：该推断会改变 SPU ID

**模板**：

```
✓ CPU 推断：Ice Lake → 标准型 S6（推断依据：implicit-spec-cpu.md）
   👉 改成？
     ☐ 列全部 Ice Lake 候选（让 Phase 4 列出 S6/S6.LARGE 等）
     ☐ 强制 SA5（用户主动指定 AMD）
     ☐ 不推断（按"标准型"模糊搜，Phase 4 候选会更多）
   ✅ 默认：不推断（保守路径，搜索词不含 S6）
```

**默认值合法范围**：✅ 默认 = "不推断"。

理由：

- "不推断" 是**保守路径**，不会引入错误的 SKU 偏好
- 用户即使忘了改，Phase 4 映射表会展示候选，用户最终决策权不丢
- "强制套用 AI 推断"才违反 §全局禁令第 3 条

### B.2 未识别列处置（默认 = 忽略）

**触发条件**：

- A.1 列级语义分类时无法归到 7 类的列（即 `unmapped_columns > 0`）

**模板**：

```
✓ 未识别列：'优先采购等级'（A / B / C 三档）
   👉 改成？
     ☐ 业务备注（写入 备注 列，不影响搜索）
     ☐ 折扣信号（按值进 优惠策略 列）
     ☐ 影响 SKU（请说明如何影响）
   ✅ 默认：忽略（不进 phase1.md，归 META 后丢弃）
```

**默认值合法范围**：✅ 默认 = "忽略"。

理由：

- "忽略" 是不影响下游的最保守选择
- 用户没回应不会传递错误信号
- 配合 C 段一次性告知，给用户最后的发现机会

---

## C 段 · 一次性告知项（不追问 · 决策 7 补丁）

**触发条件**：

- 决策 7 = A 全归 META 时的"告知不追问"补丁
- A.1 已识别为 META 类的列（如 `备注` / `负责人` / `单价`）

**模板**：

```
⚠️ 以下信息已识别但忽略，请确认无误（不影响流程，可继续）：
  - 列 '业务部门'（识别为 META，归为业务标识，不进 phase1.md）
  - 列 '负责人'（识别为 META，归为人员标识，不进 phase1.md）
  - 列 '单价' / '总价'（识别为 META，归为价格列，由 D 段询价覆盖）
  - 列 '备注'（识别为 META，已抽取折扣信号 → 优惠策略列，原文丢弃）

如果其中含报价相关信号（如战略客户标识 / 框架协议号），请告知。
否则继续。
```

**用户回复处理**：

- 用户没回应 / 直接回复 "go" → 视为确认，按归类处理
- 用户喊停（如"`备注` 列其实是折扣口径，不要丢"）→ AI 重新分类该列，**重跑 A.1 + A.2**（局限于受影响列），不算违反不可逆原则（Phase 1 还没落盘）

## 用户回复解析规则

### 6.1 完整接受默认

```
用户：go
```

**解析**：

- 检查 A 段是否所有项都已答 → 否则报错"A 段必须显式回答，不能 go"
- A 段已答 + B 段全用默认 + C 段视为确认
- 落盘 phase1.md

### 6.2 部分修改

```
用户：1=预留实例RI, 2=拆两单, 4=标准型 SA5
```

**解析**：

- `1=预留实例RI` → A.1 售卖模式 = 预留实例 RI
- `2=拆两单` → A.2 多地域 = 拆两单
- `4=标准型 SA5` → A.4 OCR 修正
- B 段未提及 → 用默认
- C 段视为确认
- 落盘 phase1.md

### 6.3 全部接受 A 段默认（不允许）

```
用户：go
（A 段未答）
```

**解析**：报错并重新追问：

```
❌ A 段必须显式回答（无默认值）：
   1. 售卖模式 ?
   2. 多地域取舍 ?

请回复完整选项后再 "go"。
```

### 6.4 错误格式

```
用户：可以
用户：随便
用户：你看着办
用户：默认就行（A 段未答时）
```

**解析**：识别为**模糊回复**，不允许擅自填默认。重新追问：

```
请明确回答 A 段问题，模糊回复（如"看着办"/"默认"）会让我无法决策。
```

## 与 Phase 2.6 选品意图追问的边界

| 阶段                     | 追问内容                                         | 时机                         |
| ------------------------ | ------------------------------------------------ | ---------------------------- |
| Phase 1 阶段 D（本模板） | 售卖模式 / 多地域 / 推断 / 未识别列 / OCR / 合规 | Phase 1 落盘前               |
| Phase 2.6 选品意图       | 每行的 a/b/c 意图选择                            | Phase 2.5 之后、Phase 3 之前 |

两者**不重叠**：

- Phase 1 D 段问的是"原始输入怎么解析"
- Phase 2.6 问的是"已解析的清单怎么搜索"

❌ 禁止把 Phase 2.6 的意图追问提前到 Phase 1（违反阶段职责）。

---

## 追问失败的兜底

如果用户中断 / 长时间无回复 / 主动取消：

| 场景                     | 处置                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| 用户回复 "取消" / "停止" | 不落盘 phase1.md，告知"Phase 1 已取消，请重新启动"                                               |
| 用户长时间无回复         | 不主动催促，等待用户下次激活会话；不落盘                                                         |
| 用户在 D 段切换话题      | 把 D 段歧义清单**留在上下文**或写到 `<CPQ_SESSION_DIR>/phase1-pending.md` 临时文件；下次回来继续 |

> **关键**：D 段未完成时**不允许落盘 phase1.md**。否则 phase1.md 会带着错误的字段进 Phase 2，违反不可逆原则。

## 模板示例：完整追问

以下是国际站 CVM + 系统盘 + 数据盘 + Ice Lake / IOPS≥1800 case 的完整追问示例：

```
Phase 1 解析完成（识别出 3 行产品），请确认下列推断（任意修改后回复 "go"）：

────────────────────────────────────
【A 段 · 必须确认（无默认值）】
────────────────────────────────────

1. 售卖模式：原始清单"承诺使用周期=三年"未明确售卖模式。
   ☐ 包年包月 3 年（按月计费 × 36）
   ☐ 预留实例 RI 3 年（一次性付清）
   ☐ 节省计划 SP 3 年承诺
   ☐ 包销 3 年
   👉 请选一项

────────────────────────────────────
【B 段 · 默认提案（不修改即接受）】
────────────────────────────────────

✓ CPU 推断：Ice Lake → 标准型 S6（依据：implicit-spec-cpu.md）
   👉 改成？
     ☐ 列全部 Ice Lake 候选
     ☐ 强制 SA5
     ☐ 不推断（按"标准型"模糊搜）
   ✅ 默认：不推断

────────────────────────────────────
【C 段 · 一次性告知（不追问）】
────────────────────────────────────

⚠️ 以下信息已识别但忽略：
  - 列 '资源要求' 中的"基频 2.5GHz / CPU 独享 / X86 架构"
    → 已归为 DEFAULT_ATTR（标准型 S6 默认属性，不进搜索词）
  - 列 '资源要求' 中的"IOPS≥1800"
    → 已归为 PERFORMANCE_FILTER，写入 约束条件 列（Phase 4 让你筛选）
  - 列 '产品单价' / '产品折扣' / '其他费用' / '税费' / '最终结算价'
    → 已归为 META 价格列，由 D 段询价覆盖
  - 列 '备注'（空）→ 忽略

如有遗漏请告知，否则继续。

────────────────────────────────────
回复格式：
  - "go" 接受全部默认（A 段必须答）
  - "1=预留实例RI" 仅修改 A.1
────────────────────────────────────
```

用户回复 `1=预留实例RI` + 接受 B/C 段默认 → 落盘 phase1.md（详见 [`how-to-parse-product-list.md`](./how-to-parse-product-list.md) §产物示例）。

## 反模式

- ❌ 把追问拆成多轮（如先问售卖模式，再问推断，再问未识别列）→ 违反单次执行原则
- ❌ A 段问题让用户自由作答（"承诺三年是什么意思？"）→ 必须给有限选项
- ❌ A 段填默认值（如售卖模式默认包年包月）→ 违反"不许默认"
- ❌ 用户回复模糊（"看着办"）擅自填值 → 必须重新追问
- ❌ 在 Phase 1 阶段 D 问 Phase 2.6 才该问的问题（如"这行你想要精确还是框架？"）
- ❌ 漏问导致信息丢失 → 单次执行原则下下游回不来，必须本次问完
