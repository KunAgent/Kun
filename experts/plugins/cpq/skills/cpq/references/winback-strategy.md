# Winback 对标策略

cloud-mapping 参考数据为每个友商规格提供两种对标策略，Winback 方案需根据用户意图选择输出维度。

## 策略定义

| 策略 | 含义 | 选型倾向 |
|------|------|----------|
| 性能对等 | 性能、规格对等替换 | 优先选择同代或更高代次、同类型的腾讯云机型，保证性能不降级 |
| 成本优先 | 在满足基本需求前提下降低成本 | 优先选择性价比更高的机型（如 SA 系列 AMD 实例），可跨类型映射 |

## 意图识别

根据用户输入中的关键词判断策略偏好：

### 明确指定"性能对等"

用户输入包含以下信号词时，仅按**性能对等**策略输出：

- "性能对等""标准推荐""标准方案""同等配置""不降配""1:1 替换""对等替换""性能优先"

### 明确指定"成本优先"

用户输入包含以下信号词时，仅按**成本优先**策略输出：

- "成本优先""降本""省钱""低成本""预算有限""便宜""经济""性价比"

### 意图不明确

用户仅说"生成对标清单""Winback 方案""帮我对标"等，未体现策略偏好时：

→ 标记为**待定**，先完成数据查询，再根据查询结果中实际包含的策略类型决定：
- 数据仅含一种策略 → 自动采用，无需提问
- 数据含两种策略 → 调用 `askUser` 让用户从"性能对等""成本优先""两种都要"中选择

## 输出规则

### 规则 A：单策略输出

用户明确指定策略，或数据仅含一种策略，或用户在提问后选择了其中一种时，按该策略从映射结果中筛选对应行（`策略：标准推荐` 或 `策略：成本优先`），输出一张 Winback 表格。

### 规则 B：双策略输出

用户在提问后选择"两种都要"时，分别按两种策略筛选映射结果，输出两张独立表格：

1. **方案一：性能对等**（规格对等替换）
2. **方案二：成本优先**（最优性价比）

每张表格结构与单策略输出一致。两张表格之间用标题区分。

## 映射结果中的策略字段

cloud-mapping 字典 `../cloud-mapping/references/data/cloud-mapping/instance.md` 每条映射均包含 `策略：标准推荐` 或 `策略：成本优先` 后缀。

在步骤二委托 cloud-mapping 执行映射时，字典查询阶段不过滤策略，完整保留两种结果供步骤三/四使用。

筛选示例（在映射流程的字典查询阶段）：

```bash
# 提取全部结果（不过滤策略）
grep -i "g7" ../cloud-mapping/references/data/cloud-mapping/instance.md || true

# 步骤四按策略筛选时：
# 仅性能对等
grep -i "g7" ../cloud-mapping/references/data/cloud-mapping/instance.md | grep "标准推荐" || true

# 仅成本优先
grep -i "g7" ../cloud-mapping/references/data/cloud-mapping/instance.md | grep "成本优先" || true
```
