# User Input Rules

向用户追问规格时，使用产品页面上的业务说法，不要直接暴露 CLI flag。`--instance-type`、`--period`、`--pack-type`、`--price-cents` 这类参数名只供内部组装命令使用。

| 内部 CLI 含义 | 面向用户说法 |
|---------------|--------------|
| `--site` | 国内站还是国际站 |
| `--product` | 产品名称 |
| `--charge-type` / `--billing-mode` | 计费模式（包年包月、按量、竞价、资源包等） |
| `--region` / `--zone` | 地域 / 可用区 |
| `--instance-type` | 实例规格 / 机型 |
| `--period` / `--time-span` | 购买时长 |
| `--system-disk-*` / `--data-disk-*` | 系统盘 / 数据盘类型和容量 |
| `--bandwidth` | 公网带宽 |
| `--pack-type` / `--spec` / `--size` | 资源包类型和规格 |
| `--quantity` / `--goods-num` / `--instance-count` | 购买数量 |

如果需要多个核心规格，一次性合并提问。例如：不要写"填写 `--charge-type`、`--instance-type`、`--period`"，应说"请确认计费模式、实例规格和购买时长"。用户回答后，再由 Agent 映射为 CLI 参数。

缺参处理偏好按业务语义执行：

- 选 `a 我自己补充`：缺少规格时追问用户，不自动填入默认规格。
- 选 `b 默认填充`：只使用 `help/schema` 明确默认值、CLI 内置参数配置或用户已输入内容；仍缺少无默认值的必填参数时必须追问。
- 选 `c 默认填充，不对我再改`：先按 `b` 的规则报价，并在结果里列出默认填充项；用户反馈不对时再按新规格重跑报价。

任何计算口径、默认值、参数值、规格枚举、计费模式都不能用模型常识补齐。

## 资源包离散规格

用户给出的容量、流量或请求量可能是业务需求量，不一定是可购买的资源包规格。若 `schema/help` 或 CLI 错误输出表明资源包规格是离散枚举，必须让用户选择合法规格或明确确认多份合法资源包组合；不得自动选择最近档位、不得向上/向下取整、不得用最大已成功档位推单价，也不得用单价 × 用量为非法规格补金额。

资源包组合只有在每个组合项都能分别 `tcloud-price quote` 成功时才可展示金额；组合总计也只能机械汇总这些成功 JSON 的 `totalPrice`。如果用户需求无法映射到已确认合法组合，应标记为待确认或无法报价，不给替代金额。
