# 类案检索

查找与待决案件相似的已决案例，评估相似度，排序筛选，输出结构化结果。

---

## 一、定位与依赖

本技能只描述**类案检索的领域方法论与报告格式**。以下规则不在此重复，统一遵循上层：

- **反幻觉、联网回库隔离、行政执法类检索路径、法言法语映射** → `legal-search-engine` 技能。
- **输出铁律、引用规范、风险标记、免责声明** → 专家人设 `agents/legal-search-pro.md` 的"输出规范"。

一句话约束：本技能产出的每一个案例，都必须来自可核验来源的真实返回，严禁凭记忆生成；不得编造案号、当事人或裁判要旨。内部必须先静默判断并优先调用可用的案例专业库/MCP/Skill：北大法宝 `pkulaw` / `mcp__pkulaw*`（`mcp__pkulaw__mcp-case-search-service/search_case`、`mcp__pkulaw__mcp-case/get_case_list`）、华宇元典 `yuandian-mcp` / `mcp__yuandian*`（如可用）、其他法律案例库或团队自有检索 Skill；不足时再用官方文书/裁判来源或公开 Web 来源补足。若当前工具 schema 未预加载，必须先用工具发现能力精确查找上述北大法宝案例工具，不得直接判定不可用并进入 Web。不要向用户说明工具连接状态、数据库名称或兜底路径。未取得可核验案例时，只说明未检索到可核验案例，不暴露内部检索能力状态。

## 二、检索准备

### 2.1 案件要素拆解

把用户描述拆成三组要素，每组在检索中承担不同功能：

**定性层（决定检索方向，必须确定）**
- 案由 / 纠纷类型
- 核心法律关系
- 主要争议焦点
- 已知的适用法律条文

**情节层（刻画案件特征，尽量补全）**
- 当事人类型（自然人 / 法人 / 其他组织）
- 行为模式与性质
- 损害的类型与程度
- 因果关系与过错形态

**筛选层（圈定检索范围，按需使用）**
- 地域（全国 / 特定省市 / 特定法院）
- 时间区间
- 审级
- 标的额区间

定性层缺失则无法启动检索，需先向用户追问；情节层与筛选层用于在检索过程中收窄结果。

### 2.2 确定检索锚点

不同检索需求对应不同的"锚点"——即 query 应当围绕什么来构造。先判断属于哪一类，再决定关键词的着力点：

| 检索锚点 | 适用需求 | query 构造方向 |
|---------|---------|--------------|
| 条文锚点 | 想了解某法条/司法解释在实践中怎么用 | 以目标条文为中心，找"引用本条"的案例 |
| 事实锚点 | 想了解某类事实/情节如何认定 | 以构成要件事实和情节关键词为中心 |
| 规则锚点 | 想了解某类证据或程序规则如何适用 | 以证据类型、采信标准、程序节点为中心 |

> 检索目的（支撑己方 / 反驳对方 / 风险摸底等）影响的是**正反案例的取舍配比**，不影响能否检到——此项已并入第四章"轮间评估"的正反平衡判断，此处不单列。

### 2.3 关键词生成

**关键词分类**：

| 类型 | 定义 | 示例 |
|------|------|------|
| 法言法语 | 出现在法条或裁判文书中的规范表述 | 表见代理、善意取得、格式条款、违约金酌减、按份责任 |
| 生活用语 | 当事人口语、行业俗称，文书中通常不直接出现 | 砍单、跑路、薅羊毛、阴阳合同、捆绑销售 |

**四种提取方法**：

1. **法律概念关键词**：从法条中拆分精确术语（如"一人有限责任公司""独立财产""连带责任"）
2. **事实关键词**：从案件材料中提取行业术语和事实要素（如"违法转包""逾期完工"）
3. **案由关键词**：直接使用案由或请求权基础作为关键词
4. **组合关键词**：上述关键词的交叉组合，包括法言法语×生活用语的混合

**关键词组合策略**：

为多轮检索准备多组关键词，每组针对不同检索角度：

```
第一组：核心概念（案由 + 争议焦点 + 核心法律关系）
第二组：法定/裁判表述（用户命题词对应的法条原文用语 + 司法用语变体）
第三组：事实维度（关键事实要素 + 行为模式）
第四组：法源维度（相关法条号 + 司法解释条文号）
第五组：锚点关键词（来自2.4预检索的具体企业名/案号/文号/独特短语，如有）
```

> **强制：命题特有词必须先展开到"法定表述层"再检索（最易漏检的环节）。**
> 用户口语化的命题词（如"防沉迷""大数据杀熟""自动续费"）在裁判文书里**常常根本不出现**——文书用的是法条原文用语。检索前必须建立一张映射，并把右两列**都作为第二组的一等检索词**，与命题原词地位相同：
>
> | 命题口语词 | 法条原文用语（必查） | 裁判常用表述（必查） |
> |-----------|--------------------|--------------------|
> | 防沉迷 | 未要求未成年人以真实身份信息注册并登录网络游戏（未保法75条） | 实名认证 / 实名注册 / 时间管理 / 消费管理 / 未经审批运营 |
> | 大数据杀熟 | 利用算法对交易条件实行不合理的差别待遇 | 差异化定价 / 价格歧视 / 个性化推荐 |
> | 自动续费 | 未以显著方式提请注意续费条款 | 默认勾选 / 不当扣费 / 格式条款 |
>
> 上表仅为示例。**任何检索都必须先为本案命题词现做这张映射**，宁可多列同义词，不可只用用户原词。匹配的判断单位是"法律实质"，不是"字面命中"。

### 2.4 预检索线索收集

内部先通过公开信息源收集具体案例线索，为关键词矩阵补充精准锚点；该过程只用于提升检索质量，不向用户透传。

**核心逻辑**：纯法律概念关键词容易命中大量泛相关结果。预检索的目标是获取**具体锚点**——真实的企业名、案号、处罚文号、独特短语——使后续检索从"概念搜索"升级为"锚点定位"。锚点的价值在于：它是"主体关联检索"的入口，**入口越多，捞到关联裁判文书或行政处罚材料的概率越高**。

**操作步骤**：

1. **线索搜索（广撒网）**：围绕检索主题准备 **≥8 组** web 关键词（不同地域、不同企业、不同表述各一组），尽可能多地 surface 具体案例。关注以下来源：
   - 政府官网执法公示、行政处罚信息公示、信用中国、"双随机一公开"结果
   - 权威法律媒体报道
   - 知名律所公众号分析文章
   - 学术论文中引用的案例

2. **检索批次持久化（强制）**：每一批公开信息检索/网页读取结果，都必须整理为 `retrieval-batch-XXX.json` 并运行 `legal-verify capture --task <taskDir> --input retrieval-batch-XXX.json --provider web`。搜索结果只有标题/摘要时只作为 raw-search 留痕；读取到网页/文档全文后再次 capture，进入 `sources/index` 段落库。预检索资料不得只停留在上下文中。

3. **锚点提取（多多益善）**：从已持久化的搜索结果中提取可用于精准定位的信息，**尽量凑齐多个不同主体**：
   - 具体当事人/企业名称
   - 案号或处罚决定书文号
   - 独特短语或裁判摘要片段
   - 涉案法条的具体条款号

4. **融入关键词矩阵 + 主体关联复检**：将锚点作为 2.3 第五组送入多轮检索。**凡预检索拿到的每一个企业名/文号，都必须在可用的专业库、官方来源或公开可核验来源中做一次主体关联复检**（以企业名为关键词查其关联案件）——很多对题案例（尤其非诉执行裁定、行政处罚决定）只有用主体名/文号才能命中。注意：公开信息只用于产出锚点，**未经复检取得完整可核验文本前不作为案例引用**（详见第十一章）。

**适用判断**：

| 检索类型 | 预检索 | 原因 |
|---------|------|------|
| 行政处罚/监管执法类 | **强制执行** | 此类案件在裁判文书库中覆盖率低、噪音高，公开执法信息是更直接的线索来源，且预检索企业名是回库捞非诉执行裁定的主要入口 |
| 新型/前沿法律问题 | 建议执行 | 学术文章和律所分析可能已引用相关案例 |
| 常规民商事案件 | 可选 | 概念关键词通常足够命中，效果不佳时再启动 |
| 单点确认性查询 | 可跳过 | 时间成本不合算 |

## 三、类案识别基础

### 3.1 类案的定义

类案是指与待决案件在**基本事实、争议焦点、法律适用问题**等方面具有相似性，且已经人民法院裁判生效的案件。

在我国成文法体系下，案例不具有普遍约束力（指导性案例除外），类案检索的核心价值在于：通过已决案例辅助对抽象法律条文进行解释，增强法律适用的说服力和可预测性。

### 3.2 相似性判断的三种维度组合

判断待决案件与检索结果是否构成"类案"，学界和实务界存在三种主流标准，适用场景各异：

| 标准 | 比较维度 | 适用场景 |
|------|---------|---------|
| 标准一 | 基本事实 + 法律适用 | 与指导性案例的比对（实施细则第9条的标准） |
| 标准二 | 基本事实 + 争议焦点 + 法律适用 | 一般类案比对（目前主流，指导意见第1条的标准） |
| 标准三 | 案由 + 争议焦点定位关键事实 | 案由明确、需快速锁定范围时 |

**实务建议**：默认采用标准二（三维度），在案由明确时可结合标准三辅助缩小范围。三种标准不互斥，可灵活组合。

### 3.3 三层比对标尺

类案识别落到操作上，是把待决案件与候选案例在三个层面逐层比对（对应最高法《关于统一法律适用加强类案检索的指导意见》第一条的基本事实、争议焦点、法律适用三要素）：

| 比对层 | 看什么 | 判断口径 |
|------|---------|---------|
| **规范层** | 适用的法律规范是否同一范畴 | 案由相同只是入口而非定论，须落到具体法条 |
| **争点层** | 核心法律争议是否同一 | 比的是法律适用之争，而非单纯的事实之争 |
| **事实层** | 对结果起决定作用的关键事实是否相似 | 只比构成要件事实，剔除无关细节 |

> 三层须合并判断：某一层高度吻合能加分，但任一层出现根本差异，类案关系即不成立。实践中由规范层入手收窄范围，再用争点层、事实层精筛。

## 四、多轮检索执行

### 4.1 核心原则

- **目的驱动**：每轮检索必须有明确的、与前轮不同的检索角度
- **轮次随噪音自适应**：默认 2-4 轮，但**以"结果质量达标"为唯一停止条件，轮次上不封顶**。低噪音单点查询可 1-2 轮收手；高噪音复合命题（命题词泛、民事/行政/线下场所案件混杂）必须加轮，直到对题案例被顶出或穷尽性闸门（第七章）跑完
- **抓取量随噪音自适应**：`size` 默认 10；高噪音复合命题或首轮命中稀疏时，**提到 20-30**，避免对题裁判被排到首屏之外而漏检
- **结果合并**：各轮返回结果按案号去重，统一进入筛选评估

> **0 命中 = 放宽信号，不是"不存在"的证据。** 检索数据源多为单个扁平 query、无案由/全文分字段，Boolean 控制弱，组合词一多极易 0 命中。某条 query 返回 0 时，**禁止据此推断"该类案不存在"**，应按下列顺序逐步放宽再搜，而不是收手：
>
> 1. **先拆掉最窄的命题特有词**（如去掉"防沉迷"，保留"未成年人 实名 网络游戏"或 case-type 词）
> 2. 再换法定表述/裁判表述（2.3 第二组映射里的同义词）
> 3. 再放宽地域/时间限定
> 4. 仍为 0，才记录"此组合无命中"，并换下一个检索角度——而非结束检索

### 4.2 检索轮次设计

**第一轮：核心命中**
- 关键词：最核心的概念关键词组（案由/争议焦点 + 核心法律关系）；如已执行2.4预检索，同时用锚点关键词（企业名/案号/文号）做定向检索
- 目的：命中主流案例，建立基础结果集

**后续轮次（按需选择）**：

| 策略 | 适用场景 | 示例 |
|------|---------|------|
| 换裁判表述 | 第一轮遗漏了用不同措辞的裁判 | "酌减" → "酌情减少" → "调整" |
| 补充维度 | 需要特定角度的案例 | 增加"公平原则""补偿金比例"等关键词 |
| 扩展对立方向 | 正面案例足够但缺反面案例 | 调整关键词组合，专门检索对立裁判 |
| 法条关联检索 | 从法条入手找引用案例 | 从相关法条找"引用本法条"的案例 |
| 放宽限定条件 | 限定过严导致结果太少 | 扩大时间范围/地域范围 |

### 4.3 轮间评估（定性判断）

每轮结束后回答三个问题：

1. **焦点覆盖**：核心争议焦点是否都有对应案例了？
2. **正反平衡**：正面和反面案例都有了吗？
3. **角度遗漏**：还有没有明显遗漏的检索角度？

→ 三个问题都满足则停止，进入筛选评估
→ 任一不满足则继续下一轮，针对不足之处调整关键词

### 4.4 检索示例

以"竞业限制违约金过高如何调整"为例：

| 轮次 | 关键词 | 检索目的 | 结果评估 |
|------|--------|---------|---------|
| 第一轮 | 竞业限制 + 违约金 + 酌减 | 基础检索，命中主流酌减案例 | 找到3个正面案例，缺反面 |
| 第二轮 | 竞业限制 + 违约金过高 + 酌情减少 | 换裁判表述，补充查全 | 补充2个，仍缺"不予调整"案例 |
| 第三轮 | 竞业限制 + 违约金 + 公平原则 + 补偿金 | 补充维度，发现对立案例 | 找到反面案例，三个问题均满足，停止 |

## 五、补充检索方式

除关键词多轮检索外，以下三种方式可在任一轮次中作为补充手段使用：

| 方式 | 适用场景 | 方法 |
|------|---------|------|
| 法条关联 | 法律适用明确时 | 从目标法条找"引用本法条"的案例 |
| 案例关联 | 对领域陌生时 | 从种子案例中提取法官引用的法条和关键词，扩展检索 |
| 主体关联 | 针对特定主体的诉讼策略 | 以当事人名称为关键词检索关联案件 |
| 行政执行关联 | 行政处罚/监管执法类检索 | 搜索"非诉行政行为申请执行"+行业关键词，覆盖企业被罚后的强制执行裁定（详见下方说明） |

> 前三种方式对应司法实务中通行的关键词检索、法条关联案件检索、案例关联检索三种方法。第四种针对行政案件的特殊存在形态。

### 行政案件特殊检索路径

行政处罚、监管执法类案件在裁判文书库中的存在形态与民商事案件不同。**对此类命题，"非诉行政执行"不是可选补充，而是首要猎物——必须主动、优先、反复地去捞，而非等其他角度无果后才想起。**

**关键技巧：case-type 词与命题实质词解耦组合。** 把"非诉行政行为申请执行""行审""准予强制执行"这类**案件类型词**单独拎出来，与**行业词**交叉，而**不要**叠加命题特有词（如"防沉迷"）。因为非诉执行裁定的正文常只写法条原文用语（"未要求未成年人以真实身份注册登录"），叠加"防沉迷"反而把它们过滤掉。正确示例：`网络游戏 非诉行政行为申请执行 案例`、`文化和旅游局 申请执行 网络游戏 案例`；错误示例：`防沉迷 非诉执行 案例`（过窄，易 0 命中）。

| 检索角度 | 说明 | 关键词示例 |
|---------|------|----------|
| 非诉行政执行（**首要**） | 企业被罚后未起诉也未缴纳罚款，行政机关申请法院强制执行，形成"非诉行政行为申请执行审查"裁定书。**这是行政处罚案件在裁判文书库中最常见的存在形式，须优先且多轮检索** | "非诉行政行为申请执行" + 行业词；"申请执行" + 处罚机关名；"行审" + 行业词 |
| 处罚文号 / 主体名检索 | 用预检索（2.4）拿到的文号、企业名精准定位关联司法案件 | 具体文号（如"文综罚字[20XX]X号"）；预检索得到的每个企业名 |
| 执法机关+行业 | 用监管部门名称+被监管行业关键词交叉检索 | "文化和旅游局" + "网络游戏"；"市场监督管理局" + "价格欺诈" |
| 行政诉讼 | 企业不服处罚提起行政诉讼，数量远少于非诉执行 | "行政处罚" + 行业词 + "撤销"/"维持" |

> **关键认知（须用对，别用反）**：行政处罚案件中，大量处罚以企业缴纳罚款告终、不进入司法程序——但这**绝不等于"裁判文书库里没有对题类案"**。进入司法程序的主要是非诉执行（行政机关申请强制执行）。这条认知的正确用法是：**"所以更要把非诉执行当成主战场反复去捞"**，而**不是**："所以大概搜不到、可以早收手"。把它当成早收手的理由，是本类检索最常见、最致命的失误。

## 六、案例筛选与验证

### 6.1 入选前核验（强制，不通过则排除）

每个候选案例引用前过两关：

**第一关 · 效力核验**——确认这份裁判现在还算数：
- *是否已生效*：检索到一审判决时，须查有无二审；有二审的以二审为准。未生效判决不得引用。
- *是否被推翻*：以主要当事人名称检索关联案件，查有无再审、提审或第三人撤销之诉将其改判/撤销。已被推翻的，裁判规则失效。

**第二关 · 不利信息核验**——确认这份裁判不会反咬己方：
- 通读"查明"与"本院认为"两部分，排查有无对己方不利的事实描述或否定性评价（如"原告亦有过错"）。
- 发现不利表述的，标注风险点，评估改用其他案例或预备应对。

### 6.2 筛选排序：三组维度

通过核验的案例，按三组维度综合排序（效力层级与审级序列源自最高法相关规程）：

**第一组 · 效力与权威（决定参照力度）**

- *效力层级*：指导性案例 > 入库案例 > 公报案例 > 典型案例 > 最高法院裁判 > 高院参考性案例 > 上级法院案例 > 本院案例 > 其他。指导性案例"应当参照"且须在文书说理中引述；入库案例同样应当检索参照；在先顺位足量时，原则上不再补后一顺位。
- *审级严谨度*：民再 > 民终 > 民初 > 民申。再审说理最严谨；"民申"字号多代表原审高院观点，参考价值较低。
- *特殊背书*：经审判委员会讨论决定、或合议庭成员参与过相关司法解释起草的案例，权威性更高。

**第二组 · 关联与时效（决定贴合度）**

- *辖区关联*：本地法院 > 经济人文相近地区（如长三角、珠三角可互参） > 其他地区。涉地方性法规的纠纷优先本辖区案例。
- *时效*：裁判时间越近越优先，一般取近 3-5 年；涉新旧法衔接时，事实发生时间可能比裁判时间更关键，并警惕法律变更使旧案规则过时（如《合同法》→《民法典》）。指导性案例不受时间限制。

**第三组 · 说理质量（决定可用性）**

以下案件裁判通常经更审慎考量、说理更充分，参考价值更高：重大疑难复杂敏感案件、群体性或可能影响社会稳定的案件、与本院或上级法院类案可能冲突的案件、尚无统一裁判规则的案件。识别特征：文书载明"经本院审判委员会讨论决定"、案由属新型疑难、判决篇幅长且说理详尽。

**复合命题路由**：若用户的检索目标为复合命题（主体+行为+法律后果/程序三要素中限定了两项及以上），筛选完成后须继续执行第七章相关性闸门。

## 七、复合命题的相关性闸门（强制）

### 7.0 适用场景

当用户的检索目标是一个**复合命题**——即同时限定了【主体 + 行为 + 法律后果/程序】三要素中的两项及以上时触发本章。

典型复合命题示例：
- "游戏公司 + 未落实防沉迷 + 被行政处罚"
- "平台 + 大数据杀熟 + 被罚款"
- "物业公司 + 高空抛物 + 承担侵权责任"

非复合命题（如"竞业限制违约金的裁判规则"）不触发本章，直接进入第八章。

### 7.1 第一步：拆解命题三要素，建立"法律实质层"对题标尺

检索前先把命题拆成可勾选的要素清单，作为后续每个候选案例的过滤标尺。

> **标尺建在"法律实质层"，不是"字面层"（直接决定召回率）。** "行为"一栏尤其要先用 2.3 的映射展开到法条原文用语，再用展开后的实质含义去勾选候选案例。否则会把"用同义法定表述命中、实质完全对题"的案例误判为不符而排除——这正是漏检 A 级类案最常见的原因。

| 要素 | 本案目标值（含法定/裁判同义表述） | 候选案例须满足（按法律实质判断） |
|------|-----------|--------------|
| 主体 | （如：网络游戏运营企业） | 被告/被处罚人是否为该类主体 |
| 行为 | （如：未落实防沉迷系统 = **未要求未成年人实名注册登录 / 未接入实名认证 / 未经审批运营**等法定表述） | 涉案行为在**法律实质上**是否属该行为，**不要求字面出现命题原词** |
| 后果/程序 | （如：行政处罚，含**非诉行政执行裁定中确认处罚合法**的情形） | 案件性质是否为该类 |

### 7.2 第二步：对每个候选案例做三档分级（**纯内部逻辑，不对用户呈现**）

A/B/C 只是 Skill 内部用来"决定收录哪些、怎么排序"的工作标记，**绝不出现在面向用户的报告里**（用户看到的是"案件类型"标签，见 10.3）。分级只回答相关性一个问题，**与文书类型无关**：

- **A级（核心命中）**：三要素全部吻合。**注意：只要三要素吻合即为 A 级，与它是判决书、裁定书还是行政处罚决定无关**——一份真实可核验、对题的行政处罚决定同样是 A 级，不因"未进入诉讼"而降级。
- **B级（部分命中）**：要素部分吻合但有实质差异（如主体是网吧而非游戏公司，或性质是民事退款而非行政处罚）。可列入报告，但需逐案标注差异要素、排在 A 级之后，不与 A 级混淆。
- **C级（不命中）**：仅关键词相关、核心要素不符（如游戏公司是原告去告别人）。**不得作为对题类案罗列**；确有方法论价值的，仅可在"延伸参考"中简述并说明为何不对题。

> **两个轴必须分开，别再压成一个。** "相关性"（A/B/C，内部用）和"案件类型/文书形态"（行政处罚决定/非诉执行裁定/行政诉讼判决/民事判决/指导性案例…，对用户呈现）是**两件事**。把"不是判决书"当成"不够 A 级"，正是旧版"明明查到 14 件却像没查到"的根源。诉讼/高效力文书在**排序**上优先，但不是"对题"的必要条件。

### 7.3 第三步：下"零结论"前的穷尽性前置闸门（强制，先于诚实披露）

**"诚实地说没有"必须以"已尽力找过"为前提。** 这里的"零结论"指**任何文书类型的对题案例都没有**（行政处罚决定、非诉执行裁定、判决书全都没找到），**而不是"没有进入诉讼程序的案例"**——后者只是文书类型的缺口，不构成"没查到对题案例"。在得出"对题案例为 0 / 极少"这一结论之前，必须确认下列三类检索**已全部实际执行**（且在检索过程中体现），缺任何一类，**不得**下零结论，应补跑后再判断：

- [ ] **非诉执行 × 行业词**（case-type 词与命题特有词解耦）：如 `行业词 + 非诉行政行为申请执行 / 申请执行 / 行审`，且首轮 0 命中时已按"放宽再搜"重试
- [ ] **法定/裁判同义表述全组**：2.3 第二组映射里的每个法定表述都已单独作为检索词跑过（不是只用命题口语词）
- [ ] **主体关联**：2.4 预检索拿到的每个企业名/文号都已回库检索过关联案件

> 这道闸门的作用，是把第七章原本"鼓励敢说没有"的诚实导向，校正为"**先穷尽、再诚实**"。诚实披露针对的是"确实没有"，不是"我没搜到"——后者是召回失败，不是客观结论。把"行政处罚多不进诉讼"当作跳过上述检索的理由，是被明确禁止的。

### 7.4 第四步：结论先报成果，缺口作为背景如实说明

**结论第一句先报"检到了什么"，不要先报"缺了什么"。** 区分两种情况：

- **检到了对题案例（任何文书类型，含行政处罚决定）**：结论开篇直接报成果，例如"检索到 N 件直接对题的案例，均为/主要为〔案件类型〕"。若其中**进入诉讼程序的（行政诉讼判决/非诉执行裁定）很少或没有**，把这一点作为**背景信息**补充说明（"其中进入司法程序的较少，多停留在行政处罚阶段"），帮助用户判断证据形态——而**不是**写成"本主题几乎没有对题案例"这种像没查到的句子。
- **穷尽性闸门跑完后，确实任何类型的对题案例都为 0 / 极少**：才在结论**第一句**如实点破"本主题在案例库中不存在（或极少存在）直接对题的案例"，并简述结构性原因（如该类监管以约谈/责令整改等非诉手段为主）。

**严禁**用大量 B/C 级关联案例堆砌篇幅，营造"成果丰硕"的错觉而回避真实缺口。报告的丰满度不是质量指标，**相关性与诚实度**才是。

> 三条底线并存：①检到了就先报检到的；②"缺的只是诉讼文书"≠"没查到对题案例"，别把前者说成后者；③真的全都没有时，穷尽后的"确实没有"合格，没跑完闸门的"我没搜到"不合格。

### 7.5 第五步：标题—内容一致性自检

生成报告前自检：标题/命题中的每个限定词（主体、行为、后果），是否都能在A级案例中找到对应？
- 若不能，调整标题或在结论中明确说明"现有案例覆盖的是X，而非命题要求的Y"
- 禁止"标题写'被处罚'，正文全是民事退款案"这类错位

### 7.6 第六步：量化表述的克制

凡"责任比例通常在X%—Y%之间""多数法院认为……"等量化/普遍性断言，必须有所列案例的明确数据支撑；样本不足时，改为"个案酌定，无统一比例"等克制表述。不得将少数案例的归纳包装成普遍裁判规则。

## 八、相似度评估

对通过入选核验的案例，按"是不是同类 → 规则能不能搬 → 落到本案稳不稳"三层递进判断参考价值。不设固定权重，以定性描述为准。

### 8.1 第一层：同类性判断（是不是一类案子）

把"法律关系、争议焦点、关键事实"三项放在一起看，三项整体对位，才进入下一层。

| 比对项 | 看什么 | 不对位的后果 |
|------|---------|---------|
| 法律关系 | 案由、当事人法律地位、权利义务结构、基础法律关系是否同类 | 法律关系根本不同，后两层再像也不能作核心参考 |
| 争议焦点 | 双方争的核心法律问题、涉及的条文解释是否同一 | 焦点不同，裁判规则难以直接搬用 |
| 关键事实 | 对结果起决定作用的构成要件事实是否相似 | 细微情节差异即可能翻转结论，须最审慎 |

> **情节代入检验**：把候选案例的关键情节替换成本案情节，看裁判结论是否仍成立。结论一旦动摇，说明两案在决定性事实上存在实质差异，同类性存疑。
>
> 关键事实的识别：从"法院查明"部分提取被认定为对结果有重大影响的事实，对照法律规范的构成要件筛出要件事实，剔除与法律适用无关的细节。

### 8.2 第二层：规则可移植性（裁判规则能不能搬到本案）

同类性通过后，看案例给出的裁判规则能否为本案所用：

- 裁判要旨是否清晰（如形成"在 A 条件下应认定 B"的明确表述），还是含糊其辞
- 规则是否依赖个案特定事实，能否一般化后移植到本案
- 规则是孤例，还是被多个案例印证
- 是否对模糊条文作了具体化解释，而非照抄法条

说理透彻、规则清晰的一个案例，价值远超一堆含糊案例。提取规则时重点看"本院认为"部分的规则性表述（"应当认定""不应支持""可以参照"等），将个案事实抽象为类型化描述后归纳可普遍适用的标准。

### 8.3 第三层：本案适配性（程序与背景是否影响适用前提）

规则可移植后，再看程序层面的差异是否动摇适用前提：

- 审理程序是否可比（二审 / 再审说理通常更稳）
- 举证责任分配、证明标准是否一致
- 诉讼阶段是否对应（本诉 / 执行异议之诉等）

此层通常在前两层高度吻合时才需细究，但程序差异（如再审改判）可能显著增减参考价值。

### 8.4 评估通则

- **整体判断**：三层结合看，不因单层高/低就绝对认定或排除
- **事实敏感**：某些问题中一个细微事实差异即导致相反结论
- **反面同等**：对立案例同样按三层评估，讲清差异所在
- **交叉验证**：多案对比，分清裁判规则的主流与例外

## 九、裁判分歧的处理

检索结果在法律适用上互相打架时，按"就近原则"定哪个更值得参照——离受理法院越近、越权威、越新，分量越重。

### 9.1 三条就近规则（依次适用）

1. **审级就近**：受理法院的直接上级法院案例最具约束力（直接关系到被改判 / 发回的风险）；上级法院之外，同一上级法院辖下的同级法院案例次之；外辖区案例仅作说理参考。
2. **庭别就近**：同一法院内，与本案审理庭室相同的专业庭案例，优先于其他庭室。
3. **时间在后**：上述仍无法区分时，裁判时间靠后的优先——通常反映了新的法律、司法解释或政策。

### 9.2 经审委会讨论的优先

无论层级远近，裁判文书载明"经审判委员会讨论决定"的，权威性高于未经讨论的同类案例。

### 9.3 仍无法统一时

三条规则用尽仍存分歧的，不强行抹平——在输出中如实列出各方观点及依据。**分歧本身就是有价值的信息**：它说明该问题尚存争议，应让用户看到全貌，而非给一个虚假确定的答案。

## 十、结果整理

### 10.1 排序方式

**先按相关性（对题程度）排序，再在同等相关性内按文书效力/审级排序。** 对题的案例排在前面，不因文书类型（行政处罚决定 vs 判决书）而被压到后面。

每个案例标注 **"案件类型"标签** 作为元信息呈现给用户：行政处罚决定 / 非诉行政执行裁定 / 行政诉讼判决 / 民事判决 / 刑事判决 / 指导性案例 / 公报案例 / 典型案例 等。这是用户真正用得上的信号——它告诉用户"这是哪一类案子、处在哪个程序阶段"，由用户自行判断是否需要诉讼阶段的文书。

- 属裁判文书的案例，**可在案件类型后附效力/审级标签**（指导性案例/入库案例/公报案例/最高法院裁判/高院裁判/中院裁判/基层法院裁判），帮助判断参考力度。
- 内部排序仍可参考第六章三组维度（效力与权威、关联与时效、说理质量），但**那是内部排序逻辑，A/B/C 等内部分级一律不出现在报告里**。

### 10.2 数量控制

总量控制在**5-10个精品**为宜。与其追求数量，不如针对性地挑出说理最透彻、效力层级最高、与本案最相关的案例深入分析。

### 10.3 案例呈现结构

每个案例统一按以下结构呈现（报告模式必须严格遵循，快速回答模式可灵活裁剪但核心要素不可缺失）：

元信息表格**首行必须是"案件类型"标签**。其余字段随案件类型自适应：裁判文书用"案号/审理法院/裁判日期"，行政处罚决定用"处罚文号/处罚机关/处罚日期"。

裁判文书类（判决书/裁定书）：

```markdown
### {案件标题}

| 基本信息 | 内容 |
|------|------|
| **案件类型** | {行政诉讼判决 / 非诉行政执行裁定 / 民事判决 …}（裁判文书可加注效力层级，如"高院裁判"） |
| **案号** | {案号} |
| **审理法院** | {法院名称} |
| **裁判日期** | {裁判日期} |

**案件事实：** {当事人基本情况、起因、主要事实经过。一段叙述，不分小节。}

**裁判要旨：**

1. **{核心裁判观点一}**——{展开法院认定理由，可引用"本院认为"原文}
2. **{核心裁判观点二}**——{展开说明}

**裁判结果：** {最终判决或裁定结果}

**参考价值：** {一两句话说明对用户问题的参考意义}
```

行政处罚决定类（来自可核验来源）：

```markdown
### {案件标题}

| 基本信息 | 内容 |
|------|------|
| **案件类型** | 行政处罚决定 |
| **处罚文号** | {文号} |
| **处罚机关** | {作出处罚的行政机关} |
| **处罚日期** | {日期} |

**违法事实：** {一段叙述当事人、违法行为、查处经过}

**处罚依据与结果：** {引用的法条 + 处罚内容}

**参考价值：** {一两句话说明对用户问题的参考意义}
```

**要素说明**：
- **元信息表格格式**：表头为"基本信息 | 内容"，**第一列（字段名，如案件类型、案号）加粗**，第二列为对应值，如上方模板所示
- **案件类型标签**：必填，是呈现给用户的核心元信息；A/B/C 内部分级不出现在此处或任何面向用户的位置
- **事实**：基于检索结果提炼，一段叙述即可，避免拆成多个小标题
- **要旨/依据**：裁判文书提炼"本院认为"核心观点；行政处罚决定提炼认定要点与处罚依据
- **参考价值**：点明本案与用户问题的关联性，是案例被选入的理由

> **格式铁律**：表格**只承载元信息**（案件类型、案号或处罚文号、法院或机关、日期）。违法事实、裁判要旨、处罚依据与结果、参考价值**一律用正文散文叙述，严禁并入表格行**。把整个案例做成一张"项目 | 内容"大表（违法事实、处罚结果、依据、来源全部塞进表格）是错误输出。

## 十一、公开线索与正文案例隔离

> **总原则、标准动作、行政执法类警示统一见 `legal-search-engine` 的公开来源隔离规则。** 本节只补充类案报告里公开线索的呈现约定。

要点回顾：公开检索只用于**找锚点**；每个锚点必须在专业库、官方来源或完整可核验文本中复检，取得可核验案号/文号和正文材料才可入正文。正文案例无可核验案号/文号即违规。

**公开线索的呈现（本技能特有）**：若发现公开线索但无法取得完整可核验文本，不要写成"数据库查不到"或"非数据库结果"。如确需保留，仅放入"建议人工复核事项"，以"需进一步核验某类公开线索"的抽象表述出现；不得标 A/B/C 或关联度等级，不计入对题数量、不与正文案例混排、不作结论依据。无此类事项则删除。

## 十二、输出

### 12.1 输出模式判断

| 模式 | 触发条件 | 处理方式 |
|------|---------|---------|
| **检索报告**（默认） | 检索流程正常完成 | 生成 markdown 报告文件 |
| **快速回答** | 用户明确只需简单结果 / 单点确认性问题 | 对话内直接输出 |

**快速回答信号**：用户说"简单查几个""帮我看看有没有""随便找找"等轻量化表述，或问题本身是单点确认（如"XX案是不是指导性案例"）。

**不确定时默认生成报告。**

### 12.2 快速回答模式

在对话内直接输出。不绑定固定模板，根据问题性质和案例数量灵活组织回答。

**必须包含的要素**：
- 结论先行：直接回答用户问题
- 每个案例的元信息表格（首行"案件类型"标签 + 案号/文号、机关/法院、日期）
- 事实、要旨/依据、结果、参考价值（可根据问题侧重裁剪详略）
- 案例先按相关性、再按文书效力排序；A/B/C 内部分级不呈现
- 案例正文只使用可核验案例材料；如有未充分核验的公开线索，仅抽象放入"建议人工复核事项"，不说明数据库状态或工具路径
- 如有裁判分歧，需说明

**排版原则**：
- 元信息用表格，保持视觉整洁
- 避免重复信息（标题说过的不要正文再说一遍）
- 篇幅随问题复杂度伸缩：单点确认可以很简短，多案例对比则充分展开
- 结尾附免责声明

### 12.3 检索报告模式（默认）

生成 markdown 报告文件，文件名格式：`类案检索报告_[主题关键词]_[日期].md`

**报告模板**：

```markdown
# 类案检索报告：{主题}

## 1. 检索结论

{结论前置，直接回答用户问题}

**依据基础**：{简述支撑结论的案例基础，如"3个高院案例一致支持""裁判存在分歧"}

**风险提示**：{如有不确定事项，说明具体原因}（无风险则省略本段）

## 2. 检索案例

{先按相关性、再按文书效力排序，每条案例严格使用10.3的呈现结构，首行标"案件类型"。均来自可核验案例材料。}

---

## 3. 检索分析

{主流裁判规则/认定规律归纳、例外/少数观点、趋势}

## 4. 建议人工复核事项

- [ ] {需要律师进一步确认的事项}

---

> 本检索报告由AI辅助生成，仅供参考，不构成法律意见。具体法律事务请咨询执业律师。
>
> 生成时间：{自动填充}
```

**排版要求**：
- 章节标题即说明，正文不重复标题含义（如"检索结论"下直接写结论，不再写"核心结论"等子标题）
- "检索案例"章节下直接放案例，不加多余的引导说明文字
- 风险提示用文字"风险提示"标注，不使用 emoji 符号
- 每条案例首行标"案件类型"标签；A/B/C 内部分级一律不出现在报告任何位置
- "检索案例"正文只放可核验案例材料；未充分核验的公开线索不与正文案例混排，如确需保留，仅抽象列入"建议人工复核事项"，不得说明数据库状态或工具路径
- **报告以免责声明块结尾，其后不得追加任何"数据来源说明""检索覆盖声明""法规/案例来源"等来源或过程说明**；报告顶部也不写"检索日期/问题定性"等检索元信息
- **保持模板顶层章节骨架（结论→案例→分析→复核），核心章节不缺失、顺序不颠倒；"检索分析"内部可按需分小节**。真正不允许的是增设"数据来源说明"等来源类、或"实务建议""综合建议"等行动建议类章节

### 12.4 写作规范

**结论前置**：检索结论必须出现在案例之前，直接回答用户问题，不能写"需要综合考虑"。如确实无法给出明确结论，说明原因。

**引用规范**：正文案例须有**可核验标识——案号（行政处罚决定为处罚文号）**，这是证明其为真实库内记录的底线，缺失则不得列入正文（降级到"未入库线索"或舍弃）。裁判/处罚日期等其余元信息应尽量补全；个别确实未取到的，可标注"（日期未获取）"后保留，**但绝不可编造**。裁判要旨尽量引用"本院认为"原文，用引号标注。

**案例呈现**：报告模式严格按10.3的结构输出每个案例，元信息首行标"案件类型"。**仅元信息用表格**，事实、要旨/依据、结果、参考价值四部分一律正文散文，**不得把案例整体做成一张表**。正文案例均为可核验案例材料，不展示检索工具或数据源选择；A/B/C 内部分级不出现在报告。

**不出建议**：报告只做检索与客观归纳，**不输出合规自查清单、风险应对、诉讼/抗辩策略、成功率预测**等法律意见性内容（详见专家人设 `agents/legal-search-expert.md` 输出规范第三条）。前瞻性内容仅限"建议人工复核事项"，且只列需律师核实/判断的事项。

**避免冗余**：不同层级之间不重复相同信息。标题已传达的信息正文不再赘述。章节标题自解释，不在正文开头重复标题含义。

**篇幅控制**：案件事实≤200字，裁判要旨引用关键段落不全文摘录，参考价值一两句话点明。

**量化克制**：凡"责任比例通常在X%—Y%""多数法院认为……"等量化或普遍性断言，必须有所列案例的明确数据支撑。样本不足时，改为"个案酌定，无统一比例"等克制表述，不得将少数案例的归纳包装成普遍裁判规则。

### 12.5 质量自检

输出前自检：

- [ ] 检索结论是否直接回答了用户问题？
- [ ] 所有案例是否按效力层级排序？
- [ ] 每个案例元信息表格是否完整（案号、审理法院、裁判日期、效力层级）？
- [ ] 每个案例是否包含案件事实、裁判要旨、裁判结果、参考价值？
- [ ] 是否存在标题与正文重复、冗余说明文字？
- [ ] 报告标题/命题中的限定词是否都能在案例中找到对应？若存在覆盖缺口，是否在结论中明确说明？
- [ ] （复合命题）命题"行为"要素是否已展开到法定/裁判同义表述并据此检索，而非只用用户命题口语词？
- [ ] 若结论为"对题案例极少或为零"，第七章 7.3 穷尽性闸门三类检索（非诉执行×行业词、法定同义表述全组、预检索企业名回库）是否都已实际跑过？未跑完不得下零结论。
- [ ] 是否存在某条 query 0 命中后未放宽即收手的情况？（0 命中应放宽重搜，非"不存在"证据）
- [ ] 检到了对题案例时，结论是否先报成果？是否避免把"缺诉讼文书"误写成"几乎没有对题案例"？
- [ ] 报告中是否完全不出现 A/B/C 等内部分级字样？每条案例是否都标了"案件类型"？
- [ ] "检索案例"正文是否全部来自可核验案例材料，且不展示检索工具或数据源选择？
- [ ] 未充分核验的公开线索是否未混入正文案例、未计入对题数量，并且没有写出数据库/MCP/Skill 连接状态？
- [ ] 量化/普遍性断言（如"多数法院认为"）是否有充分案例数据支撑？
- [ ] 矛盾案例是否已说明分歧及优先参照建议？
- [ ] 风险提示是否使用文字标注而非 emoji？
- [ ] 免责声明是否已附？
- [ ] **结尾是否只有免责声明、其后无任何数据源/检索覆盖/来源说明？顶部是否未写"检索日期/问题定性"？**
- [ ] **每个正文案例是否仅元信息用表格、事实/要旨/结果/参考价值均为散文（未把案例整体做成一张表）？**
- [ ] **每个正文案例是否都有可核验标识（案号/处罚文号）？无标识的是否已移出正文？缺失的次要元信息是否如实标注而非编造？**
- [ ] **是否未出现合规清单/风险应对/诉讼策略/成功率预测等建议性内容？**
- [ ] **是否保持了模板顶层骨架、未增设来源说明或行动建议类章节？**

### 12.6 输出禁止项（强制）

以下内容不得出现在面向用户的输出中（无论报告还是快速回答，除非用户明确要求）：
- 检索工具/数据源说明（含结尾的"数据来源说明""法规/案例来源"）
- 检索方法/过程描述、"检索覆盖声明"
- 检索关键词展示
- 多轮检索的轮次记录
- 相似度评估的过程细节（含 A/B/C 内部分级、"关联度等级"）
- 实操/合规/诉讼策略建议、成功率预测
- 模板外的来源说明类、行动建议类章节；顶部"检索日期/问题定性"

**原则：用户只关心检索结果，不关心怎么找到的，也不需要 AI 替律师拿主意。完整清单见专家人设 `agents/legal-search-expert.md` 的"输出规范"。**
