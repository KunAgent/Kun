# 合同 · 输出适配（交付定稿工序）

> 这是合同专家的**最后一道工序**。前面各 skill 负责"想清楚、查准确、写到位"，本 skill 负责"以最匹配的形态交付出去"。原则：**不新增法律实体内容，只做形态选择、结构编排、体例统一、风险标注、定稿封装。** 若发现实体内容缺失或自相矛盾，退回对应上游 skill 补齐，不要在这一层硬凑。

## 零、定稿前自检（铁律，先过这关）

回复前必须逐项确认，任何一项不满足则退回上游：

1. **立场一致**：全文是否始终站在 intake 确认的本方立场（甲方/乙方/第三方、强势/弱势/中立）？有无"立场漂移"？
2. **场景对齐**：交付物形态是否与命中的 C1-C9 场景匹配？（见第一节映射表）
3. **要素闭环**：可变商业要素（主体、标的、金额、期限、交付、付款、违约责任等）是否已落实或已显式标注 `【待确认：…】`？严禁用看似具体实则虚构的数字/名称填充空白。
4. **法律有据**：凡引用法律条文、强制性规定、效力判断，是否来自 `contract-legal-research` 的检索结果，而非凭空生成？无据则降级表述为"建议核实"，不得伪造法条编号。
5. **风险已标级**：所有风险点是否标注了等级（🔴高 / 🟠中 / 🟡低）并给出可落地建议？
6. **免责声明**：是否附末尾标准声明？

## 一、场景 → 交付物形态映射

| 命中场景 | 主交付物 | 配套交付物 | 关键体例 |
|---|---|---|---|
| C1 合同管理架构 | 架构方案/分层管理框架 | 角色权责表、流程图说明 | 分层级、列权责、可落地 |
| C2 合同管理制度 | 管理制度文本 | 审批授权矩阵、表单清单 | 条文式、含适用范围与罚则 |
| C3 合同模板库 | 标准合同模板 | 填写指引、风险提示批注 | 留可变占位符 + 批注 |
| C4 具体合同起草 | 完整合同文本 | 起草说明、风险批注 | 标准合同体例（见第二节） |
| C5 合同背景评估 | 背景评估意见书 | 主体核查结论、风险清单 | 总述 + 分点 + 结论 |
| C6 合同条款审查 | **带修订痕迹的合同修订稿（docx）** 或 **审查三项产物（Excel+Markdown+Word批注）** | 修订要点摘要、风险清单 | "帮我改"→track changes（第三·五节）；"出报告/Excel"→三项产物（第三·六节）|
| C7 合同谈判支持 | 谈判策略简报 | 争点立场矩阵、让步底线表 | 争点-我方-对方-策略 |
| C8 合同纠纷应急（非诉） | 应对方案/处置建议 | 函件文本、证据梳理清单 | 分阶段 + 函件成品 |
| C9 条款变更/补充协议 | 补充协议文本 | 变更对照说明 | 引用原约 + 增删改清单 |

> 一次请求可能跨多场景（如"起草+审查"），按主场景定主交付物，其余作配套。

## 二、标准合同文本体例（C3/C4/C9 通用）

```
合同名称（XX合同 / 补充协议）
甲方：【主体全称、统一社会信用代码、住所、法定代表人】
乙方：【同上】
鉴于条款（背景/缔约基础，按需）

第一条 定义与解释（按需）
第二条 标的与范围
第三条 价款/费用与支付（金额、币种、节点、方式、发票）
第四条 履行（交付/服务标准、时间、地点、验收）
第五条 双方权利义务
第六条 知识产权 / 保密（按需）
第七条 违约责任（违约情形、责任方式、违约金/赔偿计算）
第八条 不可抗力
第九条 合同变更、解除与终止
第十条 争议解决（管辖法院 / 仲裁机构，二选一明确）
第十一条 通知与送达
第十二条 其他（生效条件、份数、附件效力）
落款：双方签章 + 日期
```

体例规则：
- **固定法律条款**（违约、不可抗力、争议解决、通知送达等）用稳健通用表述，确保效力与可执行性。
- **可变商业要素**用 `【方括号占位】` 明确标出，未确认的一律写 `【待确认：xxx】`，绝不臆造。
- 高风险或需提醒之处，行内插入 `〔风险提示：……〕` 批注，不混入正文权利义务。

## 三、审查意见书 / 风险清单体例（C5/C6）

风险清单统一字段，按风险等级从高到低排序：

| # | 条款定位 | 风险描述 | 风险等级 | 法律/商业依据 | 修改建议 |
|---|---|---|---|---|---|
| 1 | 第X条 第X款 | 站在本方立场的不利点 | 🔴/🟠/🟡 | 法条或商业逻辑 | 可直接落地的改法 |

意见书结构：**一、总体结论**（可否签 / 需重大修改后签 / 不建议签）→ **二、重点风险（高级优先）** → **三、逐条意见** → **四、修改建议汇总** → 免责声明。

## 三·五、合同修订稿（C6/C9 默认交付，docx 原生修订痕迹 + 批注）—— 铁律

当用户提供了一份 **`.docx` 合同**并要求"审核修订 / 帮我改 / 出修订稿"时，**默认交付物是
在原文上做了 Word 原生修订痕迹 + 批注的修订稿 docx**，而不是把条款摘出来写"原文/修订后"对照块。

### 必须这样做（✅）

- 在**原始 docx 本身**上，对**真正变化的字符片段**打痕迹：删除的字带删除线、新增的字带下划线，
  **未改动的字原样保留**——同一句话里通常只有几个词带痕迹，像真人律师逐字改的稿子。
- 每处改动旁挂**批注气泡**，写清"为什么改 + 依据（法条/商业逻辑）+ 谈判提示"。
- 用户在 Word/WPS 里可逐条"接受/拒绝修订"、可查看批注。

### 禁止这样做（❌）

- ❌ 把条款挑出来排成"【原文】……／【修订后】……"的大段对照块当作修订稿。
- ❌ 新建一个文档逐条罗列替换、整段删旧写新（那是审查笔记，不是修订稿）。
- ❌ 让用户自己把改动誊回原文。

### 工具与流程

用 `bin/redline-docx`（详见 `references/redline-docx-guide.md`）：

```bash
python3 <expert>/bin/redline-docx apply --in 原合同.docx --edits edits.json --out 修订稿.docx --author "合同专家"
python3 <expert>/bin/redline-docx verify --in 修订稿.docx   # 交付前必校验，痕迹/批注数应>0
```

`edits.json` 每条 = `find`（原文精确锚文本）+ `replace`（改后整句，工具自动 diff 出增删）+
`comment`（修订理由）。锚文本必须从提取的原文逐字复制，匹配不到会进 `edits_missed`。

### 正文回复

交付修订稿后，正文**只给精简的"修订要点表"**（条款 | 改了什么 | 风险等级 | 依据），
**不再重复大段原文/修订后对照**。然后 `present_files` 交付 docx，末尾附免责声明。

> 例外：若用户明确只要"审查意见书/风险清单"而非改文件，或原件非 docx（如 PDF/图片/纯文本贴入），
> 则退回第三节的意见书/清单体例；如能转成 docx 文本则仍优先出修订稿。

## 三·六、专业审查三项产物（C5/C6 · 用户要"出报告/Excel/批注"时启用）—— 来自审合君

当用户明确要"审一下这份合同并出报告 / 给我 Excel / 标批注"时，进入**专业审查模式**，交付**三项产物**。风险等级统一用 **🔴高风险 / 🟡中风险 / 💡提示** 三级；仅输出风险项与提示项，审查通过/不涉及的条款不列出。三项产物的风险数据均来自 `contract-review-engine` 专业审查模式（八步动作 + 定级矩阵）。

### 产物一：Excel 文件（2 Sheet）

调用 `/xlsx` skill 生成，文件名 `合同审查结果-[合同名称]-YYMMDD.xlsx`（YYMMDD 为当前日期）。

| Sheet | 表头 | 内容 |
|---|---|---|
| **风险项** | 合同原文 \| 风险等级 \| 审查维度 \| 法律依据 \| 风险提示 | 高风险 + 中风险，高风险在前 |
| **提示** | 合同原文 \| 审查维度 \| 提示说明 | 提示项 |

字段说明：风险等级用 🔴高风险/🟡中风险；审查维度=Playbook 分类名（如"违约责任与救济"）；法律依据=具体法条引用（形式审查风险项留空）；风险提示按 `【风险】…【建议】…` 格式。**不出现审查点名称、审查规则列。**

### 产物二：对话内 Markdown 风险报告

与 Excel 同时在对话中给出，固定 5 段：
```
# 合同审查报告 — 《[合同名称]》
## 基本信息（审查立场/对方主体/合同类型/审查日期）
## 风险总览（高/中/提示 数量+占比表 + 一句话综合评价）
## 风险清单（按审查维度分组 #### ，每项含关联条款/法律依据/风险说明/建议；🔴→🟡→💡）
## 关键建议摘要（编号列出最重要的几条）
---
📊 完整数据见 Excel：`合同审查结果-[合同名称]-YYMMDD.xlsx`
*本报告基于合同文本分析，不替代专业律师出具的法律意见书。*
```
规则：动态识别风险项在审查维度后标注 `[动态识别]`；某等级无项则在总览标 0 且该等级不出现在清单；不出现内置 PB 名称、不展示审查分析过程。

### 产物三：Word 批注文件

调用 `/docx` skill 将高/中/提示项以批注形式标注在合同上，文件名 `合同审查批注稿-[合同名称]-YYMMDD.docx`。
- 输入为 Word → 直接在原文加批注；输入为 PDF/纯文本 → 先创建 Word 再批注。
- 批注人统一署名「**审合君**」；每条锚定在对应原文位置，提示项无法锚定时锚定合同首部。
- **Word 批注不输出法律依据**（法律依据仅出现在 Excel 和 Markdown）。
- 批注格式：`[🔴高风险/🟡中风险/💡提示] [审查维度]` + 风险说明 + 建议（提示项为提示说明）。

### 三项产物模式的执行与自检铁律

- **执行静默**：合同解析、逐条审查过程不在对话展示；对话中仅出现"我方/审查规则确认信息"与"最终三项产物"。
- **交付前自检**（任一不过则修正后再交付）：
  - [ ] Excel 恰好 2 个 Sheet（风险项/提示），表头正确，高风险在前；不含通过项/未涉及项/审查规则列。
  - [ ] Markdown 含 5 段，风险按维度分组，不出现内置 PB 名称与分析过程。
  - [ ] Word 批注署名「审合君」，三级标注，批注中不含法律依据，非 Word 输入已先转 Word。
  - [ ] 工作目录仅留 Excel 与 Word 两个输出文件，无中间/临时文件。
- 最后用 `present_files` 交付 Excel + Word 两个文件，并附免责声明。

> 与 docx 修订稿（第三·五节）的分工：用户要"**帮我改**"→ 出 track changes 修订稿；用户要"**审了告诉我哪有风险/出报告/Excel**"→ 出三项产物。两者可按用户措辞二选一，也可在用户要求时同时给。



## 四、其他形态要点

- **谈判策略简报（C7）**：争点矩阵（争点｜我方立场与依据｜对方可能立场｜应对策略｜让步底线），明确"必争/可让/可换"三档。
- **应急处置方案（C8 非诉）**：按"止损固证 → 立场研判 → 函件/协商 → 后续路径"分阶段；函件作为成品附上，措辞与本方立场和目的一致。
- **管理制度/架构（C1/C2）**：条文式 + 配套审批授权矩阵；标注适用范围、生效方式，落地性优先于面面俱到。
- **补充协议（C9）**：开头引用原合同名称与签署日期，正文以"增/删/改"对照方式表述，明确"本协议与原合同冲突时以本协议为准 / 未尽事宜仍依原合同"。

## 五、统一体例与措辞规范

- 法条引用统一为《中华人民共和国民法典》第XXX条 格式；同一文档内体例一致。
- 风险等级标识全篇统一用 🔴高 / 🟠中 / 🟡低。
- 金额、日期、主体名称等关键信息，确认的写实、未确认的占位，**禁止半真半假**。
- 面向不同读者适配深度：法务/律师可保留法条与论证细节；业务/管理层侧重结论、风险与行动建议，论证收敛为要点。

## 六、标准免责声明（每次交付末尾必附）

> 本内容由 AI 依据你提供的信息与公开法律资料生成，仅供参考，不构成正式法律意见。合同的最终签署与重大决策，请结合具体事实并经执业律师或法务复核。涉及金额重大、结构复杂或争议风险高的事项，强烈建议委托专业人士出具正式意见。

## 不要做

- 不在本层新增/篡改法律实体判断或商业条款实质。
- 不为追求"看起来完整"而臆造主体名称、金额、法条编号、机构名称。
- 不暴露内部工具调用、检索过程、技能名称等机理细节。
- 不省略免责声明。
