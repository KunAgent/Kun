# 合同场景决策表

> 本表是场景识别的核心知识库。命中某个三级场景后，即可确定该场景的「核心应用目的」「输出标准」「典型工作流」，直接驱动后续交互采集、检索与实质工序。
> 三级结构：场景分类（一级：合同管理）→ 二级场景 → 三级场景（C1–C9）。

---

## 一级场景：合同管理

合同专家服务于企业合同管理全生命周期：从管理体系搭建，到起草、审查、谈判，再到履行处置与变更。在此一级范围下，划分为四个二级场景、九个三级场景。

---

## 二级场景 A：合同管理（体系搭建）

面向"如何把合同管起来"的体系性需求——管理架构与管理制度。

### C1. 合同管理架构

- **核心应用目的**：明确企业合同管理涉及哪些部门、需要哪些专业能力、部门之间如何分工。
- **输出标准**：常见合同管理模式类型 + 不同类型的适用情况（集团/公司）+ 各部门职责分工体系 + 总结。最终交付《企业合同管理架构与职责清单》。
- **是否交互采集**：是。需先收集组织架构图、核心业务线说明、各部门岗位职责。
- **典型工作流**：
  1. 用对话式问答收集企业现有组织架构图、核心业务线说明及各部门岗位职责。
  2. 识别并罗列合同业务中必须参与的关键部门（业务部门、财务部门、法务/合规部门、决策管理层）。
  3. 界定各部门在合同流转中的职权与分工边界（业务定业务场景与技术标准，财务审收付款与税务，法务把控文本结构与法律风险）。
  4. 按合同从发起到完结的时间顺序，梳理跨部门协作流转路径（谁起草、经谁审核、谁定稿）。
  5. 按标的金额、交易类型及重要程度，建立分级授权与审批矩阵，明确不同级别合同的决策人。
  6. 整合输出结构化的《企业合同管理架构与职责清单》。
- **典型提问示例**：我是一个法务，该如何在现有企业组织架构下设计合同管理架构？

### C2. 合同管理制度

- **核心应用目的**：围绕签署流程—过程节点管控—到期后处置—归档，搭建合同全生命周期管理制度。
- **输出标准**：管理目标与原则 + 制度核心模块设计（分类、编号、权限、版本管理、台账搭建等）+ 关联关注点提示 + 引导用户进一步补充信息。
- **是否交互采集**：是。需结合用户背景（有无线上系统、合同类型分布、痛点）。
- **典型工作流**：
  1. 问题解读与定位：结合背景说明明确本次目标及重点待解决问题。
  2. 基于目标和问题，结合实际情况确立管理目标和管理原则。
  3. 调取知识库或全网检索，进行核心管理模块设计，将制度拆解为落地执行细节。
  4. 拉通全部核心管理模块，搭建合同管理全生命周期流程设计。
  5. 调取知识库或全网检索，分析制度搭建的关联风险并输出提示。
  6. 综合分析用户现阶段需求，引导用户继续交互补充。
- **典型提问示例**：公司暂时没有线上合同管理系统，但想规范合同管理制度，应该如何设计？

## 二级场景 B：合同起草

面向"造合同"的需求——模板库建设与具体合同起草。

### C3. 合同模板库建设

- **核心应用目的**：依据用户需求，提供合同模板起草和合同模板库架构设计建议。
- **输出标准**：合同模板库结构体系 + 各细分合同类型的模板条款目录 + 调用/检索知识库或权威数据库内容构建的模板。
- **是否交互采集**：是。需收集核心业务场景、需建模板的合同类型分类。
- **典型工作流**：
  1. 梳理企业核心业务场景，确定模板库的合同类型分类架构（买卖、租赁、服务等）。
  2. 按合同大类的交易时间轴与商业闭环，依次起草各类别专属的核心结构组块条款。
  3. 提取通用的保密、违约、争议解决等规则，做成统一的基础条款库。
  4. 把基础条款与专属核心条款拼装，每份模板拆成"后台锁定的固定法律条款"与"供用户填写的可变商业要素"两部分。
  5. 对初代标准模板做合法性与合规性审查，确认无违反现行法律强制性规定后定稿。
  6. 定稿模板分类入库，建立定期更新机制，确保紧跟法律法规变化。
  7. 编制模板调用操作指引，指导用户填入交易对象、金额、付款时间等核心商业信息一键生成正式文本。
- **典型提问示例**：我想为公司搭建合同模板库，先帮我起草设备采购合同/网页设计制作合同的模板。

### C4. 具体合同起草

- **核心应用目的**：针对既有模板无法匹配的特殊合作需求，基于用户提供的具体需求起草对应合同。
- **输出标准**：完整合同文本 + 合同中的特殊条款 + 风险批注。
- **是否交互采集**：是。需收集核心商业目的、资金流向、各方权责分配、商业预期及底线。
- **典型工作流**：
  1. 接收起草申请，通过合同分类逻辑比对，确认该复杂需求无法适用任何标准模板。
  2. 用对话式方式引导用户输入并收集特殊需求细节（商业目的、资金流向、权责分配、预期与底线）。
  3. 据交易频率和复杂程度，提供三种合同结构套餐：单次独立交易选"完整主合同"，长期持续交易选"框架协议+订单"，复杂技术或服务交易选"主合同+附件清单"。
  4. 从模板库定向调用不可随意修改的通用基础条款（争议解决管辖地、保密义务、常规违约责任）。
  5. 针对特定商业诉求，用严谨法律语言将各方权利义务转化为具体条款，与通用基础条款组装。
  6. 对突破常规商业惯例的高风险条款、或需重点关注严格履行的环节，添加客观清晰的风险提示批注。
  7. 草案交付用户复核，依据商务谈判进展对条款迭代修正，形成合同文本。
- **典型提问示例**：我方（甲方）出品牌商标和素材授权，对方（乙方）据此设计周边并开网店售卖，这个合作合同应该如何写？

## 二级场景 C：合同审查

面向"审合同"的需求——签约前背景评估、条款审查与谈判支持。

### C5. 合同背景评估

- **核心应用目的**：签订合同前对合作项目本身进行风险评估，如评估合作方资质、合同形式、交易模式等是否合法合规。
- **输出标准**：总结性说明 + 分点对背景输出评估意见（含风险等级）。
- **是否交互采集**：是。需提取/补充交易主体、交易类型、合同标的、金额规模、行业领域、地域/法域、特殊背景，并引导用户补充合作方具体信息。
- **典型工作流**：
  1. 提取合同背景要素（交易主体、交易类型、标的、金额、行业、地域/法域、特殊背景）；信息模糊或缺失则引导补充。
  2. 调用法律法规 skills/数据库或联网检索，了解该类型交易的最低合法门槛。
  3. 引导补充合作方信息，调用企业信用信息 skills/数据库，核查交易相对方主体资格、法定资质及履约能力。
  4. 分析交易模式、商业目的、标的物属性、预期资金流向，评估交易模式合法性。
  5. 审查拟采用的合同类型是否与实际交易模式匹配。
  6. 涉及特殊程序（行政许可、备案、审批、内部决策）时，评估关键程序是否完备。
  7. 就上述方面逐一分析，明确风险等级，做总结性说明并给出分点评估意见。
- **典型提问示例**：我们想委托食品加工企业订制带公司logo的月饼礼盒，这个合作应重点关注哪些要点？

### C6. 合同条款审查

- **核心应用目的**：针对用户提供的合同，对具体条款进行风险审查，提示风险并给出处理建议。
- **输出标准**：总结性提示 + 结构化风险清单（含风险等级、风险描述、法律依据、应对建议）+ 行动指南总结。可提供批注修改版合同 / 合同审查意见书。
- **是否交互采集**：是。**必须先确认立场口径**（甲方/乙方/第三方，强势/弱势/中立）、合同背景/特殊需求。
- **典型工作流**：
  1. 询问并确认本方立场、审查口径、合同背景/特殊需求；必要时按交易背景与类型进一步设选项询问关键事实。
  2. 审核文本完整性（必要条款、附件是否缺失，是否有待补充信息）；校对引用法条时效/名称、机构名称、文字错漏/关联条款矛盾等常识性问题。
  3. 审核签约主体（名称是否准确、是否存在履约风险如被执行/重大处罚/负面舆情、是否具备必要资质）。
  4. 将文本模块化拆解，提取权利义务分配、违约责任、争议解决等核心条款。
  5. 结合审查背景，依据现行法律法规及司法实践，对条款逐一做合法性、商业合理性审查，系统核查风险（条款无效、权义失衡、核心利益缺保障、缺乏可执行性等）。
  6. 针对问题条款撰写风险描述，指出可能引发的法律后果；列明风险等级、风险类型，按审查口径提供应对/修改建议。
  7. 提供可选的结构化成果：批注修改版合同、合同审查意见书等。
- **典型提问示例**：（附件：待审合同文本）站在甲方立场审阅这份协议，提示风险点。

### C7. 合同谈判支持

- **核心应用目的**：参与重大合同签署的商务谈判，制定谈判策略，实时提供法律意见。
- **输出标准**：分析并总结用户需求 + 核心法律依据示例 + 法律商业双重分析 + 可提供材料的建议 + 谈判策略建议 + 总结。
- **是否交互采集**：是。需确认本方交易地位（优势/促成交易）、核心商业诉求与底线、双方核心冲突点。
- **典型工作流**：
  1. 确认本方在本次合作中的地位（优势地位或促成交易地位），梳理本方核心商业诉求与合作底线。
  2. 引导用户明确双方核心利益冲突点，做法律、商业层面双重分析。
  3. 结合交易地位、冲突点及分析结果，制定谈判策略——明确哪些死守、哪些可作筹码、哪些可放行。
  4. 设计谈判路线图：先谈什么、后谈什么、什么用来交换。
  5. 就策略和路线图，提供法律依据示例、行业惯例案例、同类合同条款对比表等支撑。
  6. 谈判结束后对最终文本整体复核，确认表述准确且符合谈判共识后，出具准予签署的书面法律意见。
- **典型提问示例**：一个平台主体转移需求，我方是转出方，含大量数据转移，对方担忧数据转移风险及是否非法出境，我该如何说服对方律师不存在这些问题？

## 二级场景 D：合同履行

面向"合同签了之后"的需求——履行中纠纷处置与条款变更。

### C8. 合同纠纷应急处置（非诉）

- **核心应用目的**：针对履行过程中发生的问题，结合背景信息，就相关问题的处置提出建议。
- **输出标准**：引导完善用户需求 + 核心法律依据列示 + 结合法律和实际争议点分析 + 可落地的实际风险应对建议 + 总结。
- **是否交互采集**：是。需收集纠纷关键事实、证据材料盘点、对方反应。
- **典型工作流**：
  1. 引导用户输入违约或纠纷事件的关键事实，形成案情时间线摘要。
  2. 全面收集并固定基础事实材料（合同正本、往来邮件、送货验收凭证、付款流水、沟通记录），确保非诉应对证据链完整。
  3. 依据固定的事实证据与现行法律法规，判断责任归属和违约性质，输出法律风险评估。
  4. 结合本方交易地位制定非诉应对策略，明确对外沟通话术模板，起草《催告函》《律师函》《沟通函》等文件。
  5. 基于案件严重程度和对方反应，预设案件升级阈值。
- **典型提问示例**：我是广告联盟平台，约定先充值才可推广，但业务人员先推广未充值产生欠款，广告主以"操作人员未获授权且已离职"为由不认账，应如何解决？

### C9. 合同条款的变更/增删（补充协议）

- **核心应用目的**：解决合同履行过程中需要变更/增删原始条款时的问题。
- **输出标准**：分析并总结用户需求 + 补充协议的文本内容模板 + 签署流程建议。
- **是否交互采集**：是。需获取原合同文本、要变更的条款与诉求。
- **典型工作流**：
  1. 接收变更或增删需求，核对原生效合同文本，确认需变更的类型、内容。
  2. 评估本次变更对原合同履约基础的影响，排查是否触发新合规风险、是否改变违约责任/争议解决机制、是否产生条款冲突。
  3. 依据商业诉求与风险评估，专项起草《补充协议》，明确变更条款措辞 + 生效条件 + 与原合同关系说明。
  4. 将《补充协议》交付己方相关人员与相对方进行商业确认和审核。
  5. 文本一致后，按原合同同等授权层级启动内部审批与用印流程，签署后原件与原合同归集封存，同步更新电子档案与履约台账。
- **典型提问示例**：（附件：原合同文本）合同三个月前已签署，现想改变合同有效期约定，该如何签补充协议？

## 输出档位与交付形态规则

| 输出档位 | 交付物形态 | 是否交互采集 | 主导工序 |
|---|---|---|---|
| 轻量 | 单点合同知识咨询、条款含义解释 | 通常否 | 直接回答 / 轻量检索 |
| 中量 | 合同背景评估意见、谈判要点、补充协议、单类模板 | 是 | review-engine / lifecycle-advisor / drafting-engine |
| 重量 | 完整合同文本、合同审查意见书/风险清单、管理制度、模板库体系、纠纷非诉处置方案 | 是 | drafting-engine / review-engine / lifecycle-advisor |

| 用户需求特征 | 命中场景 | 交付物形态 | 输出档位 | 主导工序 |
|---|---|---|---|---|
| "怎么设计合同管理架构/部门分工/审批权限" | C1 | 管理架构与职责清单 | 重量 | lifecycle-advisor |
| "怎么搭建合同管理制度/全流程管控/归档" | C2 | 管理制度文件 | 重量 | lifecycle-advisor |
| "帮我搭合同模板库/起草XX合同模板" | C3 | 模板库体系 + 模板 | 重量 | drafting-engine |
| "帮我起草一份XX合同/这个合作合同怎么写" | C4 | 完整合同文本（含批注） | 重量 | drafting-engine |
| "这个合作要重点关注什么/签约前评估" | C5 | 背景评估意见 | 中量 | review-engine |
| "帮我审这份合同/提示风险点" | C6 | 风险清单/审查意见书 | 重量 | review-engine |
| "怎么谈这个合同/谈判策略" | C7 | 谈判策略与路线图 | 中量/重量 | lifecycle-advisor |
| "履行中出问题/对方违约怎么办（非诉）" | C8 | 非诉处置方案 + 函件 | 重量 | lifecycle-advisor |
| "想改原合同某条/怎么签补充协议" | C9 | 补充协议 + 签署流程 | 中量 | drafting-engine |
| 单点确认性合同问题 | 简易咨询 | 对话内联回答 | 轻量 | 直接回答 |

> 一个需求可能横跨多场景（如"先评估这个合作、再帮我起草"= C5 + C4）。允许命中多个场景并按先后串联工序。
