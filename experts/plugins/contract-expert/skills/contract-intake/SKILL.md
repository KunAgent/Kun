# 合同 · 交互式信息采集

> 这是合同专家的**信息地基工序**。合同工作高度依赖具体交易细节——主体、标的、金额、立场、商业目的、底线——这些缺失时，任何起草/审查/谈判结论都是空中楼阁。本 skill 用对话式问答（字段多时用问卷式清单）把开工所需的关键事实收集齐，**缺什么问什么，绝不臆造**。

> ⚠️ **本质不是"念题库"，而是"做分析"。** 下文各场景清单是**参考基线（非穷举）**，用来兜底、防漏，不是要逐条照搬的固定问卷。真正要做的是：读懂用户这次的具体需求与交易场景，**推导出本案真正影响结论的未知量**，据此适配性地提出问题——该扩充就扩充、该删减就删减、该追加场景特有的问题就追加，永远以"这一案缺什么关键信息"为准，而非"清单上还剩哪几条没问"。

## 核心原则

1. **先采集，后动手**：场景识别任务单标记【是否交互采集：是】时，必须先完成本工序，再进入起草/审查/履行工序。
2. **分析驱动，而非清单驱动**：每次采集前，先针对用户的具体需求做一次快速拆解（见下节"适配性提问方法"），由分析结果决定问什么；参考清单只用于查漏补缺，不主导提问。
3. **缺口驱动，不做无谓追问**：只问"缺了会导致结论跑偏"的关键事实；用户已提供或可从附件提取的，绝不重复问。
4. **能假设的先假设**：核心要件缺失但存在有限互斥取值时（如"是否已书面约定""本方是甲方还是乙方"），优先给互斥选项让用户一选即定，或先按两分支并行覆盖，而非开放式追问拖慢节奏。
5. **分批适配**：缺 1–3 项关键事实时用自然对话逐个确认；缺一整组（如起草所需的全套交易要素）时，输出结构化问卷清单让用户一次性补齐。
6. **采集即结构化**：收到回答后立即把事实整理成结构化要素清单，作为后续工序的直接输入。
7. **起草/审查类顺带告知"可提供自有标准"**：命中起草（C3/C4/C9）或审查（C5/C6）场景且用户尚未提供模板/规则时，在采集时自然带一句——"贵司若有合同模板、惯用条款、审查规则或 Playbook，可一并发我，我会优先按贵司标准起草/审查"。告知一次即可，用户不提供就用通用标准，详见 `contract-standards-ingest`。

## 适配性提问方法（核心，先做这步）

不要一上来就抛清单。先用下面这套思路从用户的需求与场景中**生成**问题：

1. **复述并拆解需求**：把用户这句话拆成"想达成什么交易目的 / 处于什么场景 / 已经给了哪些信息"。
2. **定位本案的决策关键变量**：问自己——要在这个场景里给出靠谱结论，哪些信息是"不知道就会出错或写不下去"的？这些就是必问项。典型维度（按需取用、可超出）：
   - **主体**：各方是谁、自然人还是企业、资质与履约能力。
   - **标的与范围**：交易什么、边界在哪、有无质量/验收标准。
   - **对价与资金流**：金额、计价、付款节点、票据。
   - **立场与强弱**：本方是甲/乙/第三方、强势/弱势/中立（审查、谈判、起草的命门）。
   - **商业目的与底线**：必须拿到的、绝不接受的、可让渡的。
   - **时间与履行**：期限、交付节奏、持续还是单次。
   - **风险与特殊性**：行业监管、跨境、关联交易、行政许可、知识产权、独家性等。
3. **针对每个未知变量生成一个具体问题**：把抽象维度转成用户能直接回答的问句，必要时附通俗解释和示例；能给互斥选项的就给选项。
4. **追加场景特有问题**：参考清单兜底后，再想"这个具体交易有没有它独有、清单覆盖不到的关键点"（如直播带货合同的坑位费/退货率、对赌协议的业绩指标），主动补问。
5. **删掉不相关项**：用户场景明显用不到的清单项直接略过，不为凑数而问。
6. **判断深浅**：简单标准交易问到能开工即止；金额大/结构复杂/争议风险高的，问得更深、更细。

> 一句话：**清单负责"别漏"，分析负责"问得准"。两者结合，但分析优先。**

## 提问方式选择

| 缺口规模 | 方式 | 形态 |
|---|---|---|
| 1–3 个关键点 | 对话式追问 | 编号问题 + 互斥选项（如适用） |
| 一整组要素 | 问卷式清单 | 分组表格/清单，标注"必填/选填" |
| 立场/口径类单点 | 选项式确认 | "你是甲方还是乙方？强势/弱势/中立？" |

> 提问时，对专业字段给出通俗解释和示例，降低用户填写门槛；对必填项明确标注，对可缺省项说明缺省后的处理（如按通用惯例假设）。

## 各场景参考清单（非穷举 · 按实际情况增删调整）

> 以下清单是**兜底参考基线**，命中场景后用它对照"是否漏了关键项"，而不是逐条照念。请先用上节"适配性提问方法"分析本案，再用清单查漏补缺，并按本案特点扩充/删减/改写。每条后的【必填/选填】也只是常态默认，可随场景调整。

### C1 合同管理架构
- 企业组织架构图 / 主要部门设置【必填】
- 核心业务线说明（主营业务、典型交易类型）【必填】
- 各相关部门现有岗位职责【必填】
- 是集团还是单一公司、是否多层级、是否跨地域/跨法域【必填】
- 现有合同审批/用印/归档流程（如有）【选填】
- 合同年度量级与高频合同类型【选填】
- _按需扩充：是否有线上系统、是否需对接 OA/ERP、是否分子公司分权等_

### C2 合同管理制度
- 当前是否有线上合同管理系统【必填】
- 主要合同类型分布与年度合同量级【必填】
- 本次最想解决的痛点（如审批慢、归档乱、版本失控、用印不可控）【必填】
- 管理目标与希望坚持的原则【选填】
- 现有制度/流程文件（如有）【选填】
- _按需扩充：分级审批权限设想、风险分级标准、违规罚则期望等_

### C3 合同模板库建设
- 需建模板库覆盖的核心业务场景【必填】
- 优先要起草的具体合同类型【必填】
- 本方通常的交易立场（多为甲方/乙方）【必填】
- 是否有现成范本或惯用条款【选填】
- _按需扩充：是否需多版本（强/弱势版、内外部版）、是否留可变占位符规范等_

### C4 具体合同起草
- 核心商业目的（这笔交易要达成什么）【必填】
- 各方主体身份与角色（谁是甲方/乙方，自然人/公司）【必填】
- 标的物/服务内容与范围【必填】
- 资金流向（金额、付款节点、计价方式）【必填】
- 各方核心权利义务分配【必填】
- 商业预期与底线（必须拿到的、绝不接受的）【必填】
- 交易频率与复杂度（单次/长期持续/复杂技术服务）→ 决定合同结构套餐【必填】
- 特殊需求条款（排他、知识产权归属、保密、竞业、数据合规等）【选填】
- _按需扩充：行业特有要素（如带货坑位费与退货率、加工的原料归属与残次率、租赁的押金与维修责任）_

### C5 合同背景评估
- 交易主体（双方名称、性质）【必填】
- 交易类型与合同标的【必填】
- 金额规模【必填】
- 行业领域、地域/法域【必填】
- 合作方具体信息（用于主体资格核查）【必填】
- 特殊背景（关联交易、跨境、需行政许可/备案、是否涉及国资/上市公司等）【选填】

### C6 合同条款审查
- 待审合同文本（附件或粘贴）【必填】
- **本方立场口径：甲方 / 乙方 / 第三方？强势 / 弱势 / 中立？**【必填，最关键】
- 合同背景与交易目的【必填】
- 特殊关注点或已知争议【选填】
- _按需扩充：本次审查的侧重（全面体检 / 只看付款与违约 / 只看知识产权与保密）_

### C7 合同谈判支持
- 本方在本次合作中的地位（优势地位 / 促成交易地位）【必填】
- 本方核心商业诉求与合作底线【必填】
- 已知的双方核心利益冲突点【必填】
- 对方背景与谈判风格（如已知）【选填】
- _按需扩充：可让渡的筹码、必争的红线、备选方案（BATNA）_

### C8 合同纠纷应急处置（非诉）
- 纠纷/违约事件关键事实与时间线【必填】
- 已签合同正本及关键条款【必填】
- 现有证据材料盘点（邮件、验收凭证、付款流水、沟通记录）【必填】
- 对方目前的态度与反应【必填】
- 本方诉求（要回款/解约/继续履行/止损）【必填】
- _按需扩充：是否有时效/期限压力、是否已发函、是否涉及担保或第三方_

### C9 合同条款变更/增删（补充协议）
- 原生效合同文本【必填】
- 要变更/增删的具体条款【必填】
- 变更背后的商业诉求【必填】
- 变更是否已与对方达成初步一致【选填】
- _按需扩充：变更是否影响对价/期限/担保，是否需重新走审批_

## 采集输出格式

采集到足够信息后，输出一份结构化「交易事实清单」，交给下一工序：

```
【交易事实清单 · C4 具体合同起草】
- 商业目的：甲方授权品牌商标与素材，乙方设计周边并开网店售卖、分成
- 主体：甲方=【品牌方公司，待填名称】；乙方=【设计运营方，待填名称】
- 标的：商标/素材授权 + 周边产品设计与网店运营
- 资金流向：销售分成【比例待确认】，是否有保底/授权金【待确认】
- 核心权义：甲方授权范围与品控权；乙方设计、运营、结算义务
- 底线：甲方品牌不得被滥用、授权可终止；乙方需独家/非独家【待确认】
- 交易频率/复杂度：长期持续合作 → 建议"框架协议+订单"或主合同+附件
- 仍缺/待确认：双方主体名称、分成比例、授权独家性、授权期限
```

## 关键约束

- **分析优先于清单**：先拆需求、定关键变量、生成问题，再用清单查漏，禁止把清单当唯一来源逐条照念。
- **不被预设问题框死**：本案特有的关键点哪怕清单没有，也必须主动问；清单上明显无关的项要略过。
- **绝不臆造**：用户未提供的当事人名称、金额、关键事实，一律标为"待填写【】"或列入"仍缺/待确认"，不得编造具体值冒充真实信息。
- **一次问全，避免反复打断**：字段多时优先用问卷清单一次性收集，不要挤牙膏式逐条追问消耗用户耐心。
- **立场口径是审查/谈判类的命门**：C6/C7 缺立场口径时，必须先问清再继续，不得默认。
- 采集只负责"把事实问清楚并结构化"，不在本工序做实质起草/审查结论。
