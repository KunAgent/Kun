# 研究交付物框架

本标准规定股票研究输出的产出形式、质量标准和结构规范。

## 交付物类型优先级

根据任务复杂度和用户需求，选择合适的产出形式：

| 优先级 | 形式 | 适用场景 |
|--------|------|---------|
| 1 | HTML 独立报告 | 首次覆盖、深度分析、多空推介、组合风险计划 |
| 2 | Markdown 结构化输出 | 业绩分析、行业综述、催化日历、晨会纪要 |
| 3 | 对话式回复 | 快速问答、单一指标查询、简单观点 |

### HTML 报告标准

当产出为 HTML 独立报告时，遵循以下规范：

- **自包含**：CSS/JS 内联，无外部依赖，可直接浏览器打开
- **响应式**：支持桌面和移动端阅读
- **数据可视化**：使用内联 Chart.js 或 ECharts（CDN 引入）渲染图表
- **专业排版**：标题层级清晰、表格对齐、数字右对齐、注释在脚注
- **打印友好**：包含 `@media print` 样式

### Markdown 输出标准

- 使用清晰的标题层级（H1-H4）
- 定量数据使用表格呈现
- 关键结论加粗或使用 callout
- 来源标注使用脚注格式

## 报告通用结构

### 1. 封面/摘要
- 标的名称、代码、市场
- 评级/目标价/当前价
- 报告日期
- 核心观点（3 句话以内）

### 2. 投资要点
- 3-5 个核心 bullet point
- 每个要点有数据支撑

### 3. 正文分析
- 根据具体技能类型展开
- 遵循"先结论后论证"的写作逻辑

### 4. 估值与评级
- 估值方法和结果
- 情景分析
- 评级依据

### 5. 风险提示
- 上行风险
- 下行风险
- 关键假设风险

### 6. 免责声明
- "本报告仅供研究参考，不构成个人投资建议"
- 数据截至日期

## 质量标准

### 数据纪律
- 所有数字有来源标注
- 陈旧数据（>90天）标注 [STALE]
- 缺失数据标注 [MISSING]，不编造
- 管理层声明与事实数据明确区分

### 分析纪律
- 禁止无结论的"两边都有道理"式分析
- 必须给出明确方向性判断
- 判断须有可证伪的条件
- 不确定性通过概率权重表达

### 格式纪律
- 表格数字统一精度（通常保留 1-2 位小数）
- 货币单位统一标注
- 百分比变化标注基期
- 时间序列数据标注频率
