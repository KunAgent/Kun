# 安全策略

## 必须确认的操作

执行下列操作前，必须展示操作摘要并取得用户明确确认：

- 新增、修改、删除、提交、撤销、审批、驳回
- 导入、导出、批量处理
- 影响薪资、社保、绩效、合同、入转调离、招聘候选人的操作
- 会触发通知、消息、邮件或流程流转的操作

摘要至少包含：

- 操作类型
- 目标对象
- 数量和范围
- 关键参数
- 是否支持 dry-run

## 敏感数据处理

默认不要完整展示：

- API Token、Cookie、session、Authorization header
- 身份证号、手机号、银行卡号、住址
- 薪资、个税、社保、公积金明细
- 绩效评分、考核明细
- 合同、离职、候选人隐私信息

需要展示时做脱敏或汇总；用户明确要求完整结果时，也不要展示认证凭据。

## 批量边界

- 批量写操作默认单批不超过 30 条。
- 超过 30 条时拆批，并逐批确认。
- 大批量读操作默认分页和摘要，不要把全部明细直接刷屏。

## 禁止事项

- 不要把 token 放在命令行历史里；优先使用 stdin。
- 不要把线上接口抓取结果中的一次性 token、cookie 或动态 `r_id` 写入 reference。
- 不要绕过 `ihr-cli` 执行生产写操作，除非用户明确要求底层 API 调试且已确认风险。
