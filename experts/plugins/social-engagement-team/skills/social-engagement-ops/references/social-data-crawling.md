# 社媒数据采集指南

## 概述

本文档定义了社交媒体平台公开数据的采集规范，包括支持平台、采集能力、执行流程、合规边界和数据处理方法。数据采集服务于竞品分析、热门内容研究、素材收集和趋势追踪等场景。

---

## 一、支持平台与采集能力

### 1.1 平台能力矩阵

| 平台 | 视频采集 | 图片采集 | 文字采集 | 元数据 | 评论数据 | 互动数据 |
|------|---------|---------|---------|--------|---------|---------|
| B站 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| YouTube | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| TikTok | ✅ | - | ✅ | ✅ | ✅ | ✅ |
| 抖音 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 小红书 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 快手 | ✅ | - | ✅ | ✅ | ✅ | ✅ |

### 1.2 可采集内容类型

**视频内容**：
- 视频文件（MP4格式）
- 视频封面/缩略图
- 视频时长信息
- 清晰度信息

**图片内容**：
- 帖子配图（JPG/PNG）
- 头图/Banner
- 轮播图（多图帖子全部图片）

**文字内容**：
- 标题
- 正文描述/文案
- 话题标签（Hashtags）
- @提及
- 评论文本

**元数据**：
- 发布时间
- 发布者信息（用户名/粉丝数/认证状态）
- 内容分类/分区
- 地理位置（如公开）
- 音乐/BGM信息

**互动数据**：
- 播放/浏览量
- 点赞数
- 评论数
- 分享/转发数
- 收藏数
- 弹幕数（B站）

## 二、采集流程标准

### 2.1 标准采集工作流

```
Step 1: 提交采集任务
  ├── 输入：目标URL / 关键词 / 用户主页
  ├── 配置：采集范围（内容类型/数量/时间范围）
  └── 输出：任务ID

Step 2: 轮询任务状态
  ├── 轮询间隔：30秒
  ├── 首次检查：提交后等待30-60秒
  └── 状态值：pending → running → success / failed

Step 3: 获取采集结果
  ├── 成功：返回数据（媒体URL + 元数据 + 互动数据）
  └── 失败：返回错误信息（原因 + 建议）

Step 4: 数据持久化
  ├── 媒体文件：下载保存到本地/云存储
  ├── 元数据：结构化存储
  └── 注意：媒体URL有时效性，需及时保存
```

### 2.2 任务状态机

```
         提交任务
            │
            ▼
        ┌─────────┐
        │ pending │ ──── 等待调度
        └────┬────┘
             │
             ▼
        ┌─────────┐
        │ running │ ──── 执行中
        └────┬────┘
             │
        ┌────┴────┐
        │         │
        ▼         ▼
   ┌─────────┐ ┌────────┐
   │ success │ │ failed │
   └─────────┘ └────────┘
```

### 2.3 失败处理策略

| 失败原因 | 处理方式 | 重试建议 |
|---------|---------|---------|
| 内容已删除 | 终止，无法恢复 | 不重试 |
| 平台限频 | 等待一段时间后重试 | 5分钟后重试，最多3次 |
| 网络超时 | 可能是大文件导致 | 立即重试，最多2次 |
| URL格式错误 | 检查URL有效性 | 修正URL后重试 |
| 地域限制 | 内容不在可访问区域 | 不重试 |
| 登录要求 | 内容需要登录才能访问 | 仅采集公开内容 |

## 三、各平台采集规范

### 3.1 B站采集指南

**支持的URL格式**：
- 视频页：`https://www.bilibili.com/video/BVxxxxxxxxxx`
- 用户空间：`https://space.bilibili.com/{uid}`
- 番剧/综艺：`https://www.bilibili.com/bangumi/play/ss{sid}`

**可采集数据**：
- 视频文件（多清晰度）
- 标题、描述、标签、分区
- 封面图、发布时间
- 播放量、弹幕数、点赞、投币、收藏、分享
- UP主信息（粉丝数、视频数）
- 评论列表（文本+点赞数+时间）
- 弹幕列表（文本+时间轴位置）

**注意事项**：
- 大会员专享内容可能无法完整采集
- 弹幕数据量大，可能需要更长处理时间
- 番剧内容可能有版权限制

### 3.2 YouTube采集指南

**支持的URL格式**：
- 视频页：`https://www.youtube.com/watch?v={videoId}`
- 频道：`https://www.youtube.com/@{channelName}`
- Shorts：`https://www.youtube.com/shorts/{videoId}`
- 播放列表：`https://www.youtube.com/playlist?list={playlistId}`

**可采集数据**：
- 视频文件（多清晰度，最高1080p公开）
- 标题、描述、标签、类别
- 缩略图（多尺寸）
- 观看数、点赞数、评论数
- 频道信息（订阅数、总视频数）
- 评论列表（含回复）
- 字幕文件（如有）

**注意事项**：
- 部分视频可能有地域限制
- 私有/不公开视频无法采集
- 评论量大的视频采集时间较长

### 3.3 TikTok采集指南

**支持的URL格式**：
- 视频页：`https://www.tiktok.com/@{user}/video/{videoId}`
- 用户主页：`https://www.tiktok.com/@{user}`
- 短链接：`https://vm.tiktok.com/{shortcode}`

**可采集数据**：
- 视频文件（无水印版本）
- 标题/描述
- 话题标签、@提及
- 使用的音乐/音频信息
- 播放量、点赞、评论、分享、收藏
- 创作者信息
- 评论列表

**注意事项**：
- 地域限制可能影响访问
- 部分私密账号内容不可采集
- 短链接需要解析为完整URL

### 3.4 抖音采集指南

**支持的URL格式**：
- 视频页：`https://www.douyin.com/video/{videoId}`
- 用户主页：`https://www.douyin.com/user/{uid}`
- 分享链接：`https://v.douyin.com/{shortcode}`

**可采集数据**：
- 视频文件
- 标题、描述、话题
- 封面图
- 点赞数、评论数、分享数、收藏数
- 创作者信息（粉丝数、获赞数）
- 评论列表
- BGM信息

**注意事项**：
- 分享链接需要解析
- 平台反爬较严格，需控制频率
- 直播回放可能时效较短
- 部分数据可能有延迟

### 3.5 小红书采集指南

**支持的URL格式**：
- 笔记页：`https://www.xiaohongshu.com/explore/{noteId}`
- 用户主页：`https://www.xiaohongshu.com/user/profile/{uid}`
- 分享链接：`http://xhslink.com/{shortcode}`

**可采集数据**：
- 图片（多图笔记的所有图片）
- 视频文件（视频笔记）
- 标题、正文内容
- 话题标签
- 点赞、收藏、评论数
- 发布者信息
- 评论列表

**注意事项**：
- 反爬机制较严，频率需严格控制
- 图文笔记和视频笔记格式不同
- 部分内容可能仅APP内可见
- 评论可能需要登录才能完整获取

### 3.6 快手采集指南

**支持的URL格式**：
- 视频页：`https://www.kuaishou.com/short-video/{videoId}`
- 用户主页：`https://www.kuaishou.com/profile/{uid}`

**可采集数据**：
- 视频文件
- 标题、描述
- 话题标签
- 点赞、评论、分享数
- 创作者信息
- 评论列表

**注意事项**：
- 部分功能需要登录状态
- 直播相关内容时效性强
- 下沉市场内容表达方式独特

## 四、合规与安全边界

### 4.1 合规原则

1. **公开性原则**：仅采集公开可见内容，不触碰私密/仅好友可见/需登录的内容
2. **用途限制**：采集数据仅用于分析研究，不用于内容盗用或侵犯版权
3. **频率限制**：严格遵守各平台访问频率限制，不发起高频请求
4. **用户隐私**：不采集用户个人隐私信息（手机号/邮箱/地址等）
5. **版权尊重**：采集内容不用于未经授权的再发布
6. **ToS遵守**：遵守各平台的服务条款和 robots.txt 规定

### 4.2 频率控制

| 平台 | 建议间隔 | 每小时上限 | 每日上限 |
|------|---------|-----------|---------|
| B站 | ≥3秒 | 100次 | 2000次 |
| YouTube | ≥2秒 | 150次 | 3000次 |
| TikTok | ≥5秒 | 60次 | 1000次 |
| 抖音 | ≥5秒 | 60次 | 1000次 |
| 小红书 | ≥8秒 | 40次 | 500次 |
| 快手 | ≥4秒 | 80次 | 1500次 |

### 4.3 异常处理

- **429 Too Many Requests**：立即暂停，等待指定时间后恢复
- **403 Forbidden**：检查是否触发反爬，暂停15分钟
- **验证码**：暂停自动化，等待人工处理或更换策略
- **IP被封**：切换出口IP，降低频率

### 4.4 数据处理规范

- 采集的媒体URL通常有时效性（1-24小时），需要及时下载保存
- 存储时按平台/日期/类型分目录管理
- 元数据以JSON格式结构化存储
- 评论数据需要去除个人隐私信息后存储
- 定期清理过期/无效数据

## 五、应用场景与分析方法

### 5.1 竞品内容监控

**目标**：持续追踪竞品发布动态和内容策略变化

**执行方案**：
```
1. 配置竞品账号列表（每个平台3-5个竞品账号）
2. 每日定时采集竞品最新发布内容
3. 提取关键数据：发布时间、内容类型、话题标签、互动数据
4. 周度汇总：发布频率变化、热门内容特征、互动率趋势
```

### 5.2 爆款内容研究

**目标**：拆解同行业爆款内容的成功因素

**执行方案**：
```
1. 定义爆款标准（如互动率>5%，或点赞>1万）
2. 采集目标品类TOP50爆款内容
3. 分析维度：
   - 标题模式（疑问句/数字/悬念/痛点）
   - 封面风格（配色/文字/人物）
   - 内容结构（开头hook/中间发展/结尾CTA）
   - 时长分布（爆款集中在哪个时长区间）
   - 发布时间（爆款集中在哪个时段）
4. 输出爆款内容公式/模板
```

### 5.3 素材灵感库

**目标**：建立可参考的创作素材库

**执行方案**：
```
1. 按内容主题/风格分类采集优质内容
2. 提取可参考元素：
   - 创意方向
   - 拍摄手法
   - 文案结构
   - 话题使用策略
   - 互动引导技巧
3. 定期更新（每周新增50-100条参考素材）
4. 标注参考价值和适用场景
```

### 5.4 趋势追踪

**目标**：发现行业内容趋势和用户兴趣变化

**执行方案**：
```
1. 监控目标品类热门话题标签变化
2. 追踪搜索下拉词变化（反映用户兴趣）
3. 分析评论区高频关键词变化
4. 识别新兴内容形式和风格
5. 每月输出趋势报告
```

## 六、采集任务配置模板

```markdown
# 数据采集任务配置

## 任务基本信息
- 任务名称：{任务名}
- 采集目的：{竞品监控/爆款研究/素材库/趋势追踪}
- 优先级：{高/中/低}

## 采集范围
- 目标平台：{平台列表}
- 目标账号/关键词：{具体列表}
- 时间范围：{起止日期}
- 内容类型：{视频/图文/全部}
- 数量限制：{每个来源采集N条}

## 采集内容
- [ ] 媒体文件（视频/图片）
- [ ] 标题和描述
- [ ] 话题标签
- [ ] 互动数据
- [ ] 评论列表
- [ ] 创作者信息

## 频率设置
- 执行频率：{一次性/每日/每周}
- 单次间隔：{秒}
- 每小时上限：{次}

## 数据存储
- 存储路径：{本地路径/云存储}
- 文件命名规则：{平台_日期_ID}
- 保留周期：{天}

## 合规检查
- [ ] 仅采集公开内容
- [ ] 频率在平台允许范围内
- [ ] 不涉及用户隐私
- [ ] 数据用途合规
```
