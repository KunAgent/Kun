## 二、批量发布编排策略

### 策略一：同步发布（Simultaneous）
**适用场景**：重大产品发布、限时活动、新闻事件
**操作方式**：所有平台在同一时间点同时发布
**优势**：统一声量、话题造势、避免信息泄露
**风险**：无法针对各平台最佳时间优化

### 策略二：错峰发布（Staggered）
**适用场景**：日常运营内容、品牌宣传
**操作方式**：按各平台最佳时间依次发布，通常跨越2-4小时
**优势**：每个平台都在最佳时间获得推荐
**推荐顺序**：
1. 主力平台先发（抖音/TikTok 20:00）
2. 次要平台跟发（小红书 20:30、Instagram 21:00）
3. 长尾平台补发（YouTube 14:00次日、Pinterest 21:00次日）

### 策略三：梯度发布（Tiered）
**适用场景**：试探性内容、风险内容
**操作方式**：
- 第一梯队：核心平台（1-2个）先发，观察数据
- 第二梯队：数据良好则24h内扩展到3-5个平台
- 第三梯队：确认效果后72h内全平台覆盖
**优势**：降低风险，数据验证后再扩大投入

### 策略四：矩阵号协同（Matrix）
**适用场景**：MCN机构、矩阵号运营
**操作方式**：
- 主号首发（T+0）
- 子号A跟发（T+2h，改编版本）
- 子号B跟发（T+4h，另一角度）
- 评论区互动引流（T+1h开始）
**注意**：各号间需保持内容差异化（≥30%不同），避免判定搬运

|------|------|------|---------|---------|

**周计划节奏建议**：
- 周一：开场内容（干货/教程/总结）
- 周二-周四：主力内容（产品/品牌/核心价值）
- 周五：轻松内容（幕后/互动/有趣）
- 周末：用户生成内容(UGC)/复盘/预告

- 核心内容日：品牌核心价值传达（8-10次/月）
- 热点跟踪日：节日/热搜/行业事件（4-6次/月）
- 互动日：问答/投票/抽奖/挑战（4次/月）
- 转化日：促销/引导/CTA（4-6次/月）

## 四、发布队列管理

### 优先级定义
| 级别 | 定义 | 响应时间 |
|------|------|---------|
| P0 紧急 | 危机公关、突发热点 | 即时发布 |
| P1 重要 | 新品发布、活动预热 | 按计划严格执行 |
| P2 常规 | 日常运营内容 | 允许±2h浮动 |
| P3 储备 | 常青内容、补位内容 | 灵活安排 |

### 依赖关系处理
- **顺序依赖**：A平台发布成功后才触发B平台（如主号→子号）
- **时间依赖**：距上次发布间隔≥X小时（避免限流）
- **内容依赖**：B内容需引用A内容的链接/ID
- **效果依赖**：A内容数据达标后再发B（梯度发布）

### 失败重试机制
```
发布失败
├─ 网络错误 → 30s后自动重试（最多3次）
├─ 认证过期 → 标记待授权，通知运营
├─ 内容审核失败 → 标记待修改，通知运营
├─ 频率限制 → 等待限制解除后自动重试
└─ 未知错误 → 记录日志，人工排查
```

## 五、跨时区协调

### 时区换算原则
- 始终以目标受众的当地时间为准
- 提前录入各平台的目标时区设置
- 注意夏令时/冬令时切换（美国3月/11月、欧洲3月/10月）

### 跨境发布时间协调示例
```
目标：同一内容面向中国+美国+东南亚受众

中国区（UTC+8）：20:00 发布
 ↓ 对应
美国东部（UTC-5）：7:00 AM（次日早间）
美国西部（UTC-8）：4:00 AM（太早，需另外安排）
东南亚（UTC+7）：19:00（也在黄金时段）

建议方案：
- 中国区+东南亚区：20:00 CST 同时发布
- 美国区：另开一轮，当地 9:00 AM 发布
```

### 常见时区对照（相对北京时间 UTC+8）
| 地区 | 时差 | 换算 |
|------|------|------|
| 美国东部(EST) | -13h | 北京20:00 = 美东7:00 |
| 美国西部(PST) | -16h | 北京20:00 = 美西4:00 |
| 英国(GMT) | -8h | 北京20:00 = 伦敦12:00 |
| 日本(JST) | +1h | 北京20:00 = 东京21:00 |
| 东南亚(ICT) | -1h | 北京20:00 = 曼谷19:00 |
| 澳洲(AEST) | +2h | 北京20:00 = 悉尼22:00 |
