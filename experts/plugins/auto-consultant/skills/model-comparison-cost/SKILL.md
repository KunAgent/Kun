# 车型配置与用车成本对比

## 触发场景

用户在两三款车型、多个版本或不同配置之间纠结，需要判断哪个更适合、哪个版本值得买、长期用车成本是否可承受。

## 🔴 关键核验点

先确认：待对比的车型/版本、预算上限、家庭真实使用场景、用户最在意什么（空间/智能/安全/动力/能耗）、持有预期年限。不锁定关注点就对比，会输出一堆用户不关心的参数差。

## 暂停与降级条件

- 车型或版本不明确时，先暂停：确认具体年款、配置名、价格口径。
- 用户关注点不明确时，先暂停：在空间、智能、安全、动力、能耗、成本中排序前三。
- 成本结论缺年里程、城市和持有年限时，只输出估算口径，不下确定成本结论。

## 功能说明

不只罗列参数，而是把配置差异、预算压力、保险、能耗、保养、维修、补能便利性、折旧和保值放在一起判断。

核心问题是回答“多花的钱换来的体验是否高频、刚需、不可后装、长期成本是否可接受”。

## 配置四分类

| 类别 | 特征 | 价值判断 |
|---|---|---|
| 刚需配置 | 安全、基础辅助、倒车影像等 | 低配也该有，没有要警惕 |
| 体验配置 | 座椅通风加热、HUD、音响、大屏 | 高频使用才值得加钱 |
| 可选配置 | 空悬、电吸门、真皮等 | 预算充足再考虑 |
| 营销包装 | 听着高级但低频 | 慎为包装感多花钱 |

## 配置加钱判断

| 配置 | 更值得的场景 | 不一定值得的场景 |
|---|---|---|
| L2 辅助驾驶 | 高速多、拥堵通勤多 | 城市短途、用户不信任辅助驾驶 |
| 座椅通风/加热 | 南方炎热、北方寒冷、长时间开车 | 短途代步、乘坐时间短 |
| HUD | 高速多、对视线安全敏感 | 低速短途，用户不适应 HUD |
| 大电池/长续航 | 无家充、跨城频繁、冬季寒冷 | 有家充、通勤固定、价格差过大 |
| 空气悬挂 | 高端车、重视舒适和通过性 | 预算紧张、后期维修敏感 |
| 高阶音响 | 音乐高频用户 | 普通用户感知弱 |

## 成本维度

- 落地价与月供压力
- 保险、保养、维修
- 油耗/电耗/补能时间
- 折旧与保值
- 轮胎、电池、质保、售后便利性
- 家庭真实使用差异

## 用车成本估算口径

| 成本项 | 估算方式 | 注意事项 |
|---|---|---|
| 保险 | 首年报价 + 后续折扣/出险影响 | 新能源、高价车、性能车保险可能更高 |
| 能耗 | 年里程 × 单位能耗 × 油/电价格 | 要分城市、长途、冬季和充电方式 |
| 保养 | 官方保养周期 × 单次费用 | 混动/插混有发动机与电驱双系统 |
| 轮胎/易损件 | 轮胎规格、车重、驾驶习惯 | 大尺寸轮胎后期成本更高 |
| 折旧 | 品牌、能源类型、保有量、车龄 | 新能源残值波动更大 |
| 时间成本 | 充电等待、维修等待、售后距离 | 家庭主力车要重视确定性 |

## 工作流程

1. 锁定车型/版本、预算上限、关注点和持有年限。
2. 按刚需、体验、可选、营销包装分类配置差异。
3. 按保险、能耗、保养、轮胎、折旧、时间成本估算持有压力。
4. 把配置差异映射到用户真实场景，判断加钱是否值。
5. 输出明确倾向、可省配置、试驾验证项和风险。

## 输出模板

| 对比维度 | 车型/版本 A | 车型/版本 B | 谁更优 | 判断 |
|---|---|---|---|---|

- 更适合谁
- 值得加钱的配置
- 可以省的钱
- 长期成本提醒
- 试驾验证项
- 最终倾向：优先推荐 / 可选 / 不建议

## 可视化输出

当用户要比较 2 个以上车型/版本，或需要家庭决策材料时，可输出 HTML 可视化报告。

## 失败分支

| 情况 | 处理 |
|---|---|
| 只给车型名不给版本 | 先提示版本差异会影响结论，按主销版本临时对比并标注假设 |
| 用户只关心低价 | 单独列低价代价：安全、质保、舒适、保值或补能便利 |
| 参数资料缺失 | 不补编参数，改用用户关注点和试驾验证项收敛 |
| 车型跨级别对比 | 先说明级别差异，再按真实场景对比，不硬比参数 |

## 反例（不要做）

- 不把配置数量多直接判为更值。
- 不只比较账面续航、马力、屏幕尺寸。
- 不忽略后期保险、轮胎、折旧和售后便利性。

## 边界

- 不给“都不错”这种空结论。
- 不诱导为低频配置多花钱。
- 不把配置数量当作价值大小。
- 不忽略售后便利性、质保、电池和残值风险。
- 不编造实时落地价、保险价、金融方案或残值。
- 实际费用以当地门店、保险公司和平台行情为准。
