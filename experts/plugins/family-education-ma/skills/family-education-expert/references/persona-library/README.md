# 🚨 Persona Library · 使用边界声明

> ## ⚠️⚠️⚠️ 重要声明
>
> 本目录下的所有资源是 **虚构合成人物**——
> 每一条 Persona 都由 10-30 个真实案例的"共性特征"融合而成，
> **不指向任何具体家庭**。
>
> 设计目的是：让对外传播既有故事温度，又完全规避隐私伦理风险。

---

## 🔴 默认使用场景

| 场景 | 是否可用 | 说明 |
|---|---|---|
| **家长咨询对话**（Agent 主战场） | ❌ **默认禁用** | 这些是虚构人物，引述给家长会违反 §0.66"不凭空推断" |
| 公众号长图文 / 媒体通稿 | ✅ 可用 | 资源原始定位 |
| 短视频剧本 / 海报金句 | ✅ 可用 | 资源原始定位 |
| 演讲案例 / 学术报告 | ✅ 可用 | 资源原始定位 |
| 内部培训教材 | ✅ 可用 | 资源原始定位 |
| Agent 用户场景 = 编辑/策划/写文章 | ✅ 可用 | 用户主动询问 Persona 用法时 |

---

## 🛡 三层防火墙（Agent 调用约束）

### 第一层：默认禁用

家长咨询对话中，**默认不调用 Persona 故事**。要讲案例，优先从：
1. `case-library/` 8 份正式 CASE
2. `case-library/raw-imports/` 26 份真实轻量卡

### 第二层：例外场景的判别条件

只有当**满足以下全部条件**时，才允许调用 Persona：
- ✅ 用户身份明确不是来咨询孩子问题的家长（如：编辑、策划、培训师、写论文者）
- ✅ 用户主动询问"如何讲这类故事 / 有没有典型案例可用 / 帮我写公众号"
- ✅ 引用时**显式声明虚构性**："这是营地基于 10-30 个真实案例融合的虚构人物 X 姐……"

### 第三层：方法层提炼可用

**即使在家长咨询对话中**，也可以引用 Persona 文档里提炼出的**方法论**——但**不引故事**：

| 方法层（✅ 可引用） | 故事层（❌ 不引用） |
|---|---|
| "先支持父母自身、再谈育儿" | "A 姐 39 岁，深夜 11:28 打来电话…" |
| "父亲的'自我暴露'是最有效的关系重启动作" | "B 哥告诉儿子'你爸爸 15 岁时怕过什么'…" |
| "解决家庭权力结构比直接管孩子更重要" | "C 家爷爷奶奶连夜收拾行李…" |
| "先肯定家长再解决问题" | "D 妈说'我什么都没做对'…" |
| "健康家庭的微调辅导模型" | "E 同学说'我们家是 9 分家庭'…" |

## ⛔ 使用红线（来自原文件 · 一律遵守）

- ❌ 绝对不在 Persona 基础上声称"这是真实的某某家庭"
- ❌ 不把多条 Persona 合并成一条"更惊人"的故事
- ❌ 不使用任何暗示具体地点、学校、单位的细节
- ❌ 不为 Persona 找"模特"拍视频（除非标注"演绎"）
- ❌ 不把 Persona 当作"营地里有个家庭"塞进 Agent 家长咨询对话
