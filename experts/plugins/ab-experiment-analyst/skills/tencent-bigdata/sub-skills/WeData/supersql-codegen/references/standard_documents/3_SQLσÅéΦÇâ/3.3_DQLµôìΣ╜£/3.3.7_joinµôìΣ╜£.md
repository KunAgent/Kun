# join操作

## 格式

### join_table

```sql
table_reference JOIN table_factor [join_condition]
| table_reference {LEFT|RIGHT|FULL} [OUTER] JOIN table_reference join_condition
```

### table_reference

```sql
table_factor | join_table
```

### table_factor

```sql
tbl_name [alias]
| table_subquery alias
| ( table_references )
```

### join_condition

```sql
ON equality_expression ( AND equality_expression )*
```

### equality_expression

```sql
expression = expression
```

## 基本连接

目前只支持等值链接，例如：

```sql
SELECT a.* FROM a JOIN b ON (a.id = b.id)
```

和

```sql
SELECT a.* FROM a JOIN b ON (a.id = b.id AND a.department = b.department)
```

都是合法的。

但是

```sql
SELECT a.* FROM a JOIN b ON (a.id <> b.id)
```

不是合法的。

## 多表连接

支持多表链接，如：

```sql
SELECT a.val, b.val, c.val
FROM a JOIN b ON (a.key = b.key1) JOIN c ON (c.key = b.key2)
```

## Hash Map Join操作

### 格式

```sql
join_table:
  table_factor JOIN table_factor join_condition

table_factor:
  tbl_name [alias]

join_condition:
  ON equality_expression

equality_expression:
  expression = expression

mapjoin_hints:
  /*+mapjoin(alias|tbl_name)*/

SELECT mapjoin_hints select_expr, select_expr, ... FROM jointable
```

### 说明

- `OUTER`是可选的，有outer和没有outer语义是等价的。
- 必须显式的使用hints，并将小表名写在hints中，例如：
  ```sql
  SELECT /*+mapjoin(a)*/ a.* FROM table1 a JOIN table2 b ON (a.qq_num = b.qq_num);
  ```
- 连接顺序必须为小表连接大表。比如，在上例中，a表应为在hints中提到的需要在map端缓存的表。
- 和连接一样目前只支持等值连接。
- 目前提供内连接、左外连接（左表不可以是小表）和右外连接（右表不可以是小表）功能。
- Hash Map Join支持对大表或小表进行分支修剪。
- 考虑到map join比较消耗内存，不支持多表连接。

### 参数设置

在开始执行hash map join之前，需要对部分参数进行设置。主要包括：

#### hive.mapjoin.cache.numrows

hash map join会优先将计算所需的小表键值对保存在内存容器中，剩下的键值对将被保存到硬盘。

- 该参数决定保存在内存中的记录条数
- 系统默认设置该参数为**500000**
- 该条数越多，所需的内存越多，则需要将`mapred.child.java.opts`设的越大
- TDW中的默认hash分区数为500，因此，用户可以根据小表的行数算出将该参数设为多少较合适

示例：

```sql
SET hive.mapjoin.cache.numrows = 3000000;
```

#### mapred.child.java.opts

- 该参数设置map任务和reduce任务可用的虚拟机最大内存
- 由于map join是一个比较消耗内存的操作，而默认的内存大小为1G（1024M）
- 根据经验数据，在列数不多的情况下，一百万条记录所需的内存容器大小约为500~700MB
- 如果在内存中缓冲的数据条数为300万，则将该参数设为3072M较为稳妥
- 原则上，`mapred.child.java.opts`的大小不要超过4096M
- 如果单个map任务要处理的条数较多，超过内存限制，则可以根据可用内存大小设置`hive.mapjoin.cache.numrows`，超出部分将被放入硬盘文件缓存

示例：

```sql
SET mapred.child.java.opts = -Xmx4096M;
```

#### Sorted.Merge.Map.Join

TDW中提供了两种hash map join算法：

1. **默认算法**：使用hash map作为内存容器
2. **优化算法**：使用数组（sorted list）作为内存容器
   - 速度更快，对内存的需求更少
   - 要求小表的每个hash分区中的数据必须是有序的
   - 如果小表的hash分区是二级分区，不能有多个一级分区参与计算

使用基于sorted list的算法：

```sql
SET Sorted.Merge.Map.Join = true;
```

否则：

```sql
SET Sorted.Merge.Map.Join = false;
```

## 注意事项

Hash Map Join不支持与其他查询组合在一起形成复杂的查询语句。
