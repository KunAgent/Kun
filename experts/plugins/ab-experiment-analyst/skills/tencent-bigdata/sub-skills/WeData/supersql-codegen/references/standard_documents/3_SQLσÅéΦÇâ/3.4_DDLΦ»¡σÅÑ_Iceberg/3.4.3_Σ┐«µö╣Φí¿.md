# 3.4.3 修改表 (ALTER TABLE)

## 概述

Iceberg 在 Spark 3 中提供了完整的 `ALTER TABLE` 支持，包括表重命名、属性设置、列操作（增删改）、重排字段、类型拓宽等。所有操作都是元数据级别的，不会重写数据文件。

## 表级操作

### 重命名表

```sql
ALTER TABLE table_name RENAME TO new_table_name
```

**示例：**

```sql
ALTER TABLE prod.db.sample RENAME TO prod.db.new_sample;
```

### 设置表属性

```sql
-- 设置属性
ALTER TABLE table_name SET TBLPROPERTIES ('key' = 'value', ...)

-- 移除属性
ALTER TABLE table_name UNSET TBLPROPERTIES ('key', ...)
```

**示例：**

```sql
-- 设置读取分片大小
ALTER TABLE prod.db.sample SET TBLPROPERTIES (
    'read.split.target-size' = '268435456'
);

-- 设置表注释
ALTER TABLE prod.db.sample SET TBLPROPERTIES (
    'comment' = 'Updated table description'
);

-- 移除属性
ALTER TABLE prod.db.sample UNSET TBLPROPERTIES ('read.split.target-size');
```

## 列操作

### 添加列 (ADD COLUMN)

支持添加顶层列和嵌套字段，可以使用 `FIRST` 或 `AFTER` 指定位置。

#### 基本语法

```sql
ALTER TABLE table_name 
ADD COLUMN[S] (
    column_name data_type [COMMENT 'comment']
    [FIRST | AFTER existing_column]
)
```

#### 示例

```sql
-- 添加单个列
ALTER TABLE prod.db.sample
ADD COLUMN new_column string COMMENT 'new column description';

-- 添加多个列
ALTER TABLE prod.db.sample
ADD COLUMNS (
    status string COMMENT 'record status',
    updated_at timestamp COMMENT 'last update time'
);

-- 指定列位置
ALTER TABLE prod.db.sample
ADD COLUMN priority int AFTER status;

ALTER TABLE prod.db.sample
ADD COLUMN id bigint FIRST;

-- 添加嵌套字段
ALTER TABLE prod.db.sample
ADD COLUMN address.zipcode string;
```

### 重命名列 (RENAME COLUMN)

支持重命名字段，包括嵌套字段的叶子节点。

```sql
ALTER TABLE table_name 
RENAME COLUMN old_name TO new_name
```

**示例：**

```sql
-- 重命名顶层列
ALTER TABLE prod.db.sample 
RENAME COLUMN data TO payload;

-- 重命名嵌套列
ALTER TABLE prod.db.sample 
RENAME COLUMN address.street TO address.street_name;
```

### 修改列 (ALTER COLUMN)

用于类型拓宽、设置注释、重排字段和修改可空性。

#### 类型拓宽

仅支持安全的类型转换（不会丢失数据）：

| 原类型 | 可拓宽到 |
|--------|---------|
| int | long (bigint) |
| float | double |
| decimal(P,S) | decimal(P2,S) 其中 P2 > P |

```sql
ALTER TABLE table_name 
ALTER COLUMN column_name TYPE new_type
```

**示例：**

```sql
-- int 拓宽为 bigint
ALTER TABLE prod.db.sample 
ALTER COLUMN count TYPE bigint;

-- float 拓宽为 double
ALTER TABLE prod.db.sample 
ALTER COLUMN measurement TYPE double;

-- decimal 精度拓宽
ALTER TABLE prod.db.sample 
ALTER COLUMN price TYPE decimal(20,2);  -- 原来是 decimal(10,2)
```

#### 修改注释

```sql
ALTER TABLE table_name 
ALTER COLUMN column_name COMMENT 'new comment'
```

**示例：**

```sql
ALTER TABLE prod.db.sample 
ALTER COLUMN measurement COMMENT 'unit is bytes per second';
```

#### 修改可空性

只能将必填列（NOT NULL）改为可选列，不能反向操作。

```sql
-- 允许列为 NULL
ALTER TABLE table_name 
ALTER COLUMN column_name DROP NOT NULL
```

**示例：**

```sql
ALTER TABLE prod.db.sample 
ALTER COLUMN id DROP NOT NULL;
```

**注意**：不支持 `SET NOT NULL`，因为可能导致现有数据违反约束。

#### 重排列位置

```sql
-- 移动到第一列
ALTER TABLE table_name 
ALTER COLUMN column_name FIRST

-- 移动到某列之后
ALTER TABLE table_name 
ALTER COLUMN column_name AFTER other_column
```

**示例：**

```sql
ALTER TABLE prod.db.sample 
ALTER COLUMN id FIRST;

ALTER TABLE prod.db.sample 
ALTER COLUMN status AFTER name;
```

### 删除列 (DROP COLUMN)

```sql
ALTER TABLE table_name 
DROP COLUMN column_name
```

**示例：**

```sql
-- 删除顶层列
ALTER TABLE prod.db.sample 
DROP COLUMN old_column;

-- 删除嵌套列
ALTER TABLE prod.db.sample 
DROP COLUMN address.zipcode;
```

**注意**：
- 删除列不会删除数据文件中的数据
- 仅在元数据中标记列为删除
- 查询时该列不可见

## 完整列操作示例

```sql
-- 创建示例表
CREATE TABLE prod.db.users (
    id int NOT NULL,
    name string,
    email string,
    created_at timestamp
)
USING iceberg;

-- 1. 添加新列
ALTER TABLE prod.db.users
ADD COLUMNS (
    phone string COMMENT 'phone number',
    status string COMMENT 'user status',
    updated_at timestamp COMMENT 'last update time'
);

-- 2. 重命名列
ALTER TABLE prod.db.users
RENAME COLUMN email TO email_address;

-- 3. 修改列类型（拓宽）
ALTER TABLE prod.db.users
ALTER COLUMN id TYPE bigint;

-- 4. 添加列注释
ALTER TABLE prod.db.users
ALTER COLUMN name COMMENT 'user full name';

-- 5. 重新排列列
ALTER TABLE prod.db.users
ALTER COLUMN status AFTER name;

-- 6. 删除不需要的列
ALTER TABLE prod.db.users
DROP COLUMN phone;

-- 7. 修改可空性
ALTER TABLE prod.db.users
ALTER COLUMN id DROP NOT NULL;
```

## 类型转换限制

### 支持的类型转换

✅ **安全转换（支持）**：
- `int` → `long`
- `float` → `double`
- `decimal(10,2)` → `decimal(20,2)` （扩大精度）

### 不支持的类型转换

❌ **不安全转换（不支持）**：
- `long` → `int` （可能溢出）
- `double` → `float` （丢失精度）
- `decimal(20,2)` → `decimal(10,2)` （缩小精度）
- `string` → `int` （类型不兼容）
- `timestamp` → `date` （丢失信息）

### 类型转换最佳实践

```sql
-- ✅ 推荐：从小类型开始
CREATE TABLE prod.db.metrics (
    count int,        -- 开始用 int
    price decimal(10,2)
)
USING iceberg;

-- 后续根据需要拓宽
ALTER TABLE prod.db.metrics ALTER COLUMN count TYPE bigint;
ALTER TABLE prod.db.metrics ALTER COLUMN price TYPE decimal(20,2);

-- ❌ 避免：一开始就用过大的类型
CREATE TABLE prod.db.metrics (
    count long,       -- 如果 int 够用，浪费存储
    price decimal(38,10)  -- 过高精度影响性能
)
USING iceberg;
```

## Schema Evolution 特性

Iceberg 的 Schema Evolution（模式演变）允许安全地修改表结构而不影响现有数据。

### 优势

1. **向后兼容**：旧数据在新 Schema 下仍可读取
2. **无需重写数据**：所有操作都是元数据级别
3. **查询不中断**：可以边查询边修改 Schema

### 示例场景

```sql
-- 场景：需要添加新的用户属性字段

-- 1. 添加新列
ALTER TABLE prod.db.users
ADD COLUMN membership_level string COMMENT 'user membership level';

-- 2. 旧数据该列为 NULL，新数据有值
-- 查询旧数据
SELECT * FROM prod.db.users 
WHERE created_at < '2024-01-01';
-- membership_level 列显示 NULL

-- 查询新数据
SELECT * FROM prod.db.users 
WHERE created_at >= '2024-01-01';
-- membership_level 列可能有值

-- 3. 可以为旧数据填充默认值
UPDATE prod.db.users
SET membership_level = 'basic'
WHERE membership_level IS NULL;
```

## 嵌套类型操作

Iceberg 支持对嵌套结构（struct、map、array）进行列操作。

### Struct 类型

```sql
-- 创建包含 struct 的表
CREATE TABLE prod.db.users (
    id bigint,
    name string,
    address struct<
        street: string,
        city: string,
        state: string
    >
)
USING iceberg;

-- 添加嵌套字段
ALTER TABLE prod.db.users
ADD COLUMN address.zipcode string;

-- 重命名嵌套字段
ALTER TABLE prod.db.users
RENAME COLUMN address.street TO address.street_address;

-- 删除嵌套字段
ALTER TABLE prod.db.users
DROP COLUMN address.state;

-- 修改嵌套字段注释
ALTER TABLE prod.db.users
ALTER COLUMN address.city COMMENT 'city name';
```

### Map 和 Array 类型

Map 和 Array 的值类型可以是 struct，可以对 struct 的字段进行操作：

```sql
CREATE TABLE prod.db.events (
    id bigint,
    properties map<string, struct<value: string, type: string>>
)
USING iceberg;

-- 添加到 map 值的 struct 中
ALTER TABLE prod.db.events
ADD COLUMN properties.value.timestamp long;
```

## 性能与注意事项

### 性能特征

1. **元数据操作**：所有 ALTER TABLE 操作都是元数据级别，不涉及数据文件重写
2. **即时生效**：操作通常在毫秒级完成
3. **无需锁表**：不会阻塞读写操作

### 最佳实践

1. **批量修改**
   ```sql
   -- ✅ 推荐：批量添加列
   ALTER TABLE prod.db.sample
   ADD COLUMNS (
       col1 string,
       col2 int,
       col3 timestamp
   );
   
   -- ❌ 避免：逐个添加
   ALTER TABLE prod.db.sample ADD COLUMN col1 string;
   ALTER TABLE prod.db.sample ADD COLUMN col2 int;
   ALTER TABLE prod.db.sample ADD COLUMN col3 timestamp;
   ```

2. **谨慎删除列**
   - 删除列后数据仍在文件中，只是不可见
   - 考虑使用重命名代替删除，保留历史

3. **规划 Schema**
   - 初始设计时考虑未来扩展
   - 使用 struct 组织相关字段
   - 预留扩展字段（如 properties map<string,string>）

## 错误处理

### 常见错误

**错误 1：类型转换不兼容**
```sql
ALTER TABLE prod.db.sample ALTER COLUMN id TYPE int;
-- Error: Cannot change column type from long to int
```

**错误 2：列不存在**
```sql
ALTER TABLE prod.db.sample DROP COLUMN non_existent;
-- Error: Column 'non_existent' does not exist
```

**错误 3：设置 NOT NULL**
```sql
ALTER TABLE prod.db.sample ALTER COLUMN id SET NOT NULL;
-- Error: SET NOT NULL is not supported
```
