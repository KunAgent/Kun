# 3.4.2 删除表 (DROP TABLE)

## 概述

Iceberg 的 `DROP TABLE` 命令用于删除表的元数据。从 Iceberg 0.14 版本开始，`DROP TABLE` 的行为发生了重要变化。

## 基本语法

```sql
DROP TABLE [IF EXISTS] table_name [PURGE]
```

## 版本差异

### Iceberg 0.14 及以后（当前行为）

**默认行为（不带 PURGE）**：
- 仅从 Catalog 中移除表的元数据
- **不删除**表的数据文件
- **不删除**表的元数据文件
- 数据文件保留在存储系统中，可以手动恢复

```sql
-- 仅删除元数据，保留数据文件
DROP TABLE prod.db.sample;
```

**带 PURGE 选项**：
- 从 Catalog 中移除表
- **删除所有数据文件**
- **删除所有元数据文件**
- 彻底清理表的所有内容

```sql
-- 删除表并清理所有数据
DROP TABLE prod.db.sample PURGE;
```

### Iceberg 0.14 之前（遗留行为）

`DROP TABLE` 会同时删除元数据和数据文件（类似于现在的 `DROP TABLE ... PURGE`）。

## 使用示例

### 示例 1：仅删除元数据

```sql
-- 删除表但保留数据
DROP TABLE IF EXISTS prod.db.sample;

-- 数据文件仍在 HDFS/S3 中
-- 可以通过重新注册表来恢复
```

**使用场景**：
- 表的元数据损坏，需要重新注册
- 临时从 Catalog 中移除表，但保留数据备份
- 需要迁移表到其他 Catalog

### 示例 2：完全删除

```sql
-- 彻底删除表和所有数据
DROP TABLE IF EXISTS prod.db.sample PURGE;
```

**使用场景**：
- 确认不再需要该表和数据
- 释放存储空间
- 清理测试表

### 示例 3：条件删除

```sql
-- 仅在表存在时删除（推荐）
DROP TABLE IF EXISTS prod.db.temp_table PURGE;

-- 如果表不存在，会报错
DROP TABLE prod.db.temp_table PURGE;
```

## 删除行为对比

| 操作 | 删除元数据 | 删除数据文件 | 删除元数据文件 | 可恢复性 |
|------|----------|------------|--------------|---------|
| `DROP TABLE` | ✅ | ❌ | ❌ | 可通过重新注册恢复 |
| `DROP TABLE PURGE` | ✅ | ✅ | ✅ | **不可恢复** |

## 数据恢复

### 从保留的数据文件恢复表

如果使用 `DROP TABLE`（不带 PURGE），可以通过重新注册表来恢复：

```sql
-- 1. 确定表的原始位置
-- 例如：hdfs://namenode:8020/warehouse/db/sample

-- 2. 重新注册表
CALL system.register_table(
  table => 'prod.db.sample',
  metadata_file => 'hdfs://namenode:8020/warehouse/db/sample/metadata/v1.metadata.json'
);
```

**注意**：需要知道表的元数据文件路径。

## 与传统 Hive 表的区别

| 特性 | Hive 表 | Iceberg 表 (0.14+) |
|------|---------|-------------------|
| DROP TABLE 默认行为 | 删除元数据和数据 | 仅删除元数据 |
| 数据保护 | 需要使用外部表 | 默认保护数据 |
| 完全删除 | DROP TABLE (托管表) | DROP TABLE PURGE |
| 可恢复性 | 外部表可恢复 | 默认可恢复 |

## 最佳实践

### 1. 使用 IF EXISTS 避免错误

```sql
-- 推荐
DROP TABLE IF EXISTS prod.db.sample PURGE;

-- 不推荐（表不存在时会报错）
DROP TABLE prod.db.sample PURGE;
```

### 2. 生产环境谨慎使用 PURGE

```sql
-- 开发/测试环境：可以直接 PURGE
DROP TABLE IF EXISTS dev.db.test_table PURGE;

-- 生产环境：先删除元数据，确认无误后再清理数据
DROP TABLE IF EXISTS prod.db.old_table;
-- 等待一段时间确认
-- 手动清理数据或使用 PURGE
```

### 3. 删除前备份重要表

```sql
-- 1. 创建快照或备份
CREATE TABLE prod.db.sample_backup
USING iceberg
AS SELECT * FROM prod.db.sample;

-- 2. 或创建分支
ALTER TABLE prod.db.sample CREATE BRANCH backup_before_drop;

-- 3. 然后删除
DROP TABLE prod.db.sample PURGE;
```

### 4. 定期清理孤立文件

使用 `DROP TABLE`（不带 PURGE）会导致孤立文件累积。定期清理：

```sql
-- 清理 7 天前的孤立文件
CALL prod.system.remove_orphan_files(
  table => 'db.sample',
  older_than => TIMESTAMP '2024-01-24 00:00:00',
  location => 'hdfs://namenode:8020/warehouse/db/sample'
);
```

## 权限要求

删除表需要以下权限：
- 对表的 DROP 权限
- 使用 PURGE 时，需要对表所在 HDFS/S3 路径的写入权限

```sql
-- 检查权限
SHOW GRANTS ON TABLE prod.db.sample;
```

## 错误处理

### 常见错误

**错误 1：表不存在**
```
AnalysisException: Table prod.db.sample not found
```

**解决方案**：
```sql
DROP TABLE IF EXISTS prod.db.sample;
```

**错误 2：没有删除权限**
```
AccessControlException: Permission denied: user=xxx, access=WRITE
```

**解决方案**：
- 联系管理员授予权限
- 或使用有权限的账户

**错误 3：PURGE 失败**
```
Could not delete file: hdfs://...
```

**解决方案**：
- 检查 HDFS/S3 权限
- 检查文件系统状态
- 可能需要手动清理残留文件

## 完整示例

### 安全删除流程

```sql
-- 1. 检查表是否存在
SHOW TABLES IN prod.db LIKE 'sample';

-- 2. 查看表的快照和分支
SELECT * FROM prod.db.sample.snapshots;
SELECT * FROM prod.db.sample.refs;

-- 3. 可选：创建备份
CREATE TABLE prod.db.sample_backup_20260203
USING iceberg
AS SELECT * FROM prod.db.sample;

-- 4. 删除元数据（保留数据）
DROP TABLE IF EXISTS prod.db.sample;

-- 5. 验证表已删除
SHOW TABLES IN prod.db LIKE 'sample';

-- 6. 确认后清理数据文件
-- 方式1：重新创建表然后 PURGE
-- 方式2：手动删除 HDFS/S3 文件
-- 方式3：使用 remove_orphan_files 清理
```

### 批量删除

```sql
-- 删除某个数据库下所有以 test_ 开头的表
-- 注意：生产环境慎用！

SHOW TABLES IN dev.db LIKE 'test_*';

-- 手动逐个删除
DROP TABLE IF EXISTS dev.db.test_table1 PURGE;
DROP TABLE IF EXISTS dev.db.test_table2 PURGE;
DROP TABLE IF EXISTS dev.db.test_table3 PURGE;
```

## 性能考虑

### DROP TABLE（不带 PURGE）
- **速度**：非常快（仅元数据操作）
- **I/O**：极低
- **适用场景**：需要快速删除但保留数据

### DROP TABLE PURGE
- **速度**：取决于文件数量和大小
- **I/O**：高（需要删除所有数据文件）
- **适用场景**：彻底清理不需要的表

## 相关命令

### 删除分区（不删除表）

```sql
-- 删除特定分区的数据
DELETE FROM prod.db.sample 
WHERE event_date = '2024-01-01';
```

### 清空表（保留结构）

```sql
-- 删除所有数据但保留表结构
DELETE FROM prod.db.sample;
```

### 截断表（Iceberg 不支持 TRUNCATE）

Iceberg 不支持 `TRUNCATE TABLE`。如需清空表：

```sql
-- 方式1：DELETE 所有行
DELETE FROM prod.db.sample;

-- 方式2：重建表
DROP TABLE prod.db.sample PURGE;
CREATE TABLE prod.db.sample (...) USING iceberg;
```
