# 转义字符

## 概述

在编程和 SQL 查询中，为了表示具有特殊含义或无法直接输入的字符（如引号、换行符等），需要使用转义字符。天穹 SQL 遵循标准的转义规则：

- 使用反斜线 `\` 对特殊字符进行转义
- 使用 `\\` 表示反斜线本身
- 在不同场景（SQL、JSON、正则表达式）中转义规则可能叠加

## SQL 中的转义字符

在天穹 SQL 中，字符串需要用单引号 `'` 或双引号 `"` 括起来。

### 基本规则

1. **简单情况**：如果字符串中只包含一种引号，可以使用另一种引号括起
   ```sql
   '这是双引号："abc"'
   "这是单引号：'abc'"
   ```

2. **复杂情况**：如果字符串同时包含单引号、双引号或其他特殊字符，需要使用反斜线转义
   ```sql
   'It\'s a nice day'
   "He said: \"Hello\""
   ```

### 常用转义字符

| 转义字符 | 说明 | 示例 |
|---------|------|------|
| `\\` | 反斜线 | `'\\'` 表示单个反斜线 |
| `\'` | 单引号 | `'It\'s'` |
| `\"` | 双引号 | `"He said: \"Hi\""` |
| `\n` | 换行符 | `'第一行\n第二行'` |
| `\r` | 回车符 | `'行\r'` |
| `\t` | 制表符（Tab） | `'姓名\t年龄'` |
| `\b` | 退格符 | `'abc\bdef'` |
| `\0` 或 `\00` | 空字符 | `'abc\0def'` |
| `\Z` | Control-Z | `'text\Z'` |
| `\;` | 分号 | `'\;'` |

### 使用示例

#### 示例 1：引号转义

```sql
-- 单引号内使用单引号
SELECT 'I\'m a developer';
-- 返回: I'm a developer

-- 双引号内使用双引号  
SELECT "He said: \"Hello\"";
-- 返回: He said: "Hello"
```

#### 示例 2：制表符和换行符

```sql
-- 使用制表符
SELECT 'Name\tAge\tCity';
-- 返回: Name    Age    City

-- 使用换行符
SELECT '第一行\n第二行\n第三行';
-- 返回:
-- 第一行
-- 第二行
-- 第三行
```

#### 示例 3：反斜线转义

```sql
-- 表示路径 C:\Users\data
SELECT 'C:\\Users\\data';
-- 返回: C:\Users\data

-- 一个反斜线需要写成两个
SELECT LENGTH('\\');  -- 返回: 1
SELECT LENGTH('\\\\');  -- 返回: 2
```

#### 示例 4：特殊字符解释

```sql
-- \t 被解释为制表符（1个字符）
SELECT LENGTH('a\tb');  -- 返回: 3

-- \a 不是转义字符，被解释为普通的 a
SELECT LENGTH('a\ab');  -- 返回: 3 (内容是 'aab')
```

## 正则表达式中的转义

在使用 `RLIKE`、`REGEXP_EXTRACT` 等正则函数时，需要对正则表达式的特殊字符进行转义。

### 正则表达式特殊字符

需要转义的字符：`. ^ $ * + ? { } [ ] \ | ( )`

### 常用正则转义字符

| 转义字符 | 说明 |
|---------|------|
| `\d` | 匹配数字，等价于 `[0-9]` |
| `\D` | 匹配非数字，等价于 `[^0-9]` |
| `\w` | 匹配字母数字下划线，等价于 `[0-9A-Za-z_]` |
| `\W` | 匹配非字母数字下划线 |
| `\s` | 匹配空白字符，等价于 `[\t\n\f\r ]` |
| `\S` | 匹配非空白字符 |

### SQL + 正则的双重转义

⚠️ **重要**：在 SQL 字符串中使用正则表达式时，需要进行**双重转义**：

1. 先按正则表达式规则转义
2. 再按 SQL 字符串规则转义（`\` 变成 `\\`）

#### 示例：提取电话号码区号

```sql
-- 目标：从 '010-12345678' 中提取 '010'
-- 正则表达式：(\d+)-
-- SQL 中需要写成：(\\d+)-

SELECT REGEXP_EXTRACT('010-12345678', '(\\d+)-');
-- 返回: 010
```

#### 示例：匹配点号

```sql
-- 目标：匹配字符串 'a.b' 中的点号
-- 正则表达式：\.
-- SQL 中需要写成：\\.

SELECT 'a.b' RLIKE 'a\\.b';  
-- 返回: true

SELECT 'aXb' RLIKE 'a\\.b';  
-- 返回: false
```

## JSON 中的转义

处理 JSON 字符串时，JSON 自身的转义规则与 SQL 转义规则会叠加。

### JSON 转义字符

| 转义字符 | 说明 |
|---------|------|
| `\"` | 双引号 |
| `\\` | 反斜线 |
| `\/` | 正斜线 |
| `\b` | 退格符 |
| `\f` | 换页符 |
| `\n` | 换行符 |
| `\r` | 回车符 |
| `\t` | 制表符 |
| `\uXXXX` | Unicode 字符（4位16进制） |

### JSON + SQL 双重转义

#### 示例：提取包含引号的 JSON 值

```sql
-- JSON 内容: {"key":"this is very \"important\"."}
-- 错误写法（转义不足）：
SELECT GET_JSON_OBJECT('{"key":"this is very \"important\"."}', '$.key');
-- 返回: NULL

-- 正确写法（双重转义）：
SELECT GET_JSON_OBJECT('{"key":"this is very \\"important\\"."}', '$.key');
-- 返回: this is very "important".
```

**说明**：
1. JSON 中的 `\"` 需要写成 `\\"`（SQL 转义）
2. 所以 `\"important\"` 在 SQL 中要写成 `\\"important\\"`

#### 示例：JSON + 正则 + SQL 三重转义

```sql
-- 目标：从 JSON 中提取 "important"
-- JSON: {"key":"this is very \"important\"."}
-- 正则: \\"(.*)\\"
-- SQL 转义后: \\\\"(.*)\\\\"

SELECT REGEXP_EXTRACT('{"key":"this is very \\"important\\"."}', '\\\\"(.*)\\\\"');
-- 返回: important
```

## 转义字符增强：原始字符串 (Raw String)

为了避免多层转义导致的"转义字符膨胀"（如 `\\\\\\\\`），天穹支持**原始字符串**语法。

### 语法格式

```sql
R"(字符串内容)"
-- 或
r"(字符串内容)"
```

**特点**：在 `R"()"` 括号内的字符**不需要使用 `\` 进行转义**。

### 使用示例

```sql
-- 普通字符串需要转义
SELECT '\\\\\"(.*)\\\\\"';

-- 使用原始字符串，无需转义
SELECT R'(\\\"(.*)\\")';

-- 两者等价
```

#### 示例：简化正则表达式

```sql
-- 匹配路径 C:\Users\data
-- 普通写法
SELECT 'C:\\temp' RLIKE 'C:\\\\temp';  -- 需要4个反斜线

-- 原始字符串写法
SELECT R'(C:\temp)' RLIKE R'(C:\\temp)';  -- 只需2个反斜线
```

#### 示例：简化 JSON 处理

```sql
-- 提取 JSON 中的值
-- 普通写法
SELECT GET_JSON_OBJECT('{"key":"value"}', '$.key');

-- 包含转义的 JSON
SELECT GET_JSON_OBJECT(R'({"key":"this is \"important\"."})', '$.key');
-- 返回: this is "important".
```

## 天穹引擎差异

### SuperSQL 转义字符

根据 SuperSQL FAQ 文档：

- **Spark 和 StarRocks**：转义字符是 `\t`
- **Presto**：默认转义字符是 `%`
- **SuperSQL 行为**：
  - 对于 Spark 和 StarRocks，转义字符保持原样
  - 对于 Presto，采用 Hive 解析规则，进行转义处理（`\\t` 转为 `\t`）

### WeData 与 US 差异

- **WeData 数据探索**：`split` 函数和 `regexp_replace` 函数需要**两个转义符**
- **US 平台**：需要**四个转义符**（US 需要对 `\` 进行转义，使用双倍的转义符）

```sql
-- WeData 数据探索
SELECT SPLIT('a.b.c', '\\.');

-- US 平台
SELECT SPLIT('a.b.c', '\\\\.');
```

## 最佳实践

### 1. 优先使用原始字符串

当字符串包含大量反斜线时（如正则表达式、Windows 路径），使用 `R"()"`：

```sql
-- ✅ 推荐
SELECT R'(C:\Users\data)';

-- ❌ 不推荐
SELECT 'C:\\Users\\data';
```

### 2. 理解转义层级

在使用正则或 JSON 时，明确有几层转义：

```
原始内容 → 正则转义 → JSON转义 → SQL转义
```

### 3. 使用 LIKE 时转义通配符

如果要匹配 `%` 或 `_` 字符本身：

```sql
-- 匹配包含 '_' 的字符串
SELECT 'ab_cde' LIKE 'ab\\_c%';
-- 返回: true
```

### 4. 测试转义结果

使用 `LENGTH()` 或 `REGEXP_EXTRACT()` 验证转义是否正确：

```sql
SELECT LENGTH('\\');    -- 应该返回 1
SELECT LENGTH('\\\\');  -- 应该返回 2
```

## 常见问题

### Q1：为什么我的正则表达式不work？

A：可能是转义不足。记住：SQL 字符串中的正则需要**双重转义**。

```sql
-- ❌ 错误
SELECT 'test123' RLIKE '\d+';

-- ✅ 正确
SELECT 'test123' RLIKE '\\d+';
```

### Q2：JSON 解析总是返回 NULL？

A：检查 JSON 字符串的转义是否正确，特别是引号：

```sql
-- ❌ 错误
SELECT GET_JSON_OBJECT('{"key":"value with \"quote\""}', '$.key');

-- ✅ 正确
SELECT GET_JSON_OBJECT('{"key":"value with \\"quote\\""}', '$.key');
```

### Q3：不同平台转义行为不一致？

A：不同引擎（Thive、Spark、Presto）的转义行为可能有差异。建议：
- 优先使用标准 Hive 转义规则
- 在 SuperSQL 中注意引擎差异
- 使用原始字符串 `R"()"` 减少歧义
