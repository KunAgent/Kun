# 5.3 DQL语句

## 概述

DQL（Data Query Language，数据查询语言）是SQL语言中用于从数据库中检索数据的语句集合。SuperSQL完整支持标准的DQL语法，并提供强大的**跨源查询能力**，允许在一条SQL中同时查询多个数据源的数据。

### 核心特性

- **跨源查询**：支持在一条SQL中JOIN多个数据源的表
- **标准SQL语法**：完整支持SELECT、WHERE、GROUP BY、HAVING、ORDER BY等标准子句
- **高级分析功能**：支持窗口函数、CTE（WITH子句）、集合操作（UNION/INTERSECT/EXCEPT）
- **性能优化**：智能下推、跨源优化、引擎选择

## SELECT语句

### 基本语法

```sql
SELECT [DISTINCT | ALL] selectExpression [[AS] alias], selectExpression [[AS] alias], ...
FROM table_references
[WHERE whereCondition]
[GROUP BY groupingElementList]
[HAVING havingExpression]
[WINDOW windowName AS windowSpecification, windowName AS windowSpecification, ...]
```

### 语法元素说明

| 元素 | 说明 |
|------|------|
| `DISTINCT` | 去除重复行 |
| `ALL` | 保留所有行（默认） |
| `selectExpression` | 查询表达式，可以是列名、表达式、聚合函数等 |
| `alias` | 列别名或表别名 |
| `table_references` | 表引用，可以是单表、JOIN子句或子查询 |
| `whereCondition` | 过滤条件 |
| `groupingElementList` | 分组字段列表 |
| `havingExpression` | 分组后的过滤条件 |
| `windowSpecification` | 窗口定义（参见窗口函数章节） |

### 基本示例

#### 示例1：简单查询

```sql
-- 查询所有列
SELECT * FROM mysql.employees;

-- 查询特定列
SELECT emp_id, emp_name, salary FROM mysql.employees;

-- 使用列别名
SELECT emp_id AS id, emp_name AS name, salary * 12 AS annual_salary 
FROM mysql.employees;
```

#### 示例2：使用DISTINCT

```sql
-- 查询不重复的部门
SELECT DISTINCT department FROM mysql.employees;

-- 查询不重复的部门和职位组合
SELECT DISTINCT department, position FROM mysql.employees;
```

#### 示例3：使用WHERE条件

```sql
-- 单个条件
SELECT * FROM mysql.employees WHERE salary > 10000;

-- 多个条件（AND）
SELECT * FROM mysql.employees 
WHERE department = 'Engineering' AND salary > 8000;

-- 多个条件（OR）
SELECT * FROM mysql.employees 
WHERE department = 'Engineering' OR department = 'Sales';

-- 使用BETWEEN
SELECT * FROM mysql.orders 
WHERE order_date BETWEEN DATE '2024-01-01' AND DATE '2024-12-31';

-- 使用IN
SELECT * FROM mysql.employees 
WHERE department IN ('Engineering', 'Sales', 'Marketing');

-- 使用LIKE
SELECT * FROM mysql.employees 
WHERE emp_name LIKE 'John%';
```

#### 示例4：使用表达式

```sql
-- 计算表达式
SELECT 
    product_name,
    unit_price,
    quantity,
    unit_price * quantity AS total_price,
    CASE 
        WHEN quantity > 100 THEN 'High'
        WHEN quantity > 50 THEN 'Medium'
        ELSE 'Low'
    END AS stock_level
FROM mysql.products;
```

## 跨源查询

SuperSQL的核心能力之一是**跨源查询**，允许在一条SQL中JOIN来自不同数据源的表。

### 跨源JOIN示例

#### 示例1：双源JOIN

```sql
-- MySQL表 JOIN PostgreSQL表
SELECT 
    t1.order_id,
    t1.order_date,
    t1.total_amount,
    t2.customer_name,
    t2.customer_level
FROM mysql.orders t1
INNER JOIN pg.customers t2 ON t1.customer_id = t2.customer_id
WHERE t1.order_date >= DATE '2024-01-01';
```

#### 示例2：多源复杂JOIN

```sql
-- 5个表的跨源JOIN（MySQL、PostgreSQL、Hive）
SELECT t1.cint 
FROM mysql.temp t1
INNER JOIN pg.temp t2 ON t1.cint = t2.cint
INNER JOIN mysql.temp2 t3 ON t1.cint = t3.cint
INNER JOIN hive.temp t4 ON t2.cint = t4.cint
INNER JOIN mysql.temp t5 ON t2.cint = t5.cint
WHERE t1.cfloat < 100 
  AND t2.cdouble < 200 
  AND t3.cdecimal < 300 
  AND t4.clong < 400 
  AND t5.cint < 500
LIMIT 20 OFFSET 10;
```

#### 示例3：不同JOIN类型

```sql
-- INNER JOIN
SELECT o.order_id, c.customer_name
FROM mysql.orders o
INNER JOIN pg.customers c ON o.customer_id = c.customer_id;

-- LEFT JOIN
SELECT o.order_id, c.customer_name
FROM mysql.orders o
LEFT JOIN pg.customers c ON o.customer_id = c.customer_id;

-- RIGHT JOIN
SELECT o.order_id, c.customer_name
FROM mysql.orders o
RIGHT JOIN pg.customers c ON o.customer_id = c.customer_id;

-- FULL OUTER JOIN
SELECT o.order_id, c.customer_name
FROM mysql.orders o
FULL OUTER JOIN pg.customers c ON o.customer_id = c.customer_id;
```

### 跨源查询注意事项

⚠️ **执行引擎**：
- 跨源查询通常使用Spark、Presto或StarRocks引擎执行
- SuperSQL会自动选择合适的引擎
- 可以使用EXPLAIN查看执行计划

⚠️ **性能考虑**：
- 尽量将过滤条件下推到各个数据源
- 注意数据传输量，避免JOIN大表
- 考虑使用临时表缓存中间结果

## GROUP BY子句

### 基本语法

```sql
SELECT column1, column2, aggregate_function(column3)
FROM table_name
GROUP BY column1, column2
[HAVING condition];
```

### 基本示例

#### 示例1：简单分组

```sql
-- 按部门统计人数和平均工资
SELECT 
    department,
    COUNT(*) AS emp_count,
    AVG(salary) AS avg_salary
FROM mysql.employees
GROUP BY department;
```

#### 示例2：多列分组

```sql
-- 按部门和职位统计
SELECT 
    department,
    position,
    COUNT(*) AS emp_count,
    MIN(salary) AS min_salary,
    MAX(salary) AS max_salary
FROM mysql.employees
GROUP BY department, position;
```

#### 示例3：使用HAVING

```sql
-- 统计订单数大于10的客户
SELECT 
    customer_id,
    COUNT(*) AS order_count,
    SUM(total_amount) AS total_spent
FROM mysql.orders
GROUP BY customer_id
HAVING COUNT(*) > 10;
```

#### 示例4：跨源分组聚合

```sql
-- 跨源分组统计
SELECT 
    t1.cint,
    t1.clong,
    t1.cdouble,
    COUNT(t2.clong) AS cnt_clong,
    AVG(t1.cfloat) AS avg_cfloat,
    MIN(t1.cdecimal) AS min_cdecimal
FROM pg.temp2 t1
JOIN mysql.temp t2 ON t1.cint = t2.cint
WHERE t1.cdecimal BETWEEN -10.1 AND 100.23
GROUP BY t1.cint, t1.clong, t1.cdouble
HAVING COUNT(t2.clong) > 5;
```

### 高级分组功能

#### ROLLUP

```sql
-- 生成小计和总计
SELECT 
    department,
    position,
    COUNT(*) AS emp_count,
    SUM(salary) AS total_salary
FROM mysql.employees
GROUP BY ROLLUP(department, position);
```

#### CUBE

```sql
-- 生成所有维度组合的聚合
SELECT 
    department,
    position,
    COUNT(*) AS emp_count
FROM mysql.employees
GROUP BY CUBE(department, position);
```

#### GROUPING SETS

```sql
-- 自定义分组集合
SELECT 
    department,
    position,
    COUNT(*) AS emp_count
FROM mysql.employees
GROUP BY GROUPING SETS (
    (department, position),
    (department),
    ()
);
```

## ORDER BY子句

### 基本语法

```sql
query_statement
[ORDER BY orderItem, orderItem, ...]
[LIMIT [start, count | count | ALL]]
[OFFSET start]
[FETCH (FIRST | NEXT) count (ROW | ROWS) ONLY]
```

### orderItem语法

```sql
column_name [ASC | DESC] [NULLS FIRST | NULLS LAST]
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `ASC` | 升序排序（默认） |
| `DESC` | 降序排序 |
| `NULLS FIRST` | NULL值排在前面 |
| `NULLS LAST` | NULL值排在后面（默认） |
| `LIMIT count` | 限制返回的行数 |
| `OFFSET start` | 跳过前面的start行 |
| `FETCH` | SQL标准的限制行数语法 |

### 基本示例

#### 示例1：简单排序

```sql
-- 单列升序
SELECT * FROM mysql.employees ORDER BY salary;

-- 单列降序
SELECT * FROM mysql.employees ORDER BY salary DESC;
```

#### 示例2：多列排序

```sql
-- 先按部门升序，再按工资降序
SELECT * FROM mysql.employees 
ORDER BY department ASC, salary DESC;
```

#### 示例3：NULL值处理

```sql
-- NULL值排在前面
SELECT * FROM mysql.employees 
ORDER BY bonus NULLS FIRST;

-- NULL值排在后面
SELECT * FROM mysql.employees 
ORDER BY bonus DESC NULLS LAST;
```

#### 示例4：使用LIMIT和OFFSET

```sql
-- 查询前10条记录
SELECT * FROM mysql.employees ORDER BY emp_id LIMIT 10;

-- 跳过前20条，返回10条（分页）
SELECT * FROM mysql.employees ORDER BY emp_id LIMIT 10 OFFSET 20;

-- 等价写法
SELECT * FROM mysql.employees ORDER BY emp_id LIMIT 20, 10;
```

#### 示例5：使用FETCH

```sql
-- SQL标准语法
SELECT * FROM mysql.employees 
ORDER BY emp_id 
FETCH FIRST 10 ROWS ONLY;

-- 带OFFSET
SELECT * FROM mysql.employees 
ORDER BY emp_id 
OFFSET 20 ROWS
FETCH NEXT 10 ROWS ONLY;
```

#### 示例6：复杂ORDER BY

```sql
-- Hive表，跳过前2条，返回20条
SELECT * FROM hive.temp LIMIT 20 OFFSET 2;

-- 复杂的分组聚合+排序+限制
SELECT 
    COUNT(clong) AS cnt_clong, 
    AVG(cfloat) AS avg_cfloat, 
    MIN(cdecimal) AS min_cdecimal
FROM pg.temp2
WHERE cdecimal BETWEEN -10.1 AND 100.23
GROUP BY cint, clong, cdouble
ORDER BY cint DESC, clong ASC, cdouble DESC
LIMIT 5 OFFSET 1 
FETCH NEXT 2 ROW ONLY;
```

**说明**：
- `LIMIT 5 OFFSET 1`：跳过1行，最多返回5行
- `FETCH NEXT 2 ROW ONLY`：进一步限制只返回2行
- 最终返回2行（取两者中更严格的限制）

## 窗口函数

### 窗口定义语法

```sql
(
  [PARTITION BY partitionList]
  [ORDER BY orderItemList]
  [(ROWS | RANGE) (BETWEEN lowerBound AND upperBound | lowerBound)]
)
```

### lowerBound和upperBound语法

```sql
CURRENT ROW
| UNBOUNDED (PRECEDING | FOLLOWING)
| expression (PRECEDING | FOLLOWING)
```

### 窗口函数分类

| 类型 | 函数 | 说明 |
|------|------|------|
| **排名函数** | ROW_NUMBER() | 行号，连续递增 |
| | RANK() | 排名，相同值同排名，有间隔 |
| | DENSE_RANK() | 密集排名，相同值同排名，无间隔 |
| | NTILE(n) | 将数据分为n组 |
| **聚合函数** | SUM() OVER | 累计求和 |
| | AVG() OVER | 移动平均 |
| | COUNT() OVER | 计数 |
| | MIN() OVER | 最小值 |
| | MAX() OVER | 最大值 |
| **取值函数** | FIRST_VALUE() | 窗口第一个值 |
| | LAST_VALUE() | 窗口最后一个值 |
| | LAG() | 前一行的值 |
| | LEAD() | 后一行的值 |

### 基本示例

#### 示例1：ROW_NUMBER排名

```sql
-- 按部门分组，按工资降序排名
SELECT 
    emp_id,
    emp_name,
    department,
    salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rank_in_dept
FROM mysql.employees;
```

#### 示例2：RANK和DENSE_RANK

```sql
-- 对比三种排名函数
SELECT 
    emp_name,
    salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num,
    RANK() OVER (ORDER BY salary DESC) AS rank,
    DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rank
FROM mysql.employees;
```

#### 示例3：累计求和

```sql
-- 按日期累计销售额
SELECT 
    order_date,
    daily_sales,
    SUM(daily_sales) OVER (ORDER BY order_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS cumulative_sales
FROM (
    SELECT order_date, SUM(total_amount) AS daily_sales
    FROM mysql.orders
    GROUP BY order_date
) t;
```

#### 示例4：移动平均

```sql
-- 计算7天移动平均
SELECT 
    order_date,
    daily_sales,
    AVG(daily_sales) OVER (
        ORDER BY order_date 
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS moving_avg_7days
FROM (
    SELECT order_date, SUM(total_amount) AS daily_sales
    FROM mysql.orders
    GROUP BY order_date
) t;
```

#### 示例5：LAG和LEAD

```sql
-- 计算环比增长率
SELECT 
    order_date,
    daily_sales,
    LAG(daily_sales, 1) OVER (ORDER BY order_date) AS prev_day_sales,
    LEAD(daily_sales, 1) OVER (ORDER BY order_date) AS next_day_sales,
    (daily_sales - LAG(daily_sales, 1) OVER (ORDER BY order_date)) / 
        LAG(daily_sales, 1) OVER (ORDER BY order_date) * 100 AS growth_rate
FROM (
    SELECT order_date, SUM(total_amount) AS daily_sales
    FROM mysql.orders
    GROUP BY order_date
) t;
```

#### 示例6：FIRST_VALUE和LAST_VALUE

```sql
-- 查询每个部门最高和最低工资
SELECT 
    emp_id,
    emp_name,
    department,
    salary,
    FIRST_VALUE(salary) OVER (
        PARTITION BY department 
        ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS dept_max_salary,
    LAST_VALUE(salary) OVER (
        PARTITION BY department 
        ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS dept_min_salary
FROM mysql.employees;
```

#### 示例7：使用WINDOW子句

```sql
-- 使用命名窗口
SELECT 
    COUNT(z) OVER w AS foo
FROM mysql.bids
WINDOW w AS (
    PARTITION BY y + yy, yyy 
    ORDER BY x 
    ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING
);
```

#### 示例8：RANGE窗口

```sql
-- 使用RANGE定义窗口
SELECT 
    deptno, 
    empid, 
    commission,
    FIRST_VALUE(commission) OVER (
        PARTITION BY deptno 
        ORDER BY empid DESC 
        RANGE BETWEEN 1000 PRECEDING AND 999 PRECEDING
    ) AS r
FROM hr.emps;
```

### ROWS vs RANGE

| 窗口类型 | 说明 | 适用场景 |
|---------|------|---------|
| **ROWS** | 基于物理行数 | 固定行数的窗口（如前3行、后3行） |
| **RANGE** | 基于逻辑值范围 | 基于值的窗口（如当前值±100） |

**示例对比**：

```sql
-- ROWS：前后各2行（物理行数）
SELECT 
    order_id, 
    order_amount,
    AVG(order_amount) OVER (
        ORDER BY order_id 
        ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING
    ) AS avg_5rows
FROM mysql.orders;

-- RANGE：值在当前值±100范围内（逻辑值）
SELECT 
    order_id, 
    order_amount,
    AVG(order_amount) OVER (
        ORDER BY order_amount 
        RANGE BETWEEN 100 PRECEDING AND 100 FOLLOWING
    ) AS avg_range
FROM mysql.orders;
```

## WITH语句（CTE）

### 基本语法

```sql
[withList] queryStatement (binaryQueryOperator queryStatement)*
```

### binaryQueryOperator语法

```sql
UNION [ALL | DISTINCT] 
| INTERSECT [ALL | DISTINCT] 
| (EXCEPT | MINUS) [ALL | DISTINCT]
```

### withList语法

```sql
WITH withItem, withItem, ...

withItem:
temporaryTableName [('columnList')] AS ('queryStatement')
```

### 功能说明

- **WITH子句**（也称为CTE，Common Table Expression）用于定义临时命名结果集
- 可以在主查询中引用WITH定义的临时表
- 支持定义多个临时表，后面的临时表可以引用前面定义的
- 提高SQL可读性和可维护性

### 基本示例

#### 示例1：简单CTE

```sql
-- 定义临时表，然后查询
WITH high_salary_emps AS (
    SELECT * FROM mysql.employees WHERE salary > 10000
)
SELECT 
    department, 
    COUNT(*) AS emp_count,
    AVG(salary) AS avg_salary
FROM high_salary_emps
GROUP BY department;
```

#### 示例2：多个CTE

```sql
-- 定义多个临时表
WITH 
dept_stats AS (
    SELECT 
        department,
        COUNT(*) AS emp_count,
        AVG(salary) AS avg_salary
    FROM mysql.employees
    GROUP BY department
),
high_avg_depts AS (
    SELECT department FROM dept_stats WHERE avg_salary > 8000
)
SELECT e.*
FROM mysql.employees e
JOIN high_avg_depts d ON e.department = d.department;
```

#### 示例3：递归引用

```sql
-- 后面的CTE引用前面定义的CTE
WITH 
orders_2024 AS (
    SELECT * FROM mysql.orders 
    WHERE YEAR(order_date) = 2024
),
top_customers AS (
    SELECT 
        customer_id,
        SUM(total_amount) AS total_spent
    FROM orders_2024
    GROUP BY customer_id
    HAVING SUM(total_amount) > 100000
)
SELECT 
    c.customer_name,
    tc.total_spent
FROM top_customers tc
JOIN mysql.customers c ON tc.customer_id = c.customer_id
ORDER BY tc.total_spent DESC;
```

### 复杂示例：TPC-DS Query

以下是一个真实的TPC-DS查询示例，展示了WITH子句在复杂跨源分析中的应用：

```sql
-- 6个CTE定义，用于复杂的跨源分析
WITH ss AS (
    SELECT 
        s_store_sk,
        SUM(ss_ext_sales_price) AS sales,
        SUM(ss_net_profit) AS profit
    FROM tpcds_hive.store_sales,
         tpcds_pg1.date_dim,
         tpcds_hive.store
    WHERE ss_sold_date_sk = d_date_sk
      AND d_date BETWEEN CAST('1998-08-04' AS DATE)
                     AND (CAST('1998-08-04' AS DATE) + INTERVAL '30' DAY)
      AND ss_store_sk = s_store_sk
    GROUP BY s_store_sk
),
sr AS (
    SELECT 
        s_store_sk,
        SUM(sr_return_amt) AS returns1,
        SUM(sr_net_loss) AS profit_loss
    FROM tpcds_pg1.store_returns,
         tpcds_hive.date_dim,
         tpcds_pg1.store
    WHERE sr_returned_date_sk = d_date_sk
      AND d_date BETWEEN CAST('1998-08-04' AS DATE)
                     AND (CAST('1998-08-04' AS DATE) + INTERVAL '30' DAY)
      AND sr_store_sk = s_store_sk
    GROUP BY s_store_sk
),
cs AS (
    SELECT 
        cs_call_center_sk,
        SUM(cs_ext_sales_price) AS sales,
        SUM(cs_net_profit) AS profit
    FROM tpcds_pg1.catalog_sales,
         tpcds_pg1.date_dim
    WHERE cs_sold_date_sk = d_date_sk
      AND d_date BETWEEN CAST('1998-08-04' AS DATE)
                     AND (CAST('1998-08-04' AS DATE) + INTERVAL '30' DAY)
    GROUP BY cs_call_center_sk
),
cr AS (
    SELECT 
        cr_call_center_sk,
        SUM(cr_return_amount) AS returns1,
        SUM(cr_net_loss) AS profit_loss
    FROM tpcds_hive.catalog_returns,
         tpcds_hive.date_dim
    WHERE cr_returned_date_sk = d_date_sk
      AND d_date BETWEEN CAST('1998-08-04' AS DATE)
                     AND (CAST('1998-08-04' AS DATE) + INTERVAL '30' DAY)
    GROUP BY cr_call_center_sk
),
ws AS (
    SELECT 
        wp_web_page_sk,
        SUM(ws_ext_sales_price) AS sales,
        SUM(ws_net_profit) AS profit
    FROM tpcds_pg1.web_sales,
         tpcds_pg1.date_dim,
         tpcds_pg1.web_page
    WHERE ws_sold_date_sk = d_date_sk
      AND d_date BETWEEN CAST('1998-08-04' AS DATE)
                     AND (CAST('1998-08-04' AS DATE) + INTERVAL '30' DAY)
      AND ws_web_page_sk = wp_web_page_sk
    GROUP BY wp_web_page_sk
),
wr AS (
    SELECT 
        wp_web_page_sk,
        SUM(wr_return_amt) AS returns1,
        SUM(wr_net_loss) AS profit_loss
    FROM tpcds_hive.web_returns,
         tpcds_hive.date_dim,
         tpcds_hive.web_page
    WHERE wr_returned_date_sk = d_date_sk
      AND d_date BETWEEN CAST('1998-08-04' AS DATE)
                     AND (CAST('1998-08-04' AS DATE) + INTERVAL '30' DAY)
      AND wr_web_page_sk = wp_web_page_sk
    GROUP BY wp_web_page_sk
)
-- 主查询
SELECT * FROM (
    SELECT  
        channel,
        id,
        SUM(sales) AS sales,
        SUM(returns1) AS returns1,
        SUM(profit) AS profit
    FROM (
        -- 门店渠道
        SELECT 
            'store channel' AS channel,
            ss.s_store_sk AS id,
            sales,
            COALESCE(returns1, 0) AS returns1,
            (profit - COALESCE(profit_loss, 0)) AS profit
        FROM ss 
        LEFT JOIN sr ON ss.s_store_sk = sr.s_store_sk
        
        UNION ALL
        
        -- 电话渠道
        SELECT 
            'catalog channel' AS channel,
            cs_call_center_sk AS id,
            sales,
            returns1,
            (profit - profit_loss) AS profit
        FROM cs, cr
        
        UNION ALL
        
        -- 网站渠道
        SELECT 
            'web channel' AS channel,
            ws.wp_web_page_sk AS id,
            sales,
            COALESCE(returns1, 0) AS returns1,
            (profit - COALESCE(profit_loss, 0)) AS profit
        FROM ws 
        LEFT JOIN wr ON ws.wp_web_page_sk = wr.wp_web_page_sk
    ) x
    GROUP BY ROLLUP(channel, id)
    ORDER BY channel, id
) 
LIMIT 100;
```

**说明**：
- 定义了6个CTE（ss, sr, cs, cr, ws, wr），分别统计不同渠道的销售和退货数据
- 涉及多个数据源（tpcds_hive、tpcds_pg1）
- 使用ROLLUP进行多维度汇总
- 使用UNION ALL合并不同渠道的数据

## 集合操作

SuperSQL支持标准的集合操作符，用于合并多个查询结果。

### UNION

**去重合并**（默认）：

```sql
-- UNION（去重）
SELECT emp_id, emp_name FROM mysql.employees WHERE department = 'Engineering'
UNION
SELECT emp_id, emp_name FROM mysql.employees WHERE department = 'Sales';

-- 等价于
SELECT emp_id, emp_name FROM mysql.employees WHERE department = 'Engineering'
UNION DISTINCT
SELECT emp_id, emp_name FROM mysql.employees WHERE department = 'Sales';
```

**保留重复**：

```sql
-- UNION ALL（保留重复）
SELECT emp_id, emp_name FROM mysql.employees WHERE department = 'Engineering'
UNION ALL
SELECT emp_id, emp_name FROM mysql.employees WHERE department = 'Sales';
```

### INTERSECT

**交集**（两个结果集的公共部分）：

```sql
-- 查询既在2023年又在2024年下单的客户
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2023
INTERSECT
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2024;

-- INTERSECT ALL（保留重复）
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2023
INTERSECT ALL
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2024;
```

### EXCEPT / MINUS

**差集**（第一个结果集减去第二个结果集）：

```sql
-- 查询在2023年下单但在2024年没有下单的客户
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2023
EXCEPT
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2024;

-- 等价于（MINUS是EXCEPT的别名）
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2023
MINUS
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2024;

-- EXCEPT ALL（保留重复）
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2023
EXCEPT ALL
SELECT customer_id FROM mysql.orders WHERE YEAR(order_date) = 2024;
```

### 集合操作注意事项

⚠️ **列数和类型**：
- 所有SELECT语句必须有**相同数量的列**
- 对应位置的列**类型必须兼容**

```sql
-- ✅ 正确：列数和类型匹配
SELECT emp_id, emp_name FROM mysql.employees
UNION
SELECT cust_id, cust_name FROM mysql.customers;

-- ❌ 错误：列数不匹配
SELECT emp_id, emp_name, department FROM mysql.employees
UNION
SELECT cust_id, cust_name FROM mysql.customers;
```

⚠️ **ORDER BY位置**：
- ORDER BY必须放在**最后一个SELECT**之后

```sql
-- ✅ 正确
SELECT emp_id, emp_name FROM mysql.employees
UNION
SELECT cust_id, cust_name FROM mysql.customers
ORDER BY emp_name;

-- ❌ 错误
SELECT emp_id, emp_name FROM mysql.employees ORDER BY emp_name
UNION
SELECT cust_id, cust_name FROM mysql.customers;
```

## 子查询

### 子查询类型

| 类型 | 说明 | 示例位置 |
|------|------|---------|
| **标量子查询** | 返回单个值 | SELECT列表、WHERE条件 |
| **行子查询** | 返回单行多列 | WHERE条件 |
| **表子查询** | 返回多行多列 | FROM子句 |
| **相关子查询** | 引用外部查询的列 | WHERE、SELECT |

### 标量子查询

```sql
-- 查询工资高于平均工资的员工
SELECT emp_id, emp_name, salary
FROM mysql.employees
WHERE salary > (SELECT AVG(salary) FROM mysql.employees);

-- 在SELECT列表中使用
SELECT 
    emp_id,
    emp_name,
    salary,
    (SELECT AVG(salary) FROM mysql.employees) AS avg_salary,
    salary - (SELECT AVG(salary) FROM mysql.employees) AS diff
FROM mysql.employees;
```

### 表子查询（FROM子句）

```sql
-- 查询每个部门工资最高的员工
SELECT d.department, d.max_salary, e.emp_name
FROM (
    SELECT department, MAX(salary) AS max_salary
    FROM mysql.employees
    GROUP BY department
) d
JOIN mysql.employees e 
    ON d.department = e.department 
    AND d.max_salary = e.salary;
```

### IN子查询

```sql
-- 查询有订单的客户
SELECT *
FROM mysql.customers
WHERE customer_id IN (
    SELECT DISTINCT customer_id FROM mysql.orders
);

-- NOT IN
SELECT *
FROM mysql.customers
WHERE customer_id NOT IN (
    SELECT customer_id FROM mysql.orders WHERE status = 'cancelled'
);
```

### EXISTS子查询

```sql
-- 查询有订单的客户（使用EXISTS）
SELECT c.*
FROM mysql.customers c
WHERE EXISTS (
    SELECT 1 FROM mysql.orders o WHERE o.customer_id = c.customer_id
);

-- NOT EXISTS
SELECT c.*
FROM mysql.customers c
WHERE NOT EXISTS (
    SELECT 1 FROM mysql.orders o WHERE o.customer_id = c.customer_id
);
```

### 相关子查询

```sql
-- 查询每个员工工资在其部门中的排名
SELECT 
    e1.emp_id,
    e1.emp_name,
    e1.department,
    e1.salary,
    (
        SELECT COUNT(*) + 1
        FROM mysql.employees e2
        WHERE e2.department = e1.department
          AND e2.salary > e1.salary
    ) AS rank_in_dept
FROM mysql.employees e1;
```

## 使用场景

### 场景1：跨源实时分析

**需求**：实时分析MySQL订单数据和PostgreSQL客户数据

```sql
-- 统计各客户等级的订单情况
SELECT 
    c.customer_level,
    COUNT(o.order_id) AS order_count,
    SUM(o.total_amount) AS total_amount,
    AVG(o.total_amount) AS avg_order_amount
FROM mysql.orders o
JOIN pg.customers c ON o.customer_id = c.customer_id
WHERE o.order_date >= CURRENT_DATE - INTERVAL '30' DAY
GROUP BY c.customer_level
ORDER BY total_amount DESC;
```

### 场景2：数据质量检查

**需求**：检查跨源数据一致性

```sql
-- 检查MySQL和PostgreSQL中的客户数据差异
SELECT 
    'Only in MySQL' AS location,
    customer_id,
    customer_name
FROM mysql.customers
WHERE customer_id NOT IN (SELECT customer_id FROM pg.customers)

UNION ALL

SELECT 
    'Only in PostgreSQL' AS location,
    customer_id,
    customer_name
FROM pg.customers
WHERE customer_id NOT IN (SELECT customer_id FROM mysql.customers);
```

### 场景3：复杂时间序列分析

**需求**：计算销售趋势和同比增长

```sql
WITH daily_sales AS (
    SELECT 
        DATE(order_date) AS sale_date,
        SUM(total_amount) AS daily_total
    FROM mysql.orders
    GROUP BY DATE(order_date)
)
SELECT 
    sale_date,
    daily_total,
    -- 7天移动平均
    AVG(daily_total) OVER (
        ORDER BY sale_date 
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS ma_7days,
    -- 环比增长
    (daily_total - LAG(daily_total, 1) OVER (ORDER BY sale_date)) / 
        LAG(daily_total, 1) OVER (ORDER BY sale_date) * 100 AS day_growth,
    -- 同比增长（365天前）
    (daily_total - LAG(daily_total, 365) OVER (ORDER BY sale_date)) / 
        LAG(daily_total, 365) OVER (ORDER BY sale_date) * 100 AS year_growth
FROM daily_sales
ORDER BY sale_date DESC
LIMIT 90;
```

### 场景4：维度钻取分析

**需求**：从总体到部门到员工的层次分析

```sql
-- 使用ROLLUP实现维度钻取
SELECT 
    department,
    position,
    COUNT(*) AS emp_count,
    SUM(salary) AS total_salary,
    AVG(salary) AS avg_salary
FROM mysql.employees
WHERE hire_date >= '2023-01-01'
GROUP BY ROLLUP(department, position)
ORDER BY department, position;
```

### 场景5：漏斗分析

**需求**：分析用户转化漏斗

```sql
WITH funnel_data AS (
    SELECT 
        u.user_id,
        MAX(CASE WHEN e.event_type = 'page_view' THEN 1 ELSE 0 END) AS has_view,
        MAX(CASE WHEN e.event_type = 'add_to_cart' THEN 1 ELSE 0 END) AS has_cart,
        MAX(CASE WHEN e.event_type = 'checkout' THEN 1 ELSE 0 END) AS has_checkout,
        MAX(CASE WHEN e.event_type = 'purchase' THEN 1 ELSE 0 END) AS has_purchase
    FROM mysql.users u
    LEFT JOIN pg.events e ON u.user_id = e.user_id
    WHERE e.event_date >= CURRENT_DATE - INTERVAL '7' DAY
    GROUP BY u.user_id
)
SELECT 
    'Page View' AS stage,
    SUM(has_view) AS user_count,
    100.0 AS conversion_rate
FROM funnel_data
WHERE has_view = 1

UNION ALL

SELECT 
    'Add to Cart' AS stage,
    SUM(has_cart) AS user_count,
    SUM(has_cart) * 100.0 / NULLIF(SUM(has_view), 0) AS conversion_rate
FROM funnel_data
WHERE has_view = 1

UNION ALL

SELECT 
    'Checkout' AS stage,
    SUM(has_checkout) AS user_count,
    SUM(has_checkout) * 100.0 / NULLIF(SUM(has_cart), 0) AS conversion_rate
FROM funnel_data
WHERE has_cart = 1

UNION ALL

SELECT 
    'Purchase' AS stage,
    SUM(has_purchase) AS user_count,
    SUM(has_purchase) * 100.0 / NULLIF(SUM(has_checkout), 0) AS conversion_rate
FROM funnel_data
WHERE has_checkout = 1;
```

## 最佳实践

### 1. 跨源查询优化

**✅ 推荐做法**：
- 使用EXPLAIN分析执行计划，确认下推情况
- 尽量将过滤条件下推到各个数据源
- 避免JOIN大表，考虑使用临时表缓存中间结果

```sql
-- ✅ 推荐：过滤条件在JOIN前
SELECT o.order_id, c.customer_name
FROM (
    SELECT * FROM mysql.orders WHERE order_date >= '2024-01-01'
) o
JOIN (
    SELECT * FROM pg.customers WHERE customer_level = 'VIP'
) c ON o.customer_id = c.customer_id;
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：过滤条件在JOIN后（数据传输量大）
SELECT o.order_id, c.customer_name
FROM mysql.orders o
JOIN pg.customers c ON o.customer_id = c.customer_id
WHERE o.order_date >= '2024-01-01' AND c.customer_level = 'VIP';
```

### 2. 使用CTE提高可读性

**✅ 推荐做法**：
- 将复杂查询拆分为多个CTE
- 给CTE起有意义的名字
- 逻辑清晰，便于维护

```sql
-- ✅ 推荐：使用CTE
WITH 
recent_orders AS (
    SELECT * FROM mysql.orders WHERE order_date >= CURRENT_DATE - INTERVAL '30' DAY
),
customer_stats AS (
    SELECT 
        customer_id,
        COUNT(*) AS order_count,
        SUM(total_amount) AS total_spent
    FROM recent_orders
    GROUP BY customer_id
)
SELECT c.customer_name, cs.order_count, cs.total_spent
FROM customer_stats cs
JOIN mysql.customers c ON cs.customer_id = c.customer_id
WHERE cs.order_count >= 5
ORDER BY cs.total_spent DESC;
```

### 3. 窗口函数性能优化

**✅ 推荐做法**：
- 相同的窗口定义使用WINDOW子句命名
- 避免在窗口函数中使用复杂的ORDER BY表达式

```sql
-- ✅ 推荐：使用命名窗口
SELECT 
    emp_id,
    emp_name,
    salary,
    ROW_NUMBER() OVER w AS row_num,
    RANK() OVER w AS rank,
    DENSE_RANK() OVER w AS dense_rank
FROM mysql.employees
WINDOW w AS (PARTITION BY department ORDER BY salary DESC);
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：重复定义窗口
SELECT 
    emp_id,
    emp_name,
    salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS row_num,
    RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS rank,
    DENSE_RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS dense_rank
FROM mysql.employees;
```

### 4. LIMIT和OFFSET优化

**✅ 推荐做法**：
- 总是使用ORDER BY确保结果稳定
- 深分页使用游标或时间戳过滤

```sql
-- ✅ 推荐：使用ORDER BY
SELECT * FROM mysql.orders 
ORDER BY order_id 
LIMIT 100 OFFSET 1000;

-- ✅ 推荐：深分页使用时间戳（避免OFFSET）
SELECT * FROM mysql.orders 
WHERE order_id > 1000  -- 上一页的最后一个order_id
ORDER BY order_id 
LIMIT 100;
```

### 5. 合理使用DISTINCT

**✅ 推荐做法**：
- 明确是否需要去重
- 优先使用GROUP BY而非DISTINCT

```sql
-- ✅ 推荐：使用GROUP BY（可以同时聚合）
SELECT 
    department,
    COUNT(*) AS emp_count
FROM mysql.employees
GROUP BY department;
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：不必要的DISTINCT（性能开销大）
SELECT DISTINCT department FROM mysql.employees;
-- 如果只需要去重，考虑是否数据源有问题
```

### 6. 子查询 vs JOIN

**✅ 推荐做法**：
- 优先使用JOIN而非IN子查询（性能更好）
- EXISTS适合判断存在性

```sql
-- ✅ 推荐：使用JOIN
SELECT DISTINCT c.*
FROM mysql.customers c
JOIN mysql.orders o ON c.customer_id = o.customer_id
WHERE o.order_date >= '2024-01-01';

-- ✅ 推荐：使用EXISTS（判断存在）
SELECT c.*
FROM mysql.customers c
WHERE EXISTS (
    SELECT 1 FROM mysql.orders o 
    WHERE o.customer_id = c.customer_id 
      AND o.order_date >= '2024-01-01'
);
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：IN子查询（性能可能较差）
SELECT * FROM mysql.customers
WHERE customer_id IN (
    SELECT customer_id FROM mysql.orders WHERE order_date >= '2024-01-01'
);
```

## 常见问题FAQ

### 1. SuperSQL支持所有标准SQL语法吗？

**答案**：SuperSQL基于Apache Calcite，支持**绝大部分**标准SQL语法。

**支持的语法**：
- ✅ SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY
- ✅ JOIN（INNER、LEFT、RIGHT、FULL OUTER、CROSS）
- ✅ 子查询（标量、表、IN、EXISTS）
- ✅ 窗口函数（ROW_NUMBER、RANK、SUM OVER等）
- ✅ CTE（WITH子句）
- ✅ 集合操作（UNION、INTERSECT、EXCEPT）
- ✅ ROLLUP、CUBE、GROUPING SETS

**不支持或有限制的语法**：
- ⚠️ PIVOT/UNPIVOT（部分支持）
- ⚠️ LATERAL VIEW（Hive特有，需透传）
- ⚠️ 某些数据源特有的语法

**建议**：使用`EXPLAIN`查看执行计划，确认SQL是否能正确执行。

---

### 2. 跨源查询使用什么引擎执行？

**答案**：根据查询复杂度和数据源类型，SuperSQL会自动选择合适的引擎。

| 场景 | 执行引擎 |
|------|---------|
| **单源查询** | 下推到数据源原生执行 |
| **跨源简单查询** | SuperSQL自身执行 |
| **跨源复杂查询** | Spark、Presto或StarRocks |

**示例**：
```sql
-- 使用EXPLAIN查看执行引擎
EXPLAIN 
SELECT o.order_id, c.customer_name
FROM mysql.orders o
JOIN pg.customers c ON o.customer_id = c.customer_id;
```

**输出示例**：
```
Exec engine type: SPARK
```

---

### 3. 如何优化跨源JOIN性能？

**答案**：主要从以下几个方面优化：

**1. 过滤条件下推**
```sql
-- ✅ 推荐：过滤后再JOIN
SELECT o.order_id, c.customer_name
FROM (
    SELECT * FROM mysql.orders WHERE order_date >= '2024-01-01'
) o
JOIN (
    SELECT * FROM pg.customers WHERE customer_level = 'VIP'
) c ON o.customer_id = c.customer_id;
```

**2. 小表JOIN大表**
- SuperSQL会自动优化JOIN顺序
- 但可以通过子查询强制小表在前

**3. 使用临时表缓存**
```sql
-- 缓存大表的过滤结果
CREATE TEMPORARY TABLE temp_orders AS
SELECT * FROM mysql.orders WHERE order_date >= '2024-01-01';

-- 使用临时表JOIN
SELECT o.order_id, c.customer_name
FROM temp_orders o
JOIN pg.customers c ON o.customer_id = c.customer_id;
```

**4. 分批处理**
- 对于大数据量，考虑分批处理，避免一次性传输大量数据

### 4. 窗口函数中ROWS和RANGE有什么区别？

**答案**：主要区别在于窗口的定义方式。

| 特性 | ROWS | RANGE |
|------|------|-------|
| **定义方式** | 基于物理行数 | 基于逻辑值范围 |
| **相同值处理** | 每行独立 | 相同值算一个范围 |
| **性能** | 通常更快 | 需要值比较，较慢 |

**示例**：
```sql
-- ROWS：物理行数，前后各1行（共3行）
SELECT 
    order_id, 
    order_amount,
    SUM(order_amount) OVER (
        ORDER BY order_id 
        ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
    ) AS sum_3rows
FROM mysql.orders;

-- RANGE：逻辑值范围，order_amount在当前值±100范围内的所有行
SELECT 
    order_id, 
    order_amount,
    SUM(order_amount) OVER (
        ORDER BY order_amount 
        RANGE BETWEEN 100 PRECEDING AND 100 FOLLOWING
    ) AS sum_range
FROM mysql.orders;
```

**建议**：
- 大多数情况使用**ROWS**（性能更好）
- 需要基于值的逻辑范围时使用**RANGE**

---

### 5. WITH子句（CTE）会物化结果吗？

**答案**：**取决于优化器决策**，不一定会物化。

**SuperSQL的处理方式**：
- **简单CTE**：通常会内联（inline）到主查询中，不物化
- **复杂CTE**：可能会物化为临时结果集
- **多次引用的CTE**：通常会物化以避免重复计算

**示例**：
```sql
-- CTE只引用一次，可能被内联
WITH temp AS (
    SELECT * FROM mysql.orders WHERE order_date >= '2024-01-01'
)
SELECT COUNT(*) FROM temp;

-- CTE引用多次，可能会物化
WITH temp AS (
    SELECT * FROM mysql.orders WHERE order_date >= '2024-01-01'
)
SELECT 
    (SELECT COUNT(*) FROM temp) AS total_count,
    (SELECT SUM(total_amount) FROM temp) AS total_amount;
```

**建议**：
- 使用`EXPLAIN`查看执行计划
- 对于一定需要物化的中间结果，使用`CREATE TEMPORARY TABLE`

### 6. LIMIT和OFFSET在跨源查询中如何工作？

**答案**：SuperSQL会尽量将LIMIT下推到数据源，但跨源场景下有限制。

**单源查询**：
```sql
-- LIMIT完全下推到MySQL
SELECT * FROM mysql.orders ORDER BY order_id LIMIT 100;
```

**跨源查询**：
```sql
-- LIMIT在Spark引擎中执行（无法下推）
SELECT o.order_id, c.customer_name
FROM mysql.orders o
JOIN pg.customers c ON o.customer_id = c.customer_id
ORDER BY o.order_id
LIMIT 100;
```

**注意事项**：
- ⚠️ 没有ORDER BY的LIMIT结果**不稳定**（每次可能不同）
- ⚠️ OFFSET在大数据量时**性能较差**（需要扫描前面的所有行）

**建议**：
```sql
-- ✅ 推荐：使用ORDER BY保证稳定性
SELECT * FROM mysql.orders ORDER BY order_id LIMIT 100;

-- ✅ 推荐：深分页使用WHERE代替OFFSET
SELECT * FROM mysql.orders 
WHERE order_id > :last_order_id 
ORDER BY order_id 
LIMIT 100;
```

### 7. 如何查看跨源查询的下推情况？

**答案**：使用`EXPLAIN`语句查看执行计划。

**步骤**：
```sql
EXPLAIN 
SELECT o.order_id, c.customer_name
FROM mysql.orders o
JOIN pg.customers c ON o.customer_id = c.customer_id
WHERE o.order_date >= '2024-01-01';

**关键信息**：

- **SuperSQL CBO**：显示优化器决策（Single Source / Ext. Engine Exec）

**示例输出**：

```

详见**2.12_EXPLAIN语句**章节。

### 8. 子查询中可以使用LIMIT吗？

**答案**：可以，但要注意使用场景。

**标量子查询**：
```sql
-- ❌ 错误：标量子查询必须返回单个值
SELECT * FROM mysql.employees
WHERE salary > (SELECT salary FROM mysql.employees LIMIT 1);  -- 不确定返回哪个值

-- ✅ 正确：使用聚合函数
SELECT * FROM mysql.employees
WHERE salary > (SELECT MAX(salary) FROM mysql.employees);
```

**表子查询**：
```sql
-- ✅ 正确：FROM子句中的子查询可以使用LIMIT
SELECT *
FROM (
    SELECT * FROM mysql.orders ORDER BY order_date DESC LIMIT 100
) recent_orders
WHERE total_amount > 1000;
```

**IN子查询**：
```sql
-- ⚠️ 谨慎使用：LIMIT可能导致结果不稳定
SELECT * FROM mysql.customers
WHERE customer_id IN (
    SELECT customer_id FROM mysql.orders ORDER BY order_date DESC LIMIT 100
);
```

### 9. UNION和UNION ALL的性能差异大吗？

**答案**：**差异很大**，UNION ALL通常快得多。

| 特性 | UNION | UNION ALL |
|------|-------|-----------|
| **去重** | 去重 | 不去重 |
| **性能** | 慢（需要排序、去重） | 快（直接合并） |
| **数据量影响** | 数据量越大，差异越明显 | 线性增长 |

**性能对比示例**：
```sql
-- 慢：需要去重
SELECT * FROM mysql.orders WHERE order_date >= '2024-01-01'
UNION
SELECT * FROM mysql.orders WHERE total_amount > 1000;

-- 快：直接合并
SELECT * FROM mysql.orders WHERE order_date >= '2024-01-01'
UNION ALL
SELECT * FROM mysql.orders WHERE total_amount > 1000;
```

**建议**：
- 如果**确定没有重复**或**不需要去重**，使用`UNION ALL`
- 只有在**必须去重**时才使用`UNION`

---

### 10. 如何在跨源查询中使用事务？

**答案**：SuperSQL的DQL查询**不涉及事务**，只有DML操作才涉及事务。

**DQL查询（SELECT）**：
- 不需要事务
- 读取的是查询执行时的数据快照
- 不同数据源的快照时间可能不一致

**跨源数据一致性问题**：
```sql
-- 问题：MySQL和PostgreSQL的数据快照时间可能不一致
SELECT 
    o.order_id,
    c.customer_name,
    o.order_date
FROM mysql.orders o
JOIN pg.customers c ON o.customer_id = c.customer_id;
```

**解决方案**：
1. **使用时间戳过滤**：确保查询同一时间段的数据
2. **使用数据仓库**：定期同步到同一数据源（如Hive）
3. **使用CDC工具**：实时同步数据

**建议**：
- 对于强一致性要求，考虑将数据同步到同一数据源
- 对于可接受最终一致性的场景，直接使用跨源查询

## 附录：完整示例

### 场景：电商多维度销售分析

**业务需求**：
1. 分析各渠道（线上、线下、电话）的销售情况
2. 计算销售趋势和同比增长
3. 识别高价值客户
4. 分析商品销售排名

**数据源**：
- **MySQL**：订单数据（orders）、订单明细（order_items）
- **PostgreSQL**：客户数据（customers）、商品数据（products）
- **Hive**：历史销售数据（sales_history）

**完整SQL**：

```sql
-- ========================================
-- CTE 1：最近30天的订单数据
-- ========================================
WITH recent_orders AS (
    SELECT 
        o.order_id,
        o.customer_id,
        o.order_date,
        o.channel,
        o.total_amount,
        oi.product_id,
        oi.quantity,
        oi.unit_price
    FROM mysql.orders o
    JOIN mysql.order_items oi ON o.order_id = oi.order_id
    WHERE o.order_date >= CURRENT_DATE - INTERVAL '30' DAY
      AND o.status = 'completed'
),

-- ========================================
-- CTE 2：客户信息（跨源）
-- ========================================
customer_info AS (
    SELECT 
        customer_id,
        customer_name,
        customer_level,
        register_date
    FROM pg.customers
    WHERE status = 'active'
),

-- ========================================
-- CTE 3：商品信息（跨源）
-- ========================================
product_info AS (
    SELECT 
        product_id,
        product_name,
        category,
        brand
    FROM pg.products
),

-- ========================================
-- CTE 4：客户维度统计
-- ========================================
customer_stats AS (
    SELECT 
        ro.customer_id,
        ci.customer_name,
        ci.customer_level,
        COUNT(DISTINCT ro.order_id) AS order_count,
        SUM(ro.total_amount) AS total_spent,
        AVG(ro.total_amount) AS avg_order_amount,
        MIN(ro.order_date) AS first_order_date,
        MAX(ro.order_date) AS last_order_date
    FROM recent_orders ro
    JOIN customer_info ci ON ro.customer_id = ci.customer_id
    GROUP BY ro.customer_id, ci.customer_name, ci.customer_level
),

-- ========================================
-- CTE 5：商品维度统计
-- ========================================
product_stats AS (
    SELECT 
        ro.product_id,
        pi.product_name,
        pi.category,
        pi.brand,
        SUM(ro.quantity) AS total_quantity,
        SUM(ro.quantity * ro.unit_price) AS total_sales,
        COUNT(DISTINCT ro.order_id) AS order_count,
        COUNT(DISTINCT ro.customer_id) AS customer_count
    FROM recent_orders ro
    JOIN product_info pi ON ro.product_id = pi.product_id
    GROUP BY ro.product_id, pi.product_name, pi.category, pi.brand
),

-- ========================================
-- CTE 6：渠道维度统计
-- ========================================
channel_stats AS (
    SELECT 
        ro.channel,
        COUNT(DISTINCT ro.order_id) AS order_count,
        COUNT(DISTINCT ro.customer_id) AS customer_count,
        SUM(ro.total_amount) AS total_sales,
        AVG(ro.total_amount) AS avg_order_amount
    FROM recent_orders ro
    GROUP BY ro.channel
),

-- ========================================
-- CTE 7：每日销售趋势
-- ========================================
daily_trends AS (
    SELECT 
        DATE(order_date) AS sale_date,
        channel,
        SUM(total_amount) AS daily_sales,
        COUNT(DISTINCT order_id) AS daily_orders,
        COUNT(DISTINCT customer_id) AS daily_customers
    FROM recent_orders
    GROUP BY DATE(order_date), channel
),

-- ========================================
-- CTE 8：同比数据（去年同期，从Hive读取）
-- ========================================
yoy_data AS (
    SELECT 
        DATE(sale_date) AS sale_date,
        channel,
        SUM(total_amount) AS last_year_sales
    FROM hive.sales_history
    WHERE sale_date >= CURRENT_DATE - INTERVAL '395' DAY
      AND sale_date < CURRENT_DATE - INTERVAL '365' DAY
    GROUP BY DATE(sale_date), channel
)

-- ========================================
-- 主查询：综合分析报表
-- ========================================

-- 1. 客户价值排名（TOP 20）
SELECT 
    'Top Customers' AS report_type,
    customer_id,
    customer_name,
    customer_level,
    order_count,
    total_spent,
    avg_order_amount,
    RANK() OVER (ORDER BY total_spent DESC) AS value_rank
FROM customer_stats
ORDER BY total_spent DESC
LIMIT 20

UNION ALL

-- 2. 商品销售排名（TOP 20）
SELECT 
    'Top Products' AS report_type,
    product_id AS id,
    product_name AS name,
    category AS level,
    order_count,
    total_sales AS spent,
    total_sales / total_quantity AS avg_price,
    RANK() OVER (ORDER BY total_sales DESC) AS rank
FROM product_stats
ORDER BY total_sales DESC
LIMIT 20

UNION ALL

-- 3. 渠道对比分析
SELECT 
    'Channel Analysis' AS report_type,
    channel AS id,
    channel AS name,
    NULL AS level,
    order_count,
    total_sales AS spent,
    avg_order_amount,
    RANK() OVER (ORDER BY total_sales DESC) AS rank
FROM channel_stats

UNION ALL

-- 4. 每日销售趋势（最近7天，含同比）
SELECT 
    'Daily Trends' AS report_type,
    CAST(dt.sale_date AS VARCHAR) AS id,
    dt.channel AS name,
    NULL AS level,
    dt.daily_orders AS order_count,
    dt.daily_sales AS spent,
    -- 同比增长率
    CASE 
        WHEN yoy.last_year_sales IS NOT NULL AND yoy.last_year_sales > 0 
        THEN (dt.daily_sales - yoy.last_year_sales) / yoy.last_year_sales * 100
        ELSE NULL
    END AS yoy_growth,
    -- 7天移动平均
    AVG(dt.daily_sales) OVER (
        PARTITION BY dt.channel 
        ORDER BY dt.sale_date 
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS ma_7days
FROM daily_trends dt
LEFT JOIN yoy_data yoy 
    ON dt.sale_date = yoy.sale_date 
    AND dt.channel = yoy.channel
WHERE dt.sale_date >= CURRENT_DATE - INTERVAL '7' DAY
ORDER BY dt.sale_date DESC, dt.channel;
```
