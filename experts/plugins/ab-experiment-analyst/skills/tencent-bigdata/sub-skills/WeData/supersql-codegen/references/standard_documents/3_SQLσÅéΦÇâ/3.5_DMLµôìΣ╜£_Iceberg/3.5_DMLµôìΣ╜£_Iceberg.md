# 3.5 DML操作 (Iceberg)

本章节介绍 Apache Iceberg 表的数据操作语言（DML）操作，包括数据的插入、更新、删除和合并。

## 概述

Iceberg 使用 Spark 的 DataSourceV2 API 支持完整的 DML 操作。相比传统 Hive 表，Iceberg 提供了原生的行级更新和删除支持。

## 前置要求

- Spark 3.0+ 版本
- 已配置 Iceberg Catalog
- 某些操作需要启用 Iceberg SQL 扩展
- 推荐设置 `spark.sql.storeAssignmentPolicy=ANSI`

## INSERT INTO（追加数据）

### 基本语法

```sql
INSERT INTO [catalog.][db.]table 
[(col1, col2, ...)]
VALUES (val1, val2, ...), (val1, val2, ...)

INSERT INTO [catalog.][db.]table 
[(col1, col2, ...)]
SELECT ...
```

### 示例

```sql
-- 插入字面值
INSERT INTO prod.db.table VALUES (1, 'a'), (2, 'b');

-- 插入查询结果
INSERT INTO prod.db.table 
SELECT * FROM source_table WHERE date = '2024-01-01';

-- 指定列插入
INSERT INTO prod.db.table (id, name, status)
SELECT user_id, user_name, 'active' FROM users;
```

### 注意事项

- 所有插入操作都是原子的
- 支持动态分区写入
- 建议批量插入以提高性能

## MERGE INTO（行级合并）

### 基本语法

```sql
MERGE INTO target_table t
USING source_table s
ON t.key = s.key
WHEN MATCHED [AND condition] THEN 
  UPDATE SET col1 = val1, col2 = val2, ...
WHEN MATCHED [AND condition] THEN 
  DELETE
WHEN NOT MATCHED [AND condition] THEN 
  INSERT (col1, col2, ...) VALUES (val1, val2, ...)
```

### 示例

```sql
-- CDC 场景：插入、更新、删除
MERGE INTO prod.db.target t
USING (SELECT * FROM source) s
ON t.id = s.id
WHEN MATCHED AND s.op = 'delete' THEN DELETE
WHEN MATCHED AND s.op = 'update' THEN 
  UPDATE SET t.count = t.count + s.count, t.updated_at = s.updated_at
WHEN NOT MATCHED AND s.op = 'insert' THEN 
  INSERT (id, count, updated_at) VALUES (s.id, s.count, s.updated_at);

-- 简化版：自动插入或更新
MERGE INTO prod.db.target t
USING source s
ON t.id = s.id
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;
```

### 特点

- 支持多个 MATCHED/NOT MATCHED 子句
- 单次操作完成所有变更
- 原子性保证

## INSERT OVERWRITE（覆盖数据）

### 基本语法

```sql
-- 动态覆盖（推荐）
INSERT OVERWRITE [catalog.][db.]table
SELECT ...

-- 静态分区覆盖
INSERT OVERWRITE TABLE [catalog.][db.]table
PARTITION (partition_col = value)
SELECT ...
```

### 示例

```sql
-- 动态覆盖（仅覆盖涉及的分区）
SET spark.sql.sources.partitionOverwriteMode = dynamic;
INSERT OVERWRITE prod.db.table
SELECT * FROM source_table WHERE date = '2024-01-01';

-- 静态分区覆盖
INSERT OVERWRITE TABLE prod.db.table
PARTITION (date = '2024-01-01')
SELECT id, name FROM source_table;

-- 全表覆盖
SET spark.sql.sources.partitionOverwriteMode = static;
INSERT OVERWRITE prod.db.table
SELECT * FROM source_table;
```

### 覆盖模式对比

| 模式 | 行为 | 使用场景 |
|------|------|---------|
| **dynamic** (推荐) | 仅覆盖查询涉及的分区 | 分区表增量更新 |
| **static** | 覆盖整个表或指定分区 | 全表重建 |

## UPDATE（更新数据）

### 基本语法

```sql
UPDATE [catalog.][db.]table
SET col1 = val1, col2 = val2, ...
WHERE condition
```

### 示例

```sql
-- 简单更新
UPDATE prod.db.table
SET status = 'completed', updated_at = current_timestamp()
WHERE process_date = '2024-01-01';

-- 基于子查询更新
UPDATE prod.db.orders t
SET total_amount = (
    SELECT SUM(amount) FROM order_items 
    WHERE order_id = t.order_id
)
WHERE order_date = '2024-01-01';

-- 条件更新
UPDATE prod.db.table
SET discount = 0.1
WHERE category = 'electronics' AND price > 1000;
```

### 注意事项

- 必须包含 WHERE 子句（避免全表更新）
- 支持复杂的更新表达式
- 更新是原子操作

## DELETE（删除数据）

### 基本语法

```sql
DELETE FROM [catalog.][db.]table
WHERE condition
```

### 示例

```sql
-- 基于条件删除
DELETE FROM prod.db.table
WHERE date < '2024-01-01';

-- 基于子查询删除
DELETE FROM prod.db.orders t
WHERE EXISTS (
    SELECT 1 FROM prod.db.cancelled_orders c 
    WHERE t.order_id = c.order_id
);

-- 基于 JOIN 删除
DELETE FROM prod.db.table
WHERE id IN (SELECT id FROM to_delete_table);
```

### 注意事项

- 必须包含 WHERE 子句
- 删除操作是原子的
- 可使用快照恢复误删数据

## DML 操作对比

| 操作 | 用途 | 原子性 | 性能 | 推荐场景 |
|------|------|--------|------|---------|
| INSERT INTO | 追加数据 | ✅ | 高 | 增量数据加载 |
| MERGE INTO | 行级合并 | ✅ | 中 | CDC、增量更新 |
| INSERT OVERWRITE | 覆盖数据 | ✅ | 中 | 分区重建 |
| UPDATE | 更新记录 | ✅ | 中 | 批量修改 |
| DELETE | 删除记录 | ✅ | 中 | 数据清理 |

## Iceberg 写入特性

### 1. Copy-on-Write vs Merge-on-Read

**Copy-on-Write (默认)**
- 更新/删除时重写整个数据文件
- 读取性能最优
- 写入性能较低
- 适合读多写少场景

```sql
ALTER TABLE prod.db.table SET TBLPROPERTIES (
    'write.update.mode' = 'copy-on-write',
    'write.delete.mode' = 'copy-on-write'
);
```

**Merge-on-Read**
- 更新/删除时写入 delete 文件
- 写入性能最优
- 读取需要合并数据
- 适合写多读少场景

```sql
ALTER TABLE prod.db.table SET TBLPROPERTIES (
    'write.update.mode' = 'merge-on-read',
    'write.delete.mode' = 'merge-on-read'
);
```

### 2. Distribution Mode（分布模式）

| 模式 | 说明 | 使用场景 |
|------|------|---------|
| **none** | 不重分布 | 数据已按分区排序 |
| **hash** (默认) | 按分区值哈希分布 | 通用场景 |
| **range** | 按范围排序分布 | 有排序要求的表 |

```sql
ALTER TABLE prod.db.table SET TBLPROPERTIES (
    'write.distribution-mode' = 'hash'
);
```

### 3. 文件大小控制

```sql
ALTER TABLE prod.db.table SET TBLPROPERTIES (
    'write.target-file-size-bytes' = '536870912'  -- 512MB
);
```

### 4. Schema Evolution

允许写入时自动添加新列：

```sql
ALTER TABLE prod.db.table SET TBLPROPERTIES (
    'write.spark.accept-any-schema' = 'true'
);
```

## DataFrame 写入 API

### Append 模式

```scala
df.writeTo("prod.db.table")
  .append()

// 或
df.write
  .format("iceberg")
  .mode("append")
  .save("prod.db.table")
```

### Overwrite 模式

```scala
// 动态覆盖
df.writeTo("prod.db.table")
  .overwritePartitions()

// 全表覆盖
df.writeTo("prod.db.table")
  .overwrite(lit(true))
```

### 写入到分支

```scala
// WAP 模式
df.writeTo("prod.db.table")
  .option("branch", "audit-branch")
  .append()
```

## 写入性能优化

### 1. 批量写入

```sql
-- ✅ 推荐：批量插入
INSERT INTO prod.db.table
SELECT * FROM source_table;

-- ❌ 避免：逐条插入
INSERT INTO prod.db.table VALUES (1, 'a');
INSERT INTO prod.db.table VALUES (2, 'b');
```

### 2. 使用 MERGE INTO 代替多次操作

```sql
-- ✅ 推荐：单次 MERGE
MERGE INTO target t
USING source s
ON t.id = s.id
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;

-- ❌ 避免：UPDATE + INSERT
UPDATE target t SET ... WHERE EXISTS (...);
INSERT INTO target SELECT * FROM source WHERE NOT EXISTS (...);
```

### 3. 控制文件数量

```sql
-- 通过 repartition 控制文件数
INSERT INTO prod.db.table
SELECT /*+ REPARTITION(10) */ * FROM source_table;

-- 按分区值分布
INSERT INTO prod.db.table
SELECT /*+ REPARTITION_BY_RANGE(date) */ * FROM source_table;
```

## 与传统 Hive 表的区别

| 特性 | Hive 表 | Iceberg 表 |
|------|---------|-----------|
| INSERT INTO | 支持 | 支持 |
| INSERT OVERWRITE | 支持 | 支持（推荐动态模式）|
| UPDATE | 需要 ACID 表 | 原生支持 |
| DELETE | 需要 ACID 表 | 原生支持 |
| MERGE INTO | 不支持 | 支持 |
| 行级操作性能 | 低 | 高 |
| 并发写入 | 有限 | 完全支持 |
| 事务保证 | 有限 | 完整 ACID |

## 最佳实践

1. **使用 MERGE INTO 处理 CDC**
   - 单次操作完成插入、更新、删除
   - 性能优于分别执行

2. **动态分区覆盖**
   - 避免误删除其他分区
   - 设置 `spark.sql.sources.partitionOverwriteMode=dynamic`

3. **控制文件大小**
   - 避免小文件过多
   - 使用 repartition 或设置 target-file-size

4. **选择合适的写入模式**
   - 读多写少：Copy-on-Write
   - 写多读少：Merge-on-Read

5. **定期维护**
   - 运行 REWRITE DATA FILES 优化小文件
   - 运行 EXPIRE SNAPSHOTS 清理旧快照
