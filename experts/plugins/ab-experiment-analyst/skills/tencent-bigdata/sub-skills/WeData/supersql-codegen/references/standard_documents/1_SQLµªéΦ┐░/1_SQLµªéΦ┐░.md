## 简介

天穹 SQL（基于 TDW Hive/SuperSQL）是天穹大数据计算平台中用于数据查询和分析的 SQL 语言。其语法基于 Hive SQL，并在此基础上进行了扩展和优化，以更好地服务于腾讯内部大规模数据仓库的场景。

天穹 SQL 支持两种主要引擎：
- **TDW Hive（Thive）**：兼容 Hive SQL 语法，适用于离线批量计算
- **SuperSQL**：跨源查询引擎，支持多种数据源的统一查询

## 应用场景

天穹 SQL 适用于以下场景：

### 1. 海量数据离线批量计算
适用于 GB、TB、PB 级别的海量数据处理。提交作业后，会经过调度排队（通常几十秒到数分钟），因此适合处理批作业，一次提交批量处理大量数据。

**不适合的场景**：
- 需要每秒处理几千至数万笔事务的在线业务系统
- 需要毫秒级响应的实时查询场景

### 2. 跨源数据查询（SuperSQL）
SuperSQL 支持跨多种数据源进行统一查询，包括：
- TDW Hive 表
- PostgreSQL 外表
- 其他异构数据源

## 天穹特色功能

### 1. 跨数据库引用
天穹支持使用 `db::table` 的形式跨数据库引用表：
```sql
-- 查询其他数据库的表
SELECT * FROM other_db::user_table;

-- 跨数据库 JOIN
SELECT a.*, b.* 
FROM db1::table1 a 
JOIN db2::table2 b ON a.id = b.id;
```

### 2. 丰富的分区类型
支持多种分区类型：
- **RANGE 分区**：按范围分区
- **LIST 分区**：按列表值分区  
- **HASHKEY 分区**：按哈希分区
- **子分区**：支持二级分区

### 3. 多种存储格式
- **TextFile**：文本格式
- **RCFile**：行列混合格式
- **ORCFile**：优化的行列格式（推荐）
- **ColumnFile**：列式存储格式

### 4. 压缩支持
支持多种压缩格式：
- ZLIB（默认）
- SNAPPY
- ZSTD（推荐，压缩比和性能平衡）
- LZO

## 最佳实践建议

1. **数据类型选择**
   - 整型优先使用 `BIGINT`
   - 浮点型优先使用 `DOUBLE`
   - 避免隐式类型转换带来的性能问题

2. **存储格式选择**
   - 新建表优先使用 **ORC 格式** + **ZSTD 压缩**
   - 避免使用 `FORMATFILE`（已过时，性能差）

3. **分区设计**
   - 合理设计分区，避免小文件过多
   - 分区字段选择查询频繁的字段

4. **SQL 优化**
   - 避免使用 `SELECT *`，明确指定需要的字段
   - 合理使用分区裁剪
   - 大表 JOIN 时，小表放在 JOIN 的右侧

## 常见问题

### Q: 天穹 SQL 与 Hive SQL 的主要区别是什么？
A: 天穹 SQL 基于 Hive SQL，但增加了跨数据库引用（`db::table`）、更丰富的分区类型、以及腾讯内部优化的函数和特性。

### Q: 如何选择使用 Thive 还是 SuperSQL？
A: 
- 如果只查询 TDW 内部表，使用 **Thive**（性能更好）
- 如果需要跨多种数据源查询，使用 **SuperSQL**

### Q: 为什么我的查询很慢？
A: 可能的原因：
1. 没有使用分区裁剪
2. 数据倾斜
3. 小文件过多
4. JOIN 顺序不合理
