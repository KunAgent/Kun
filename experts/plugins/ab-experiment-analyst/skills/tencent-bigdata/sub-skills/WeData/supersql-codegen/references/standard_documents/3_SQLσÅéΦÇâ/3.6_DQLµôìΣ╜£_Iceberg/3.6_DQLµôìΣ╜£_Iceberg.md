# 3.6 DQL操作 (Iceberg)

本章节介绍 Apache Iceberg 表的数据查询语言（DQL）操作，包括标准查询、时间旅行、元数据查询等高级特性。

## 概述

Iceberg 在 Spark 中使用 DataSourceV2 API 提供强大的查询功能。除了标准 SQL 查询外，Iceberg 还支持时间旅行、增量读取和丰富的元数据查询。

## 前置要求

- Spark 3.0+ 版本
- 已配置 Iceberg Catalog
- 某些功能需要启用 Iceberg SQL 扩展

## 基本查询

### 标准查询

```sql
-- 简单查询
SELECT * FROM prod.db.table WHERE date = '2024-01-01';

-- 使用三段式表名
SELECT * FROM catalog.db.table;

-- 跨 Catalog 查询
SELECT t1.*, t2.*
FROM prod.db.table1 t1
JOIN staging.db.table2 t2 ON t1.id = t2.id;

-- 聚合查询
SELECT date, COUNT(*), SUM(amount)
FROM prod.db.orders
GROUP BY date
HAVING SUM(amount) > 10000;
```

### 表标识符

Iceberg 支持多种表标识符格式：

```sql
-- 1. 完整三段式
SELECT * FROM catalog.db.table;

-- 2. 两段式（使用当前 catalog）
SELECT * FROM db.table;

-- 3. 单段式（使用当前 catalog 和 db）
SELECT * FROM table;

-- 4. 路径表
SELECT * FROM `hdfs://namenode:8020/warehouse/db/table`;

-- 5. 分支表
SELECT * FROM prod.db.table.branch_audit;

-- 6. 标签表
SELECT * FROM prod.db.table.tag_v1_0_0;

-- 7. 元数据表
SELECT * FROM prod.db.table.snapshots;
```

## 时间旅行查询

Iceberg 支持查询历史数据，用于数据审计、恢复和对比。

### 按时间戳查询

```sql
-- TIMESTAMP AS OF（Spark 3.3+）
SELECT * FROM prod.db.table 
TIMESTAMP AS OF '2024-01-01 10:00:00';

-- FOR SYSTEM_TIME AS OF（标准 SQL）
SELECT * FROM prod.db.table 
FOR SYSTEM_TIME AS OF '2024-01-01';

-- 使用时间戳表达式
SELECT * FROM prod.db.table
TIMESTAMP AS OF current_timestamp() - INTERVAL 1 DAY;
```

### 按快照 ID 查询

```sql
-- VERSION AS OF
SELECT * FROM prod.db.table 
VERSION AS OF 1234567890;

-- FOR SYSTEM_VERSION AS OF
SELECT * FROM prod.db.table 
FOR SYSTEM_VERSION AS OF 1234567890;
```

### 按分支/标签查询

```sql
-- 查询分支
SELECT * FROM prod.db.table 
VERSION AS OF 'audit-branch';

-- 或使用分支表语法
SELECT * FROM prod.db.table.branch_audit;

-- 查询标签
SELECT * FROM prod.db.table.tag_v1_0_0;
```

### 时间旅行示例

```sql
-- 对比今天和昨天的数据
SELECT 
    COUNT(*) as today_count
FROM prod.db.table;

SELECT 
    COUNT(*) as yesterday_count
FROM prod.db.table
TIMESTAMP AS OF current_timestamp() - INTERVAL 1 DAY;

-- 查看数据变化
SELECT 
    current.id,
    current.amount - historical.amount as amount_change
FROM prod.db.table current
JOIN prod.db.table TIMESTAMP AS OF '2024-01-01' historical
  ON current.id = historical.id
WHERE current.amount != historical.amount;
```

## 元数据表查询

Iceberg 提供丰富的元数据表用于查看表的内部信息。

### 元数据表类型

| 元数据表 | 说明 |
|---------|------|
| `history` | 表的提交历史 |
| `snapshots` | 所有快照信息 |
| `files` | 当前数据文件和删除文件 |
| `data_files` | 仅数据文件 |
| `delete_files` | 仅删除文件 |
| `manifests` | 清单文件信息 |
| `partitions` | 分区统计信息 |
| `refs` | 分支和标签引用 |
| `entries` | 清单条目 |

### 查看表历史

```sql
SELECT 
    made_current_at,
    snapshot_id,
    parent_id,
    is_current_ancestor
FROM prod.db.table.history
ORDER BY made_current_at DESC
LIMIT 10;
```

### 查看快照详情

```sql
SELECT 
    committed_at,
    snapshot_id,
    parent_id,
    operation,
    manifest_list,
    summary
FROM prod.db.table.snapshots
ORDER BY committed_at DESC;
```

### 分析数据文件

```sql
-- 查看文件大小分布
SELECT 
    file_format,
    COUNT(*) as file_count,
    SUM(file_size_in_bytes) / 1024 / 1024 / 1024 as total_size_gb,
    AVG(file_size_in_bytes) / 1024 / 1024 as avg_size_mb
FROM prod.db.table.files
GROUP BY file_format;

-- 查看小文件
SELECT 
    file_path,
    file_size_in_bytes / 1024 / 1024 as size_mb,
    record_count
FROM prod.db.table.files
WHERE file_size_in_bytes < 10485760  -- 小于 10MB
ORDER BY file_size_in_bytes;
```

### 查看分区统计

```sql
-- 查看每个分区的记录数和文件数
SELECT 
    partition,
    record_count,
    file_count,
    total_data_file_size_in_bytes / 1024 / 1024 as size_mb
FROM prod.db.table.partitions
WHERE record_count > 0
ORDER BY size_mb DESC
LIMIT 20;
```

### 查看分支和标签

```sql
SELECT 
    name,
    type,
    snapshot_id,
    max_reference_age_in_ms
FROM prod.db.table.refs;
```

## 增量读取

使用 DataFrame API 读取两个快照之间的增量数据。

```scala
// 读取快照 A 到快照 B 之间的新增数据
val incrementalDF = spark.read
  .format("iceberg")
  .option("start-snapshot-id", "1234567890")
  .option("end-snapshot-id", "1234567899")
  .load("prod.db.table")

// 从指定快照到最新快照
val incrementalDF = spark.read
  .format("iceberg")
  .option("start-snapshot-id", "1234567890")
  .load("prod.db.table")
```

**注意事项**：
- 仅支持 append 操作的增量
- 不支持 delete/update 的增量
- 适合流式增量处理场景

## Iceberg 查询特性

### 1. 隐藏分区（Hidden Partitioning）

无需在查询中显式指定分区列：

```sql
-- 传统 Hive 表
SELECT * FROM hive_table 
WHERE dt = '2024-01-01' AND hour = '10';

-- Iceberg 表（自动分区裁剪）
SELECT * FROM iceberg_table 
WHERE event_time >= '2024-01-01 10:00:00'
  AND event_time < '2024-01-01 11:00:00';
```

### 2. Schema Evolution

查询自动适配 Schema 变化：

```sql
-- 表添加了新列 'new_col'
-- 查询旧数据时，new_col 显示为 NULL
SELECT id, name, new_col 
FROM prod.db.table
TIMESTAMP AS OF '2024-01-01';  -- new_col 之前的数据
```

### 3. 快照隔离读取

每个查询看到一致的快照：

```sql
-- 查询 A 和查询 B 看到相同的数据（即使期间有写入）
SELECT count(*) FROM prod.db.table;  -- 假设返回 1000

-- 此时有写入操作
INSERT INTO prod.db.table VALUES (...);

-- 查询 B（同一会话）
SELECT count(*) FROM prod.db.table;  -- 仍返回 1000（快照隔离）
```

## 查询性能优化

### 1. 分区裁剪

Iceberg 自动进行分区裁剪：

```sql
-- 自动裁剪到 2024-01-01 的分区
SELECT * FROM prod.db.table
WHERE event_time >= '2024-01-01 00:00:00'
  AND event_time < '2024-01-02 00:00:00';
```

### 2. 列裁剪

只读取需要的列：

```sql
-- ✅ 推荐：只选择需要的列
SELECT id, name, status FROM prod.db.table;

-- ❌ 避免：SELECT *
SELECT * FROM prod.db.table;
```

### 3. 谓词下推

将过滤条件下推到存储层：

```sql
-- 过滤条件自动下推
SELECT * FROM prod.db.table
WHERE status = 'active' AND amount > 100;
```

### 4. 文件级统计

利用文件级统计信息跳过不相关文件：

```sql
-- min/max 统计自动应用
SELECT * FROM prod.db.table
WHERE id BETWEEN 1000 AND 2000;
```

### 5. Bloom Filter

使用 Bloom Filter 加速查询（Iceberg 0.13+）：

```sql
-- 启用 Bloom Filter
ALTER TABLE prod.db.table SET TBLPROPERTIES (
    'write.bloom-filter-enabled.column.user_id' = 'true',
    'write.bloom-filter-max-bytes' = '1048576'
);

-- 查询自动使用 Bloom Filter
SELECT * FROM prod.db.table WHERE user_id = 12345;
```

## DataFrame API 查询

### 基本读取

```scala
// 读取 Iceberg 表
val df = spark.table("prod.db.table")

// 或使用 read API
val df = spark.read
  .format("iceberg")
  .load("prod.db.table")
```

### 时间旅行

```scala
// 按时间戳
val df = spark.read
  .option("as-of-timestamp", "1609459200000")  // 毫秒时间戳
  .format("iceberg")
  .load("prod.db.table")

// 按快照 ID
val df = spark.read
  .option("snapshot-id", "1234567890")
  .format("iceberg")
  .load("prod.db.table")

// 按分支
val df = spark.read
  .option("branch", "audit-branch")
  .format("iceberg")
  .load("prod.db.table")
```

### 读取元数据表

```scala
val historyDF = spark.read
  .format("iceberg")
  .load("prod.db.table.history")

val snapshotsDF = spark.read
  .format("iceberg")
  .load("prod.db.table.snapshots")
```

## 常见查询模式

### 数据对比

```sql
-- 对比两个快照的差异
SELECT 'current' as version, COUNT(*) as cnt FROM prod.db.table
UNION ALL
SELECT 'previous' as version, COUNT(*) as cnt 
FROM prod.db.table VERSION AS OF 123456;
```

### 数据审计

```sql
-- 查看昨天的数据
SELECT * FROM prod.db.table
TIMESTAMP AS OF current_timestamp() - INTERVAL 1 DAY
WHERE user_id = 12345;
```

### 回滚验证

```sql
-- 验证回滚前的数据
SELECT * FROM prod.db.table.tag_before_rollback
WHERE critical_field IS NULL;
```

## 与传统 Hive 表的区别

| 特性 | Hive 表 | Iceberg 表 |
|------|---------|-----------|
| 隐藏分区 | 不支持 | 支持 |
| 时间旅行 | 不支持 | 支持 |
| Schema Evolution | 有限 | 完全支持 |
| 快照隔离 | 否 | 是 |
| 元数据查询 | 有限 | 丰富 |
| 增量读取 | 需要手动实现 | 原生支持 |
| 文件级统计 | 有限 | 完整 |

## 最佳实践

1. **使用列裁剪**
   - 避免 `SELECT *`
   - 只查询需要的列

2. **利用分区裁剪**
   - 在 WHERE 子句中使用分区列
   - Iceberg 自动处理隐藏分区

3. **使用时间旅行进行审计**
   - 查看历史数据
   - 对比不同时间点的数据

4. **监控查询性能**
   - 查看元数据表了解文件分布
   - 定期运行维护命令优化性能

5. **增量处理**
   - 使用增量读取处理新数据
   - 避免全表扫描

## 性能注意事项

1. **元数据表查询可能较慢**
   - `all_*` 表需要扫描所有历史元数据
   - 使用 WHERE 子句过滤

2. **时间旅行的 Schema 差异**
   - 历史查询使用历史 Schema
   - 注意新增/删除的列

3. **增量读取的限制**
   - 仅支持 append 操作
   - 不支持 delete/update 的增量
