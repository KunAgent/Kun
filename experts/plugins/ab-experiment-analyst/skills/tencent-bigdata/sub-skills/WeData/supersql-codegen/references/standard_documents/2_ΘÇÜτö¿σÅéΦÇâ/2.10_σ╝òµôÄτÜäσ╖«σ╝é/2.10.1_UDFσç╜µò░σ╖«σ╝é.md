# 2.10.1 UDF函数差异

## 函数支持概览

SuperSQL支持三类UDF函数，不同引擎的支持情况如下：

| 函数类别 | 函数数量 | THive | Spark 3.3 | StarRocks | 主要特点 |
|---------|---------|-------|-----------|-----------|----------|
| **4.1.2 TDW扩展函数** | 66个 | ✅ | ✅ | ⚠️ | Oracle兼容、腾讯业务特有、加密函数 |
| **4.1.4 HIVE内置函数** | 164个 | ✅ | ✅ | ⚠️ | 标准Hive函数库，最全面的基础函数 |
| **4.1.6 Spark3.3函数** | 71个 | ❌ | ✅ | ⚠️ | Spark 3.3特有，现代化数据处理 |
| **总计** | **301个** | 230个 | 301个 | 部分 | - |

**说明**：
- ✅ 完全支持
- ⚠️ 部分支持，需要在透传模式下使用
- ❌ 不支持

---

## 引擎特有函数分类

### 1. TDW扩展函数（66个）

**特色功能**：
- **Oracle兼容**（14个）：`NVL`, `NVL2`, `DECODE`, `TO_NUMBER`, `TO_CHAR`, `TO_DATE`等
- **加密与哈希**（13个）：`md5`, `AesEncryption`, `AesDecryption`, `rc4`, `base64`, `hash`等
- **腾讯业务**（3个）：`parse_qqfriend_flag`, `gbk2utf8`, `geohash_encode`
- **网络函数**（2个）：`get_main_domain`, `ipchange`
- **XML解析**（2个）：`parse_xml_count`, `parse_xml`

**引擎支持**：
- THive: ✅ 完全支持
- Spark 3.3: ✅ 完全支持（通过UDF注册）
- StarRocks: ❌ 不支持，仅透传模式

**详细说明**：

参考文档：[4.1.2 TDW扩展函数](../../4_函数参考/4.1_UDF函数/4.1.2_TDW扩展函数/4.1.2_TDW扩展函数.md)

---

### 2. HIVE内置函数（164个）

**核心分类**：
- **数学函数**（50个）：基础数学、三角函数、对数、进制转换、SM4加密
- **字符串函数**（47个）：正则表达式、URL/JSON解析、编码转换、字符串分析
- **时间函数**（23个）：时间戳转换、日期运算、时区处理
- **聚合函数**（21个）：基础聚合、统计分析、集合操作
- **IP函数**（15个）：IPv4/IPv6转换、IP信息查询、地址段判断
- **条件函数**（7个）：`IF`, `CASE`, `COALESCE`, `NULLIF`等
- **类型转换**（1个）：`CAST`

**引擎支持**：
- THive: ✅ 完全支持（原生函数）
- Spark 3.3: ✅ 完全支持
- StarRocks: ⚠️ 部分支持（见兼容性表）

**详细说明**：

参考文档：[4.1.4 HIVE内置函数](../../4_函数参考/4.1_UDF函数/4.1.4_HIVE内置函数/4.1.4_HIVE内置函数.md)

---

### 3. Spark3.3函数（71个）

**现代化特性**：
- **JSON/CSV处理**（9个）：`from_json`, `to_json`, `from_csv`, `to_csv`, `schema_of_json`等
- **XML函数**（9个）：完整的`xpath`系列函数
- **高级数学**（12个）：双曲函数（`acosh`, `asinh`, `atanh`）、`hypot`, `cot`等
- **聚合增强**（11个）：`max_by`, `min_by`, `bool_and`, `bool_or`, `every`等
- **元数据查询**（9个）：`input_file_name`, `spark_partition_id`, `uuid`等
- **数组/Map增强**（4个）：`arrays_zip`, `array_join`, `map_from_arrays`, `map_concat`

**引擎支持**：
- THive: ❌ 不支持
- Spark 3.3: ✅ 完全支持（原生函数）
- StarRocks: ❌ 不支持，需透传模式

**详细说明**：

参考文档：[4.1.6 Spark3.3函数](../../4_函数参考/4.1_UDF函数/4.1.6_Spark3.3函数/4.1.6_Spark3.3函数.md)

## 引擎差异总结

### THive引擎

**支持的函数**：
- TDW扩展函数：66个 ✅
- HIVE内置函数：164个 ✅
- Spark3.3函数：0个 ❌
- **总计**：230个函数

**特点**：
- 标准Hive兼容
- 完整支持TDW扩展函数
- 不支持Spark 3.3特有函数

### Spark 3.3引擎

**支持的函数**：
- TDW扩展函数：66个 ✅
- HIVE内置函数：164个 ✅
- Spark3.3函数：71个 ✅
- **总计**：301个函数（全部）

**特点**：
- 最完整的函数支持
- 支持所有THive函数
- 支持Spark社区特有的现代化函数
- **推荐作为首选引擎**

### StarRocks引擎

**支持的函数**：
- 部分HIVE内置函数 ⚠️
- 不支持TDW扩展函数 ❌
- 不支持Spark3.3函数 ❌

**特点**：
- 对TIMESTAMP类型支持有限
- 部分函数需要透传模式
- 适合OLAP场景但函数兼容性较差

### Presto引擎

**支持的函数**：
- 部分HIVE内置函数 ⚠️
- 不支持TDW扩展函数 ❌
- 不支持Spark3.3函数 ❌

**特点**：
- 函数兼容性与StarRocks类似
- 有自己的函数体系
- 需要注意兼容性问题

## 使用建议

### 1. 函数选择建议

```sql
-- ✅ 推荐：优先使用HIVE内置函数（兼容性最好）
SELECT CONCAT(first_name, ' ', last_name) FROM users;

-- ⚠️ 注意：使用TDW扩展函数时，确认目标引擎为THive或Spark
SELECT NVL(nullable_col, 'default') FROM table1;

-- ⚠️ 注意：使用Spark3.3函数时，必须使用Spark引擎
SELECT from_json(json_col, 'name STRING, age INT') FROM table2;
```

### 2. 跨引擎兼容性

```sql
-- 场景1：需要在所有引擎运行
-- 使用HIVE内置函数
SELECT 
    CAST(col1 AS INT),
    CONCAT(col2, col3),
    DATE_ADD(date_col, 7)
FROM table1;

-- 场景2：Oracle用户迁移（THive/Spark）
-- 可以使用TDW扩展函数
SELECT 
    NVL(col1, 0),
    DECODE(status, 1, 'active', 0, 'inactive', 'unknown'),
    TO_CHAR(date_col, 'YYYY-MM-DD')
FROM table2;

-- 场景3：需要Spark特有功能
-- 使用Spark3.3函数，指定Spark引擎
SELECT 
    from_json(json_col, schema_of_json('[{"id":1}]')),
    arrays_zip(array1, array2),
    max_by(value, timestamp)
FROM table3;
```

### 3. 函数不支持的解决方案

```sql
-- 问题：StarRocks不支持from_utc_timestamp
-- 解决：使用标准的CAST和时区转换
-- THive/Spark写法
SELECT from_utc_timestamp(timestamp_col, 'Asia/Shanghai') FROM table1;

-- StarRocks兼容写法
SELECT timestamp_col + INTERVAL 8 HOUR FROM table1;  -- 假设UTC+8

-- 问题：StarRocks不支持NVL
-- 解决：使用COALESCE（所有引擎都支持）
-- TDW写法
SELECT NVL(col1, 'default') FROM table1;

-- 通用写法
SELECT COALESCE(col1, 'default') FROM table1;
```
