# SQL注释

## 概述

SQL 注释用于在代码中添加说明文字，帮助开发者理解 SQL 语句的逻辑和意图。天穹 SQL 支持多种注释语法，包括单行注释、多行注释和 Hint 注释。

## 注释类型

### 单行注释

使用 `--` 或 `#` 开头，注释内容从符号开始到行尾结束。

#### 语法

```sql
-- 这是单行注释
# 这也是单行注释
```

#### 示例

```sql
-- 查询活跃用户数量
SELECT COUNT(*) FROM users WHERE status = 'active';

# 按日期分区过滤
SELECT * FROM orders WHERE dt = '20240115'; -- 只查询当天数据

-- 多个单行注释
-- 作者：张三
-- 日期：2024-01-15
-- 说明：统计每日订单量
SELECT 
    dt,                    -- 日期
    COUNT(*) AS order_count -- 订单数量
FROM orders
GROUP BY dt;
```

### 多行注释

使用 `/* ... */` 包裹注释内容，可以跨越多行。

#### 语法

```sql
/* 这是多行注释 */

/*
 * 这是多行注释
 * 可以写多行
 */
```

#### 示例

```sql
/*
 * 功能：用户行为分析查询
 * 作者：张三
 * 日期：2024-01-15
 * 说明：
 *   1. 统计每日活跃用户数
 *   2. 计算用户留存率
 *   3. 分析用户行为路径
 */
SELECT 
    date,
    COUNT(DISTINCT user_id) AS dau,
    /* 计算次日留存 */
    COUNT(DISTINCT CASE WHEN next_day_active THEN user_id END) AS retained_users
FROM user_activity
WHERE dt = '20240115'
GROUP BY date;

/* 
   临时禁用的代码
   SELECT * FROM old_table;
*/

SELECT * FROM new_table; /* 使用新表 */
```

### Hint 注释

Hint 是特殊的注释，用于向优化器提供执行建议，格式为 `/*+ hint_content */`。

#### 语法

```sql
/*+ hint_name(parameters) */
```

#### 常用 Hint

| Hint | 说明 | 示例 |
|------|------|------|
| `MAPJOIN` | 强制使用 MapJoin | `/*+ MAPJOIN(small_table) */` |
| `STREAMJOIN` | 使用 StreamJoin | `/*+ STREAMJOIN(large_table) */` |
| `BROADCAST` | 广播小表 | `/*+ BROADCAST(dim_table) */` |
| `SKEWJOIN` | 处理数据倾斜 | `/*+ SKEWJOIN(skewed_table) */` |
| `NO_INDEX` | 禁用索引 | `/*+ NO_INDEX(table_name) */` |

#### Hint 示例

```sql
-- MapJoin Hint
SELECT /*+ MAPJOIN(b) */
    a.user_id,
    a.order_amount,
    b.user_name
FROM orders a
JOIN users b ON a.user_id = b.user_id;

-- 多个 Hint
SELECT /*+ MAPJOIN(b) BROADCAST(c) */
    a.order_id,
    b.user_name,
    c.product_name
FROM orders a
JOIN users b ON a.user_id = b.user_id
JOIN products c ON a.product_id = c.product_id;

-- 处理数据倾斜
SELECT /*+ SKEWJOIN(orders) */
    category,
    COUNT(*) AS order_count
FROM orders
GROUP BY category;
```

## 注释位置

### 语句级注释

在 SQL 语句前添加注释说明整个查询的目的。

```sql
-- 统计每日新增用户数
-- 业务需求：运营报表
-- 更新频率：每日
SELECT 
    dt,
    COUNT(DISTINCT user_id) AS new_users
FROM user_registration
WHERE dt = '20240115'
GROUP BY dt;
```

### 子句注释

在特定子句旁添加注释说明该部分逻辑。

```sql
SELECT 
    user_id,
    user_name,
    order_count,
    total_amount
FROM users
WHERE status = 'active'          -- 只统计活跃用户
  AND register_date >= '2024-01-01' -- 2024年注册的用户
ORDER BY total_amount DESC        -- 按消费金额降序
LIMIT 100;                        -- 取前100名
```

### 列注释

在列定义或选择列表中添加注释。

```sql
SELECT 
    user_id,                      -- 用户ID
    user_name,                    -- 用户名
    register_date,                -- 注册日期
    last_login_time,              -- 最后登录时间
    order_count,                  -- 订单数量
    total_amount,                 -- 总消费金额
    CASE 
        WHEN total_amount > 10000 THEN 'VIP'
        WHEN total_amount > 1000 THEN 'Gold'
        ELSE 'Normal'
    END AS user_level             -- 用户等级
FROM users;
```

### 表注释

在 CREATE TABLE 时为表和列添加注释。

```sql
-- 创建用户表
CREATE TABLE users (
    user_id BIGINT COMMENT '用户ID，主键',
    user_name STRING COMMENT '用户名',
    email STRING COMMENT '邮箱地址',
    phone STRING COMMENT '手机号',
    register_date DATE COMMENT '注册日期',
    status STRING COMMENT '用户状态：active-活跃, inactive-不活跃, deleted-已删除'
)
COMMENT '用户基础信息表'
PARTITIONED BY (dt STRING COMMENT '数据日期，格式：yyyyMMdd')
STORED AS ORC;
```

### 复杂逻辑注释

在复杂的 SQL 逻辑中添加详细注释。

```sql
/*
 * 复杂用户价值计算逻辑
 * 
 * 计算公式：
 * 用户价值 = (订单金额 * 0.5) + (订单数量 * 10) + (登录天数 * 2)
 * 
 * 分级标准：
 * - 高价值：score >= 1000
 * - 中价值：500 <= score < 1000
 * - 低价值：score < 500
 */
SELECT 
    user_id,
    user_name,
    -- 第一步：计算各项得分
    order_amount,
    order_count,
    active_days,
    -- 第二步：加权计算总分
    (order_amount * 0.5 + order_count * 10 + active_days * 2) AS user_score,
    -- 第三步：根据得分分级
    CASE 
        WHEN (order_amount * 0.5 + order_count * 10 + active_days * 2) >= 1000 
            THEN '高价值'
        WHEN (order_amount * 0.5 + order_count * 10 + active_days * 2) >= 500 
            THEN '中价值'
        ELSE '低价值'
    END AS user_value_level
FROM (
    -- 第零步：汇总用户数据
    SELECT 
        u.user_id,
        u.user_name,
        COALESCE(SUM(o.amount), 0) AS order_amount,      -- 订单总金额
        COALESCE(COUNT(o.order_id), 0) AS order_count,   -- 订单总数
        COALESCE(COUNT(DISTINCT l.dt), 0) AS active_days -- 活跃天数
    FROM users u
    LEFT JOIN orders o ON u.user_id = o.user_id
    LEFT JOIN login_log l ON u.user_id = l.user_id
    GROUP BY u.user_id, u.user_name
) user_summary;
```

## 注释最佳实践

### 1. 注释应说明"为什么"而非"是什么"

```sql
-- ❌ 不好的注释：重复代码内容
SELECT COUNT(*) FROM users; -- 统计用户数量

-- ✅ 好的注释：说明业务原因
SELECT COUNT(*) FROM users; -- 用于每日运营报表，需要统计总注册用户数
```

### 2. 为复杂逻辑添加注释

```sql
-- ✅ 复杂 CASE 表达式添加注释
SELECT 
    order_id,
    CASE 
        -- 大额订单（>10000）享受最高折扣
        WHEN amount > 10000 THEN amount * 0.8
        -- 中额订单（1000-10000）享受标准折扣
        WHEN amount > 1000 THEN amount * 0.9
        -- 小额订单不打折
        ELSE amount
    END AS final_amount
FROM orders;
```

### 3. 为临时方案添加注释

```sql
-- TODO: 临时方案，等待维度表上线后改用 JOIN
-- 当前通过硬编码维护映射关系
SELECT 
    order_id,
    CASE city_code
        WHEN '110000' THEN '北京'
        WHEN '310000' THEN '上海'
        WHEN '440100' THEN '广州'
        ELSE '其他'
    END AS city_name
FROM orders;
```

### 4. 标记废弃或需要修改的代码

```sql
-- DEPRECATED: 此查询逻辑已过时，请使用 v2 版本
-- SELECT * FROM old_user_table;

-- 新版本查询
SELECT * FROM user_table_v2;

-- FIXME: 此处 JOIN 条件可能导致数据重复，需要优化
SELECT a.*, b.*
FROM table_a a
JOIN table_b b ON a.id = b.id;
```

### 5. 记录性能优化点

```sql
-- PERFORMANCE: 此查询已优化，使用 MapJoin 避免 Shuffle
SELECT /*+ MAPJOIN(dim_table) */
    fact.order_id,
    dim.product_name
FROM fact_orders fact
JOIN dim_products dim ON fact.product_id = dim.product_id;

-- NOTE: 分区过滤极大提升性能，请务必保留
WHERE fact.dt = '20240115';
```

### 6. 团队协作注释

```sql
/*
 * 查询说明
 * 作者：张三
 * 创建日期：2024-01-15
 * 最后修改：李四 (2024-01-20)
 * 
 * 修改记录：
 * - 2024-01-20: 增加用户等级过滤条件 (李四)
 * - 2024-01-18: 优化 JOIN 顺序 (王五)
 * 
 * 依赖表：
 * - users: 用户基础表
 * - orders: 订单明细表
 * - products: 商品信息表
 * 
 * 产出表：
 * - user_order_summary: 用户订单汇总表
 */
INSERT OVERWRITE TABLE user_order_summary PARTITION(dt='20240115')
SELECT 
    u.user_id,
    u.user_name,
    COUNT(o.order_id) AS order_count,
    SUM(o.amount) AS total_amount
FROM users u
LEFT JOIN orders o ON u.user_id = o.user_id
WHERE o.dt = '20240115'
  AND u.user_level IN ('VIP', 'Gold') -- 只统计高价值用户
GROUP BY u.user_id, u.user_name;
```

## 注释规范

### 命名约定

使用标准标签标识特殊注释：

| 标签 | 说明 | 示例 |
|------|------|------|
| `TODO` | 待办事项 | `-- TODO: 添加异常处理逻辑` |
| `FIXME` | 需要修复的问题 | `-- FIXME: 此处可能导致性能问题` |
| `HACK` | 临时解决方案 | `-- HACK: 临时绕过系统限制` |
| `NOTE` | 重要说明 | `-- NOTE: 此字段不能为空` |
| `WARNING` | 警告信息 | `-- WARNING: 可能产生大量数据` |
| `DEPRECATED` | 已废弃 | `-- DEPRECATED: 请使用新函数` |
| `PERFORMANCE` | 性能相关 | `-- PERFORMANCE: 已优化` |

### 格式规范

```sql
-- 单行注释格式：-- 空格 + 注释内容
-- 正确：
-- 这是正确的单行注释

-- 不推荐：
--这是不推荐的格式（缺少空格）

/*
 * 多行注释格式：
 * 1. 每行以 * 开头
 * 2. 使用缩进对齐
 * 3. 结束符独立一行
 */

/* 不推荐的多行注释格式
   没有对齐，不易阅读
*/
```

## 注释与性能

### 注释不影响执行性能

SQL 注释在解析阶段被移除，不会影响执行性能。

```sql
-- 大量注释不影响性能
SELECT 
    col1,  -- 列1
    col2,  -- 列2
    col3,  -- 列3
    /* ... 更多注释 ... */
    col100 -- 列100
FROM large_table;
```

### Hint 注释影响执行计划

Hint 注释会影响查询的执行计划，应谨慎使用。

```sql
-- Hint 会改变执行计划
SELECT /*+ MAPJOIN(small_table) */
    *
FROM large_table
JOIN small_table ON large_table.id = small_table.id;
```

## 注释的局限性

### 注释不能替代清晰的代码

```sql
-- ❌ 不好：用注释解释混乱的代码
SELECT 
    a, -- 用户ID
    b, -- 用户名
    c  -- 金额
FROM t; -- 用户表

-- ✅ 好：使用清晰的命名
SELECT 
    user_id,
    user_name,
    order_amount
FROM user_orders;
```

### 注释需要维护

```sql
-- ❌ 不好：注释与代码不一致
-- 统计活跃用户数
SELECT COUNT(*) FROM users WHERE status = 'deleted'; -- 代码已修改但注释未更新

-- ✅ 好：保持注释与代码同步
-- 统计已删除用户数
SELECT COUNT(*) FROM users WHERE status = 'deleted';
```

## 注释工具

### 使用 SHOW CREATE TABLE 查看表注释

```sql
SHOW CREATE TABLE users;
-- 输出包含表和列的注释信息
```

### 使用 DESC 查看列注释

```sql
DESC users;
-- 输出列名、类型和注释
```

### 提取注释生成文档

可以使用脚本提取 SQL 文件中的注释生成文档：

```bash
# 提取所有注释
grep -E "^--|\*" script.sql > comments.txt

# 提取表注释
grep -i "COMMENT" create_tables.sql > table_comments.txt
```

## 多语言注释

支持中英文混合注释：

```sql
-- 用户表查询 (User Table Query)
/* 
 * 功能说明 (Description):
 * 1. 统计活跃用户 (Count active users)
 * 2. 计算转化率 (Calculate conversion rate)
 */
SELECT 
    user_id,        -- 用户ID (User ID)
    user_name,      -- 用户名 (Username)
    status          -- 状态 (Status)
FROM users;
```
