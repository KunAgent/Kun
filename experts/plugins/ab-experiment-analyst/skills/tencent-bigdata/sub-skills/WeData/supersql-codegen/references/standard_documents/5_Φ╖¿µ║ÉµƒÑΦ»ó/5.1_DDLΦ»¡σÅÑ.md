# 5.1 DDL语句

## 概述

DDL（Data Definition Language，数据定义语言）用于定义和管理数据库对象，如数据源、表、视图等。SuperSQL支持标准的DDL语句，并扩展了跨数据源的能力。

本文档介绍SuperSQL中支持的DDL语句，包括数据源管理、视图管理等操作。

---

## 创建数据源

### 语法

```sql
CREATE DATASOURCE [IF NOT EXISTS] datasourceName 
WITH (key1=value1, key2=value2, ...)
```

### 语法说明

| 参数 | 说明 | 必需 |
|------|------|------|
| `IF NOT EXISTS` | 如果数据源已存在，不执行任何操作且不抛出异常 | 否 |
| `datasourceName` | 数据源名称，支持层级命名（如`dc.cluster.mysql.db`） | 是 |
| `key=value` | 数据源属性键值对 | 是 |

### 执行行为

| 场景 | IF NOT EXISTS | 行为 |
|------|--------------|------|
| 数据源不存在 | 无 | 创建数据源 |
| 数据源不存在 | 有 | 创建数据源 |
| 数据源已存在 | 无 | 抛出"数据源已存在"异常 |
| 数据源已存在 | 有 | 不执行任何操作（NOP），不抛出异常，服务端日志记录提示信息 |

**说明**：与传统RDBMS一样，CREATE DATASOURCE语句执行成功后不返回结果（ResultSet），失败才会抛出异常。

### 系统属性说明

SuperSQL会保存所有属性的键值对文本，但当前只有系统属性才会被SuperSQL内部逻辑使用。

**JDBC数据源的重要系统属性**：

| 属性名 | 说明 | 必需 |
|--------|------|------|
| `datasource` | 数据源类型（通常为`jdbc`） | 是 |
| `type` | 数据库类型（如`mysql`、`postgresql`、`hive`等） | 是 |
| `url` | JDBC连接URL | 是 |
| `driver` | JDBC驱动类名 | 是 |
| `username` | 用户名 | 是 |
| `password` | 密码明文 | 是 |
| `catalog` | 数据库catalog | 通常二选一 |
| `schema` | 数据库schema | 通常二选一 |

**其他属性**：用户可以自由定义任意的key-value键值对作为数据源的属性（如version、description等），这些属性会被保存但不会被系统逻辑使用。

**注意**：`catalog`和`schema`属性通常只需要指定一个，详见数据源注册文档。

### 语法示例

#### 基本示例

```sql
-- 请通过这种"数据源隔离器"的方式，来创建所有类型的SuperSQL数据源
CREATE DATASOURCE IF NOT EXISTS dc2.cluster2.mysql2.db2 WITH (
  datasource=jdbc,
  type=mysql,
  url=`jdbc:supersql:datasource:url='jdbc:mysql://localhost:3306/db2';driver='com.mysql.jdbc.Driver';jarPath='./supersql-drivers.zip/mysql/'`,
  driver=com.tencent.supersql.connector.SuperSqlDataSourceDriver,
  username=user2,
  password=`xxxxxx`,   -- 这里需要输入密码明文
  catalog=db2
)
```

#### 包含自定义属性

```sql
CREATE DATASOURCE IF NOT EXISTS mysql_prod WITH (
  datasource=jdbc,
  type=mysql,
  url=`jdbc:supersql:datasource:url='jdbc:mysql://prod-server:3306/mydb';driver='com.mysql.jdbc.Driver';jarPath='./supersql-drivers.zip/mysql/'`,
  driver=com.tencent.supersql.connector.SuperSqlDataSourceDriver,
  username=admin,
  password=`prod_password`,
  catalog=mydb,
  version=5.7,           -- 自定义属性
  description=`生产环境MySQL数据源`  -- 自定义属性
)
```

## ALTER TABLE语句

### 重要说明

SuperSQL **不原生支持**标准的ALTER TABLE语句（如`ALTER TABLE t1 ADD COLUMN c varchar(255)`）。

如果需要执行ALTER TABLE操作，必须通过**SQL透传**方式，将DDL语句直接发送到目标数据源执行。

### 使用SQL透传执行ALTER TABLE

#### 方式1：使用配置参数

```sql
-- 开启强制透传
SET `supersql.bypass.forceAll` = TRUE;

-- 设置默认数据源
SET `supersql.datasource.default` = `mysql_online`;

-- 创建表（透传到mysql_online执行）
CREATE TABLE t1 (a int, b double);

-- 增加列（透传到mysql_online执行）
ALTER TABLE t1 ADD COLUMN c varchar(255);
```

#### 方式2：不使用透传（会报错）

```sql
-- 关闭强制透传
SET `supersql.bypass.forceAll` = FALSE;

-- 重置默认数据源
RESET `supersql.datasource.default`;

-- 创建表（在ROOT schema中创建内存表）
CREATE TABLE t1 (a int, b double);

-- 尝试ALTER TABLE（会抛出异常）
ALTER TABLE t1 ADD COLUMN c varchar(255);
-- 错误：Encountered "table" at line x, column x
```

### ALTER TABLE透传示例

```sql
-- 示例1：增加列
SET `supersql.bypass.forceAll` = TRUE;
SET `supersql.datasource.default` = `mysql_online`;
ALTER TABLE t1 ADD COLUMN new_col INT;

-- 示例2：修改列类型
SET `supersql.bypass.forceAll` = TRUE;
SET `supersql.datasource.default` = `mysql_online`;
ALTER TABLE t1 MODIFY COLUMN col1 BIGINT;

-- 示例3：删除列
SET `supersql.bypass.forceAll` = TRUE;
SET `supersql.datasource.default` = `mysql_online`;
ALTER TABLE t1 DROP COLUMN old_col;

-- 示例4：重命名列
SET `supersql.bypass.forceAll` = TRUE;
SET `supersql.datasource.default` = `mysql_online`;
ALTER TABLE t1 CHANGE old_name new_name VARCHAR(100);
```

## 创建/更新视图

### 语法

```sql
CREATE [OR REPLACE] VIEW viewName [('columnName', ...)] AS selectStatement
```

### 语法说明

| 参数 | 说明 | 必需 |
|------|------|------|
| `OR REPLACE` | 如果视图已存在，则替换视图定义 | 否 |
| `viewName` | 视图名称，建议使用`datasourceName.viewName`形式 | 是 |
| `columnName` | 显式指定列名（可选） | 否 |
| `selectStatement` | SELECT查询语句 | 是 |

### 视图说明

SuperSQL中的视图（view）与表一样，必须定义在某个数据源之中。

**建议**：
- 对于视图定义中引用的表，建议使用`datasourceName.tableName`的形式
- 对于视图名称，建议使用`datasourceName.viewName`的形式
- 这样可以方便地进行跨数据源引用

### 视图类型

#### 1. 单源视图（数据源视图）

视图定义仅涉及同一数据源中的表。

**特点**：
- CREATE VIEW命令会下推到数据源执行
- 视图定义直接在数据源的元数据库持久化
- 即直接在数据源中创建视图

**条件**：
- 数据源不是抽象数据源或系统内部数据源
- 视图定义仅涉及同数据源中的一张或几张表

#### 2. 多源视图（跨源视图）

视图定义涉及多个数据源中的表。

**特点**：
- CREATE VIEW语句无法下推，在SuperSQL中执行
- 视图名称（全路径名）与SQL文本（SuperSQL语法格式）会写入对应数据源的`views`属性中
- 不同的视图定义之间用特殊字符串`:[_SUPERSQL_]:`分割

### 创建视图示例

#### 示例1：单源视图（UNION ALL）

```sql
CREATE VIEW mysql_online.v1 (a, b) AS
SELECT cint, cfloat FROM mysql_online.temp
UNION ALL
SELECT cint, cfloat FROM mysql_online.temp2;
```

**说明**：
- 视图`v1`定义在`mysql_online`数据源中
- 引用了同一数据源的两张表
- 视图会直接在MySQL数据源中创建

#### 示例2：单源视图（UNION）

```sql
CREATE OR REPLACE VIEW mysql_online.v2 AS
SELECT * FROM mysql_online.temp
UNION
SELECT * FROM mysql_online.temp2;
```

**说明**：
- 使用`OR REPLACE`，如果视图已存在则替换
- 未显式指定列名，使用查询结果的列名
- UNION会自动去重

#### 示例3：多源视图（跨数据源JOIN）

```sql
CREATE VIEW mysql_online.v3 (a, b) AS
SELECT t1.cint, t2.cstring
FROM mysql_online.temp t1
JOIN pg_online.temp t2
  ON t1.cint = t2.cint;
```

**说明**：
- 视图定义涉及两个数据源：`mysql_online`和`pg_online`
- 无法下推到数据源执行，在SuperSQL中创建
- 视图定义保存在`mysql_online`数据源的`views`属性中

### 查看跨源视图定义

```sql

```

**输出示例**：


### 跨源视图元数据同步注意事项

⚠️ **重要提示**：

因为SuperSQL持久化保存了跨源视图的定义文本到数据源属性中，如果用户后续在视图涉及的数据源表上进行了以下操作：
- 删除了列
- 修改了列名称
- 修改了列类型

相关元数据更新**不会自动同步**到SuperSQL的跨源视图定义中。

**解决方案**：
1. 删除视图：`DROP VIEW mysql_online.v3`
2. 重新创建视图：执行原CREATE VIEW语句

否则可能因为元数据不匹配导致视图上SQL执行失败的问题。

## 删除视图

### 语法

```sql
DROP VIEW [IF EXISTS] viewName
```

### 语法说明

| 参数 | 说明 | 必需 |
|------|------|------|
| `IF EXISTS` | 如果视图不存在，不抛出异常 | 否 |
| `viewName` | 要删除的视图名称 | 是 |

### 执行行为

| 场景 | IF EXISTS | 行为 |
|------|-----------|------|
| 视图存在 | 无 | 删除视图 |
| 视图存在 | 有 | 删除视图 |
| 视图不存在 | 无 | 抛出"视图不存在"异常 |
| 视图不存在 | 有 | 不执行任何操作，不抛出异常 |

### 删除视图示例

#### 示例1：安全删除（推荐）

```sql
DROP VIEW IF EXISTS hive_online.v1;
```

**说明**：
- 如果视图存在则删除
- 如果视图不存在则不执行任何操作
- 不会抛出异常

#### 示例2：直接删除

```sql
DROP VIEW hive_online.v1;
```

**说明**：
- 如果视图存在则删除
- 如果视图不存在则抛出异常

#### 示例3：删除跨源视图

```sql
DROP VIEW IF EXISTS mysql_online.v3;
```

**说明**：
- 跨源视图的删除同样适用
- 会从数据源的`views`属性中移除视图定义

## 使用场景

### 1. 数据源管理

创建和管理多个数据源，实现跨数据源查询。

```sql
-- 创建MySQL数据源
CREATE DATASOURCE IF NOT EXISTS mysql_prod WITH (
  datasource=jdbc,
  type=mysql,
  url=`jdbc:supersql:datasource:url='jdbc:mysql://mysql-server:3306/prod_db';driver='com.mysql.jdbc.Driver';jarPath='./supersql-drivers.zip/mysql/'`,
  driver=com.tencent.supersql.connector.SuperSqlDataSourceDriver,
  username=admin,
  password=`mysql_password`,
  catalog=prod_db
);

-- 创建PostgreSQL数据源
CREATE DATASOURCE IF NOT EXISTS pg_prod WITH (
  datasource=jdbc,
  type=postgresql,
  url=`jdbc:supersql:datasource:url='jdbc:postgresql://pg-server:5432/prod_db';driver='org.postgresql.Driver';jarPath='./supersql-drivers.zip/postgresql/'`,
  driver=com.tencent.supersql.connector.SuperSqlDataSourceDriver,
  username=admin,
  password=`pg_password`,
  catalog=prod_db
);
```

### 2. 单源视图封装

将复杂的单数据源查询封装为视图，简化后续查询。

```sql
-- 创建订单统计视图
CREATE VIEW mysql_prod.order_stats AS
SELECT 
  customer_id,
  COUNT(*) AS order_count,
  SUM(amount) AS total_amount,
  AVG(amount) AS avg_amount
FROM mysql_prod.orders
GROUP BY customer_id;

-- 使用视图查询
SELECT * FROM mysql_prod.order_stats WHERE order_count > 10;
```

### 3. 跨源视图整合

创建跨数据源视图，整合多个数据源的数据。

```sql
-- 创建客户订单视图（跨MySQL和PostgreSQL）
CREATE VIEW mysql_prod.customer_orders AS
SELECT 
  c.customer_id,
  c.customer_name,
  o.order_id,
  o.order_date,
  o.amount
FROM pg_prod.customers c
JOIN mysql_prod.orders o
  ON c.customer_id = o.customer_id;

-- 使用跨源视图查询
SELECT customer_name, SUM(amount) AS total
FROM mysql_prod.customer_orders
GROUP BY customer_name
HAVING SUM(amount) > 10000;
```

### 4. 表结构修改（透传）

通过透传方式修改数据源表结构。

```sql
-- 设置透传模式
SET `supersql.bypass.forceAll` = TRUE;
SET `supersql.datasource.default` = `mysql_prod`;

-- 创建表
CREATE TABLE user_profiles (
  user_id INT PRIMARY KEY,
  username VARCHAR(50),
  email VARCHAR(100)
);

-- 增加列
ALTER TABLE user_profiles ADD COLUMN phone VARCHAR(20);

-- 修改列类型
ALTER TABLE user_profiles MODIFY COLUMN email VARCHAR(200);

-- 删除列
ALTER TABLE user_profiles DROP COLUMN phone;
```

## 最佳实践

### 1. 使用IF NOT EXISTS避免重复创建

创建数据源或视图时，始终使用`IF NOT EXISTS`：

```sql
-- 推荐
CREATE DATASOURCE IF NOT EXISTS mysql_prod WITH (...);
CREATE VIEW IF EXISTS mysql_prod.v1 AS ...;

-- 不推荐（可能抛出异常）
CREATE DATASOURCE mysql_prod WITH (...);
```

### 2. 使用完全限定名

在视图定义中使用完全限定名（datasourceName.tableName）：

```sql
-- 推荐
CREATE VIEW mysql_prod.v1 AS
SELECT * FROM mysql_prod.table1
JOIN pg_prod.table2 ON ...;

-- 不推荐（可能引起歧义）
CREATE VIEW v1 AS
SELECT * FROM table1
JOIN table2 ON ...;
```

### 3. 及时更新跨源视图

当修改了跨源视图涉及的表结构时，及时删除并重建视图：

```sql
-- 1. 删除旧视图
DROP VIEW IF EXISTS mysql_prod.customer_orders;

-- 2. 重新创建视图
CREATE VIEW mysql_prod.customer_orders AS
SELECT ... -- 新的视图定义
```

### 4. 透传时明确指定数据源

使用透传时，明确指定目标数据源：

```sql
-- 明确指定数据源
SET `supersql.bypass.forceAll` = TRUE;
SET `supersql.datasource.default` = `mysql_prod`;
ALTER TABLE t1 ADD COLUMN ...;

-- 完成后恢复设置
SET `supersql.bypass.forceAll` = FALSE;
RESET `supersql.datasource.default`;
```

### 5. 使用OR REPLACE更新视图

更新视图定义时使用`OR REPLACE`：

```sql
-- 推荐（原子操作）
CREATE OR REPLACE VIEW mysql_prod.v1 AS
SELECT ... -- 新的定义

-- 不推荐（两步操作）
DROP VIEW mysql_prod.v1;
CREATE VIEW mysql_prod.v1 AS ...;
```

### 6. 合理使用视图列名

对于复杂查询，显式指定视图列名：

```sql
-- 推荐（列名清晰）
CREATE VIEW mysql_prod.order_summary (
  customer_id,
  total_orders,
  total_amount
) AS
SELECT customer_id, COUNT(*), SUM(amount)
FROM mysql_prod.orders
GROUP BY customer_id;

-- 可接受（使用默认列名）
CREATE VIEW mysql_prod.order_summary AS
SELECT 
  customer_id,
  COUNT(*) AS total_orders,
  SUM(amount) AS total_amount
FROM mysql_prod.orders
GROUP BY customer_id;
```

## 常见问题（FAQ）

### Q1: SuperSQL支持ALTER TABLE语句吗？

**A**: 不支持。SuperSQL不原生支持ALTER TABLE语句。如果需要修改表结构，必须通过SQL透传方式，将DDL语句直接发送到目标数据源执行。

### Q2: 如何判断视图是单源视图还是跨源视图？

**A**: 
- **单源视图**：视图定义仅引用一个数据源的表，会直接在数据源中创建
- **跨源视图**：视图定义引用多个数据源的表，保存在SuperSQL的数据源属性中

可以通过`DESCRIBE DATASOURCE`命令查看数据源的`views`属性来判断。

### Q3: 跨源视图的性能如何？

**A**: 跨源视图的性能取决于：
- 数据源之间的网络延迟
- 数据量大小
- JOIN条件的选择性
- 是否能够下推过滤条件

建议对大表进行适当的过滤和聚合后再进行跨源JOIN。

### Q4: 修改了表结构后，跨源视图会自动更新吗？

**A**: 不会。跨源视图的定义保存在数据源属性中，不会自动同步表结构变化。需要手动删除并重建视图。

### Q5: 可以在跨源视图上创建视图吗？

**A**: 可以。SuperSQL支持在视图上创建视图（嵌套视图），但要注意性能影响。

```sql
-- 基础跨源视图
CREATE VIEW mysql_prod.v1 AS
SELECT * FROM mysql_prod.t1 JOIN pg_prod.t2 ON ...;

-- 在视图上创建视图
CREATE VIEW mysql_prod.v2 AS
SELECT * FROM mysql_prod.v1 WHERE ...;
```

### Q6: 如何查看数据源的所有视图？

**A**: 使用`DESCRIBE DATASOURCE`命令查看数据源的`views`属性：

```sql
DESCRIBE DATASOURCE mysql_prod;
```

单源视图会在数据源本身的元数据中，跨源视图会在`views`属性中。

### Q7: 创建数据源时密码必须是明文吗？

**A**: 是的。在CREATE DATASOURCE命令中，password参数必须提供明文密码。SuperSQL会在内部进行加密存储。

### Q8: 不同版本的Hive使用不同的jarPath吗？

**A**: 是的。不同版本的Hive需要配置相应的jarPath：
- Hive 1.2.x: `./supersql-drivers.zip/hive121`
- Hive 2.2.x: `./supersql-drivers.zip/hive220`
- Hive 2.3.x: `./supersql-drivers.zip/hive230`
- Hive 3.1.x: `./supersql-drivers.zip/hive310`

### Q9: 可以使用DROP VIEW删除单源视图吗？

**A**: 可以，但需要注意：
- 如果是真正的单源视图（在数据源中创建的），DROP VIEW会删除数据源中的视图
- 如果视图在使用中，可能会影响其他查询

### Q10: 视图名称可以不包含数据源前缀吗？

**A**: 技术上可以，但强烈不推荐。建议始终使用`datasourceName.viewName`的形式，这样可以：
- 避免命名冲突
- 明确视图所属的数据源
- 方便跨数据源引用

```sql
-- 创建Hive数据源（存储日志数据）

  username=hive,
  password=`hive_password`,
  catalog=logs_db,
  description=`日志数据库`
);
```

#### 2. 创建单源视图

```sql
-- 订单统计视图（MySQL）
CREATE VIEW mysql_orders.order_stats AS
SELECT 
  order_id,
  customer_id,
  order_date,
  total_amount,
  status
FROM mysql_orders.orders
WHERE status != 'cancelled';

-- 活跃客户视图（PostgreSQL）
CREATE VIEW pg_customers.active_customers AS
SELECT 
  customer_id,
  customer_name,
  email,
  registration_date,
  customer_level
FROM pg_customers.customers
WHERE status = 'active';

-- 访问日志统计视图（Hive）
CREATE VIEW hive_logs.access_stats AS
SELECT 
  user_id,
  date,
  COUNT(*) AS visit_count,
  COUNT(DISTINCT page_id) AS page_count
FROM hive_logs.access_logs
GROUP BY user_id, date;
```

#### 3. 创建跨源视图

```sql
-- 客户订单分析视图（MySQL + PostgreSQL）
CREATE VIEW mysql_orders.customer_order_analysis AS
SELECT 
  c.customer_id,
  c.customer_name,
  c.customer_level,
  o.order_id,
  o.order_date,
  o.total_amount
FROM pg_customers.active_customers c
JOIN mysql_orders.order_stats o
  ON c.customer_id = o.customer_id;

-- 用户行为分析视图（MySQL + PostgreSQL + Hive）
CREATE VIEW mysql_orders.user_behavior_analysis AS
SELECT 
  c.customer_id,
  c.customer_name,
  COUNT(DISTINCT o.order_id) AS order_count,
  SUM(o.total_amount) AS total_spent,
  AVG(l.visit_count) AS avg_daily_visits
FROM pg_customers.active_customers c
LEFT JOIN mysql_orders.order_stats o
  ON c.customer_id = o.customer_id
LEFT JOIN hive_logs.access_stats l
  ON c.customer_id = l.user_id
GROUP BY c.customer_id, c.customer_name;
```

#### 4. 使用视图查询

```sql
-- 查询高价值客户
SELECT 
  customer_name,
  order_count,
  total_spent,
  avg_daily_visits
FROM mysql_orders.user_behavior_analysis
WHERE total_spent > 10000
ORDER BY total_spent DESC
LIMIT 100;

-- 查询特定客户的订单明细
SELECT *
FROM mysql_orders.customer_order_analysis
WHERE customer_id = 12345
ORDER BY order_date DESC;
```
