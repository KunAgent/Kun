# 3.1.6 视图操作

## 概述

本文介绍TDW中的视图（View）操作，包括创建视图、更新视图、删除视图和查看视图。

## 创建/更新视图

### 基本语法

```sql
CREATE [OR REPLACE] VIEW [IF NOT EXISTS] view_name AS SELECT ...;
```

### 说明

- `OR REPLACE`和`IF NOT EXISTS`不能同时使用
- 对于视图定义中引用的表，建议采用`DBName::TableName`的形式，以方便跨数据库引用

### 示例

```sql
CREATE OR REPLACE VIEW view1 AS 
SELECT * FROM db1::table1;
```

### 创建视图的多种方式

#### 简单视图

```sql
CREATE VIEW user_view AS
SELECT 
    user_id,
    username,
    email
FROM users
WHERE status = 'active';
```

#### 跨库视图

```sql
CREATE VIEW sales_summary AS
SELECT 
    o.order_id,
    o.amount,
    u.username
FROM order_db::orders o
LEFT JOIN user_db::users u ON o.user_id = u.user_id;
```

#### 聚合视图

```sql
CREATE VIEW daily_stats AS
SELECT 
    dt,
    COUNT(*) as order_count,
    SUM(amount) as total_amount,
    AVG(amount) as avg_amount
FROM orders
GROUP BY dt;
```

#### 带条件的视图

```sql
CREATE VIEW vip_users AS
SELECT 
    user_id,
    username,
    vip_level,
    total_amount
FROM users
WHERE vip_level >= 3
  AND total_amount > 10000;
```

### 使用OR REPLACE更新视图

```sql
-- 创建视图
CREATE VIEW test_view AS
SELECT id, name FROM users;

-- 更新视图定义（使用OR REPLACE）
CREATE OR REPLACE VIEW test_view AS
SELECT id, name, email FROM users;
```

### 使用IF NOT EXISTS

```sql
-- 如果视图不存在则创建，存在则跳过
CREATE VIEW IF NOT EXISTS user_view AS
SELECT * FROM users;
```

## 删除视图

### 基本语法

```sql
DROP VIEW view_name;
```

### 示例

```sql
DROP VIEW view1;
```

### 安全删除

```sql
-- 如果视图不存在也不报错
DROP VIEW IF EXISTS view1;
```

## 查看视图

### 基本语法

```sql
DESC EXTENDED view_name;
```

### 说明

`DESC EXTENDED`命令可以查看视图的详细信息，包括视图的定义SQL。

### 示例

```sql
DESC EXTENDED view1;
```

### 查看视图结构

```sql
-- 查看视图的列信息
DESC view1;

-- 查看视图的详细定义
DESC EXTENDED view1;
```

### 查看视图定义SQL

```sql
-- 查看创建视图的SQL语句
SHOW CREATE TABLE view1;
```

## 使用注意事项

### 视图命名规范

1. **命名限制**
   - 正则限制：`[\w]+`
   - 支持字母、数字和下划线
   - 不能以数字开头

2. **命名建议**
   - 使用`_view`或`v_`前缀/后缀标识视图
   - 使用有意义的名称
   - 避免与表名冲突

### 视图设计最佳实践

1. **明确引用数据库**
   ```sql
   -- 推荐：使用完整的数据库.表名引用
   CREATE VIEW cross_db_view AS
   SELECT 
       u.user_id,
       o.order_id
   FROM user_db::users u
   LEFT JOIN order_db::orders o ON u.user_id = o.user_id;
   ```

2. **避免SELECT ***
   ```sql
   -- 不推荐
   CREATE VIEW bad_view AS SELECT * FROM large_table;
   
   -- 推荐：明确指定需要的列
   CREATE VIEW good_view AS
   SELECT col1, col2, col3 FROM large_table;
   ```

3. **添加注释**
   ```sql
   CREATE VIEW monthly_summary AS
   -- 每月销售汇总视图
   -- 包含订单数、销售额、平均单价
   SELECT 
       month,
       COUNT(*) as order_count,
       SUM(amount) as total_sales,
       AVG(amount) as avg_price
   FROM sales
   GROUP BY month;
   ```

4. **合理使用聚合**
   ```sql
   -- 预聚合视图可以提高查询性能
   CREATE VIEW user_stats AS
   SELECT 
       user_id,
       COUNT(DISTINCT order_id) as order_count,
       SUM(amount) as total_spend,
       MAX(order_date) as last_order_date
   FROM orders
   GROUP BY user_id;
   ```

### 视图的限制

1. **不能插入数据**
   - 视图是只读的，不能执行`INSERT`、`UPDATE`、`DELETE`操作
   
2. **依赖基表**
   - 视图依赖于基表，基表删除会导致视图失效
   - 基表结构变化可能影响视图

3. **性能考虑**
   - 视图不存储数据，每次查询都会执行定义的SQL
   - 复杂视图可能影响查询性能

## 完整示例

### 创建多层视图

```sql
-- 第一层：基础视图
CREATE VIEW v_active_users AS
SELECT 
    user_id,
    username,
    email,
    register_date
FROM users
WHERE status = 'active';

-- 第二层：聚合视图（基于第一层视图）
CREATE VIEW v_user_summary AS
SELECT 
    u.user_id,
    u.username,
    COUNT(o.order_id) as order_count,
    SUM(o.amount) as total_amount
FROM v_active_users u
LEFT JOIN orders o ON u.user_id = o.user_id
GROUP BY u.user_id, u.username;

-- 第三层：业务视图（基于第二层视图）
CREATE VIEW v_vip_candidates AS
SELECT 
    user_id,
    username,
    order_count,
    total_amount
FROM v_user_summary
WHERE order_count >= 10 AND total_amount >= 5000;
```

### 跨库数据整合

```sql
-- 整合多个数据库的数据
CREATE VIEW v_customer_360 AS
SELECT 
    -- 基本信息（来自用户库）
    u.user_id,
    u.username,
    u.email,
    u.register_date,
    
    -- 订单信息（来自订单库）
    o.order_count,
    o.total_amount,
    o.last_order_date,
    
    -- 行为信息（来自日志库）
    l.login_count,
    l.last_login_date
FROM user_db::users u
LEFT JOIN (
    SELECT 
        user_id,
        COUNT(*) as order_count,
        SUM(amount) as total_amount,
        MAX(order_date) as last_order_date
    FROM order_db::orders
    GROUP BY user_id
) o ON u.user_id = o.user_id
LEFT JOIN (
    SELECT 
        user_id,
        COUNT(*) as login_count,
        MAX(login_date) as last_login_date
    FROM log_db::user_logs
    WHERE action = 'login'
    GROUP BY user_id
) l ON u.user_id = l.user_id;
```

### 视图维护示例

```sql
-- 1. 创建初始视图
CREATE VIEW product_sales AS
SELECT 
    product_id,
    product_name,
    SUM(quantity) as total_quantity,
    SUM(amount) as total_amount
FROM sales
GROUP BY product_id, product_name;

-- 2. 查看视图
DESC product_sales;

-- 3. 使用视图
SELECT * FROM product_sales WHERE total_amount > 10000;

-- 4. 更新视图定义（添加新字段）
CREATE OR REPLACE VIEW product_sales AS
SELECT 
    product_id,
    product_name,
    SUM(quantity) as total_quantity,
    SUM(amount) as total_amount,
    AVG(amount) as avg_amount,  -- 新增
    COUNT(*) as order_count      -- 新增
FROM sales
GROUP BY product_id, product_name;

-- 5. 验证更新
DESC product_sales;

-- 6. 删除视图
DROP VIEW IF EXISTS product_sales;
```

## 常见错误处理

### 错误：视图已存在

```sql
-- 错误
CREATE VIEW my_view AS SELECT * FROM table1;
-- Error: View 'my_view' already exists

-- 解决方案1：使用OR REPLACE
CREATE OR REPLACE VIEW my_view AS SELECT * FROM table1;

-- 解决方案2：先删除再创建
DROP VIEW IF EXISTS my_view;
CREATE VIEW my_view AS SELECT * FROM table1;

-- 解决方案3：使用IF NOT EXISTS
CREATE VIEW IF NOT EXISTS my_view AS SELECT * FROM table1;
```

### 错误：基表不存在

```sql
-- 错误
CREATE VIEW my_view AS SELECT * FROM non_existing_table;
-- Error: Table 'non_existing_table' not found

-- 解决：确保基表存在
SHOW TABLES;
```

### 错误：OR REPLACE与IF NOT EXISTS同时使用

```sql
-- 错误：不能同时使用
CREATE OR REPLACE VIEW IF NOT EXISTS my_view AS SELECT * FROM table1;
-- Error: OR REPLACE and IF NOT EXISTS cannot be used together

-- 正确：选择其一
CREATE OR REPLACE VIEW my_view AS SELECT * FROM table1;
-- 或
CREATE VIEW IF NOT EXISTS my_view AS SELECT * FROM table1;
```

### 错误：尝试插入视图

```sql
-- 错误：视图是只读的
INSERT INTO my_view VALUES (1, 'test');
-- Error: Cannot insert into view

-- 解决：直接操作基表
INSERT INTO base_table VALUES (1, 'test');
```

## 视图 vs 表的对比

| 特性 | 视图 | 表 |
|------|------|-----|
| 存储数据 | 否，只存储定义 | 是 |
| 查询性能 | 取决于基表和SQL复杂度 | 通常更快 |
| 磁盘空间 | 几乎不占用 | 占用存储空间 |
| 数据一致性 | 总是最新的 | 需要刷新维护 |
| INSERT/UPDATE | 不支持 | 支持 |
| 跨库引用 | 方便 | 需要导入数据 |

## 使用场景

### 适合使用视图的场景

1. **简化复杂查询**
   - 将复杂的JOIN和子查询封装成视图
   - 提供简洁的查询接口

2. **数据安全**
   - 限制用户只能访问特定列
   - 通过WHERE条件限制可见行

3. **逻辑数据独立性**
   - 基表结构变化时，只需修改视图
   - 应用程序代码不需要修改

4. **跨库数据整合**
   - 整合多个数据库的数据
   - 提供统一的数据视图

### 不适合使用视图的场景

1. **需要频繁修改数据**
   - 视图不支持INSERT/UPDATE/DELETE

2. **性能关键的查询**
   - 复杂视图可能影响性能
   - 考虑使用物化视图或汇总表

3. **大量数据计算**
   - 视图每次查询都重新计算
   - 考虑预计算并存储结果
