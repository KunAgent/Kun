# Order by子句（带limit）

## 格式

```sql
SELECT [ALL | DISTINCT] select_expr, select_expr, ...
FROM table_reference
[WHERE where_condition]
ORDER BY col_list
LIMIT number
```

## 说明

目前带limit的order by语句通过在每一个Map取topN，在Reduce阶段将`#Map×N`条记录拉到同一台机器做排序，从而完成数据的取前Top N的操作。可以实现数据的排序后取前N的操作。

```sql
SELECT key, value FROM src ORDER BY key LIMIT N;
```

## Order by + limit中limit值的设置

默认配置在`hive-default.xml`文件中：

```xml
<property>
  <name>hive.sortby.limit.maxcount</name>
  <value>1024</value>
  <description>When limit is specified after sort by, this is the max value for limit</description>
</property>
```

默认limit的最大值为**1024**，当sql中的limit值大于设置的最大值时，会在语法检查中报错并有如下提示：

```
FAILED: Error in semantic analysis: line 1:42 Limit value is Too BIG for ORDER BY(Default Max Limit:1024)
```

## 修改limit最大值

若需修改limit的最大值可通过在hive命令行下修改`hive.sortby.limit.maxcount`变量的值即可。修改命令如下所示：

```sql
SET hive.sortby.limit.maxcount = 10240;
```

## 注意事项

- 带LIMIT的ORDER BY相比不带LIMIT性能更好
- 可以根据实际需求调整`hive.sortby.limit.maxcount`参数
- 建议合理设置LIMIT值，避免过大导致性能问题
