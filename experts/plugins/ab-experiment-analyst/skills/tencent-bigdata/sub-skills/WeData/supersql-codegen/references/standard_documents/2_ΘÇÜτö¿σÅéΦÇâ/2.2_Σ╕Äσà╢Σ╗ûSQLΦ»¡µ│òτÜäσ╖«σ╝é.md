# 与其他SQL语法的差异

## 概述

天穹 SQL（TDW Hive 和 SuperSQL）虽然基于标准 SQL，但在语法和行为上与常见的 SQL 引擎（如 MySQL、Oracle、Hive）存在一些差异。了解这些差异有助于用户从其他 SQL 平台迁移或进行跨平台开发。

## 与 MySQL 的差异

### DDL 语句差异

| 功能 | MySQL | 天穹 SQL | 说明 |
|------|-------|---------|------|
| **表引擎** | 支持多种引擎（InnoDB、MyISAM） | 不支持 ENGINE 子句 | 天穹使用统一存储引擎 |
| **AUTO_INCREMENT** | 支持 | 不支持 | 需手动实现自增逻辑或使用序列 |
| **主键约束** | 强制主键约束 | 仅语法支持，不强制 | 主键不保证唯一性 |
| **外键约束** | 支持外键约束 | 不支持 | 无外键关联校验 |
| **索引** | 支持多种索引 | 不支持传统索引 | 使用分区和排序优化查询 |

**示例：**
```sql
-- MySQL 风格（天穹不支持）
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    FOREIGN KEY (dept_id) REFERENCES dept(id)
) ENGINE=InnoDB;

-- 天穹 SQL 风格
CREATE TABLE users (
    id BIGINT,
    name STRING,
    dept_id BIGINT
) PARTITIONED BY (dt STRING);
```

### DML 语句差异

| 功能 | MySQL | 天穹 SQL | 说明 |
|------|-------|---------|------|
| **UPDATE 语句** | 支持直接 UPDATE | 不支持（或有限制） | 建议使用 INSERT OVERWRITE |
| **DELETE 语句** | 支持直接 DELETE | 不支持（或有限制） | 建议使用 INSERT OVERWRITE 过滤数据 |
| **REPLACE INTO** | 支持 | 不支持 | 使用 INSERT OVERWRITE 替代 |
| **LIMIT 语法** | `LIMIT offset, count` | `LIMIT count` 或 `LIMIT count OFFSET offset` | 语法顺序不同 |

**UPDATE/DELETE 替代方案：**
```sql
-- ❌ MySQL 风格（天穹不支持或有限制）
UPDATE users SET status = 'active' WHERE id = 123;
DELETE FROM users WHERE id = 123;

-- ✅ 天穹 SQL 风格（使用 INSERT OVERWRITE）
INSERT OVERWRITE TABLE users PARTITION(dt='20240101')
SELECT id, name, 'active' AS status, dept_id
FROM users
WHERE dt = '20240101';

-- 删除操作：通过过滤实现
INSERT OVERWRITE TABLE users PARTITION(dt='20240101')
SELECT * FROM users 
WHERE dt = '20240101' AND id != 123;
```

### 数据类型差异

| MySQL 类型 | 天穹 SQL 类型 | 说明 |
|-----------|--------------|------|
| `INT` | `INT` 或 `BIGINT` | 推荐使用 BIGINT |
| `VARCHAR(n)` | `STRING` | STRING 无长度限制（最大 8MB） |
| `TEXT` | `STRING` | 统一使用 STRING |
| `DATETIME` | `TIMESTAMP` 或 `STRING` | 时间戳或字符串格式 |
| `ENUM` | `STRING` | 不支持 ENUM 类型 |
| `SET` | `ARRAY<STRING>` | 使用数组表示集合 |

### 函数差异

| MySQL 函数 | 天穹 SQL 对应函数 | 说明 |
|-----------|-----------------|------|
| `IFNULL(a, b)` | `NVL(a, b)` 或 `COALESCE(a, b)` | 空值处理 |
| `CONCAT_WS(sep, str1, str2)` | `CONCAT_WS(sep, str1, str2)` | 相同 |
| `DATE_FORMAT(date, format)` | `DATE_FORMAT(date, format)` | 格式略有不同 |
| `GROUP_CONCAT()` | `WM_CONCAT()` 或 `COLLECT_LIST()` | 聚合函数 |
| `SUBSTRING(str, pos, len)` | `SUBSTR(str, pos, len)` | 函数名不同 |

## 与 Oracle 的差异

### 语法差异

| 功能 | Oracle | 天穹 SQL | 说明 |
|------|--------|---------|------|
| **FROM DUAL** | 需要 DUAL 表 | 不需要 | `SELECT 1` 即可 |
| **序列** | `SEQUENCE` | 不直接支持 | 需自行实现 |
| **同义词** | `SYNONYM` | 不支持 | 使用视图或别名 |
| **ROWNUM** | `ROWNUM` | `ROW_NUMBER()` | 使用窗口函数 |
| **MINUS** | `MINUS` | `EXCEPT` | 集合差运算 |
| **NULL 排序** | `NULLS FIRST/LAST` | 支持 | 相同 |

**示例：**
```sql
-- Oracle 风格
SELECT * FROM users WHERE ROWNUM <= 10;

-- 天穹 SQL 风格
SELECT * FROM (
    SELECT *, ROW_NUMBER() OVER (ORDER BY id) AS rn
    FROM users
) t WHERE rn <= 10;
```

### 函数差异

| Oracle 函数 | 天穹 SQL 对应函数 | 说明 |
|------------|-----------------|------|
| `NVL(a, b)` | `NVL(a, b)` | 相同 |
| `NVL2(a, b, c)` | `IF(a IS NULL, c, b)` | 三元判断 |
| `DECODE(expr, ...)` | `CASE WHEN ... END` | 使用 CASE 表达式 |
| `TO_CHAR(date, format)` | `DATE_FORMAT(date, format)` | 日期格式化 |
| `TO_DATE(str, format)` | `TO_DATE(str)` | 日期解析 |
| `SYSDATE` | `CURRENT_TIMESTAMP` 或 `NOW()` | 当前时间 |

## 与 Hive 的差异

### 兼容性

天穹 SQL（TDW Hive）与 Apache Hive 高度兼容，但仍存在一些细微差异。

| 功能 | Apache Hive | 天穹 SQL | 说明 |
|------|------------|---------|------|
| **事务支持** | 支持 ACID（有限） | 不支持事务 | 无 BEGIN/COMMIT |
| **UPDATE/DELETE** | 支持（需开启事务） | 不支持或有限制 | 使用 INSERT OVERWRITE |
| **存储格式** | ORC、Parquet 等 | 支持 ORC、TXT 等 | 推荐 ORC |
| **SerDe** | 支持自定义 SerDe | 支持部分 SerDe | 需确认兼容性 |
| **Metastore** | 独立 Metastore | 集成 Metastore | 元数据管理方式不同 |

### 语法增强

天穹 SQL 在 Hive 基础上进行了一些扩展：

| 功能 | 说明 |
|------|------|
| **VALUES 子句** | 支持 `SELECT ... FROM (VALUES ...) AS t` |
| **窗口函数增强** | 更多窗口函数支持 |
| **内置函数扩展** | 新增大量内置函数 |
| **性能优化** | 自动优化、物化视图等 |

## 通用差异总结

### 不支持的标准 SQL 特性

1. **事务处理**：不支持 `BEGIN`、`COMMIT`、`ROLLBACK`
2. **约束**：主键、外键、唯一约束仅语法支持，不强制执行
3. **存储过程**：不支持传统存储过程，支持 UDF/UDAF/UDTF
4. **触发器**：不支持数据库触发器
5. **游标**：不支持游标操作
6. **临时表**：支持临时表，但生命周期与会话相关

### 建议的最佳实践

1. **批量处理**：优先使用批量插入和分区操作
2. **避免小文件**：合理规划分区策略，减少小文件
3. **使用 ORC 格式**：获得更好的压缩和性能
4. **合理使用 UDF**：复杂逻辑封装为 UDF
5. **分区过滤**：查询时始终使用分区过滤条件

## 跨平台迁移注意事项

### 从 MySQL 迁移

- 重新设计主键生成策略（如使用 UUID 或分布式 ID）
- 将 `AUTO_INCREMENT` 改为手动生成或序列
- 将 `UPDATE/DELETE` 改为 `INSERT OVERWRITE`
- 调整数据类型（如 VARCHAR → STRING）

### 从 Oracle 迁移

- 将 `SEQUENCE` 改为自定义实现
- 将 `ROWNUM` 改为 `ROW_NUMBER()`
- 将 `DECODE` 改为 `CASE WHEN`
- 调整日期函数（如 `SYSDATE` → `CURRENT_TIMESTAMP`）

### 从 Hive 迁移

- 检查 SerDe 兼容性
- 验证自定义 UDF 功能
- 确认存储格式支持
- 测试性能和优化配置
