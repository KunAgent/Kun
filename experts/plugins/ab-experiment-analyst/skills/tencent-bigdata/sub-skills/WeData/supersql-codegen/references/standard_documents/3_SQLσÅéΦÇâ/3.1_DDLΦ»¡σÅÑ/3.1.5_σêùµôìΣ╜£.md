# 列操作

## 概述

本文介绍TDW中的列（字段）操作，包括增加字段和修改字段。

> **重要提示：** TDW默认不支持修改字段类型，`ALTER TABLE`只是修改表元数据中定义的字段类型，已存在的数据依然是修改前类型。用户需要谨慎考虑前后类型的兼容性，只建议用户修改无数据的表。

## 增加字段

### 基本语法

```sql
ALTER TABLE <table_name> ADD COLUMNS (col_name data_type [COMMENT col_comment],...)
```

### 说明

- 增加字段的功能，只能加在表的末尾
- 用户必须对表有alter权限

### 示例

给表增加两个INT型字段key1和key2：

```sql
ALTER TABLE test ADD COLUMNS (key1 INT, key2 INT);
```

带注释的字段添加：

```sql
ALTER TABLE test ADD COLUMNS (
    email STRING COMMENT '用户邮箱',
    phone STRING COMMENT '联系电话'
);
```

## 修改字段

### 基本语法

```sql
ALTER TABLE <table_name> CHANGE [COLUMN] col_old_name col_new_name new_data_type [COMMENT col_comment]
```

### 重要说明

执行`ALTER TABLE`前需要添加参数：

```sql
SET hive.alterschema.without.check=true;
```

### 类型转换风险

如果文件中字段类型与元数据定义类型不一致，读取数据时引擎会抛异常：

```
java.lang.ClassCastException: org.apache.hadoop.io.BooleanWritable cannot be cast to org.apache.hadoop.io.IntWritable
```

**因此建议修改完字段类型后重写数据。**

### 限制说明

0. 文本表暂不支持修改表结构
1. 建议对外表不要修改schema（禁止）
2. PB表不允许修改schema（[pb表字段更新参考](https://iwiki.woa.com/p/1426746897#更新pb表)）
3. 对内表中的分区字段和索引字段不允许修改schema
4. 增加字段的功能，只能加在表的末尾
5. 减少列和替换所有列（replace）功能暂时不支持（tdw做了存储压缩，数据结构化后，字段顺序固定了，目前要实现中间插入或删除比较难）
6. 用户必须对表有alter权限

### 注意事项

Hive官方版本支持所有字段的替换操作（replace功能），TDW目前不开放这个功能。

### 示例

#### 修改列名

```sql
ALTER TABLE test CHANGE COLUMN key1 key_1 INT;
```

#### 修改字段类型

```sql
SET hive.alterschema.without.check=true;
ALTER TABLE test_table CHANGE COLUMN oldname_column new_column INT COMMENT 'new col';
```

#### 修改字段注释

```sql
ALTER TABLE test CHANGE COLUMN user_id user_id BIGINT COMMENT '用户唯一标识';
```

## 使用注意事项

### 字段修改最佳实践

1. **修改前备份数据**
   ```sql
   -- 创建备份表
   CREATE TABLE test_backup LIKE test;
   INSERT OVERWRITE TABLE test_backup SELECT * FROM test;
   
   -- 然后再修改字段
   SET hive.alterschema.without.check=true;
   ALTER TABLE test CHANGE COLUMN old_col new_col BIGINT;
   ```

2. **修改后重写数据**
   ```sql
   -- 修改字段类型后，重写数据确保一致性
   INSERT OVERWRITE TABLE test 
   SELECT * FROM test_backup;
   ```

3. **分步骤进行**
   - 先在测试环境验证
   - 确认数据兼容性
   - 再在生产环境操作

### 数据类型转换建议

#### 安全的类型转换

以下转换通常是安全的：

- `INT` → `BIGINT`
- `FLOAT` → `DOUBLE`
- `SMALLINT` → `INT` → `BIGINT`

#### 需要谨慎的类型转换

以下转换需要特别注意：

- `STRING` → 数值类型（需要确保所有值都可转换）
- `BIGINT` → `INT`（可能溢出）
- `DOUBLE` → `FLOAT`（可能丢失精度）

### 字段命名规范

1. **命名限制**
   - 正则限制：`[\w]+`
   - 支持字母、数字和下划线
   - 不能以数字开头

2. **命名建议**
   - 使用小写字母和下划线
   - 使用有意义的名称
   - 避免使用保留字

## 完整示例

### 创建表并添加字段

```sql
-- 1. 创建初始表
CREATE TABLE user_info (
    user_id BIGINT COMMENT '用户ID',
    username STRING COMMENT '用户名'
)
STORED AS ORCFILE;

-- 2. 添加新字段
ALTER TABLE user_info ADD COLUMNS (
    email STRING COMMENT '邮箱地址',
    phone STRING COMMENT '手机号码',
    create_time TIMESTAMP COMMENT '创建时间'
);

-- 3. 查看表结构
DESC user_info;
```

### 修改字段示例

```sql
-- 1. 创建测试表
CREATE TABLE test_modify (
    id INT,
    name STRING,
    age INT
);

-- 2. 插入测试数据
INSERT INTO test_modify VALUES (1, 'Alice', 25);

-- 3. 修改字段名
ALTER TABLE test_modify CHANGE COLUMN name user_name STRING;

-- 4. 修改字段类型（需要谨慎）
SET hive.alterschema.without.check=true;
ALTER TABLE test_modify CHANGE COLUMN id user_id BIGINT COMMENT '用户ID';

-- 5. 重写数据确保类型一致
CREATE TABLE test_modify_new LIKE test_modify;
INSERT OVERWRITE TABLE test_modify_new SELECT * FROM test_modify;
DROP TABLE test_modify;
ALTER TABLE test_modify_new RENAME TO test_modify;
```

### 批量添加字段

```sql
-- 一次性添加多个字段
ALTER TABLE sales ADD COLUMNS (
    -- 基本信息
    customer_name STRING COMMENT '客户姓名',
    customer_phone STRING COMMENT '客户电话',
    
    -- 金额信息
    discount_amount DOUBLE COMMENT '折扣金额',
    final_amount DOUBLE COMMENT '最终金额',
    
    -- 时间信息
    order_time TIMESTAMP COMMENT '下单时间',
    payment_time TIMESTAMP COMMENT '支付时间'
);
```

## 常见错误处理

### 错误：表不支持修改

```sql
-- 错误：文本表不支持修改
ALTER TABLE text_table ADD COLUMNS (new_col STRING);
-- Error: Text tables do not support schema modification

-- 解决：创建新表并迁移数据
CREATE TABLE new_table (...) STORED AS ORCFILE;
INSERT OVERWRITE TABLE new_table SELECT *, NULL FROM text_table;
```

### 错误：字段已存在

```sql
-- 错误：字段已存在
ALTER TABLE test ADD COLUMNS (id BIGINT);
-- Error: Column 'id' already exists

-- 解决：先检查表结构
DESC test;
```

### 错误：类型转换失败

```sql
-- 错误：类型不兼容
SET hive.alterschema.without.check=true;
ALTER TABLE test CHANGE COLUMN name name INT;
-- 运行时错误：字符串无法转换为整数

-- 解决：确保数据兼容或重写数据
```

### 错误：修改分区字段

```sql
-- 错误：不能修改分区字段
ALTER TABLE partitioned_table CHANGE COLUMN dt dt STRING;
-- Error: Cannot modify partition column

-- 解决：分区字段在创建表时定义，无法修改
```

## 性能优化建议

1. **批量操作**
   - 尽量一次性添加多个字段
   - 减少元数据修改次数

2. **选择合适的数据类型**
   - 使用`BIGINT`而不是`INT`避免未来扩展问题
   - 使用`DOUBLE`而不是`FLOAT`提高精度

3. **避免频繁修改**
   - 在设计阶段充分考虑字段需求
   - 预留一些备用字段
