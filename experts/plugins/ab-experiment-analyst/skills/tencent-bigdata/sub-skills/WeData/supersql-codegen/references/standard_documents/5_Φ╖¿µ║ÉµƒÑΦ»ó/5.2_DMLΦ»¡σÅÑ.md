# 5.2 DML语句

## 概述

DML（Data Manipulation Language，数据操作语言）是SQL语言中用于对数据库表中数据进行操作的语句集合。SuperSQL支持标准的DML语句，包括INSERT、UPSERT、UPDATE、DELETE等操作。

### 核心特性

- **跨源INSERT支持**：支持跨数据源的INSERT ... SELECT操作
- **分区表支持**：完整支持Hive动态分区和静态分区写入
- **UPSERT扩展**：提供UPSERT语法，针对MySQL自动转换为REPLACE INTO
- **透传机制**：不支持的语法可通过透传模式执行

## INSERT INTO语句

### 基本语法

```sql
-- 插入查询结果
INSERT INTO tableName [('COLUMNLIST')] queryExpression

-- 插入多行常量数据
INSERT INTO tableName [('COLUMNLIST')] VALUES ('row_value0'), ('row_value1'), ...
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `tableName` | 目标表名，支持完全限定名（datasourceName.tableName） |
| `COLUMNLIST` | 可选的列名列表，用单引号括起来 |
| `queryExpression` | SELECT、WITH-SELECT或VALUES语句 |
| `row_value` | 一行数据的值，用逗号分隔 |

### 基本示例

#### 示例1：插入常量值

```sql
-- 插入单行或多行常量数据
INSERT INTO mysql.temp3
VALUES (1, 'test', 0.1, 0.22, 0.23, DATE '2010-01-01', TIMESTAMP '2010-01-01 12:13:25', TRUE, 1),
       (2, 'demo', 1.1, 1.1, 1.1, DATE '2010-01-02', TIMESTAMP '2010-01-02 14:25:30', FALSE, 11);
```

#### 示例2：插入查询结果

```sql
-- 从另一个表插入数据
INSERT INTO mysql.temp3 
SELECT * FROM mysql2.temp;
```

#### 示例3：使用列名列表

```sql
-- 指定要插入的列
INSERT INTO pg.temp ('cdouble', 'ctimestamp') 
SELECT cdouble, ctimestamp FROM pg.temp2;
```

### 日期类型常量格式

⚠️ **重要说明**：INSERT ... VALUES语句中的日期类型常量，**必须**使用以下格式：

```sql
-- 正确格式：类型名 + 空格 + 字符串表示
DATE '2010-01-01'
TIMESTAMP '2010-01-01 12:13:25'
TIME '12:13:25'

-- 错误格式（缺少类型名）
'2010-01-01'  -- ❌ 错误
'2010-01-01 12:13:25'  -- ❌ 错误
```

**示例**：

```sql
INSERT INTO mysql.orders
VALUES (1, 'Order001', DATE '2024-01-15', TIMESTAMP '2024-01-15 09:30:00');
```

## 分区表插入

### Hive动态分区插入（推荐）

对于社区Hive或TDW Hive的List分区表，SuperSQL支持**省略partition子句**，使用动态分区+自动拼接的方式。

#### 语法特点

- **不需要**显式指定`PARTITION`子句
- 分区字段**必须**按照目标表中的次序写在`SELECT`列表的对应位置
- 分区字段**不能省略**，否则会导致列缺失或错位

#### 示例1：动态分区（单个分区字段）

```sql
-- cp是分区字段，写在selectList的最后
INSERT INTO hive_online.temp_par2
SELECT cint, cstring, cp 
FROM mysql_online.temp;
```

#### 示例2：动态分区（多个分区字段）

```sql
-- cp、bp是两个分区字段，按次序写在selectList的最后
INSERT INTO thive_online.temp_par1
SELECT cint, cstring, cp, bp 
FROM mysql_online.temp;
```

#### 注意事项

⚠️ **TDW Hive动态分区特殊行为**：

```sql
-- 如果指定的分区不存在（如cp=10），数据会写入default分区，不会自动创建分区
INSERT INTO TABLE thive_online.temp_par
SELECT cint, cstring, 10 FROM mysql_online.temp;
```

**问题**：
- 数据写入default分区后，只有THive能读出数据
- 社区Hive、SparkSQL和Presto都**读不出**数据

**建议**：往TDW Hive分区表写入数据前，**务必先创建好分区**！

### Hive静态分区插入

#### 语法

```sql
INSERT INTO TABLE tableName PARTITION(partition_spec)
SELECT ...
```

#### 示例1：静态分区写入

```sql
-- TDW Hive静态分区写入
-- SELECT中最后的分区字段值（11）必须与指定分区（cp=11）匹配
INSERT INTO TABLE thive_online.temp_par PARTITION(cp=11)
SELECT cint, cstring, 11 FROM mysql_online.temp;
```

**行为**：
- 如果分区不存在，THive Server会**自动创建**该分区
- 数据只写入指定的分区

#### 示例2：分区值不匹配的情况

```sql
-- 分区字段值（10）与指定分区（cp=11）不匹配
INSERT INTO TABLE thive_online.temp_par PARTITION(cp=11)
SELECT cint, cstring, 10 FROM mysql_online.temp;
```

**行为**：
- 数据**既不会**写入partition指定的分区（cp=11）
- 也**不会**写入字段值对应的分区（cp=10）或default分区
- 数据会**直接被忽略**

## INSERT OVERWRITE语句

### 基本语法

```sql
-- 覆盖写入整个表
INSERT OVERWRITE tableName [('COLUMNLIST')] queryExpression

-- 覆盖写入特定分区
INSERT OVERWRITE TABLE tableName PARTITION(partition_spec)
SELECT ...
```

### 示例1：覆盖写入整个表

```sql
-- 覆盖mysql表的所有数据
INSERT OVERWRITE mysql_online.temp
SELECT * FROM mysql2.source_table WHERE created_date >= '2024-01-01';
```

### 示例2：覆盖写入分区

```sql
-- 覆盖特定分区的数据
INSERT OVERWRITE TABLE hive_online.temp_par PARTITION(cp=10)
SELECT cint, cstring, 10 FROM mysql_online.temp;
```

## 跨源INSERT限制与建议

### 跨源INSERT的执行引擎

对于跨非天穹外部数据源的INSERT ... SELECT查询（例如：读MySQL表写入PostgreSQL表），SuperSQL当前**仅能调度Livy + Spark3计算引擎**来执行。

### 不支持的特性

由于Spark INSERT本身的限制，跨源INSERT有以下限制：

1. **不支持COLUMNLIST子句**（虽然可以写但会被改写）
2. **不支持自增列**
3. **不支持列默认值**
4. **不支持其他JDBC数据源的列值自动填充特性**

### 推荐语法（跨源INSERT）

```sql
-- ✅ 推荐：selectList中明确依次列出目标表的所有列
INSERT INTO pg.temp 
SELECT cint, cstring, cfloat, cdouble, cdecimal, cdate, ctimestamp, cboolean, clong
FROM mysql.temp t1 
WHERE t1.cint > 100 AND t1.cdouble > 1000;
```

### 不推荐的写法（自动改写）

如果用户指定了`COLUMNLIST`子句，SuperSQL不会报错，但会**自动改写SQL**：

```sql
-- 用户SQL
INSERT INTO pg.temp ('cint', 'cdouble', 'ctimestamp') 
SELECT cint, cdouble, ctimestamp FROM mysql.temp;

-- 实际执行的SQL（自动改写）
INSERT INTO pg.temp 
SELECT cint, NULL, NULL, cdouble, NULL, NULL, ctimestamp, NULL, NULL 
FROM mysql.temp;
```

**说明**：SuperSQL会删除`COLUMNLIST`子句，并为缺失的列补上`NULL`值。

### 单源INSERT（无限制）

单源INSERT**没有上面的限制**，用户可以使用数据源支持的任意语法：

```sql
-- 单源INSERT，完全支持COLUMNLIST
INSERT INTO pg.temp ('cdouble', 'ctimestamp') 
SELECT cdouble, ctimestamp FROM pg.temp2;
```

当遇到SuperSQL不支持的语法时，会**自动透传**到对应的数据源执行。

### 透传模式优化

对于含有子`COLUMNLIST`的`INSERT ... VALUES ...`语句，SuperSQL当前可支持但仍在优化中，**建议使用透传模式**更为高效：

```sql
-- 设置透传模式
SET `supersql.bypass.forceAll` = TRUE;
SET `supersql.datasource.default` = `mysql`;

-- 执行INSERT
INSERT INTO temp3 ('cint', 'cstring', 'cfloat', 'cdouble', 'cdecimal', 'cdate', 'ctimestamp', 'cboolean', 'clong')
VALUES (1, 'test', 0.1, 0.22, 0.23, DATE '2010-01-01', TIMESTAMP '2010-01-01 12:13:25', TRUE, 1),
       (2, 'demo', 1.1, 1.1, 1.1, DATE '2010-01-02', TIMESTAMP '2010-01-02 14:25:30', FALSE, 11);
```

## UPSERT语句

### 基本语法

```sql
UPSERT INTO tableName [('COLUMNLIST')] queryExpression
```

### 处理规则

SuperSQL对于UPSERT INTO语句的处理规则如下：

| 场景 | 处理方式 |
|------|---------|
| **单源MySQL** | 转换为`REPLACE INTO`语句 |
| **单源其他数据源** | 等价于`INSERT INTO`语句 |
| **跨源SQL** | 等价于`INSERT INTO`语句 |

### MySQL REPLACE INTO转换

当目标数据源为MySQL时，SuperSQL会将UPSERT转换为REPLACE INTO：

```sql
-- 用户SQL
UPSERT INTO mysql.users ('id', 'name', 'email')
VALUES (1, 'Alice', 'alice@example.com');

-- 实际执行的MySQL语句
REPLACE INTO users(id, name, email) 
VALUES (1, 'Alice', 'alice@example.com');
```

或者：

```sql
-- 用户SQL
UPSERT INTO mysql.users 
SELECT id, name, email FROM mysql.temp_users;

-- 实际执行的MySQL语句
REPLACE INTO users(id, name, email) 
SELECT id, name, email FROM temp_users;
```

### 限制说明

**不支持的语法**：
```sql
-- ❌ 不支持的语法
REPLACE INTO tbl_name SET col_name=value, ...
```

**跨源限制**：
- UPSERT语句**仅支持单源SQL**
- 跨源SQL的UPSERT等价于INSERT INTO
- 原因：Livy（Spark3）、Presto、Hive MR等计算引擎都不支持UPSERT语法

### 示例

#### 示例1：MySQL单源UPSERT

```sql
-- 单源UPSERT，转换为REPLACE INTO
UPSERT INTO mysql.products
VALUES (101, 'Laptop', 999.99, 50),
       (102, 'Mouse', 29.99, 200);
```

#### 示例2：其他数据源UPSERT

```sql
-- PostgreSQL单源UPSERT，等价于INSERT INTO
UPSERT INTO pg.products
SELECT * FROM pg.temp_products;
```

#### 示例3：跨源UPSERT

```sql
-- 跨源UPSERT，等价于INSERT INTO
UPSERT INTO pg.products
SELECT product_id, product_name, price, stock 
FROM mysql.source_products;
```

## UPDATE语句

### 基本语法

```sql
UPDATE tableName [[AS] alias] 
SET columnName = expression, columnName1 = expression1, ... 
[WHERE condition]
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `tableName` | 要更新的表名 |
| `alias` | 表的别名（可选） |
| `columnName` | 要更新的列名 |
| `expression` | 更新表达式，可以是常量、列引用或计算表达式 |
| `WHERE condition` | 过滤条件（可选），只更新满足条件的行 |

### 语法特点

- **SET子句**：可以包含多个列赋值，用逗号分隔
- **WHERE子句**：可选，只有一个，对所有SET语句都有效
- **WHERE限制**：不支持子查询表达式（如EXISTS、IN (SELECT ...)）
- **IN支持**：支持`IN(1, 2, 3)`形式，但不支持`IN (SELECT ...)`

### 基本示例

#### 示例1：更新单列

```sql
-- 更新所有行的clong列
UPDATE pg_online.temp 
SET clong = 100;
```

#### 示例2：更新多列

```sql
-- 同时更新多列
UPDATE pg_online.temp 
SET clong = cint * 12, 
    cfloat = cfloat + 0.1, 
    cstring = 'updated'
WHERE cint <= 10;
```

#### 示例3：使用表达式

```sql
-- 使用列引用和计算表达式
UPDATE mysql.orders o
SET o.total_price = o.quantity * o.unit_price,
    o.discount = CASE 
        WHEN o.quantity > 100 THEN 0.1 
        WHEN o.quantity > 50 THEN 0.05 
        ELSE 0 
    END
WHERE o.status = 'pending';
```

#### 示例4：使用别名

```sql
-- 使用表别名
UPDATE pg.employees AS e
SET e.salary = e.salary * 1.1,
    e.last_updated = CURRENT_TIMESTAMP
WHERE e.department = 'Engineering' AND e.performance_score >= 4.0;
```

### 数据源支持情况

| 数据源类型 | UPDATE支持情况 |
|-----------|--------------|
| **MySQL** | ✅ 完全支持 |
| **PostgreSQL** | ✅ 完全支持 |
| **Oracle** | ✅ 完全支持 |
| **SQL Server** | ✅ 完全支持 |
| **Hive** | ❌ 不支持（需要事务表） |
| **Spark** | ⚠️ 部分支持（Delta Lake） |
| **内存表** | ❌ 不支持 |

### 注意事项

⚠️ **内存表限制**：
```sql
-- ❌ 若未指定数据源也未设置默认数据源，对内存表进行UPDATE会抛出异常
UPDATE temp_table SET col1 = 100;
```

⚠️ **重复赋值**：
```sql
-- 是否支持取决于数据源
UPDATE mysql.temp SET cint = 12, cint = 10;  -- 可能报错或使用最后一个值
```

⚠️ **多列累计运算**：
```sql
-- 某些数据源可能不支持
UPDATE mysql.temp SET cint = 12, clong = cint + 10;  -- clong使用的是更新前还是更新后的cint？
```

⚠️ **类型不匹配**：
```sql
-- 是否报错取决于数据源
UPDATE mysql.temp SET cint = 'string';  -- cint是INT类型
```

### 透传模式

如果数据源支持UPDATE但语法与SuperSQL不同，可以通过**透传模式**执行：

```sql
-- 设置当前默认数据源
USE mysql_datasource;

-- 使用数据源原生的UPDATE语法
UPDATE temp SET col1 = col1 + 1 WHERE col2 IN (SELECT col2 FROM temp2);
```

## DELETE语句

### 基本语法

```sql
DELETE FROM tableName [[AS] alias] [WHERE condition]
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `tableName` | 要删除数据的表名 |
| `alias` | 表的别名（可选） |
| `WHERE condition` | 过滤条件（可选），只删除满足条件的行 |

### 语法特点

- **WHERE子句可选**：如果没有WHERE条件，将删除表中**所有行**
- **WHERE限制**：不支持子查询表达式（如EXISTS）
- **IN支持**：支持`IN(1, 2, 3)`形式，但不支持`IN (SELECT ...)`

### 基本示例

#### 示例1：删除满足条件的行

```sql
-- 删除cdouble小于0的行
DELETE FROM mysql_online.temp 
WHERE cdouble < 0;
```

#### 示例2：删除所有行

```sql
-- 删除表中所有数据（保留表结构）
DELETE FROM mysql.temp_table;
```

⚠️ **危险操作**：没有WHERE子句会删除所有数据，请谨慎使用！

#### 示例3：使用复杂条件

```sql
-- 使用AND/OR组合条件
DELETE FROM pg.orders 
WHERE status = 'cancelled' 
  AND created_date < DATE '2024-01-01' 
  AND total_amount = 0;
```

#### 示例4：使用IN条件

```sql
-- 使用IN条件（常量列表）
DELETE FROM mysql.products 
WHERE product_id IN (101, 102, 103, 104);

-- ❌ 不支持IN子查询
DELETE FROM mysql.products 
WHERE product_id IN (SELECT product_id FROM obsolete_products);  -- 不支持
```

#### 示例5：使用表别名

```sql
-- 使用表别名
DELETE FROM pg.employees AS e
WHERE e.status = 'resigned' AND e.last_working_date < CURRENT_DATE - INTERVAL '1' YEAR;
```

### 数据源支持情况

| 数据源类型 | DELETE支持情况 |
|-----------|--------------|
| **MySQL** | ✅ 完全支持 |
| **PostgreSQL** | ✅ 完全支持 |
| **Oracle** | ✅ 完全支持 |
| **SQL Server** | ✅ 完全支持 |
| **Hive** | ❌ 不支持（需要事务表） |
| **Spark** | ⚠️ 部分支持（Delta Lake） |
| **内存表** | ✅ 支持 |

### 注意事项

✅ **内存表支持**：
```sql
-- 若未指定数据源也未设置默认数据源，支持对内存表进行DELETE操作
DELETE FROM memory_table WHERE id < 100;
```

⚠️ **子查询限制**：
```sql
-- ❌ 不支持EXISTS
DELETE FROM mysql.orders WHERE EXISTS (SELECT 1 FROM cancelled_orders WHERE ...);

-- ❌ 不支持IN子查询
DELETE FROM mysql.orders WHERE order_id IN (SELECT order_id FROM temp_orders);

-- ✅ 支持IN常量列表
DELETE FROM mysql.orders WHERE order_id IN (1001, 1002, 1003);
```

### 透传模式

如果数据源支持DELETE但语法与SuperSQL不同，可以通过**透传模式**执行：

```sql
-- 设置当前默认数据源
USE mysql_datasource;

-- 使用数据源原生的DELETE语法
DELETE FROM orders WHERE order_id IN (SELECT order_id FROM cancelled_orders);
```

## 使用场景

### 场景1：跨源数据同步

**需求**：从MySQL同步数据到PostgreSQL

```sql
-- 全量同步
INSERT INTO pg.target_table
SELECT id, name, email, created_date 
FROM mysql.source_table;

-- 增量同步（按日期）
INSERT INTO pg.target_table
SELECT id, name, email, created_date 
FROM mysql.source_table
WHERE created_date >= CURRENT_DATE;
```

### 场景2：Hive分区表ETL

**需求**：从MySQL导入数据到Hive分区表

```sql
-- 动态分区插入（推荐）
INSERT INTO hive.fact_orders
SELECT 
    order_id, 
    customer_id, 
    total_amount, 
    order_status,
    DATE_FORMAT(order_date, 'yyyyMMdd') AS dt  -- 分区字段放最后
FROM mysql.orders
WHERE order_date = CURRENT_DATE;
```

### 场景3：数据清洗

**需求**：删除异常数据，更新有效数据

```sql
-- 1. 删除异常数据
DELETE FROM mysql.orders 
WHERE total_amount < 0 OR customer_id IS NULL;

-- 2. 更新订单状态
UPDATE mysql.orders 
SET status = 'expired', 
    updated_at = CURRENT_TIMESTAMP
WHERE status = 'pending' AND created_at < CURRENT_DATE - INTERVAL '30' DAY;
```

### 场景4：MySQL UPSERT操作

**需求**：插入新记录或更新已存在的记录

```sql
-- 使用UPSERT（自动转换为REPLACE INTO）
UPSERT INTO mysql.user_profiles
SELECT 
    user_id,
    username,
    email,
    last_login_time,
    login_count
FROM mysql.temp_user_data;
```

### 场景5：覆盖写入

**需求**：定期覆盖历史统计表

```sql
-- 覆盖写入整个表
INSERT OVERWRITE mysql.daily_summary
SELECT 
    DATE_FORMAT(CURRENT_DATE, 'yyyy-MM-dd') AS stat_date,
    category,
    SUM(amount) AS total_amount,
    COUNT(*) AS order_count
FROM mysql.orders
WHERE DATE(order_date) = CURRENT_DATE
GROUP BY category;
```

## 最佳实践

### 1. 跨源INSERT使用建议

**✅ 推荐做法**：
- 在`SELECT`列表中明确列出目标表的所有列
- 按照目标表的列顺序排列
- 不要依赖自增列、默认值等自动填充特性

```sql
-- ✅ 推荐：明确所有列
INSERT INTO pg.target_table
SELECT col1, col2, col3, col4, col5, col6
FROM mysql.source_table;
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：使用COLUMNLIST（会被改写）
INSERT INTO pg.target_table ('col1', 'col3', 'col5')
SELECT col1, col3, col5 FROM mysql.source_table;
```

### 2. Hive分区表写入建议

**✅ 推荐做法**：
- 使用动态分区（省略PARTITION子句）
- 分区字段按次序放在SELECT列表末尾
- 对于TDW Hive，提前创建好分区

```sql
-- ✅ 推荐：动态分区
INSERT INTO hive.orders_partitioned
SELECT order_id, customer_id, amount, order_date 
FROM mysql.orders;

-- TDW Hive：提前创建分区
ALTER TABLE hive.orders_partitioned ADD IF NOT EXISTS PARTITION (dt='20240115');
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：分区字段值与PARTITION子句不匹配
INSERT INTO TABLE thive.orders PARTITION(dt='20240115')
SELECT order_id, customer_id, amount, '20240116' FROM mysql.orders;
```

### 3. UPDATE和DELETE建议

**✅ 推荐做法**：
- 总是使用WHERE子句限制更新/删除范围
- 在执行前先用SELECT验证WHERE条件
- 对于大批量操作，分批执行

```sql
-- ✅ 推荐：先验证
SELECT COUNT(*) FROM mysql.orders WHERE status = 'cancelled';

-- 然后执行
DELETE FROM mysql.orders WHERE status = 'cancelled';
```

**❌ 不推荐做法**：
```sql
-- ❌ 危险：没有WHERE子句，会删除所有数据
DELETE FROM mysql.orders;

-- ❌ 不推荐：依赖子查询（不支持）
UPDATE mysql.orders SET status = 'closed' 
WHERE order_id IN (SELECT order_id FROM temp_table);
```

### 4. UPSERT使用建议

**✅ 推荐做法**：
- 仅在MySQL单源场景使用UPSERT
- 确保目标表有主键或唯一索引
- 对于其他数据源，使用数据源原生的UPSERT语法（通过透传）

```sql
-- ✅ 推荐：MySQL单源UPSERT
UPSERT INTO mysql.products
SELECT * FROM mysql.temp_products;
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：跨源UPSERT（等价于INSERT，不会去重）
UPSERT INTO pg.products
SELECT * FROM mysql.temp_products;
```

### 5. 日期类型常量建议

**✅ 推荐做法**：
- 始终使用类型名前缀
- 使用标准日期格式

```sql
-- ✅ 推荐
INSERT INTO mysql.events
VALUES (1, 'Login', DATE '2024-01-15', TIMESTAMP '2024-01-15 09:30:00');
```

**❌ 不推荐做法**：
```sql
-- ❌ 错误：缺少类型名
INSERT INTO mysql.events
VALUES (1, 'Login', '2024-01-15', '2024-01-15 09:30:00');
```

### 6. 性能优化建议

**批量插入**：
```sql
-- ✅ 推荐：批量插入多行
INSERT INTO mysql.orders
VALUES (1, 'Order1', 100.0),
       (2, 'Order2', 200.0),
       (3, 'Order3', 300.0),
       ... -- 一次插入几百到几千行
       (1000, 'Order1000', 99999.0);
```

**分批处理大数据量**：
```sql
-- 分批删除（避免长时间锁表）
DELETE FROM mysql.logs WHERE created_date < '2023-01-01' LIMIT 10000;
-- 重复执行直到删除完成
```

## 常见问题FAQ

### 1. SuperSQL支持所有数据源的UPDATE和DELETE吗？

**答案**：不是。UPDATE和DELETE是否支持**取决于数据源本身的能力**。

| 数据源 | UPDATE | DELETE | 说明 |
|--------|--------|--------|------|
| MySQL | ✅ | ✅ | 完全支持 |
| PostgreSQL | ✅ | ✅ | 完全支持 |
| Oracle | ✅ | ✅ | 完全支持 |
| SQL Server | ✅ | ✅ | 完全支持 |
| Hive | ❌ | ❌ | 需要事务表（ORC + ACID） |
| Spark | ⚠️ | ⚠️ | 仅Delta Lake支持 |
| 内存表 | ❌ | ✅ | DELETE支持，UPDATE不支持 |

**建议**：对于不支持的数据源，使用INSERT OVERWRITE或重建表的方式替代。

---

### 2. 跨源INSERT为什么不推荐使用COLUMNLIST？

**答案**：因为Spark引擎不支持COLUMNLIST子句。

**原因**：
- 跨源INSERT使用Spark引擎执行
- Spark的INSERT语法不支持`INSERT INTO table (col1, col2) SELECT ...`
- SuperSQL会自动改写，删除COLUMNLIST并补NULL值

**示例**：
```sql
-- 用户SQL
INSERT INTO pg.temp ('col1', 'col3') 
SELECT col1, col3 FROM mysql.source;

-- 自动改写为
INSERT INTO pg.temp 
SELECT col1, NULL, col3, NULL, NULL FROM mysql.source;
```

**建议**：直接在SELECT中明确列出所有列，避免改写。

---

### 3. INSERT ... VALUES中的日期为什么必须加类型名？

**答案**：这是SuperSQL/Calcite的语法要求，用于明确类型。

**正确格式**：
```sql
DATE '2024-01-15'
TIMESTAMP '2024-01-15 09:30:00'
TIME '09:30:00'
```

**错误格式**：
```sql
'2024-01-15'  -- ❌ 被识别为字符串，可能导致类型转换错误
```

**原因**：SQL标准要求日期字面量使用类型前缀。

---

### 4. 为什么Hive分区字段不能省略？

**答案**：因为SuperSQL需要根据SELECT列表的字段顺序匹配目标表的列（包括分区列）。

**示例**：
```sql
-- 假设目标表结构：(col1 INT, col2 STRING, part1 STRING, part2 INT)

-- ✅ 正确：分区字段按次序放最后
INSERT INTO hive.target_table
SELECT col1, col2, part1, part2 FROM mysql.source;

-- ❌ 错误：缺少分区字段
INSERT INTO hive.target_table
SELECT col1, col2 FROM mysql.source;  -- 会导致列错位或缺失

-- ❌ 错误：分区字段顺序错误
INSERT INTO hive.target_table
SELECT col1, part1, col2, part2 FROM mysql.source;  -- col2和part1位置错误
```

**建议**：始终按照目标表的列顺序（包括分区列）列出所有字段。

---

### 5. TDW Hive动态分区写入有什么特殊行为？

**答案**：如果分区不存在，数据会写入default分区，而不是自动创建分区。

**问题**：
- 数据写入default分区后，只有THive能读取
- 社区Hive、Spark、Presto都读不出数据

**解决方案**：
```sql
-- 1. 提前创建分区
ALTER TABLE thive.orders ADD IF NOT EXISTS PARTITION (dt='20240115');

-- 2. 然后插入数据
INSERT INTO thive.orders
SELECT order_id, customer_id, amount, '20240115' FROM mysql.source;
```

---

### 6. UPSERT在跨源场景下有什么限制？

**答案**：跨源场景下，UPSERT等价于INSERT INTO，不会有去重/更新行为。

**原因**：
- 跨源SQL使用Spark/Presto/Hive MR引擎执行
- 这些引擎都不支持UPSERT语法
- SuperSQL只能将UPSERT降级为INSERT

**建议**：
- 单源MySQL：使用UPSERT（转换为REPLACE INTO）
- 跨源：先DELETE再INSERT，或使用MERGE INTO（如果数据源支持）

---

### 7. 如何在SuperSQL中使用数据源原生的DML语法？

**答案**：使用透传模式。

**步骤**：
```sql
-- 1. 启用透传模式
SET `supersql.bypass.forceAll` = TRUE;

-- 2. 设置默认数据源
SET `supersql.datasource.default` = `mysql_online`;
-- 或使用 USE datasource_name;

-- 3. 执行数据源原生的DML语句
UPDATE orders o
JOIN customers c ON o.customer_id = c.id
SET o.discount = c.vip_discount
WHERE c.vip_level >= 3;
```

---

### 8. DELETE和TRUNCATE有什么区别？

**答案**：主要区别在于性能和事务处理。

| 特性 | DELETE | TRUNCATE |
|------|--------|----------|
| 速度 | 较慢（逐行删除） | 很快（直接清空） |
| 事务 | 可以回滚 | 不可回滚（某些数据源） |
| WHERE | 支持WHERE条件 | 不支持（删除所有行） |
| 触发器 | 触发DELETE触发器 | 不触发触发器 |
| 自增列 | 不重置 | 重置为初始值 |

**SuperSQL中的使用**：
```sql
-- DELETE：逐行删除，可以有WHERE条件
DELETE FROM mysql.orders WHERE status = 'cancelled';

-- TRUNCATE：快速清空（需透传到数据源）
SET `supersql.bypass.forceAll` = TRUE;
USE mysql_datasource;
TRUNCATE TABLE orders;
```

---

### 9. INSERT OVERWRITE会删除整个表吗？

**答案**：分情况。

**覆盖整个表**：
```sql
INSERT OVERWRITE mysql.orders
SELECT * FROM mysql.temp_orders;
-- 会删除orders表的所有数据，然后插入新数据
```

**覆盖特定分区**：
```sql
INSERT OVERWRITE TABLE hive.orders PARTITION(dt='20240115')
SELECT * FROM mysql.temp_orders;
-- 只删除dt='20240115'分区的数据，其他分区不受影响
```

**注意**：不同数据源的INSERT OVERWRITE行为可能不同，请查阅数据源文档。

---

### 10. 如何验证DML语句的执行效果？

**答案**：建议在执行DML前后都使用SELECT验证。

**示例流程**：
```sql
-- 1. 执行前验证：确认受影响的行数
SELECT COUNT(*) FROM mysql.orders WHERE status = 'cancelled';
-- 假设返回 1500

-- 2. 可选：查看具体数据
SELECT * FROM mysql.orders WHERE status = 'cancelled' LIMIT 10;

-- 3. 执行DML
DELETE FROM mysql.orders WHERE status = 'cancelled';

-- 4. 执行后验证：确认删除成功
SELECT COUNT(*) FROM mysql.orders WHERE status = 'cancelled';
-- 应该返回 0

-- 5. 验证总行数变化
SELECT COUNT(*) FROM mysql.orders;
-- 应该减少了 1500 行
```

## 附录：完整示例

### 场景：跨源数据ETL完整流程

**业务需求**：
1. 从MySQL的订单表和客户表读取数据
2. 进行数据清洗和转换
3. 写入PostgreSQL的分析表
4. 同时更新Hive的分区表（用于离线分析）

**完整SQL脚本**：

```sql
-- ========================================
-- 第1步：数据清洗 - 删除异常数据
-- ========================================

-- 删除MySQL中的无效订单
DELETE FROM mysql.orders 
WHERE total_amount < 0 
   OR customer_id IS NULL 
   OR order_date IS NULL;

-- 更新订单状态
UPDATE mysql.orders 
SET status = 'expired',
    updated_at = CURRENT_TIMESTAMP
WHERE status = 'pending' 
  AND created_at < CURRENT_DATE - INTERVAL '30' DAY;

-- ========================================
-- 第2步：跨源数据同步到PostgreSQL
-- ========================================

-- 清空PostgreSQL的临时表
DELETE FROM pg.stg_order_summary;

-- 从MySQL插入数据到PostgreSQL（跨源INSERT）
INSERT INTO pg.stg_order_summary
SELECT 
    o.order_id,
    o.customer_id,
    c.customer_name,
    c.customer_level,
    o.order_date,
    o.total_amount,
    o.discount_amount,
    o.final_amount,
    o.status,
    CURRENT_TIMESTAMP AS etl_time
FROM mysql.orders o
JOIN mysql.customers c ON o.customer_id = c.customer_id
WHERE o.order_date >= CURRENT_DATE - INTERVAL '7' DAY;

-- ========================================
-- 第3步：聚合到PostgreSQL的汇总表（UPSERT）
-- ========================================

-- 先删除今天的汇总数据
DELETE FROM pg.daily_order_summary 
WHERE summary_date = CURRENT_DATE;

-- 插入新的汇总数据
INSERT INTO pg.daily_order_summary
SELECT 
    CURRENT_DATE AS summary_date,
    customer_level,
    COUNT(*) AS order_count,
    SUM(total_amount) AS total_amount,
    SUM(discount_amount) AS total_discount,
    SUM(final_amount) AS total_final_amount,
    AVG(final_amount) AS avg_order_amount
FROM pg.stg_order_summary
WHERE DATE(order_date) = CURRENT_DATE
GROUP BY customer_level;

-- ========================================
-- 第4步：同步到Hive分区表（用于离线分析）
-- ========================================

-- 为Hive表创建分区（TDW Hive必须提前创建）
-- ALTER TABLE hive.fact_orders ADD IF NOT EXISTS PARTITION (dt='20240115');

-- 使用动态分区插入数据到Hive
INSERT INTO hive.fact_orders
SELECT 
    o.order_id,
    o.customer_id,
    c.customer_name,
    o.total_amount,
    o.discount_amount,
    o.final_amount,
    o.status,
    DATE_FORMAT(o.order_date, 'yyyyMMdd') AS dt  -- 分区字段放最后
FROM mysql.orders o
JOIN mysql.customers c ON o.customer_id = c.customer_id
WHERE o.order_date = CURRENT_DATE;

-- ========================================
-- 第5步：验证数据
-- ========================================

-- 验证PostgreSQL
SELECT 
    summary_date, 
    customer_level, 
    order_count, 
    total_final_amount 
FROM pg.daily_order_summary
WHERE summary_date = CURRENT_DATE;

-- 验证Hive
SELECT 
    dt, 
    COUNT(*) AS record_count, 
    SUM(final_amount) AS total_amount
FROM hive.fact_orders
WHERE dt = DATE_FORMAT(CURRENT_DATE, 'yyyyMMdd')
GROUP BY dt;
```

### 执行结果

**PostgreSQL汇总表结果**：
```
 summary_date | customer_level | order_count | total_final_amount
--------------+----------------+-------------+-------------------
 2024-01-15   | VIP            | 1,250       | 2,450,000.00
 2024-01-15   | Gold           | 3,500       | 5,800,000.00
 2024-01-15   | Silver         | 8,900       | 8,900,000.00
 2024-01-15   | Regular        | 12,350      | 9,800,000.00
```

**Hive分区表验证结果**：
```
     dt      | record_count | total_amount
-------------+--------------+--------------
  20240115   | 26,000       | 26,950,000.00
```
