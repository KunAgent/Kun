# 3.4.1 创建表 (CREATE TABLE)

## 概述

Iceberg 表的创建使用标准的 SQL `CREATE TABLE` 语法，但必须包含 `USING iceberg` 子句。Iceberg 会自动将 Spark 列类型转换为对应的 Iceberg 类型。

## 基本语法

### 创建简单表

```sql
CREATE TABLE [IF NOT EXISTS] table_name (
    column_name data_type [NOT NULL] [COMMENT 'column_comment'],
    ...
)
USING iceberg
[COMMENT 'table_comment']
[LOCATION 'path']
[TBLPROPERTIES ('key'='value', ...)]
```

**示例：**

```sql
CREATE TABLE prod.db.sample (
    id bigint NOT NULL COMMENT 'unique id',
    data string,
    category string,
    created_at timestamp
)
USING iceberg
COMMENT 'Sample Iceberg table';
```

## 分区表

### PARTITIONED BY 子句

Iceberg 支持使用转换表达式创建**隐藏分区**，查询时无需在 WHERE 子句中显式指定分区列。

#### 简单分区

```sql
CREATE TABLE prod.db.sample (
    id bigint,
    data string,
    category string
)
USING iceberg
PARTITIONED BY (category);
```

#### 转换分区（推荐）

```sql
CREATE TABLE prod.db.logs (
    id bigint,
    level string,
    message string,
    ts timestamp
)
USING iceberg
PARTITIONED BY (
    days(ts),           -- 按天分区
    bucket(16, id)      -- ID 哈希分桶
);
```

### 支持的分区转换

| 转换函数 | 说明 | 适用类型 | 示例 |
|---------|------|---------|------|
| `years(ts)` | 按年分区 | timestamp, date | `PARTITIONED BY (years(ts))` |
| `months(ts)` | 按月分区 | timestamp, date | `PARTITIONED BY (months(ts))` |
| `days(ts)` / `date(ts)` | 按天分区 | timestamp, date | `PARTITIONED BY (days(ts))` |
| `hours(ts)` / `date_hour(ts)` | 按小时分区 | timestamp | `PARTITIONED BY (hours(ts))` |
| `bucket(N, col)` | 哈希分桶（N 个桶） | int, long, string, binary, decimal, date, time, timestamp | `PARTITIONED BY (bucket(16, id))` |
| `truncate(L, col)` | 截断/分箱 | int, long, string, decimal | `PARTITIONED BY (truncate(10, data))` |

**复合分区示例：**

```sql
CREATE TABLE prod.db.events (
    event_id bigint,
    user_id bigint,
    event_type string,
    event_time timestamp,
    data string
)
USING iceberg
PARTITIONED BY (
    bucket(16, user_id),    -- 用户 ID 分桶
    days(event_time),       -- 按天分区
    event_type              -- 按事件类型分区
);
```

### 隐藏分区的优势

1. **查询简化**：无需在 WHERE 子句中指定分区列
   ```sql
   -- 传统分区表需要
   SELECT * FROM table WHERE dt='2024-01-01' AND hour='10';
   
   -- Iceberg 隐藏分区只需
   SELECT * FROM table WHERE ts >= '2024-01-01 10:00:00';
   ```

2. **分区演变**：可以随时修改分区策略而不影响现有数据

3. **避免数据倾斜**：使用 bucket 分区可以均匀分布数据

## CREATE TABLE AS SELECT (CTAS)

使用查询结果创建并填充表。

### 基本语法

```sql
CREATE TABLE [IF NOT EXISTS] table_name
USING iceberg
[PARTITIONED BY (partition_spec)]
[LOCATION 'path']
[TBLPROPERTIES ('key'='value', ...)]
AS select_statement
```

**示例：**

```sql
CREATE TABLE prod.db.summary
USING iceberg
PARTITIONED BY (days(event_date))
TBLPROPERTIES (
    'write.format.default' = 'parquet',
    'write.parquet.compression-codec' = 'snappy'
)
AS 
SELECT 
    user_id,
    event_date,
    count(*) as event_count,
    max(event_time) as last_event
FROM prod.db.events
WHERE event_date >= '2024-01-01'
GROUP BY user_id, event_date;
```

### 注意事项

1. **SparkCatalog vs SparkSessionCatalog**
   - 使用 `SparkCatalog` 时，CTAS 是**原子操作**
   - 使用 `SparkSessionCatalog` 时，CTAS **不是原子操作**

2. **不继承源表属性**
   - 新表不会继承源表的分区规范
   - 新表不会继承源表的表属性
   - 需要在 CTAS 中显式声明

## REPLACE TABLE AS SELECT (RTAS)

原子地替换现有表的内容和元数据。

### 基本语法

```sql
REPLACE TABLE table_name
USING iceberg
[PARTITIONED BY (partition_spec)]
[TBLPROPERTIES ('key'='value', ...)]
AS select_statement
```

或使用：

```sql
CREATE OR REPLACE TABLE table_name
USING iceberg
AS select_statement
```

**示例：**

```sql
-- 重建表并保留历史
REPLACE TABLE prod.db.summary
USING iceberg
PARTITIONED BY (days(event_date))
AS 
SELECT user_id, event_date, count(*) as cnt
FROM prod.db.events
GROUP BY user_id, event_date;
```

### RTAS 特性

1. **原子操作**：使用 `SparkCatalog` 时支持原子替换
2. **保留历史**：替换操作会创建新快照，但保留表的历史记录
3. **时间旅行**：仍可以查询替换前的数据

## 表属性 (TBLPROPERTIES)

### 常用表属性

```sql
CREATE TABLE prod.db.sample (...)
USING iceberg
TBLPROPERTIES (
    -- 存储格式
    'write.format.default' = 'parquet',  -- 默认: parquet
    'write.parquet.compression-codec' = 'snappy',
    
    -- 文件大小控制
    'write.target-file-size-bytes' = '536870912',  -- 512MB
    
    -- 写入分布模式
    'write.distribution-mode' = 'hash',  -- hash, range, none
    
    -- 删除模式
    'write.delete.mode' = 'merge-on-read',  -- copy-on-write, merge-on-read
    
    -- 更新模式
    'write.update.mode' = 'merge-on-read',
    
    -- 合并模式
    'write.merge.mode' = 'merge-on-read',
    
    -- 元数据配置
    'commit.manifest.min-count-to-merge' = '5',
    'commit.manifest-merge.enabled' = 'true',
    
    -- 表格式版本
    'format-version' = '2',  -- 1 或 2
    
    -- 表注释
    'comment' = 'This is a sample table'
);
```

### 写入格式配置

支持的文件格式：
- `parquet` (默认，推荐)
- `orc`
- `avro`

```sql
TBLPROPERTIES (
    'write.format.default' = 'parquet',
    'write.parquet.compression-codec' = 'snappy'  -- snappy, gzip, lz4, zstd
)
```

### 性能优化属性

```sql
TBLPROPERTIES (
    -- 目标文件大小
    'write.target-file-size-bytes' = '536870912',  -- 512MB
    
    -- 读取时的分片大小
    'read.split.target-size' = '134217728',  -- 128MB
    
    -- 启用元数据列
    'read.parquet.vectorization.enabled' = 'true',
    
    -- 文件合并
    'commit.manifest.min-count-to-merge' = '5',
    'commit.manifest-merge.enabled' = 'true'
)
```

## 指定表位置

```sql
CREATE TABLE prod.db.sample (
    id bigint,
    data string
)
USING iceberg
LOCATION 'hdfs://namenode:8020/warehouse/sample'
TBLPROPERTIES ('key' = 'value');
```

**注意事项：**
- 推荐使用外部表位置
- 确保路径对所有执行器可访问
- 删除表时注意数据清理策略

## 数据类型映射

Iceberg 支持以下 Spark 数据类型：

| Spark 类型 | Iceberg 类型 | 说明 |
|-----------|-------------|------|
| boolean | boolean | 布尔值 |
| int | int | 32位整数 |
| long / bigint | long | 64位整数 |
| float | float | 32位浮点数 |
| double | double | 64位浮点数 |
| decimal(P,S) | decimal(P,S) | 定点数 |
| date | date | 日期 |
| timestamp | timestamp | 时间戳（微秒精度）|
| string | string | 字符串 |
| binary | binary | 二进制数据 |
| array&lt;T&gt; | list&lt;T&gt; | 数组 |
| map&lt;K,V&gt; | map&lt;K,V&gt; | 映射 |
| struct&lt;...&gt; | struct&lt;...&gt; | 结构体 |

## 完整示例

```sql
-- 创建一个完整配置的 Iceberg 表
CREATE TABLE IF NOT EXISTS prod.analytics.user_events (
    -- 主键和标识
    event_id bigint NOT NULL COMMENT 'Unique event ID',
    user_id bigint NOT NULL COMMENT 'User identifier',
    session_id string COMMENT 'Session identifier',
    
    -- 事件信息
    event_type string NOT NULL COMMENT 'Event type',
    event_name string COMMENT 'Event name',
    event_properties map<string, string> COMMENT 'Event properties as key-value pairs',
    
    -- 时间戳
    event_time timestamp NOT NULL COMMENT 'Event occurrence time',
    server_time timestamp COMMENT 'Server received time',
    
    -- 用户信息
    device_type string COMMENT 'Device type',
    platform string COMMENT 'Platform',
    app_version string COMMENT 'Application version',
    
    -- 地理位置
    country string COMMENT 'Country code',
    region string COMMENT 'Region',
    city string COMMENT 'City'
)
USING iceberg
COMMENT 'User event tracking table with Iceberg format'
PARTITIONED BY (
    days(event_time),           -- 按天分区
    bucket(16, user_id)         -- 用户ID分桶16个桶
)
LOCATION 'hdfs://namenode:8020/warehouse/analytics/user_events'
TBLPROPERTIES (
    'format-version' = '2',
    'write.format.default' = 'parquet',
    'write.parquet.compression-codec' = 'snappy',
    'write.target-file-size-bytes' = '536870912',
    'write.distribution-mode' = 'hash',
    'write.metadata.delete-after-commit.enabled' = 'true',
    'write.metadata.previous-versions-max' = '10'
);
```

## 最佳实践

1. **选择合适的分区策略**
   - 根据查询模式选择分区字段
   - 使用 bucket 避免数据倾斜
   - 避免过度分区（建议每个分区 > 1GB）

2. **设置合理的文件大小**
   - 默认 512MB，可根据实际情况调整
   - 避免小文件过多影响性能

3. **使用 Format Version 2**
   - 支持行级删除和更新
   - 更好的性能和功能

4. **外部表位置**
   - 使用 LOCATION 指定表位置
   - 便于数据管理和迁移

5. **表属性文档化**
   - 使用 COMMENT 添加列和表的描述
   - 便于团队协作和维护

## 限制说明

1. **不支持 CREATE TABLE LIKE**
   ```sql
   -- 不支持
   CREATE TABLE new_table LIKE existing_table USING iceberg;
   ```

2. **分区转换限制**
   - 只能在表创建时指定
   - 后续可通过 ALTER TABLE 修改（分区演变）

3. **表属性继承**
   - CTAS 不会继承源表的属性
   - 需要显式指定所有配置
