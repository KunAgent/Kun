# 分区操作

## 概述

本文介绍TDW中的分区管理操作，包括增加分区、删除分区、清空分区等。

## 增加分区

### 基本语法

增加一级分区 - range partition：

```sql
ALTER TABLE <table_name> ADD PARTITION <partition_name> VALUES LESS THAN (const)
```

一级分区 - list partition：

```sql
ALTER TABLE <table_name> ADD PARTITION <partition_name> VALUES IN (const,...)
```

增加default partition：

```sql
ALTER TABLE <table_name> ADD DEFAULT PARTITION;
```

增加二级分区 - range partition：

```sql
ALTER TABLE <table_name> ADD SUBPARTITION <partition_name> VALUES LESS THAN (const);
```

二级分区 - list partition：

```sql
ALTER TABLE <table_name> ADD SUBPARTITION <partition_name> VALUES IN (const,...);
```

增加default subpartition：

```sql
ALTER TABLE <table_name> ADD DEFAULT SUBPARTITION;
```

### 说明

- 在分区表上增加新的分区
- 用户需要对表有alter的权限

### 注意事项

1. 如果表是两级分区的，增加一级分区后，新的一级分区内会自动按照二级分区的定义再分区。
   
   比如表一级分区为p1、p2，二级分区为sp1、sp2，则表的叶子分区为：
   - p1/sp1
   - p1/sp2
   - p2/sp1
   - p2/sp2
   
   此时如果增加一个一级分区p3，则会增加：
   - p3/sp1
   - p3/sp2
   两个叶子分区
   
   此时如果增加一个二级分区sp3，则会增加：
   - p1/sp3
   - p2/sp3
   两个叶子分区

2. 如果表在创建时没有定义一级分区，或者二级分区，则不能增加一级分区或者二级分区。

3. `DEFAULT`是默认分区的分区名，不能改变，不能用于其他分区的分区名。

4. 增加分区只是增加了元数据和目录，数据与分区的一致性需要用户去保证。例如如果新增加的分区的数据以前都在default分区中，则需要用户执行：
   
   ```sql
   INSERT INTO TABLE TABname 
   SELECT t.* FROM TABname PARTITION(default) t;
   ```
   
   来把数据导入到新的分区中。

5. 用户不能通过该命令增加hash分区。如果两级分区中的第二级分区为hash分区，则增加一级分区时，二级hash分区将自动被增加。

### 示例

表定义：

```sql
CREATE TABLE kv (
    key INT,
    value STRING
) 
PARTITION BY RANGE(key) (
    PARTITION DEFAULT
);
```

增加一个分区存放key值小于100的记录：

```sql
ALTER TABLE kv ADD PARTITION less_100 VALUES LESS THAN (100);
```

添加list分区p_20251031，存放分区值等于20251031的数据：

```sql
ALTER TABLE test ADD PARTITION p_20251031 VALUES IN (20251031);
```

## 删除分区

### 基本语法

删除一级分区：

```sql
ALTER TABLE <table_name> DROP PARTITION (<partition_name>)
```

删除二级分区：

```sql
ALTER TABLE <table_name> DROP SUBPARTITION (<partition_name>)
```

### 说明

- 删除不存在的分区，返回成功
- 用户应该对这个表有alter的权限

### 注意事项

1. 这个SQL语句将删除分区的定义和数据。

2. 删除一级分区会导致一级分区下的所有二级分区删除；删除二级分区会导致所有一级分区下的该二级分区被删除。
   
   比如表一级分区为p1、p2，二级分区为sp1、sp2，则表的叶子分区为：
   - p1/sp1
   - p1/sp2
   - p2/sp1
   - p2/sp2
   
   如果这时删除一级分区p1，则会删除：
   - p1/sp1
   - p1/sp2
   两个叶子分区
   
   如果这时删除二级分区sp1，则会删除：
   - p1/sp1
   - p2/sp1
   两个叶子分区

3. 用户不能删除hash分区。如果hash分区为二级分区，则删除一级分区时二级分区将自动被删除。

### 示例

删除分区p2：

```sql
ALTER TABLE test DROP PARTITION (p2);
```

## 清空分区

### 基本语法

清空一个叶子分区：

```sql
ALTER TABLE <table_name> TRUNCATE PARTITION <(pripar_name,subpar_name)>;
```

清空一个一级分区：

```sql
ALTER TABLE <table_name> TRUNCATE PARTITION <(par_name)>;
```

清空一个二级分区：

```sql
ALTER TABLE <table_name> TRUNCATE SUBPARTITION <(par_name)>;
```

### 说明

- 删除分区中的数据，保留分区元数据
- 用户需要对表有delete权限

### 注意事项

- 清空一级分区会导致该一级分区下的所有数据删除
- 清空二级分区会导致所有一级分区下的该二级分区数据删除
- 清空叶子分区只删除指定一级分区下的指定二级分区里的数据
- 用户不能指定清除hash分区

### 示例

清空分区p1：

```sql
ALTER TABLE test TRUNCATE PARTITION (p1);
```

清除test表p1分区下的sp1子分区：

```sql
ALTER TABLE test TRUNCATE PARTITION (p1,sp1);
```

## 使用注意事项

### 分区设计建议

1. **合理规划分区层级**
   - 最多支持两级分区
   - 根据查询习惯选择分区字段
   - 避免分区过多导致小文件问题

2. **default分区使用**
   - default分区可以接收不匹配其他分区的数据
   - 后续添加分区时，default分区数据不会自动迁移
   - 如果不希望接收脏数据，可以不创建default分区

3. **分区命名规范**
   - 使用有意义的分区名
   - 保持命名一致性
   - 避免使用保留字（如DEFAULT）

### 分区操作最佳实践

1. **批量添加分区**
   ```sql
   -- 一次性添加多个分区
   ALTER TABLE sales ADD PARTITION p_202401 VALUES IN (202401);
   ALTER TABLE sales ADD PARTITION p_202402 VALUES IN (202402);
   ALTER TABLE sales ADD PARTITION p_202403 VALUES IN (202403);
   ```

2. **删除前备份**
   ```sql
   -- 删除分区前先备份数据
   CREATE TABLE sales_backup LIKE sales;
   INSERT OVERWRITE TABLE sales_backup PARTITION(p_202401)
   SELECT * FROM sales PARTITION(p_202401);
   
   -- 然后再删除
   ALTER TABLE sales DROP PARTITION (p_202401);
   ```

3. **定期清理过期分区**
   ```sql
   -- 清理3个月前的分区数据
   ALTER TABLE logs TRUNCATE PARTITION (p_202110);
   ```

## 完整示例

### 创建两级分区表并进行操作

```sql
-- 1. 创建两级分区表
CREATE TABLE sales_detail (
    order_id STRING,
    product_name STRING,
    amount DOUBLE
)
PARTITION BY RANGE(year)
SUBPARTITION BY LIST(quarter) (
    SUBPARTITION q1 VALUES IN (1),
    SUBPARTITION q2 VALUES IN (2),
    SUBPARTITION q3 VALUES IN (3),
    SUBPARTITION q4 VALUES IN (4),
    SUBPARTITION DEFAULT
) (
    PARTITION y2023 VALUES LESS THAN (2024),
    PARTITION y2024 VALUES LESS THAN (2025),
    PARTITION DEFAULT
);

-- 2. 添加新的一级分区（会自动创建所有二级分区）
ALTER TABLE sales_detail ADD PARTITION y2025 VALUES LESS THAN (2026);

-- 3. 查看分区结构
SHOW PARTITIONS sales_detail;

-- 4. 添加新的二级分区（会在所有一级分区下创建）
ALTER TABLE sales_detail ADD SUBPARTITION q5 VALUES IN (5);

-- 5. 清空某个叶子分区的数据
ALTER TABLE sales_detail TRUNCATE PARTITION (y2023, q1);

-- 6. 删除整个一级分区
ALTER TABLE sales_detail DROP PARTITION (y2023);
```

### Range分区示例

```sql
-- 创建range分区表
CREATE TABLE orders (
    order_id STRING,
    amount DOUBLE
)
PARTITION BY RANGE(order_id) (
    PARTITION p1 VALUES LESS THAN (1000),
    PARTITION p2 VALUES LESS THAN (5000),
    PARTITION p3 VALUES LESS THAN (10000),
    PARTITION DEFAULT
);

-- 添加新的range分区
ALTER TABLE orders ADD PARTITION p4 VALUES LESS THAN (20000);
```

### List分区示例

```sql
-- 创建list分区表
CREATE TABLE user_logs (
    user_id STRING,
    action STRING
)
PARTITION BY LIST(region) (
    PARTITION p_north VALUES IN ('beijing', 'tianjin', 'hebei'),
    PARTITION p_south VALUES IN ('guangdong', 'guangxi', 'hainan'),
    PARTITION p_east VALUES IN ('shanghai', 'jiangsu', 'zhejiang'),
    PARTITION DEFAULT
);

-- 添加新的list分区
ALTER TABLE user_logs ADD PARTITION p_west VALUES IN ('sichuan', 'chongqing', 'yunnan');
```

## 常见错误处理

### 分区已存在

```sql
-- 错误：分区已存在
ALTER TABLE sales ADD PARTITION p_202401 VALUES IN (202401);
-- Error: Partition already exists

-- 解决：先检查分区是否存在
SHOW PARTITIONS sales;
```

### 无法添加分区

```sql
-- 错误：表不是分区表
ALTER TABLE normal_table ADD PARTITION p1 VALUES LESS THAN (100);
-- Error: Table is not partitioned

-- 解决：只能在创建表时定义分区
```

### 删除不存在的分区

```sql
-- 删除不存在的分区不会报错
ALTER TABLE sales DROP PARTITION (p_not_exists);
-- Success (即使分区不存在)
```
