# 5.4 DCL语句

## 概述

DCL（Data Control Language，数据控制语言）是SQL语言中用于控制数据库访问权限的语句集合。SuperSQL的DCL语句用于管理外部数据源的访问权限，通过与天穹安全中心Ranger集成，提供细粒度的权限控制。

### 核心特性

- **用户权限管理**：支持GRANT和REVOKE用户权限
- **角色权限管理**：支持基于角色（资源应用组）的权限授予
- **细粒度控制**：支持数据源级别和表级别的权限控制
- **Ranger集成**：与天穹安全中心Ranger深度集成

---

## 重要说明

⚠️ **天穹内部数据源限制**

天穹TDW Hive和社区Hive数据库对应的SuperSQL数据源，均为**系统自动注册的内部数据源**，这些数据源有以下特点：

- 数据源名字和对应的库名相同
- 权限由TDW自动同步
- **不支持SuperSQL DCL命令**（GRANT/REVOKE）
- 执行DCL命令会抛出异常

**本章节描述的内容仅适用于用户自行注册的外部数据源**（如MySQL、PostgreSQL、ClickHouse等）。

### 适用数据源

| 数据源类型 | DCL支持 | 说明 |
|-----------|---------|------|
| **天穹TDW Hive** | ❌ 不支持 | 系统自动同步权限 |
| **社区Hive** | ❌ 不支持 | 系统自动同步权限 |
| **MySQL** | ✅ 支持 | 外部数据源 |
| **PostgreSQL** | ✅ 支持 | 外部数据源 |
| **ClickHouse** | ✅ 支持 | 外部数据源 |
| **Oracle** | ✅ 支持 | 外部数据源 |
| **SQL Server** | ✅ 支持 | 外部数据源 |
| **其他外部数据源** | ✅ 支持 | 用户自行注册的数据源 |

## 权限类型

SuperSQL支持以下权限类型：

| 权限 | 说明 | 适用操作 |
|------|------|---------|
| **ALL** | 所有权限 | 代表所有其他权限 |
| **CREATE** | 创建权限 | CREATE TABLE、CREATE VIEW |
| **DROP** | 删除权限 | DROP TABLE、DROP VIEW |
| **ALTER** | 修改权限 | ALTER TABLE（透传模式） |
| **REFRESH** | 刷新权限 | 刷新元数据 |
| **SELECT** | 查询权限 | SELECT查询 |
| **DESCRIBE** | 描述权限 | DESCRIBE TABLE、SHOW TABLES |

### 权限说明

**ALL权限**：
- 包含所有其他权限（CREATE、DROP、ALTER、REFRESH、SELECT、DESCRIBE）
- 只有拥有ALL权限的用户才能执行GRANT/REVOKE命令
- 通常授予数据源管理员

**常用权限组合**：
- **只读用户**：SELECT + DESCRIBE
- **开发用户**：SELECT + DESCRIBE + CREATE + DROP
- **管理员用户**：ALL

## 授予用户权限

### 语法

```sql
-- 授予数据源级别权限
GRANT privilege ON DATASOURCE datasourceName TO USER userName;

-- 授予表级别权限
GRANT privilege ON TABLE tableName IN DATASOURCE datasourceName TO USER userName;
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `privilege` | 权限类型（ALL、CREATE、DROP、ALTER、REFRESH、SELECT、DESCRIBE） |
| `datasourceName` | 数据源名称 |
| `tableName` | 表名 |
| `userName` | 用户名（天穹用户ID） |

### 权限层级

SuperSQL的权限分为两个层级：

1. **数据源级别**：授予用户对整个数据源的权限
2. **表级别**：授予用户对数据源中特定表的权限

**重要**：如果用户被授予了某一外部数据源的X权限，那么用户就**自动拥有**该数据源中**所有表**的X权限。

### 权限优先级

对于外部数据源表，如果在SuperSQL中GRANT了权限，其**优先级高于**数据源自身的JDBC用户名/密码鉴权。

**优先级顺序**：
1. SuperSQL Ranger权限（最高）
2. 数据源自身的权限控制
3. JDBC连接的用户名/密码鉴权（最低）

### 基本示例

#### 示例1：授予数据源所有权限

```sql
-- 授予user1对mysql_online数据源的所有权限
GRANT ALL ON DATASOURCE mysql_online TO USER user1;
```

**说明**：
- user1将拥有mysql_online数据源的所有权限
- user1可以对该数据源执行任何操作（创建、删除、查询等）
- user1也可以授予或撤销其他用户的权限

#### 示例2：授予数据源查询权限

```sql
-- 授予user2对pg_datasource数据源的查询权限
GRANT SELECT ON DATASOURCE pg_datasource TO USER user2;
```

**说明**：
- user2只能查询pg_datasource数据源中的表
- user2无法执行CREATE、DROP等操作

#### 示例3：授予表级别权限

```sql
-- 授予user3对dc1.cluster1.hive1数据源中temp表的CREATE权限
GRANT CREATE ON TABLE temp IN DATASOURCE dc1.cluster1.hive1 TO USER user3;
```

**说明**：
- user3只对temp表有CREATE权限
- user3对该数据源的其他表没有任何权限（除非另外授予）

#### 示例4：授予多个权限（分别执行）

```sql
-- 授予user4查询和描述权限（分两条命令）
GRANT SELECT ON DATASOURCE mysql_online TO USER user4;
GRANT DESCRIBE ON DATASOURCE mysql_online TO USER user4;
```

**说明**：
- SuperSQL不支持一条命令授予多个权限
- 需要分别执行多条GRANT命令

#### 示例5：授予表的只读权限

```sql
-- 授予user5对特定表的只读权限
GRANT SELECT ON TABLE orders IN DATASOURCE mysql_online TO USER user5;
GRANT DESCRIBE ON TABLE orders IN DATASOURCE mysql_online TO USER user5;
```

**说明**：
- user5可以查询和描述orders表
- user5无法修改或删除该表

### 注意事项

⚠️ **执行权限要求**：
- 只有对该数据源有**ALL权限**的用户才能执行GRANT命令
- 数据源创建者默认拥有ALL权限

✅ **幂等性**：
- 同一条有效的授权命令可以被**重复执行多次**
- 不会因重复授予相同权限而报错或警告
- 这是一个安全的设计，便于权限管理脚本的幂等执行

**示例**：
```sql
-- 重复执行不会报错
GRANT SELECT ON DATASOURCE mysql_online TO USER user1;
GRANT SELECT ON DATASOURCE mysql_online TO USER user1;
GRANT SELECT ON DATASOURCE mysql_online TO USER user1;
-- ✅ 都会成功执行，不会报错
```

## 撤销用户权限

### 语法

```sql
-- 撤销数据源级别权限
REVOKE privilege ON DATASOURCE datasourceName FROM USER userName;

-- 撤销表级别权限
REVOKE privilege ON TABLE tableName IN DATASOURCE datasourceName FROM USER userName;
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `privilege` | 权限类型（ALL、CREATE、DROP、ALTER、REFRESH、SELECT、DESCRIBE） |
| `datasourceName` | 数据源名称 |
| `tableName` | 表名 |
| `userName` | 用户名（天穹用户ID） |

### 基本示例

#### 示例1：撤销数据源所有权限

```sql
-- 撤销user3对mysql_online数据源的所有权限
REVOKE ALL ON DATASOURCE mysql_online FROM USER user3;
```

**说明**：
- user3将失去mysql_online数据源的所有权限
- user3无法再访问该数据源中的任何表

#### 示例2：撤销数据源查询权限

```sql
-- 撤销user4对pg_datasource数据源的查询权限
REVOKE SELECT ON DATASOURCE pg_datasource FROM USER user4;
```

**说明**：
- user4失去查询权限，但可能仍有其他权限（如DESCRIBE）
- 如果要完全禁止访问，需要撤销所有权限

#### 示例3：撤销表级别权限

```sql
-- 撤销user4对dc1.cluster1.hive1数据源中temp表的DROP权限
REVOKE DROP ON TABLE temp IN DATASOURCE dc1.cluster1.hive1 FROM USER user4;
```

**说明**：
- user4失去对temp表的DROP权限
- user4对该表可能仍有其他权限（如SELECT）

#### 示例4：撤销多个权限（分别执行）

```sql
-- 撤销user5的多个权限（分两条命令）
REVOKE SELECT ON DATASOURCE mysql_online FROM USER user5;
REVOKE DESCRIBE ON DATASOURCE mysql_online FROM USER user5;
```

#### 示例5：撤销表的只读权限

```sql
-- 撤销user6对特定表的只读权限
REVOKE SELECT ON TABLE orders IN DATASOURCE mysql_online FROM USER user6;
REVOKE DESCRIBE ON TABLE orders IN DATASOURCE mysql_online FROM USER user6;
```

### 注意事项

⚠️ **执行权限要求**：
- 只有对该数据源有**ALL权限**的用户才能执行REVOKE命令

✅ **幂等性**：
- 同一条有效的撤销命令可以被**重复执行多次**
- 不会因重复撤销相同权限而报错或警告

**示例**：
```sql
-- 重复执行不会报错
REVOKE SELECT ON DATASOURCE mysql_online FROM USER user1;
REVOKE SELECT ON DATASOURCE mysql_online FROM USER user1;
REVOKE SELECT ON DATASOURCE mysql_online FROM USER user1;
-- ✅ 都会成功执行，不会报错
```

⚠️ **权限不会自动传播**：
- 撤销数据源级别的权限，**不会自动撤销**该用户对表级别的权限
- 如果需要完全撤销访问，需要分别撤销数据源和表级别的权限

## 授予角色权限

### 语法

```sql
-- 授予数据源级别权限给角色
GRANT privilege ON DATASOURCE datasourceName TO ROLE roleName;

-- 授予表级别权限给角色
GRANT privilege ON TABLE tableName IN DATASOURCE datasourceName TO ROLE roleName;
```

### 角色说明

在SuperSQL中，**角色（ROLE）**指的是**TDW的资源应用组**（如`g_tdw_supersql`）。

**角色的作用**：
- 将权限授予角色，角色中的所有用户自动拥有该权限
- 便于批量管理用户权限
- 简化权限分配流程

### 参数说明

| 参数 | 说明 |
|------|------|
| `privilege` | 权限类型（ALL、CREATE、DROP、ALTER、REFRESH、SELECT、DESCRIBE） |
| `datasourceName` | 数据源名称 |
| `tableName` | 表名 |
| `roleName` | 角色名称（TDW资源应用组名） |

### 基本示例

#### 示例1：授予角色数据源所有权限

```sql
-- 授予role1对dc1.cluster1.hive1数据源的所有权限
GRANT ALL ON DATASOURCE dc1.cluster1.hive1 TO ROLE role1;
```

**说明**：
- role1角色的所有成员都拥有该数据源的所有权限
- 新加入role1的用户自动获得权限

#### 示例2：授予角色查询权限

```sql
-- 授予data_analyst角色对mysql_online数据源的查询权限
GRANT SELECT ON DATASOURCE mysql_online TO ROLE data_analyst;
```

**说明**：
- data_analyst角色的所有成员都可以查询mysql_online数据源
- 适合数据分析团队的只读权限管理

#### 示例3：授予角色表级别权限

```sql
-- 授予role2对hive_online数据源中temp2表的SELECT权限
GRANT SELECT ON TABLE temp2 IN DATASOURCE hive_online TO ROLE role2;
```

**说明**：
- role2角色的成员只能查询temp2表
- 对其他表没有权限

#### 示例4：授予多个权限给角色

```sql
-- 授予开发角色多个权限
GRANT SELECT ON DATASOURCE mysql_online TO ROLE developer;
GRANT DESCRIBE ON DATASOURCE mysql_online TO ROLE developer;
GRANT CREATE ON DATASOURCE mysql_online TO ROLE developer;
GRANT DROP ON DATASOURCE mysql_online TO ROLE developer;
```

**说明**：
- developer角色拥有查询、描述、创建、删除权限
- 适合开发团队的权限配置

#### 示例5：分层权限管理

```sql
-- 为不同角色授予不同权限
-- 只读角色
GRANT SELECT ON DATASOURCE mysql_online TO ROLE readonly_users;
GRANT DESCRIBE ON DATASOURCE mysql_online TO ROLE readonly_users;

-- 开发角色
GRANT SELECT ON DATASOURCE mysql_online TO ROLE developers;
GRANT DESCRIBE ON DATASOURCE mysql_online TO ROLE developers;
GRANT CREATE ON DATASOURCE mysql_online TO ROLE developers;
GRANT DROP ON DATASOURCE mysql_online TO ROLE developers;

-- 管理员角色
GRANT ALL ON DATASOURCE mysql_online TO ROLE admins;
```

## 撤销角色权限

### 语法

```sql
-- 撤销数据源级别权限
REVOKE privilege ON DATASOURCE datasourceName FROM ROLE roleName;

-- 撤销表级别权限
REVOKE privilege ON TABLE tableName IN DATASOURCE datasourceName FROM ROLE roleName;
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `privilege` | 权限类型（ALL、CREATE、DROP、ALTER、REFRESH、SELECT、DESCRIBE） |
| `datasourceName` | 数据源名称 |
| `tableName` | 表名 |
| `roleName` | 角色名称（TDW资源应用组名） |

### 基本示例

#### 示例1：撤销角色数据源所有权限

```sql
-- 撤销role3对dc1.cluster1.hive1数据源的所有权限
REVOKE ALL ON DATASOURCE dc1.cluster1.hive1 FROM ROLE role3;
```

**说明**：
- role3角色的所有成员都失去该数据源的所有权限

#### 示例2：撤销角色查询权限

```sql
-- 撤销data_analyst角色对pg_datasource数据源的查询权限
REVOKE SELECT ON DATASOURCE pg_datasource FROM ROLE data_analyst;
```

#### 示例3：撤销角色表级别权限

```sql
-- 撤销role4对hive_online数据源中temp表的ALTER权限
REVOKE ALTER ON TABLE temp IN DATASOURCE hive_online FROM ROLE role4;
```

#### 示例4：撤销多个权限

```sql
-- 撤销开发角色的创建和删除权限（保留查询权限）
REVOKE CREATE ON DATASOURCE mysql_online FROM ROLE developer;
REVOKE DROP ON DATASOURCE mysql_online FROM ROLE developer;
-- developer角色仍保留SELECT和DESCRIBE权限
```

#### 示例5：清理角色所有权限

```sql
-- 完全清理某个角色的权限
REVOKE ALL ON DATASOURCE mysql_online FROM ROLE temp_role;
```

## 使用场景

### 场景1：新数据源初始化权限

**需求**：为新创建的MySQL数据源配置权限

```sql
-- 1. 创建数据源（由管理员执行）
CREATE DATASOURCE mysql_prod WITH (
    type = 'mysql',
    host = 'mysql.example.com',
    port = '3306',
    database = 'production',
    user = 'supersql',
    password = 'xxxxxx'
);

-- 2. 授予管理员所有权限
GRANT ALL ON DATASOURCE mysql_prod TO ROLE admins;

-- 3. 授予开发团队读写权限
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE developers;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE developers;
GRANT CREATE ON DATASOURCE mysql_prod TO ROLE developers;
GRANT DROP ON DATASOURCE mysql_prod TO ROLE developers;

-- 4. 授予数据分析团队只读权限
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE analysts;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE analysts;

-- 5. 授予特定用户表级别权限
GRANT SELECT ON TABLE sensitive_data IN DATASOURCE mysql_prod TO USER data_owner;
```

### 场景2：临时项目权限管理

**需求**：为临时项目授予临时权限，项目结束后撤销

```sql
-- 项目开始：授予项目组权限
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE project_team;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE project_team;
GRANT CREATE ON DATASOURCE mysql_prod TO ROLE project_team;

-- 项目结束：撤销权限
REVOKE CREATE ON DATASOURCE mysql_prod FROM ROLE project_team;
REVOKE SELECT ON DATASOURCE mysql_prod FROM ROLE project_team;
REVOKE DESCRIBE ON DATASOURCE mysql_prod FROM ROLE project_team;
```

### 场景3：敏感表的细粒度控制

**需求**：对敏感表进行细粒度的权限控制

```sql
-- 1. 普通表：所有开发人员可访问
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE developers;

-- 2. 敏感表：只授予特定用户
GRANT SELECT ON TABLE customer_pii IN DATASOURCE mysql_prod TO USER compliance_officer1;
GRANT SELECT ON TABLE customer_pii IN DATASOURCE mysql_prod TO USER compliance_officer2;

-- 3. 财务表：只授予财务角色
GRANT SELECT ON TABLE financial_records IN DATASOURCE mysql_prod TO ROLE finance_team;
GRANT DESCRIBE ON TABLE financial_records IN DATASOURCE mysql_prod TO ROLE finance_team;
```

### 场景4：分层权限架构

**需求**：建立分层的权限管理架构

```sql
-- 第1层：超级管理员（所有权限）
GRANT ALL ON DATASOURCE mysql_prod TO ROLE super_admins;
GRANT ALL ON DATASOURCE pg_prod TO ROLE super_admins;
GRANT ALL ON DATASOURCE clickhouse_prod TO ROLE super_admins;

-- 第2层：数据源管理员（单个数据源所有权限）
GRANT ALL ON DATASOURCE mysql_prod TO ROLE mysql_admins;
GRANT ALL ON DATASOURCE pg_prod TO ROLE pg_admins;

-- 第3层：开发人员（读写权限）
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE developers;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE developers;
GRANT CREATE ON DATASOURCE mysql_prod TO ROLE developers;
GRANT DROP ON DATASOURCE mysql_prod TO ROLE developers;

-- 第4层：数据分析师（只读权限）
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE analysts;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE analysts;

-- 第5层：实习生（特定表只读权限）
GRANT SELECT ON TABLE public_data IN DATASOURCE mysql_prod TO ROLE interns;
GRANT DESCRIBE ON TABLE public_data IN DATASOURCE mysql_prod TO ROLE interns;
```

### 场景5：跨部门数据共享

**需求**：在保证安全的前提下实现跨部门数据共享

```sql
-- 销售部门：拥有销售数据的完全控制权
GRANT ALL ON TABLE sales_data IN DATASOURCE mysql_prod TO ROLE sales_team;

-- 市场部门：可以查询销售数据进行分析
GRANT SELECT ON TABLE sales_data IN DATASOURCE mysql_prod TO ROLE marketing_team;
GRANT DESCRIBE ON TABLE sales_data IN DATASOURCE mysql_prod TO ROLE marketing_team;

-- 财务部门：可以查询销售数据进行核算
GRANT SELECT ON TABLE sales_data IN DATASOURCE mysql_prod TO ROLE finance_team;

-- 数据科学团队：可以查询所有部门数据
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE data_science;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE data_science;
```

## 最佳实践

### 1. 优先使用角色管理权限

**✅ 推荐做法**：
- 为不同职能创建角色
- 将权限授予角色而非个人
- 通过角色成员管理来控制用户权限

```sql
-- ✅ 推荐：授予角色
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE analysts;
-- 然后通过TDW管理界面将用户加入analysts角色
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：逐个授予用户（难以维护）
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;
GRANT SELECT ON DATASOURCE mysql_prod TO USER user2;
GRANT SELECT ON DATASOURCE mysql_prod TO USER user3;
-- ...数百个用户
```

### 2. 遵循最小权限原则

**✅ 推荐做法**：
- 只授予用户完成工作所需的最小权限
- 避免过度授权
- 定期审计和回收不必要的权限

```sql
-- ✅ 推荐：只读用户只授予SELECT和DESCRIBE
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE readonly_users;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE readonly_users;
```

**❌ 不推荐做法**：
```sql
-- ❌ 不推荐：给所有人ALL权限
GRANT ALL ON DATASOURCE mysql_prod TO ROLE all_users;
```

### 3. 敏感数据使用表级别权限

**✅ 推荐做法**：
- 对敏感表使用表级别权限控制
- 限制有权访问的人员范围
- 使用专门的角色管理敏感数据访问

```sql
-- ✅ 推荐：敏感表使用表级别权限
-- 普通表：数据源级别权限（所有人可访问）
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE all_employees;

-- 敏感表：表级别权限（只有特定角色可访问）
GRANT SELECT ON TABLE customer_pii IN DATASOURCE mysql_prod TO ROLE compliance_team;
GRANT SELECT ON TABLE salary_info IN DATASOURCE mysql_prod TO ROLE hr_team;
```

### 4. 使用幂等脚本管理权限

**✅ 推荐做法**：
- 将权限配置写成可重复执行的脚本
- 利用GRANT/REVOKE的幂等性
- 便于版本控制和自动化部署

```sql
-- ✅ 推荐：权限配置脚本（可重复执行）
-- init_permissions.sql

-- 基础权限
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE analysts;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE analysts;

-- 开发权限
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE developers;
GRANT DESCRIBE ON DATASOURCE mysql_prod TO ROLE developers;
GRANT CREATE ON DATASOURCE mysql_prod TO ROLE developers;
GRANT DROP ON DATASOURCE mysql_prod TO ROLE developers;

-- 管理员权限
GRANT ALL ON DATASOURCE mysql_prod TO ROLE admins;
```

### 5. 定期审计权限

**✅ 推荐做法**：
- 定期检查Ranger中的权限配置
- 发现并撤销不再需要的权限
- 记录权限变更历史

**审计检查清单**：
- [ ] 离职人员的权限是否已撤销
- [ ] 临时项目的权限是否已回收
- [ ] 是否有过度授权的情况
- [ ] 敏感数据的访问权限是否合理
- [ ] 角色成员是否需要调整

### 6. 数据源创建时立即配置权限

**✅ 推荐做法**：
- 创建数据源后立即配置基础权限
- 避免数据源处于无权限控制的状态
- 使用标准的权限配置模板

```sql
-- ✅ 推荐：创建数据源后立即配置权限
-- 1. 创建数据源
CREATE DATASOURCE new_datasource WITH (...);

-- 2. 立即授予管理员权限
GRANT ALL ON DATASOURCE new_datasource TO ROLE admins;

-- 3. 配置基础权限
GRANT SELECT ON DATASOURCE new_datasource TO ROLE readonly_users;
GRANT DESCRIBE ON DATASOURCE new_datasource TO ROLE readonly_users;
```

## 常见问题FAQ

### 1. 为什么对TDW Hive执行DCL命令会报错？

**答案**：TDW Hive是系统自动注册的内部数据源，权限由TDW自动同步，不支持SuperSQL DCL命令。

**错误示例**：
```sql
-- ❌ 错误：TDW Hive不支持DCL
GRANT SELECT ON DATASOURCE tdw_hive_db TO USER user1;
-- 会抛出异常
```

**解决方案**：
- TDW Hive的权限通过TDW管理界面配置
- SuperSQL DCL只能用于外部数据源（MySQL、PostgreSQL等）

---

### 2. 如何查看当前用户拥有的权限？

**答案**：通过天穹安全中心Ranger界面查看权限配置。

**步骤**：
1. 登录天穹管理平台
2. 进入"安全中心" → "Ranger"
3. 搜索数据源名称
4. 查看该数据源的权限策略

**注意**：SuperSQL目前没有提供SQL命令查看权限（如`SHOW GRANTS`）。

---

### 3. 授予数据源权限后，用户自动拥有所有表的权限吗？

**答案**：是的，授予数据源级别的权限后，用户自动拥有该数据源中**所有表**的相应权限。

**示例**：
```sql
-- 授予数据源级别的SELECT权限
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;

-- user1现在可以查询mysql_prod中的所有表
SELECT * FROM mysql_prod.table1;  -- ✅ 可以
SELECT * FROM mysql_prod.table2;  -- ✅ 可以
SELECT * FROM mysql_prod.table3;  -- ✅ 可以
```

**如果需要限制特定表**：
- 不要授予数据源级别权限
- 只授予特定表的权限

```sql
-- 只授予table1的权限
GRANT SELECT ON TABLE table1 IN DATASOURCE mysql_prod TO USER user1;

-- user1只能查询table1
SELECT * FROM mysql_prod.table1;  -- ✅ 可以
SELECT * FROM mysql_prod.table2;  -- ❌ 无权限
```

---

### 4. 表级别权限和数据源级别权限冲突时，以哪个为准？

**答案**：表级别权限和数据源级别权限是**叠加**的，不是覆盖关系。

**权限叠加规则**：
- 用户拥有的权限 = 数据源级别权限 ∪ 表级别权限
- 即用户拥有两者的**并集**

**示例**：
```sql
-- 用户拥有数据源级别的SELECT权限
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;

-- 又授予特定表的CREATE权限
GRANT CREATE ON TABLE table1 IN DATASOURCE mysql_prod TO USER user1;

-- 结果：user1拥有
-- - mysql_prod中所有表的SELECT权限
-- - table1的CREATE权限
```

---

### 5. 撤销数据源权限会同时撤销表级别权限吗？

**答案**：**不会**。撤销数据源级别权限，不会自动撤销表级别权限。

**示例**：
```sql
-- 1. 授予数据源级别和表级别权限
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;
GRANT CREATE ON TABLE table1 IN DATASOURCE mysql_prod TO USER user1;

-- 2. 撤销数据源级别权限
REVOKE SELECT ON DATASOURCE mysql_prod FROM USER user1;

-- 3. 结果
-- user1对mysql_prod的所有表失去SELECT权限
-- 但user1仍然拥有table1的CREATE权限
```

**如果需要完全撤销**：
```sql
-- 分别撤销数据源和表级别权限
REVOKE SELECT ON DATASOURCE mysql_prod FROM USER user1;
REVOKE CREATE ON TABLE table1 IN DATASOURCE mysql_prod FROM USER user1;
```

---

### 6. 可以一条命令授予多个权限吗？

**答案**：**不可以**。SuperSQL不支持一条命令授予多个权限，需要分别执行。

**错误示例**：
```sql
-- ❌ 错误：不支持
GRANT SELECT, CREATE, DROP ON DATASOURCE mysql_prod TO USER user1;
```

**正确做法**：
```sql
-- ✅ 正确：分别授予
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;
GRANT CREATE ON DATASOURCE mysql_prod TO USER user1;
GRANT DROP ON DATASOURCE mysql_prod TO USER user1;

-- 或者使用ALL代表所有权限
GRANT ALL ON DATASOURCE mysql_prod TO USER user1;
```

---

### 7. 重复执行GRANT命令会报错吗？

**答案**：**不会**。GRANT和REVOKE命令是幂等的，可以重复执行。

**示例**：
```sql
-- 重复执行不会报错
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;
-- ✅ 都会成功执行
```

**好处**：
- 便于编写幂等的权限配置脚本
- 不用担心重复授权导致脚本失败

---

### 8. 用户权限和角色权限可以同时授予吗？

**答案**：可以，用户同时拥有直接授予的权限和角色权限。

**权限叠加规则**：
- 用户拥有的权限 = 直接授予的权限 ∪ 角色权限
- 即用户拥有两者的**并集**

**示例**：
```sql
-- 1. 通过角色授予SELECT权限
GRANT SELECT ON DATASOURCE mysql_prod TO ROLE analysts;
-- 用户user1是analysts角色成员

-- 2. 直接授予user1 CREATE权限
GRANT CREATE ON DATASOURCE mysql_prod TO USER user1;

-- 3. 结果：user1拥有
-- - SELECT权限（来自角色）
-- - CREATE权限（直接授予）
```

---

### 9. SuperSQL权限和数据源自身权限的关系？

**答案**：SuperSQL权限（Ranger）**优先级更高**，会覆盖数据源自身的权限控制。

**优先级顺序**：
1. **SuperSQL Ranger权限**（最高优先级）
2. 数据源自身的权限系统
3. JDBC连接的用户名/密码（最低优先级）

**示例**：
```sql
-- 场景：MySQL数据源，JDBC用户名为root（有所有权限）

-- 1. 在SuperSQL中，user1只被授予SELECT权限
GRANT SELECT ON DATASOURCE mysql_prod TO USER user1;

-- 2. user1的实际权限
-- ✅ 可以执行SELECT
SELECT * FROM mysql_prod.table1;

-- ❌ 无法执行DROP（即使JDBC用户是root）
DROP TABLE mysql_prod.table1;  -- 权限拒绝
```

**说明**：
- 即使数据源连接使用的是root用户
- SuperSQL仍然会限制user1只能执行SELECT操作
- Ranger权限控制优先

---

### 10. 如何收回某个用户的所有权限？

**答案**：需要分别撤销数据源级别和表级别的权限。

**完整步骤**：

```sql
-- 1. 撤销数据源级别的所有权限
REVOKE ALL ON DATASOURCE mysql_prod FROM USER user1;

-- 2. 撤销表级别的权限（需要知道具体授予了哪些表）
REVOKE ALL ON TABLE table1 IN DATASOURCE mysql_prod FROM USER user1;
REVOKE ALL ON TABLE table2 IN DATASOURCE mysql_prod FROM USER user1;
-- ...

-- 3. 如果用户通过角色获得权限，从角色中移除该用户
-- 需要在TDW管理界面操作，将user1从角色中移除
```

**建议**：
- 在授予权限时做好记录
- 使用标准的权限配置模板
- 定期审计权限配置

## 附录：完整权限配置示例

### 场景：多租户数据平台权限配置

**业务需求**：
- 支持3个部门（销售、市场、财务）
- 每个部门有自己的数据源
- 实现数据隔离和有限共享
- 提供分层权限管理

**数据源列表**：
- `mysql_sales`：销售部门数据源
- `mysql_marketing`：市场部门数据源
- `pg_finance`：财务部门数据源
- `mysql_shared`：共享数据源

**完整权限配置脚本**：

```sql
-- ========================================
-- 第1步：超级管理员配置
-- ========================================

-- 超级管理员拥有所有数据源的所有权限
GRANT ALL ON DATASOURCE mysql_sales TO ROLE super_admins;
GRANT ALL ON DATASOURCE mysql_marketing TO ROLE super_admins;
GRANT ALL ON DATASOURCE pg_finance TO ROLE super_admins;
GRANT ALL ON DATASOURCE mysql_shared TO ROLE super_admins;

-- ========================================
-- 第2步：部门管理员配置
-- ========================================

-- 销售部门管理员
GRANT ALL ON DATASOURCE mysql_sales TO ROLE sales_admins;

-- 市场部门管理员
GRANT ALL ON DATASOURCE mysql_marketing TO ROLE marketing_admins;

-- 财务部门管理员
GRANT ALL ON DATASOURCE pg_finance TO ROLE finance_admins;

-- 共享数据源管理员
GRANT ALL ON DATASOURCE mysql_shared TO ROLE shared_data_admins;

-- ========================================
-- 第3步：部门开发人员配置
-- ========================================

-- 销售部门开发人员（对自己数据源有读写权限）
GRANT SELECT ON DATASOURCE mysql_sales TO ROLE sales_developers;
GRANT DESCRIBE ON DATASOURCE mysql_sales TO ROLE sales_developers;
GRANT CREATE ON DATASOURCE mysql_sales TO ROLE sales_developers;
GRANT DROP ON DATASOURCE mysql_sales TO ROLE sales_developers;

-- 市场部门开发人员
GRANT SELECT ON DATASOURCE mysql_marketing TO ROLE marketing_developers;
GRANT DESCRIBE ON DATASOURCE mysql_marketing TO ROLE marketing_developers;
GRANT CREATE ON DATASOURCE mysql_marketing TO ROLE marketing_developers;
GRANT DROP ON DATASOURCE mysql_marketing TO ROLE marketing_developers;

-- 财务部门开发人员
GRANT SELECT ON DATASOURCE pg_finance TO ROLE finance_developers;
GRANT DESCRIBE ON DATASOURCE pg_finance TO ROLE finance_developers;
GRANT CREATE ON DATASOURCE pg_finance TO ROLE finance_developers;
GRANT DROP ON DATASOURCE pg_finance TO ROLE finance_developers;

-- ========================================
-- 第4步：部门分析师配置（只读权限）
-- ========================================

-- 销售部门分析师
GRANT SELECT ON DATASOURCE mysql_sales TO ROLE sales_analysts;
GRANT DESCRIBE ON DATASOURCE mysql_sales TO ROLE sales_analysts;

-- 市场部门分析师
GRANT SELECT ON DATASOURCE mysql_marketing TO ROLE marketing_analysts;
GRANT DESCRIBE ON DATASOURCE mysql_marketing TO ROLE marketing_analysts;

-- 财务部门分析师
GRANT SELECT ON DATASOURCE pg_finance TO ROLE finance_analysts;
GRANT DESCRIBE ON DATASOURCE pg_finance TO ROLE finance_analysts;

-- ========================================
-- 第5步：跨部门数据共享配置
-- ========================================

-- 销售数据共享给市场部门（只读）
GRANT SELECT ON TABLE customer_behavior IN DATASOURCE mysql_sales TO ROLE marketing_analysts;
GRANT DESCRIBE ON TABLE customer_behavior IN DATASOURCE mysql_sales TO ROLE marketing_analysts;

-- 市场数据共享给销售部门（只读）
GRANT SELECT ON TABLE campaign_results IN DATASOURCE mysql_marketing TO ROLE sales_analysts;
GRANT DESCRIBE ON TABLE campaign_results IN DATASOURCE mysql_marketing TO ROLE sales_analysts;

-- 财务数据共享给高级管理层
GRANT SELECT ON TABLE revenue_summary IN DATASOURCE pg_finance TO ROLE executives;
GRANT DESCRIBE ON TABLE revenue_summary IN DATASOURCE pg_finance TO ROLE executives;

-- ========================================
-- 第6步：共享数据源配置
-- ========================================

-- 所有部门都可以读取共享数据源
GRANT SELECT ON DATASOURCE mysql_shared TO ROLE sales_analysts;
GRANT SELECT ON DATASOURCE mysql_shared TO ROLE marketing_analysts;
GRANT SELECT ON DATASOURCE mysql_shared TO ROLE finance_analysts;
GRANT DESCRIBE ON DATASOURCE mysql_shared TO ROLE sales_analysts;
GRANT DESCRIBE ON DATASOURCE mysql_shared TO ROLE marketing_analysts;
GRANT DESCRIBE ON DATASOURCE mysql_shared TO ROLE finance_analysts;

-- 只有特定角色可以写入共享数据源
GRANT CREATE ON DATASOURCE mysql_shared TO ROLE data_engineers;
GRANT DROP ON DATASOURCE mysql_shared TO ROLE data_engineers;

-- ========================================
-- 第7步：数据科学团队配置（跨部门只读）
-- ========================================

-- 数据科学团队可以读取所有数据源（用于建模和分析）
GRANT SELECT ON DATASOURCE mysql_sales TO ROLE data_scientists;
GRANT SELECT ON DATASOURCE mysql_marketing TO ROLE data_scientists;
GRANT SELECT ON DATASOURCE pg_finance TO ROLE data_scientists;
GRANT SELECT ON DATASOURCE mysql_shared TO ROLE data_scientists;
GRANT DESCRIBE ON DATASOURCE mysql_sales TO ROLE data_scientists;
GRANT DESCRIBE ON DATASOURCE mysql_marketing TO ROLE data_scientists;
GRANT DESCRIBE ON DATASOURCE pg_finance TO ROLE data_scientists;
GRANT DESCRIBE ON DATASOURCE mysql_shared TO ROLE data_scientists;

-- ========================================
-- 第8步：临时访客配置（极度受限）
-- ========================================

-- 临时访客只能访问共享数据源的特定表
GRANT SELECT ON TABLE public_data IN DATASOURCE mysql_shared TO ROLE guests;
GRANT DESCRIBE ON TABLE public_data IN DATASOURCE mysql_shared TO ROLE guests;

-- ========================================
-- 第9步：审计和合规角色配置
-- ========================================

-- 审计人员可以查看所有数据源的元数据和数据
GRANT SELECT ON DATASOURCE mysql_sales TO ROLE auditors;
```
