# SQL使用限制项

## 概述

本文档列举了天穹 SQL（TDW Hive 和 SuperSQL）的各项使用限制，帮助用户在编写 SQL 时遵循规范，避免出现错误或性能问题。

## 命名限制

### 表名和列名限制

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| **命名规则** | `[\w]+` | 表名和字段名只能包含字母、数字和下划线<br>• 必须以字母开头<br>• 不能使用特殊字符 |
| **表名长度** | 128 字节 | 表名最大长度为 128 字节 |
| **列名长度** | 128 字节 | 列名最大长度为 128 字节 |
| **注释长度** | 1024 字节 | 表和列的注释最大长度为 1024 字节 |

**示例：**
```sql
-- ✅ 正确命名
CREATE TABLE user_data (
    user_id BIGINT,
    user_name STRING,
    create_time STRING
);

-- ❌ 错误命名
CREATE TABLE user-data (       -- 不能使用连字符
    user#id BIGINT,             -- 不能使用特殊字符
    123name STRING              -- 不能以数字开头
);
```

## 表结构限制

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| **单表列数** | 1200 | 单表最多可定义 1200 个列 |
| **单表分区数** | 60000 | 单表最多可创建 60000 个分区 |
| **分区层级** | 2 级 | 最多支持两级分区（一级分区 + 二级分区） |
| **列簇数量** | 20 | 列存储表的列簇最多不能超过 20 个 |
| **单记录长度** | 8 MB | 表中单个单元（字段值）的最大长度为 8 MB |

**注意事项：**
- 分区类型支持：RANGE、LIST、HASHKEY
- HASHKEY 分区只能作为最低一级分区
- 建议使用 ORC 格式存储以获得更好的性能

## SQL 语句限制

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| **SQL 语句长度** | 2 MB | 单条 SQL 语句最大长度为 2 MB |
| **SQL 执行计划** | 1 MB | 生成的执行计划不能超过 1 MB |
| **屏显行数** | 10000 | SELECT 语句屏幕显示最多输出 10000 行 |
| **ORDER BY LIMIT** | 1024 (默认) | ORDER BY 语句的 LIMIT 默认最大值为 1024<br>可通过 `set hive.sortby.limit.maxcount` 调整 |

**调整 LIMIT 限制示例：**
```sql
-- 修改 LIMIT 最大值
SET hive.sortby.limit.maxcount = 10240;

SELECT * FROM large_table ORDER BY col1 LIMIT 5000;
```

## 查询和操作限制

### INSERT 和 UNION 限制

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| **MULTI-INSERT 目标数** | 256 | 一次性插入多个目标表时，最多 256 个表 |
| **UNION ALL 数量** | 256 | UNION ALL 最多合并 256 个表 |
| **IN 参数个数** | 1024 (建议) | IN 子句的参数数量建议不超过 1024 |
| **子查询分区过滤** | 1000 行 | 子查询中存在分区列时，返回结果不能超过 1000 行 |

**示例：**
```sql
-- ❌ IN 参数过多，影响性能
SELECT * FROM table WHERE id IN (1, 2, 3, ..., 2000);  -- 不推荐

-- ✅ 改用 JOIN
SELECT t1.* FROM table t1
JOIN (SELECT id FROM id_list) t2 ON t1.id = t2.id;
```

### JOIN 限制

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| **MAPJOIN 小表数** | 128 | MAPJOIN 最多连接 128 个小表 |
| **MAPJOIN 内存** | 512 MB (默认) | 所有小表的总内存不能超过 512 MB<br>可通过 `mapred.child.java.opts` 调整 |

**MAPJOIN 内存调整：**
```sql
-- 设置 Map/Reduce 任务内存（建议不超过 4096M）
SET mapred.child.java.opts = -Xmx4096M;

-- 设置缓存行数
SET hive.mapjoin.cache.numrows = 10000;
```

**注意：**
- MAPJOIN 不支持多表连接
- 根据经验，100万条记录约需 500-700MB 内存
- MAPJOIN 不支持与其他复杂查询组合

## 分区和查询限制

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| **最多查询分区数** | 10000 | 一次查询最多涉及 10000 个分区 |
| **分区创建频率** | 120 次/15 秒 | 表分区创建操作频率限制 |

**示例：**
```sql
-- ❌ 可能触发分区数限制
SELECT * FROM log_table WHERE dt >= '2020-01-01';  
-- 如果每天一个分区，跨度超过 27 年会超限

-- ✅ 缩小查询范围
SELECT * FROM log_table WHERE dt BETWEEN '2024-01-01' AND '2024-12-31';
```

## 时间限制

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| **单作业最大运行时间** | 72 小时 | SQL 作业最长运行 72 小时后自动停止<br>默认 24 小时，可调整到 72 小时 |

**调整作业运行时间：**
```sql
SET odps.sql.job.max.time.hours = 72;
```

## 功能限制

### 不支持的操作

| 限制项 | 说明 |
|--------|------|
| **视图写入** | 视图不支持写入，不支持 INSERT 操作 |
| **修改列类型** | 不允许直接修改列的数据类型和列位置<br>需要先设置 `set hive.alterschema.without.check=true;` |
| **删除/替换列** | 不支持减少列和替换所有列（REPLACE）功能 |
| **字段默认值** | 建表时不支持指定字段的默认值 |
| **中文别名** | 不支持中文别名 |

### ALTER TABLE 限制

```sql
-- 修改字段类型需要特殊设置（不推荐）
SET hive.alterschema.without.check = true;
ALTER TABLE test_table CHANGE COLUMN old_col new_col INT;

-- 注意事项：
-- 1. 文本表暂不支持修改表结构
-- 2. 外表不建议修改 schema
-- 3. PB 表不允许修改 schema
-- 4. 分区字段和索引字段不允许修改
-- 5. 增加字段只能加在表的末尾
```

### INSERT 限制

| 限制项 | 说明 |
|--------|------|
| **指定列插入** | 列数和类型必须一一对应 |
| **复杂类型** | 不支持直接插入复杂类型数据 |
| **函数插入** | 不支持在 VALUES 中使用函数 |
| **NULL 插入** | 必须显式使用 NULL 关键字，不能用空字符串 |
| **HASHKEY 分区** | 含 HASHKEY 分区的表不支持指定列名插入 |

**示例：**
```sql
-- ✅ 正确的 INSERT
INSERT INTO TABLE user_data VALUES (1, 'Alice', NULL);

-- ❌ 错误的 INSERT
INSERT INTO TABLE user_data VALUES (1, 'Alice', '');      -- NULL 不能用空字符串
INSERT INTO TABLE user_data VALUES (1, UPPER('Alice'));   -- 不支持函数
```

### UPDATE 和 DELETE 限制

| 操作 | 限制说明 |
|------|---------|
| **UPDATE** | • 必须显式指定分区<br>• 不支持多层嵌套和多表连接<br>• WHERE 子句不支持 EXISTS 等带子查询<br>• 不支持对分区字段 UPDATE<br>• 不支持 HASHKEY 分区表<br>• 不支持外表和视图 |
| **DELETE** | • 必须显式指定分区<br>• HDFS 外表不支持带 WHERE 条件的 DELETE<br>• 不带 WHERE 的 DELETE 相当于 TRUNCATE |

**UPDATE 示例：**
```sql
-- ✅ 正确的 UPDATE
UPDATE user_data SET age = 30 
WHERE user_id = 1001 AND dt = '2024-01-01';

-- ❌ 错误的 UPDATE
UPDATE user_data SET age = 30;                    -- 分区表必须指定分区
UPDATE user_data SET age = 30, age = 31;          -- 重复赋值只处理最后一次
UPDATE user_data SET dt = '2024-01-02';           -- 不能 UPDATE 分区字段
```

### 子查询限制

| 限制项 | 说明 |
|--------|------|
| **子查询位置** | 只有 FROM 后面可以跟子查询<br>SELECT、WHERE 中不支持子查询 |
| **DISTINCT** | 不支持一条语句含有多个对不同列的 DISTINCT 聚合函数 |

**示例：**
```sql
-- ✅ 支持：FROM 后子查询
SELECT * FROM (
    SELECT user_id, COUNT(*) as cnt 
    FROM orders GROUP BY user_id
) t WHERE cnt > 10;

-- ❌ 不支持：WHERE 中子查询
SELECT * FROM users 
WHERE user_id IN (SELECT user_id FROM orders WHERE amount > 1000);
```

### GROUP BY 和 HAVING 限制

```sql
-- ❌ 错误：HAVING 中引用 SELECT 别名
SELECT city, AVG(age) AS age 
FROM users 
GROUP BY city 
HAVING age > 20;  -- 不能直接使用别名

-- ✅ 正确：HAVING 中使用原始表达式
SELECT city, AVG(age) AS age 
FROM users 
GROUP BY city 
HAVING AVG(age) > 20;
```

### 多维分析限制

| 限制项 | 说明 |
|--------|------|
| **SELECT DISTINCT** | 多维分析不支持 SELECT DISTINCT |
| **SELECT *** | 多维分析不支持 SELECT * |
| **GROUPING SETS** | • 只能用于普通列<br>• 不支持单一列聚合，只支持两个及以上列<br>• 不支持列的组合形式如 `(col1, col2)` |

## 引擎特定限制

### Spark SQL 不支持的语法

根据内部文档，Spark SQL 不支持以下 Hive 语法：

1. **MAPJOIN 优化参数**：`hive.map.aggr`、`hive.groupby.skewindata` 等参数
2. **某些 Hive 特定语法**
3. **部分 TDW 扩展语法**

建议在使用 Spark SQL 时参考 [SQL 一致性标准](../../original_documents/SQL一致性标准.doc)。

### SuperSQL 注意事项

- SuperSQL 支持跨源查询，但不同引擎（Spark、StarRocks、Presto）的限制可能不同
- 具体差异请参考 [SuperSQL 兼容 TDW SQL](../../original_documents/【天穹】SuperSQL兼容TDW_SQL.doc)

## 其他限制

### 外表限制

| 限制项 | 说明 |
|--------|------|
| **数据库支持** | 目前只支持 PostgreSQL 9.0/9.1 和 Oracle 11g |
| **新建外表分区** | 新创建的外表暂时不支持分区 |
| **数据引号** | STRING 类型的数据不能带引号 |

### UDF 限制

| 限制项 | 说明 |
|--------|------|
| **Java UDF** | 函数不能为 ABSTRACT 或 STATIC |
| **自定义 UDF** | TDW 不支持用户自定义 UDF（需申请） |

### 其他限制

| 限制项 | 说明 |
|--------|------|
| **WITH RECURSIVE** | 不支持 WITH 递归调用 |
| **jobconf.json** | 大小限制为 1 MB |
| **字符集** | 只支持 UTF-8 字符集 |

## 建议和最佳实践

### 1. 表设计建议

```sql
-- ✅ 推荐：合理的分区设计
CREATE TABLE log_table (
    user_id BIGINT,
    action STRING,
    log_time STRING
)
PARTITIONED BY (dt STRING, hour STRING)  -- 两级分区
STORED AS ORC;  -- 使用 ORC 格式

-- ❌ 不推荐：过多列
CREATE TABLE bad_table (
    col1 STRING, col2 STRING, ..., col1500 STRING  -- 超过 1200 列限制
);
```

### 2. 查询优化建议

```sql
-- ✅ 推荐：使用分区裁剪
SELECT * FROM log_table 
WHERE dt BETWEEN '2024-01-01' AND '2024-01-31';

-- ❌ 不推荐：全表扫描
SELECT * FROM log_table WHERE log_time LIKE '2024-01%';
```

### 3. JOIN 优化建议

```sql
-- ✅ 推荐：小表 MAPJOIN
SELECT /*+ MAPJOIN(small_table) */
    a.*, b.name
FROM large_table a
JOIN small_table b ON a.id = b.id;

-- 设置合适的内存
SET mapred.child.java.opts = -Xmx3072M;
```

## 错误排查

### 常见错误及解决方案

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `The Size of Plan is too large` | 执行计划超过 1 MB | 优化 SQL，减少复杂度 |
| `Limit value is Too BIG` | LIMIT 超过最大值 | 调整 `hive.sortby.limit.maxcount` |
| `Too many partitions` | 查询分区超过 10000 | 缩小分区范围 |
| `SemanticException` | 语法错误或不支持的操作 | 检查语法，参考本文档限制项 |
