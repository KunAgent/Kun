# 2.18 EXPLAIN语句

## 概述

EXPLAIN语句用于以固定的文本格式，输出SQL语句的逻辑计划（without implementation）或物理执行计划（with implementation，默认），以及相关的CBO信息（数据源表集合、下推SQL集合、计算引擎实例、估算代价值等）。

### 核心特性

- **不执行SQL**：与传统RDBMS类似，EXPLAIN语句不会执行后带的SQL，只会解析并打印SQL优化结果
- **语法检查**：如果SQL有语法错误，EXPLAIN语句会抛出对应的异常
- **权限验证**：与直接执行SQL的情况一样，EXPLAIN命令也会对后接SQL中的库表作鉴权。如果用户没有某张库或表的对应权限，EXPLAIN命令会抛出包含相关信息的鉴权异常
- **透传SQL限制**：不符合SuperSQL语法的透传SQL，无法通过SuperSQL的EXPLAIN语句输出解析优化结果，而是会抛出语法解析的异常。这类透传SQL，只能通过数据源对应的透传explain语句来获取解析优化结果

---

## 语法

### 标准语法

```sql
EXPLAIN PLAN
  [ WITH IMPLEMENTATION | WITHOUT IMPLEMENTATION ]   -- 默认为WITH IMPLEMENTATION
  FOR ( query | insert | update | delete | ctas )
```

### 简化语法（等价形式）

```sql
EXPLAIN ( query | insert | update | delete | ctas )
```

**说明**：简化语法等价于 `EXPLAIN PLAN WITH IMPLEMENTATION FOR`

---

## 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `WITH IMPLEMENTATION` | 输出物理执行计划（包含完整的CBO信息） | 是 |
| `WITHOUT IMPLEMENTATION` | 仅输出逻辑计划（不包含执行引擎和列溯源等信息） | 否 |
| `query` | SELECT查询语句 | - |
| `insert` | INSERT语句 | - |
| `update` | UPDATE语句 | - |
| `delete` | DELETE语句 | - |
| `ctas` | CREATE TABLE AS SELECT语句 | - |

## 输出内容详解

### 1. PLAN（执行计划）

显示SQL的物理计划或逻辑计划，采用树状结构表示算子关系。

#### 常见算子类型

| 算子类型 | 说明 |
|---------|------|
| `EnumerableCalc` | 投影和计算表达式 |
| `EnumerableHashJoin` | Hash Join连接操作（跨源SQL算子，在物理计划树上层） |
| `JdbcToEnumerableConverter` | JDBC数据源转换算子（下推SQL算子子树的根节点） |
| `JdbcProject` | JDBC投影操作 |
| `JdbcTableScan` | JDBC表扫描 |
| `JdbcAggregate` | JDBC聚合操作 |
| `JdbcUnion` | JDBC联合操作 |
| `JdbcTableModify` | JDBC表修改操作（INSERT/UPDATE/DELETE/CREATE TABLE） |
| `JdbcValues` | JDBC常量值 |

### 2. SuperSQL CBO

显示CBO（基于代价的优化器）的决策结果。

| 决策类型 | 说明 |
|---------|------|
| `Ext. Engine Exec` | 使用外部计算引擎执行（如Spark） |
| `Single Source Exec` | 单数据源执行（下推到数据源） |

### 3. DataSource Pushdown SQLs

显示下推到各个数据源的SQL文本。

**格式**：
```
#序号: 数据源名称 - SQL文本
```

**说明**：
- 标识符使用数据源对应的引号字符（quoteString）
  - PG和Oracle：双引号 `"`
  - MySQL和Hive：反引号 `` ` ``
- INSERT/CREATE语句的特殊选项（如partition、stored as等）在下推SQL中不显示，但实际执行时会包含

### 4. Datasource tables

显示SQL中涉及的所有数据源表集合。

**格式**：
```
[数据源1.表1, 数据源2.表2, ...]
```

### 5. Result column types（WITH IMPLEMENTATION）

显示SQL结果集（ResultSet）中包含的列集合，包括列名称和数据类型。

**格式**：
```
#序号: 列名 - 数据类型
```

### 6. Result column origins（WITH IMPLEMENTATION）

显示结果列的溯源信息，即每个结果列由哪些数据源表列Project或通过Expression计算而得到。

**格式**：
```
#序号: 列名 - [数据源.表.列, ...]
```

**说明**：
- 仅溯源最终的SELECT列表，不溯源WHERE、JOIN ON等其它子句或嵌套查询
- 如果列是通过表达式计算得到，会列出表达式中涉及的所有源列
- 如果列是常量或聚合函数结果，显示为空数组 `[]`

### 7. Column (top) aggregate functions（WITH IMPLEMENTATION）

显示结果列是否使用了聚合函数，以及使用的聚合函数类型。

**格式**：
```
#序号: 列名 - [聚合函数列表]
```

**常见聚合函数**：
- `COUNT`
- `SUM`
- `AVG`
- `MAX`
- `MIN`
- 空数组 `[]` 表示非聚合列

### 8. GroupBy in main query（WITH IMPLEMENTATION）

显示主查询中是否使用了GROUP BY子句。

**取值**：
- `YES`：包含GROUP BY
- `NO`：不包含GROUP BY

### 9. Exec engine type（WITH IMPLEMENTATION）

显示SQL的执行引擎类型。

| 引擎类型 | 说明 |
|---------|------|
| `NATIVE` | 原生数据源执行（下推） |
| `SPARK` | Spark计算引擎执行 |
| `PRESTO` | Presto计算引擎执行 |
| `STARROCKS` | StarRocks计算引擎执行 |

### 10. Detailed info（WITH IMPLEMENTATION）

显示执行引擎的详细信息，包括数据中心、数据源、引擎和估算代价。

**格式**：
```
[singleDC] dataSourceName = xxx, engine = xxx, cost = xxx
```

### 11. Target table to insert/create/update/delete（DML/DDL）

对于INSERT/CREATE/UPDATE/DELETE语句，显示目标表信息。

**相关字段**：
- `Target table to insert`: 插入的目标表
- `Target table to create`: 创建的目标表
- `Target table does not exist and will be created`: 目标表不存在且将被创建
- `IfNotExists flag`: CREATE TABLE IF NOT EXISTS标志
- `Options to insert`: 插入选项（如partition）
- `Options to create table`: 创建表选项（如stored as orcfile）

### 示例6：使用sourceTableOnly提示

```sql
EXPLAIN 
SELECT COUNT(*) 
FROM mysql.temp t1 
JOIN hive.temp2 t2 ON t1.cint = t2.cint 
/*+ sourceTableOnly */;
```

**输出**：

```
Datasource tables: [mysql.temp, hive.temp2]
```

**说明**：
- 使用特殊的 `/*+ sourceTableOnly */` query hint（注释）
- 命令不进行鉴权
- 仅返回源表集合这一项简化信息
- 该注释可以出现在SQL中的任何位置

## 逻辑计划 vs 物理计划

### 逻辑计划（WITHOUT IMPLEMENTATION）

```sql
EXPLAIN PLAN WITHOUT IMPLEMENTATION FOR
SELECT cint FROM hive.temp;
```

**输出内容**：
- PLAN（逻辑计划树）
- SuperSQL CBO
- DataSource Pushdown SQLs
- Datasource tables

**特点**：
- 不包含执行引擎信息
- 不包含结果列类型和溯源信息
- 不包含聚合函数和GROUP BY信息
- 输出更简洁

### 物理计划（WITH IMPLEMENTATION，默认）

```sql
EXPLAIN PLAN WITH IMPLEMENTATION FOR
SELECT cint FROM hive.temp;

-- 或简化为
EXPLAIN SELECT cint FROM hive.temp;
```

**输出内容**：
- 逻辑计划的所有内容
- Result column types
- Result column origins
- Column (top) aggregate functions
- GroupBy in main query
- Exec engine type
- Detailed info

**特点**：
- 完整的执行计划信息
- 包含列溯源和类型信息
- 包含执行引擎和代价估算

## 使用场景

### 1. SQL性能分析

使用EXPLAIN查看执行计划，分析SQL性能瓶颈：

```sql
EXPLAIN 
SELECT * 
FROM large_table t1 
JOIN small_table t2 ON t1.id = t2.id;
```

**关注点**：
- 是否使用了合适的JOIN类型（Hash Join、Merge Join等）
- 是否成功下推到数据源
- 是否使用了计算引擎

### 2. 跨数据源查询优化

检查跨数据源查询的下推情况：

```sql
EXPLAIN 
SELECT * 
FROM mysql.orders o 
JOIN pg.customers c ON o.customer_id = c.id;
```

**关注点**：
- 哪些部分下推到数据源
- 哪些部分在计算引擎执行
- 数据传输量估算

### 3. 表依赖分析

快速获取SQL涉及的所有表：

```sql
EXPLAIN 
SELECT * FROM table1 
JOIN table2 ON ... 
/*+ sourceTableOnly */;
```

**用途**：
- 不需要鉴权
- 快速获取表列表
- 用于依赖分析工具

### 4. 语法验证

在不执行SQL的情况下验证语法：

```sql
EXPLAIN 
SELECT column_that_might_not_exist 
FROM table_name;
```

**用途**：
- 语法检查
- 列名验证
- 表存在性检查

### 5. 权限检查

验证用户是否有表的访问权限：

```sql
EXPLAIN SELECT * FROM restricted_table;
```

**用途**：
- 不实际读取数据
- 仅验证权限
- 快速权限检查

## 最佳实践

### 1. 使用物理计划分析性能

对于性能分析，始终使用物理计划（WITH IMPLEMENTATION）：

```sql
-- 推荐
EXPLAIN SELECT ...;

-- 或
EXPLAIN PLAN WITH IMPLEMENTATION FOR SELECT ...;
```

### 2. 使用逻辑计划检查语法

对于快速语法检查，使用逻辑计划：

```sql
EXPLAIN PLAN WITHOUT IMPLEMENTATION FOR SELECT ...;
```

### 3. 使用sourceTableOnly快速获取表列表

对于依赖分析，使用sourceTableOnly提示：

```sql
EXPLAIN SELECT ... /*+ sourceTableOnly */;
```

### 4. 关注下推SQL

检查下推SQL是否符合预期：

- 是否包含了所有可以下推的过滤条件
- 是否包含了所有可以下推的聚合操作
- 是否避免了不必要的数据传输

### 5. 分析结果列溯源

使用结果列溯源信息：

- 理解列的来源
- 检查是否存在不必要的列
- 优化SELECT列表

### 6. 检查执行引擎选择

确认CBO选择了合适的执行引擎：

- 单数据源查询应该使用NATIVE
- 跨数据源查询应该使用Spark/Presto等计算引擎
- 检查代价估算是否合理

## 常见问题（FAQ）

### Q1: EXPLAIN会实际执行SQL吗？

**A**: 不会。EXPLAIN只会解析和优化SQL，生成执行计划，但不会实际执行查询或修改数据。

### Q2: EXPLAIN是否需要表的访问权限？

**A**: 是的。EXPLAIN会对SQL中的库表进行鉴权，如果用户没有权限，会抛出鉴权异常。唯一的例外是使用`/*+ sourceTableOnly */`提示，此时不进行鉴权。

### Q3: 透传SQL可以使用EXPLAIN吗？

**A**: 不可以。不符合SuperSQL语法的透传SQL无法通过SuperSQL的EXPLAIN语句输出解析优化结果。这类SQL只能通过数据源对应的透传explain语句来获取执行计划。

### Q4: 如何快速获取SQL涉及的表列表？

**A**: 使用`/*+ sourceTableOnly */`提示：

```sql
EXPLAIN SELECT ... /*+ sourceTableOnly */;
```

这样只返回表列表，不进行鉴权，速度更快。

### Q5: 逻辑计划和物理计划有什么区别？

**A**: 
- **逻辑计划**（WITHOUT IMPLEMENTATION）：显示SQL的逻辑结构，不包含执行细节
- **物理计划**（WITH IMPLEMENTATION，默认）：显示完整的执行计划，包含执行引擎、列溯源、代价估算等详细信息

### Q6: 如何判断SQL是否会下推到数据源？

**A**: 查看`SuperSQL CBO`字段：
- `Single Source Exec`：单数据源执行，SQL会下推
- `Ext. Engine Exec`：使用外部计算引擎执行，部分下推

同时查看`DataSource Pushdown SQLs`部分，可以看到具体下推的SQL文本。

### Q7: 为什么我的跨数据源JOIN使用了Spark引擎？

**A**: 跨数据源JOIN无法完全下推到单个数据源，需要使用计算引擎（如Spark）来执行JOIN操作。每个数据源会下推部分查询，然后在计算引擎中完成JOIN。

### Q8: 如何看出SQL中使用了哪些聚合函数？

**A**: 查看`Column (top) aggregate functions`部分，每个结果列都会列出使用的聚合函数。

### Q9: Result column origins中的空数组[]表示什么？

**A**: 空数组`[]`表示该列：
- 是常量值（如VALUES中的常量）
- 是聚合函数的结果（如COUNT(*)）
- 无法溯源到具体的源表列

### Q10: EXPLAIN输出中的标识符引号为什么不一样？

**A**: 不同数据源使用不同的引号字符（quoteString）：
- MySQL和Hive：反引号 `` ` ``
- PostgreSQL和Oracle：双引号 `"`

这是为了确保下推SQL符合目标数据源的语法规范。

### 完整的EXPLAIN输出示例

```sql
EXPLAIN 
SELECT 
  t1.id,
  t1.name,
  COUNT(t2.order_id) AS order_count,
  SUM(t2.amount) AS total_amount
FROM mysql.customers t1
LEFT JOIN pg.orders t2 ON t1.id = t2.customer_id
WHERE t1.status = 'active'
GROUP BY t1.id, t1.name
HAVING COUNT(t2.order_id) > 5
ORDER BY total_amount DESC
LIMIT 100;
```

**预期输出特点**：
- 跨数据源JOIN，使用Spark引擎
- MySQL下推：表扫描、过滤（status = 'active'）
- PostgreSQL下推：表扫描
- Spark执行：JOIN、聚合、HAVING、排序、LIMIT
- 结果列包含聚合函数：COUNT、SUM
- GROUP BY：YES
