# 3.1.1 表名说明

## 概述

在 TDW SQL 中，表名可以使用不同的分隔符来指定数据库和表的完整路径。本文档说明表名的使用规范和最佳实践。

## 表名格式

### 1. 点号分隔符（推荐）

**格式**：`database.tablename`

这是 **SuperSQL 的标准语法**，也是 **推荐使用** 的格式：

```sql
-- 推荐：使用点号分隔符
SELECT * FROM mydb.table1;

-- 跨库查询
SELECT a.*, b.*
FROM db1.table1 a
JOIN db2.table2 b ON a.id = b.id;

-- INSERT 操作
INSERT INTO mydb.table1 SELECT * FROM mydb.table2;
```

### 2. 双冒号分隔符（兼容）

**格式**：`database::tablename`

这是 **THive 的历史语法**，仍然支持但优先级低于点号分隔符：

```sql
-- 兼容：使用双冒号分隔符（THive 语法）
SELECT * FROM mydb::table1;

-- 注意：不推荐在新代码中使用
SELECT * FROM db1::table1
JOIN db2::table2 ON ...;
```

### 3. 单独表名

当不指定数据库时，使用当前数据库上下文中的表：

```sql
-- 先设置当前数据库
USE mydb;

-- 然后使用表名（使用当前数据库）
SELECT * FROM table1;
INSERT INTO table2 SELECT * FROM table1;
```

## 使用规范

### 基本规则

1. **优先使用点号分隔符**
   - ✅ 推荐：`db.tablename`（SuperSQL 标准）
   - ⚠️ 兼容：`db::tablename`（THive 语法）

2. **保持一致性**
   - 在同一个脚本中统一使用一种格式
   - 建议新代码统一使用点号分隔符

3. **USE 语句**
   - `USE database;` 设置当前数据库
   - 注意：`USE` 后面只跟数据库名，不包含表名
   - 错误示例：`USE db.tablename;` ❌

### 示例对比

#### 推荐用法（点号分隔符）

```sql
-- 方式1：使用完整表名
SELECT * FROM mydb.table1;

-- 方式2：先 USE，再使用表名
USE mydb;
SELECT * FROM table1;

-- 跨库查询
SELECT a.col1, b.col2
FROM db1.table1 a
LEFT JOIN db2.table2 b ON a.id = b.id;
```

#### 兼容用法（双冒号分隔符）

```sql
-- THive 历史语法，仍然支持
SELECT * FROM mydb::table1;

-- 跨库查询
SELECT * FROM db1::table1
JOIN db2::table2 ON ...;
```

#### 错误用法

```sql
-- ❌ 错误：USE 语句包含表名
USE db.tablename;
USE db::tablename;

-- ❌ 错误：混用两种分隔符
SELECT * FROM db1.table1
JOIN db2::table2 ON ...;
```

## 最佳实践

### 1. 明确数据库上下文

```sql
-- 推荐：使用点号分隔符的完整表名
SELECT * FROM mydb.table1;
INSERT INTO mydb.table2 SELECT * FROM mydb.table1;

-- 或：先 USE，再使用表名
USE mydb;
SELECT * FROM table1;
INSERT INTO table2 SELECT * FROM table1;
```

### 2. 跨库查询

```sql
-- 推荐：点号分隔符
SELECT t1.col1, t2.col2
FROM db1.table1 t1
LEFT JOIN db2.table2 t2 ON t1.id = t2.id;

-- 兼容：双冒号分隔符（THive 语法）
SELECT t1.col1, t2.col2
FROM db1::table1 t1
LEFT JOIN db2::table2 t2 ON t1.id = t2.id;
```

### 3. 避免歧义

```sql
-- 当多个数据库有同名表时，明确指定数据库
SELECT 
    a.col1,
    b.col2
FROM production.users a
LEFT JOIN staging.users b ON a.id = b.id;
```

### 4. 保持一致性

```sql
-- ✅ 推荐：统一使用点号分隔符
SELECT * FROM db1.table1
JOIN db2.table2 ON ...;

-- ⚠️ 不推荐：混用两种格式
SELECT * FROM db1.table1
JOIN db2::table2 ON ...;
```

## 分隔符对比

| 特性 | 点号分隔符 `.` | 双冒号分隔符 `::` |
|------|--------------|----------------|
| **格式** | `database.tablename` | `database::tablename` |
| **语法来源** | SuperSQL 标准 | THive 历史语法 |
| **推荐程度** | ✅ **推荐使用** | ⚠️ 兼容支持 |
| **优先级** | 高 | 低 |
| **适用场景** | 所有 SQL 语句 | 兼容旧代码 |
| **新代码建议** | 优先使用 | 避免使用 |

## 注意事项

1. **优先使用点号分隔符**
   - 点号分隔符（`.`）是 SuperSQL 的标准语法
   - 更符合 SQL 标准规范
   - 提高代码可读性和可维护性

2. **双冒号分隔符仅用于兼容**
   - 双冒号分隔符（`::`）主要用于兼容 THive 历史代码
   - 新编写的代码建议统一使用点号分隔符
   - 优先级低于点号分隔符

3. **保持一致性**
   - 在同一个脚本或项目中保持一致的命名风格
   - 建议团队统一使用点号分隔符

4. **USE 语句的使用**
   - `USE` 后面只能跟数据库名
   - 不能包含表名：`USE database;` ✅，`USE database.table;` ❌

5. **注释中的说明**
   - 在代码注释中明确说明使用的数据库和表
   - 有助于代码维护和理解

## 表名和字段名命名规则

### 命名限制

- **正则表达式**：`[\w]+`
- **支持字符**：字母、数字和下划线
- **限制**：不能以数字开头

### 示例

```sql
-- ✅ 合法的表名
CREATE TABLE user_info (...);
CREATE TABLE table_2024 (...);
CREATE TABLE MyTable (...);

-- ❌ 非法的表名
CREATE TABLE 2024_table (...);  -- 不能以数字开头
CREATE TABLE user-info (...);   -- 不能包含连字符
CREATE TABLE user.info (...);   -- 点号用于分隔数据库和表名
```

## 常见问题

### Q: 什么时候使用点号分隔符？什么时候使用 USE？

**A**: 两种方式都可以，根据场景选择：

- **点号分隔符**：适合明确指定数据库，代码更清晰
  ```sql
  SELECT * FROM mydb.table1;
  ```

- **USE 语句**：适合在同一数据库内进行多个操作
  ```sql
  USE mydb;
  SELECT * FROM table1;
  SELECT * FROM table2;
  ```

### Q: 可以混用点号和双冒号分隔符吗？

**A**: 虽然语法上支持，但强烈不推荐混用。建议统一使用点号分隔符（`.`）。

```sql
-- ❌ 不推荐：混用两种格式
SELECT * FROM db1.table1
JOIN db2::table2 ON ...;

-- ✅ 推荐：统一使用点号分隔符
SELECT * FROM db1.table1
JOIN db2.table2 ON ...;
```

### Q: 旧代码中大量使用双冒号分隔符，需要改吗？

**A**: 不需要立即修改，双冒号分隔符仍然完全支持。但建议在新代码中统一使用点号分隔符，并在重构旧代码时逐步迁移。
