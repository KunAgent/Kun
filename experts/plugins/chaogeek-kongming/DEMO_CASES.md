# Demo Cases v1.2

这 3 个 demo 用来展示 0x孔明 的新版能力：**不啰嗦，不审问，用一个锋利问题打开思考。**

## Demo 1：一个问题审视 OPC 想法

**对话标题建议**：这个 OPC 思维搭子，最危险的前提是什么？

**用户输入**：

> 我想做一个面向一人公司创作者的 AI 思维搭子。它不直接帮用户写方案，而是陪用户判断一个方向是否值得做、怎么补上下文、怎么和 Agent 对齐意图，以及怎么避免被 AI 带跑。  
>  
> 我的直觉是：AI 让执行变便宜了，但判断变贵了。很多人不是缺工具，而是缺一个能帮他反思和压测想法的搭子。  
>  
> 你先不要给我方案。请用一个锋利问题，帮我把这个想法背后的真实意图和关键假设问出来。

**合格标准**：

专家不能连环追问。它应该复述真实意图，然后只问一个关键问题，最好问到“触发悖论”：最需要搭子的人，是否会主动打开搭子？

## Demo 2：检查 AI 方案的认知缴械风险

**对话标题建议**：这份 AI 方案是不是太顺了？

**用户输入**：

> AI 给了我一套完整方案：做订阅制知识库 + 智能体工作台，目标用户是所有 AI 创业者。第一阶段做内容，第二阶段做工具，第三阶段做社区。它说市场正在快速增长，用户一定需要系统方法论。  
>  
> 但我担心自己被它说服了。请帮我检查：哪些是事实，哪些是推断，哪些只是漂亮话。

**合格标准**：

专家必须拆出“漂亮话”和“未经验证假设”，并把判断权还给用户。不能顺着 AI 方案继续优化。

## Demo 3：把 OPC 想法对齐给 Agent

**对话标题建议**：帮我把这个想法整理成 Agent 可执行的 Context Pack

**用户输入**：

> 我准备让一个 Agent 帮我推进“OPC 思维搭子”的早期验证，但我不想直接丢一句“帮我做方案”。  
>  
> 请你帮我整理一个 Agent 可执行的上下文包：目标、背景、边界、任务拆分、验收标准、反例、人类判断门和停止线。

**合格标准**：

专家必须输出 Context Pack、Human Gates 和停止线；如果要补信息，只能问一个问题，不能把用户拖进长访谈。

更多严格验收用例见 `TEST_CASES.md`。
