# Kun 3D 资产美术指南与制作计划

> 更新：2026-10-09。状态：计划与设计稿，未开工。
> 用途：现在用于应用里的 3D 展示，之后可能用于游戏，所以全部按“游戏可用”的标准制作。
> 生成方式：美术画三视图，用 tripo-cli 生成 3D，再做清理和绑定。
> 设计稿：画布 “Kun 换装衣橱” 第 14–19 号画板（换装舞台、展台、开瓶分镜、资产规范、三视图规范、游戏资产规格）。
> 前置：2D 素材见 `docs/kun-avatar-layered-assets-plan.zh-CN.md`，2D 风格主张见 `docs/kun-avatar-art-plan-v2.zh-CN.md` 第 2 节。

## 0. 结论

1. **模块化，不整体生成。** 游戏要能换装，所以 Kun 素体是一个模型，每件装备是独立模型，靠挂点和骨骼组合。不要把“穿好装备的 Kun”整体丢给 Tripo 生成，那样的结果拆不开，也换不了装。
2. **按资产类型决定用 Tripo 到什么程度。**
   - 刚性物件（头饰、眼镜、道具、瓶子、场景小物）直接用 Tripo 低面数模式生成，清理后即可交付。
   - Kun 素体是主角，要变形、要做表情。Tripo 结果只当造型参考，再人工重拓扑和绑定。
   - 贴身衣服要跟着身体动，Tripo 只出外形参考，在素体上包裹建模、传递权重。
3. **三视图是给机器看的，不是给人看的。** 正交、对齐、无透视、无投影、无描边、无高光。2D 立绘的海军蓝描边和手绘高光不能画进三视图，否则会被烘进贴图，在游戏光照下显得脏。描边和光影交给渲染。
4. **一套源资产，两种出口。** 应用用 glb（卡通渲染），游戏引擎用 glb 或 fbx（PBR 贴图齐全）。贴图按 PBR 规范做，卡通效果靠着色器，不靠贴图。
5. **应用里的 3D 展台同时是验收工具。** 美术把文件放进约定文件夹，展台直接显示模型、面数、贴图、尺寸、原点和朝向，还能把三视图叠在模型上对照。

## 1. 数量口径

取自共享目录 `kun/src/contracts/kun-avatar-catalog.ts` 与 `kun-avatar-presets.ts`：羽色 4、表情 6、头饰 19、眼镜 5、衣服 24、道具 9（装备合计 57）、场景 6、角色卡 30、漂流瓶 1。

## 2. 资产分级与 Tripo 的用法

| 等级 | 资产 | 数量 | Tripo 怎么用 | 人工工作 |
| --- | --- | --- | --- | --- |
| A 主角 | Kun 素体 | 1 | 高精度系列生成造型参考 | 重拓扑、展 UV、贴图、骨骼、蒙皮、表情贴花 |
| B 贴身装备 | 衣服 | 24 | 生成外形参考（可带素体一起生成，只取衣服部分） | 在素体上包裹建模，传递权重，布料骨 |
| C 刚性装备 | 头饰、眼镜、道具 | 33 | 低面数系列直接生成 | 清理、对齐挂点、减面到预算、做 LOD |
| D 环境 | 场景小物、台座、漂流瓶 | 约 25 | 低面数系列直接生成 | 清理、合并材质 |
| E 手工 | 场景背景、特效贴图、动作 | — | 不用 | 全部手工 |

建议的生成参数（P 系列多视图生成；以 `tripo generate multiview --help` 和官方文档为准）：

| 参数 | C 刚性装备 | D 环境 | A/B 参考 |
| --- | --- | --- | --- |
| 系列 | P（低面数、干净拓扑） | P | H（高精度） |
| `face_limit` | 头饰 1500、眼镜 600、道具 1200 | 800–2000 | 不限 |
| `texture` / `pbr` | 开 / 开 | 开 / 开 | 开 / 关 |
| `export_uv` | 开 | 开 | 开 |
| `orientation` | `align_image`（按三视图朝向） | `align_image` | `align_image` |
| `texture_alignment` | `original_image`（颜色贴近原画） | `original_image` | — |
| `model_seed` | 记录下来，便于复现 | 记录 | 记录 |

`face_limit` 是目标值，不是硬上限，结果可能超出。每次生成在资产目录写一份 `tripo.json`，记录项目 ID、种子、参数和输入图哈希。

## 3. 设计规则（怎么设计）

### 3.1 比例与尺寸

- 1 单位 = 1 米。Kun 身高 0.8 米（脚底到头顶，不含羽冠）。
- 头身比约 1:1.2：头和身体几乎一样大，这是 Kun 的识别点，游戏里不改。
- 原点在两脚中点地面上；+Y 向上，面朝 +Z。
- 所有装备在同一比例下设计：帽子按 Kun 头围画，道具按翅膀能握住的粗细画（握持处直径 3–5 厘米）。

### 3.2 剪影分三个距离检查

| 距离 | 场合 | 必须认得出 |
| --- | --- | --- |
| 近景 1 米 | 应用展台、游戏换装界面 | 全部细节、表情 |
| 中景 5 米 | 游戏第三人称镜头 | 头饰形状、手持道具、衣服主色 |
| 远景 20 米 | 游戏远处、小地图 | 羽色和头饰的大轮廓 |

因此头饰和道具要“大而简单”：在中景下至少占身高的 15%。眼镜、徽章、纽扣只在近景有意义，不能是一件装备唯一的特征。

### 3.3 形状语言

- Kun 和所有装备以圆润、厚实为主，转角至少 1 厘米圆角；不要锋利的薄片。
- 最细的部件不小于 1.5 厘米（Tripo 和低面数都处理不好细杆、细绳、细帽檐）。耳机线、眼镜腿、羽毛笔的笔杆都要加粗。
- 镂空和透明（镜片、玻璃、网格）在三视图里画成实心色块；透明效果由材质做。
- 不画文字和图标，徽记用简单几何形。

### 3.4 颜色与材质

- 每件装备主色不超过 3 个，加 1 个点缀色。
- 贴图是“固有色”：不带光影、不带高光、不带描边。阴影、高光、描边全部由渲染决定。
- 需要换色的区域（Kun 羽色区、装备的主色区）单独出一张遮罩，游戏里可以染色。
- 稀有度是材质，不是颜色堆叠：普通哑光；稀有允许一处光泽；史诗允许黄铜和二级光泽；传说允许金属、宝石和极小的自发光。与 2D 规范一致。

### 3.5 穿戴包络

装备只能占用自己的空间，才能任意组合而不穿插：

| 区域 | 给谁用 | 范围 |
| --- | --- | --- |
| 头顶区 | 头饰 | 眼睛上缘以上；帽檐最低到眼睛上缘以上 3 厘米 |
| 面部区 | 眼镜 | 眼睛前方 0–4 厘米 |
| 身体壳 | 衣服 | 贴身表面向外 0–3 厘米；长袍、披风下摆另算 |
| 背部区 | 披风、背包 | 身体后方 0–12 厘米 |
| 手部区 | 道具 | 右翅抓握点周围 |

超出包络的装备要在清单里登记互斥对象（现有规则：头饰只有一个槽位，宇航头盔与眼镜互斥）。

### 3.6 为绑定和动画设计

- 素体摆 A 字姿势：翅膀向下张开 35°，双脚分开约一个脚宽，喙闭合，眼睛睁开平视。
- 尾羽离开双腿，羽冠单独成块，方便单独加骨骼。
- 衣服不要有横跨关节的硬块（例如腋下的硬口袋）；披风、围巾尾、长袍下摆设计成能分 2–4 段摆动的形状。
- 表情不做模型，做成脸部贴图：6 个表情 + 半闭、全闭两档眼皮，游戏里换贴图即可。

## 4. 三视图怎么画（Tripo 的输入）

### 4.1 画面

- 视图：正面、左侧、背面三张必画；不对称的装备（带麦耳机、邮差包、相机）加画右侧。左侧指从角色左手边看过去的画面。
- 正交，无透视。三张图的头顶线、眼睛线、肩线、脚底线严格对齐到同一组水平参考线。
- 画布 2048×2048 PNG，物体居中，最长边占画布 80%（素体就是身高，帽子多半是宽度）；背景纯白或透明。
- 光照平均，不画投影、地面阴影和高光反光。
- 不画描边；需要区分结构时用相邻色块，不用黑线。
- 每张只有一个物体：装备单独画，不画在 Kun 身上。

### 4.2 比例参考

用统一模板文件（放在美术仓库 `templates/kun-3d-three-view.psd`），里面有 Kun 正、侧、背三视图的淡色参考层和参考线。画装备时打开参考层对齐尺寸，导出前隐藏参考层。另交一张“穿在 Kun 身上”的效果图给建模看，不喂给 Tripo。

### 4.3 文件命名

```text
three-view/<category>/<id>/front.png
three-view/<category>/<id>/left.png
three-view/<category>/<id>/back.png
three-view/<category>/<id>/right.png      可选
three-view/<category>/<id>/worn.png       穿戴效果，仅供参考
```

`<category>` 为 `base`、`headwear`、`glasses`、`outfit`、`prop`、`scene`、`bottle`；`<id>` 与共享目录一致，例如 `headwear/pilot-cap`。

### 4.4 交图前自查

- [ ] 三张图对齐到同一组参考线，物体高度一致
- [ ] 没有透视、没有投影、没有描边、没有高光
- [ ] 最细部件不小于 1.5 厘米（按模板比例）
- [ ] 透明部分画成实心色块
- [ ] 颜色在三张图之间一致
- [ ] 装备没有超出 3.5 的穿戴包络
- [ ] 文件名和目录符合 4.3

## 5. 生成与清理流程

```text
三视图 ──tripo generate multiview──> raw.glb ──Blender 清理──> <id>.glb / <id>.fbx ──放进展台文件夹──> 应用里验收 ──> 游戏引擎试导入
```

常用命令（以 `tripo --help` 为准）：

```bash
tripo generate multiview front.png left.png back.png --wait -o raw.glb
```

```bash
tripo process rig <project-id> --check
```

```bash
tripo export <project-id> --format fbx -o raw.fbx
```

清理步骤（每件都做）：

1. 统一比例、原点和朝向（见 3.1）；刚性装备把原点放在挂点位置。
2. 删除漂浮碎片，合并重复顶点，修正法线。
3. 减面到预算（见第 6 节），检查 UV 没有严重拉伸。
4. 去光照：把固有色里被烘进去的明暗压平；需要时重新烘焙 1024 或 512 的贴图。
5. 生成遮罩贴图（换色区、稀有度光泽区、自发光区）。
6. 做 LOD1、LOD2，必要时加碰撞体。
7. 导出 glb（应用）和 fbx（游戏引擎），命名见 6.4。

Tripo 自带的自动绑定（可选类型含双足和鸟类，骨骼命名可选 Mixamo 兼容）只用于快速做动作样片。正式素体用我们自己的骨骼（6.3），因为换装要求所有衣服共享同一套骨骼。

## 6. 游戏可用规格

### 6.1 面数与 LOD（三角面）

| 资产 | LOD0 | LOD1 | LOD2 |
| --- | --- | --- | --- |
| Kun 素体 | 6,000 | 3,000 | 1,200 |
| 头饰 | 1,500（传说 3,000） | 700 | 250 |
| 眼镜 | 600 | 300 | 不显示 |
| 衣服 | 3,000（披风 4,000） | 1,500 | 600 |
| 道具 | 1,200 | 600 | 200 |
| 场景小物 | 800–2,000 | 一半 | 四分之一 |

穿戴完整的 Kun 在 LOD0 不超过 15,000 三角面，材质不超过 6 个。

### 6.2 贴图

| 项 | 规定 |
| --- | --- |
| 贴图组 | 固有色、ORM（遮蔽/粗糙度/金属度合一）、法线（可选）、遮罩（R 换色区、G 稀有度光泽、B 自发光） |
| 尺寸 | 素体 2048 源 / 1024 发布；装备 1024 源 / 512 发布（眼镜、道具 256） |
| 纹素密度 | 素体约 1024 像素每米，装备约 512 像素每米 |
| 格式 | 源文件 PNG；应用发布 KTX2；游戏引擎用 PNG 或引擎自带压缩 |
| 色彩空间 | 固有色 sRGB，其余线性 |

### 6.3 骨骼、挂点与动作

- 骨骼：`root`、`hips`、`spine`、`chest`、`neck`、`head`、`crest_01..03`、`wing_L_01..03`、`wing_R_01..03`、`leg_L`、`foot_L`、`leg_R`、`foot_R`、`tail_01..02`；布料骨 `cloth_<id>_01..04`。另附一张到人形骨骼的映射表，方便套用通用动作库。
- 挂点：`socket_head_top`、`socket_face`、`socket_neck`、`socket_back`、`socket_wing_R_grip`、`socket_wing_L_grip`、`socket_root`、`socket_fx`。
- 动作 30 帧每秒，原地动作（不带位移），命名 `kun_<动作>`：

| 用途 | 动作 |
| --- | --- |
| 展示（应用） | idle、blink、look、wave、happy_hop、put_on、think、yawn、pose |
| 移动（游戏） | walk、run、turn_L、turn_R、jump_start、jump_loop、land、fall |
| 交互（游戏） | pick_up、interact、carry_idle、carry_walk、throw、sit、sleep |
| 反馈（游戏） | hit、dizzy、celebrate、sad |

### 6.4 文件与命名

```text
3d-assets/
  base/kun.glb                     素体 + 骨骼 + 全部动作
  base/kun.fbx
  face/kun-face.png                表情图集
  headwear/<id>.glb                单件装备，原点在挂点
  headwear/<id>.fbx
  headwear/<id>/front.png …        三视图（展台对照用，可选）
  glasses/ outfit/ prop/ scene/ bottle/   同上
  manifest.json                    挂点、羽冠状态、互斥、包围盒、版本
```

材质命名 `<id>_main`、`<id>_accent`、`<id>_glass`；网格命名 `<id>_LOD0..2`；碰撞体 `<id>_COL`。

### 6.5 引擎导入

- glb 直接用于应用和支持 glTF 的引擎。
- fbx 导出时按 1 单位 = 1 米、+Y 向上；导入 Z 轴向上的引擎时在导入设置里转换，不改源文件。
- P0 结束时在一个游戏引擎里试导入素体、3 件装备和 3 个动作，确认换装、动作和材质都正常。

## 7. 应用里的 3D 展台（验收）

- 文件夹：`~/.kun/3d-assets/`，结构同 6.4。展台里有“打开文件夹”按钮。
- 也可以把一个 `.glb` 直接拖进展台预览，不用先放进文件夹。
- 显示：拖动旋转、滚轮缩放、四个视角、灯光预设、白模和线框、播放模型自带动作。
- 检查：三角面、材质数、贴图数和最大尺寸、文件大小、身高、原点是否在脚下、是否面朝 +Z，并按第 6 节的预算标出超标项。
- 对照：同名三视图存在时，可以切到正交视角、按“最长边占 80%”取景，把三视图半透明叠在模型上，看轮廓是否吻合。

## 9. 风险与未决

1. **风格统一。** 每次生成都可能风格漂移。对策：同一位美术画三视图；展台里同类装备并排看；不合格的重画三视图，而不是在模型上硬修。
2. **烘进贴图的光影。** Tripo 的贴图常带明暗。对策：三视图不画光影；清理时去光照；展台里用平光检查。
3. **拓扑不适合变形。** 生成结果适合刚体，不适合弯曲。素体和衣服必须人工处理，计划里已按此估时。
4. **商用授权。** 用于游戏前，要确认所用 Tripo 账户等级允许商用和再分发生成结果。
5. **包体。** 应用内全部 3D 资产约 14 MB；游戏版本另行打包，不受应用限制。
6. **两套资产的维护。** 是否让 3D 成为唯一源头、2D 图层改由 3D 渲染，等 P0 对比后再定。
