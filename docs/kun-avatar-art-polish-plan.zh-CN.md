# Kun 换装美术资源打磨计划

> 更新：2026-10-08。状态：第一、二批素材与现有换装界面接入已实现，第三批中的小头像头饰适配一并完成；人工美术终审待确认。
> 配套玩法与界面：`docs/kun-avatar-wardrobe-design.zh-CN.md`。现有素材管线：`docs/kun-avatar-layered-assets-plan.zh-CN.md`。

## 1. 原则

1. **画风只能延续，不能替换。** 所有新素材都以现有手绘位图（`src/asset/img/kun-avatar/` 与 `room-avatars/kun-avatar-atlas.png`）为参考，延续描边、上色和光影。矢量或扁平重画曾被否决，任何新风格素材都要先和原图并排对比再接入。
2. **锁定身体，所有部件对齐同一张画布。** 1024×1024 全画布 RGBA，锚点沿用 `manifest.json`（`faceBox [232,300,792,860]`、眼线 y≈584、喙 (512,666)）。新增的独立图标、场景、容器有各自画布，但同样记录来源和定位。
3. **素材只在开发期生成。** 用户换装、掉落、开瓶全部本地合成，不调用图像服务。
4. **可追溯。** 每张发布素材都能追到 `sources/` 原稿和 `generation-records.json` 记录；构建脚本负责提取、定位、导出，不在代码里重画。

## 2. 现状与问题

现有：4个羽色、2个表情、4/8个羽冠、4个抓握翅膀、19头饰、5眼镜、24衣服、9道具、4个后片，共79层；30个角色预设。整体画风统一、深色背景下边缘干净（无明显白边），这是继续往上加的基础。

为衣橱设计稿逐项核对后，问题按影响排序：

| 编号 | 问题 | 依据 | 影响的界面 |
| --- | --- | --- | --- |
| Q1 | 衣服只露出肩下一条“领口” | 24件衣服的可见像素都在画布 y≥0.79，高度约占画布21%；黑卫衣/安保夹克、蓝围巾/月亮围巾、米色衬衫/开衫/长袍在缩略图里难以区分 | 衣橱格子、装备槽、开瓶大图 |
| Q2 | 小头像里道具和衣服几乎看不到 | 聊天头像≤48px按 `faceBox` 裁切：道具只有0–9%的像素落在裁切框内，衣服9–26%，头饰平均39%（巫师帽仅13%），眼镜80–88% | 聊天、侧栏、成员列表 |
| Q3 | 没有独立物品图 | 格子目前按图层的透明边界裁切。带麦耳机的边界横跨整个头部，单独看是一个空圈；兜帽、宇航头盔离开身体就失去形状；道具旁边缺抓握的翅膀 | 衣橱格子、揭晓、图鉴、兑换 |
| Q4 | 表情只有两个 | 揭晓（惊喜）、上限提示（困）、套装称号（得意）等时刻没有对应表情 | 揭晓、掉落提示、舞台 |
| Q5 | 稀有度在画面上没有差别 | 传说披风和普通围巾的材质、细节密度相同，只能靠 UI 边框区分 | 舞台、揭晓 |
| Q6 | 游戏化元素没有手绘素材 | 漂流瓶、场景背景、角色卡面都不存在，设计稿里用描边图标或纯色占位 | 掉落卡片、揭晓、图鉴、背景 |
| Q7 | 4个羽色是分别生成的 | 外框对齐在2px以内，但内部光影、羽毛细节不完全一致，同一套衣服换羽色时有轻微“换了一只鸟”的感觉 | 舞台羽色切换 |
| Q8 | 半身构图在大舞台底部是平切 | 舞台把头像放到270px以上时，画布底边的直线切口很明显 | 舞台 |

## 3. 打磨任务

每项包含规格、数量、验收标准。优先级见第6节。

### A. 物品图标（解决 Q1、Q3）

为57件装备各画一张独立的物品图，用于衣橱格子、开瓶揭晓、图鉴、兑换。

- 画布 512×512 透明，物品居中，四周留白约8%；导出 128/256 WebP。
- 视角：头饰、眼镜为正面略俯视的3/4视角；衣服做“平铺/挂衣架”式的整件展示（领口、袖子、下摆都要画出来），让人一眼知道是整件衣服而不是一条领子；道具与穿戴图层同角度。
- 颜色、图案、关键标识与穿戴图层完全一致（月亮围巾的月亮扣、安保夹克的盾牌徽章、厨师服的红领巾等）。
- 不画身体、不画背景、不带文字。
- 验收：
  - 与穿戴图层并排检查，颜色和标识一致。
  - 64px 下同类之间可区分：把同类图标全部填黑做剪影，评审者在48px下能区分其中90%以上的配对。
  - 浅色、深色、棋盘格三种背景下无白边、无残渣。

### B. 衣服可读性加强（解决 Q1、Q8）

- B1（先做）：在现有画布的可见区（y 0.79–1.0）里加强每件衣服的辨识特征：拉链、帽绳、徽章、色块分区、口袋。目标是脱离图标也能在舞台上一眼认出。只重绘衣服图层，不动身体。
- B2（后做）：衣橱舞台专用的“半身立绘”。画布扩展为 1024×1280，身体画到腰部，所有衣服补画下半部分。仅舞台和揭晓使用，聊天头像仍用现有 1024 方形画布。工作量约等于重做身体 + 24件衣服，排在第三批。
- 验收：24件衣服在舞台 270px 下两两可区分；B2 的上半部分与现有图层叠加时偏差 ≤2px。

### C. 表情扩展（解决 Q4）

新增4个表情，与现有 `face/normal`、`face/happy` 共用 `faceBox` 和眼睛位置：

| id | 名称 | 用途 |
| --- | --- | --- |
| `surprised` | 惊喜 | 开瓶揭晓 |
| `wink` | 眨眼 | 套装称号、角色卡 |
| `focused` | 认真 | Agent 执行中 |
| `sleepy` | 困 | 今日掉落上限、夜间 |

- 眼睛中心必须落在现有5副眼镜的镜片中心，镜片能透出表情。
- 验收：6个表情 × 5副眼镜 × 4个羽色的合成检查图全部通过目视；宇航头盔面罩下表情可见。

### D. 稀有度特效层（解决 Q5）

- 史诗、传说装备在舞台和揭晓时叠加一层很轻的特效：`fx/epic`、`fx/legendary` 全画布透明层（散落的星点、柔光），不随物品变化，避免为每件装备单独画。
- 传说装备额外允许在穿戴图层上增加一处材质高光（金线、星光刺绣），需要重新导出该图层。
- 小于96px的头像不叠特效。
- 验收：特效不遮挡眼睛和喙；在4个羽色和6个纯色背景上都不显脏。

### E. 场景背景（解决 Q6）

首批6张手绘场景，作为可收集背景：海湾日落、深夜书房、星空甲板、咖啡馆、实验室、林间小屋。

- 画布 1024×1024，与头像同风格但更柔和：中心区域（`faceBox` 范围）低对比、少细节，保证鸟始终是主体。
- 每张出一个“小头像简化版”：在 ≤48px 时只保留主色块，避免噪点。
- 验收：30个角色预设分别放在6张场景上的合成检查图；小尺寸下脸部对比度不低于纯色背景。

### F. 漂流瓶（解决 Q6）

- 一个瓶子，三个状态：封口、发光、开瓶（瓶塞弹开、卷纸探出）。
- 发光颜色不单独画四次：画一张白色光晕层，由 UI 按稀有度着色。
- 尺寸：512 主图 + 96 小图（消息流卡片用）。
- 动效：开瓶过程由 UI 在三帧之间做缩放与淡入，不做逐帧动画。
- 验收：与 Kun 并排时画风一致；96px 下瓶子轮廓清楚。

### G. 角色卡（解决 Q6）

- 卡框、稀有度边、名牌用 UI 绘制（清晰、可换肤、可适配深色），不出美术图。
- 美术只负责卡面背景：30张卡复用 E 的场景按主题分配（例如侦探→深夜书房，领航员→海湾日落），不足的主题追加场景。
- 卡背一张（漂流瓶与海浪纹样），用于未点亮卡片的翻面动效。
- 验收：已点亮卡与未点亮剪影卡在同一网格里层次清楚。

### H. 小尺寸适配（解决 Q2）

小头像的身份主要来自脸、帽檐和眼镜，规则优先、素材次之：

1. 合成器规则：≤48px 时不加载道具和抓握翅膀（裁切后不可见），省掉解码；衣服照常加载（领口仍可见一部分）。
2. 眼镜在24px下只剩几条细线。为5副眼镜各出一个 `glasses/{id}.small` 变体：镜框加粗约1.5倍，去掉镜片高光，仅在 ≤34px 使用。
3. 头饰在裁切框内占比过低的（巫师帽、毛线帽、头戴式耳机、安全帽）出 `.small` 变体：帽体下移、收窄，让帽檐进入裁切框。
- 验收：`sizes-light.png`、`sizes-dark.png` 里30个预设在24px下可两两区分的比例明显高于现状（以评审记录为准）。

### I. 羽色统一（解决 Q7）

- 以天空蓝身体为唯一母版，其它3色由构建脚本对身体填色区域做色相/明度映射得到，描边、肚皮、腮红、喙保持不变；羽冠、抓握翅膀同理。
- 风险：映射后的颜色可能比现有生成的颜色发灰。先做一套对照图，和现有 `base/*` 并排给用户确认后再替换。
- 验收：4色身体逐像素只有填色区域不同；衣服、眼镜、头饰叠加后形状完全一致。

### J. 动效素材（可选）

- 眨眼：一张闭眼表情 `face/blink`，UI 每隔数秒切换约120ms。
- 换装“噗”：8帧烟雾/星点精灵图，换装时在装备槽位置播放一次。
- 呼吸、摇摆用 CSS 变换完成，不出素材。

### K. 装备扩充

为了让掉落长期有新鲜感，后续按批次扩充，每批8–12件，至少覆盖两个新套装（对应两张新角色卡）。每批沿用本计划的规格、检查图和验收流程，并在共享目录登记稀有度与套装。

## 4. 制作规范

- 描边：深海军蓝（接近 `#0e2f66`），1024 画布上约10–12px，内部细节线约为外描边的一半。
- 上色：两级赛璐璐阴影 + 一处高光，主光源左上。
- 用色：配件保留原色，不跟羽色变化；传说装备允许金色点缀（接近 `#f0c35a`），其它稀有度不用金色，避免混淆。
- 背景：发布图必须是真实透明像素，不允许白底或棋盘格烘焙进图。
- 边缘：alpha ≥16 的轮廓外不得有浅色残边；在 `#1d2530` 深色底和棋盘格上逐张检查。
- 命名：`{类别}/{id}.png`、`{类别}/{id}.back.png`、`{类别}/{id}.small.png`、`icon/{类别}/{id}.png`、`fx/{rarity}.png`、`scene/{id}.png`、`container/bottle-{state}.png`。
- 禁止：文字、商标、其它产品的角色或界面元素；参考图只用 Kun 自己的素材。

## 5. 生产流程与工具

1. 以锁定身体和对应的现有图层作为参考图生成，透明底输出原稿，保存到 `sources/` 并登记 `generation-records.json`。
2. `scripts/build-kun-avatar-assets.mjs` 增加 `icon`、`small`、`fx`、`scene`、`container` 五类的提取与导出；`scripts/kun-avatar-asset-recipes.mjs` 记录定位。
3. `manifest.json` 增加对应条目；共享目录 `kun/src/contracts/kun-avatar-catalog.ts` 增加 `rarity`、`set`、`flavor` 元数据，构建检查要求每件装备都有图标。
4. `scripts/kun-avatar-compose-check.mjs` 增加检查图：
   - `icons-vs-worn.png`：图标与穿戴效果并排。
   - `icons-silhouette-48.png`：同类图标剪影。
   - `faces-glasses-colors.png`：表情 × 眼镜 × 羽色。
   - `fx-overlays.png`、`scenes-presets.png`、`bottle-states.png`。
   - 小尺寸检查图增加 `.small` 变体前后对比。
5. 自动检查新增：边缘浅色残边检测（深色底上，轮廓带内亮度高于0.85且半透明的像素数超阈值即失败）、图标留白范围、文件体积预算。
6. 关键素材（全部传说装备图标、漂流瓶、6张场景）在生成后由人工修图一遍，再进入管线。

## 7. 体积预算

- 现有三档 WebP 合计约 1.97 MiB。
- 新增预算：物品图标 57 × (128+256) ≈ 1.2 MiB，场景 6 × 约80 KB，漂流瓶与特效约 0.2 MiB，表情与小尺寸变体约 0.3 MiB；合计控制在 +2.5 MiB 以内。
- 衣橱相关素材按需加载（打开衣橱、开瓶时才请求），不进入首屏；聊天头像仍只加载合成需要的图层。
