## 0. 数据口径

实测对象：`src/asset/img/kun-avatar/` 当前 168 个逻辑素材、615 个文件（`node scripts/kun-avatar-compose-check.mjs` 通过，羽色对位 ≤2px，WebP 3.93 MiB）。目视对象：重新生成的 `.cache/kun-avatar-qa/` 全部检查图，另加本次临时生成的放大图（表情特写、领口接缝、270px 舞台特效、场景脸部裁切、图标同比例排列、暗色修复预览、小帽子 4 倍放大）。

指标定义（后续要进自动检查，见第 6 节）：

| 指标 | 定义 |
| --- | --- |
| 低对比占比 | 图标中 alpha ≥200 的像素里，与底色的 WCAG 对比度 <1.5 的比例 |
| 剪影重合度 | 同类两张图标缩到 48px、alpha ≥96 二值化后的 IoU |
| 深色边缘宽度 | 逐行从左缘进入不透明区后，连续亮度 <0.03 像素的长度，取中位数（近似描边宽度） |
| 细节密度 | 图层外接框内相邻像素亮度差之和 / 不透明像素数 |
| 颜色数 | RGB 各通道按 32 量化后的不同颜色数 |
| 中心细节比 | 场景在 `faceBox [232,300,792,860]` 内的细节密度 / 全图细节密度 |
| 进框占比 | 头饰 alpha ≥16 像素落在裁切框内的比例 |

## 2. 风格方向

以下九条是本计划的审美主张。每条给出原则、理由、做法和反例。

### 2.1 脸是品牌，装备是相框

Kun 的辨识度来自"两只大眼 + 橙喙 + 腮红 + 冠羽"这四样。任何装备都不能遮挡眼睛和喙的任何一部分；帽檐最低到眼睛上缘以上 40px（1024 画布）；眼镜镜片必须透明到能看清瞳孔高光；围巾、领口最高到喙下 60px。装备的高光、最亮色、最饱和色都不能超过眼睛高光和喙的橙色，否则视线被拉走。

反例：巫师帽的星星如果再亮一档，24px 头像里先看到的就是星星不是脸。

### 2.2 一支笔

整套素材要像一个人一支笔画出来的。现在深色边缘宽度在 9–28px（1024 画布）之间，相差 3 倍：贝雷帽 26、侦探帽 22、黑卫衣 21、长袍 13、羽毛笔 9，身体 15.5。规范定为：

- 身体与所有穿戴层的**外轮廓** 14–20px，内部结构线 6–9px，细节线 3–5px（都按 1024 画布算）。
- 图标（512 画布）外轮廓 10–12px，面积小于画布 20% 的细长物件允许 12–14px，否则缩到 58px 时撑不住。
- 描边颜色只有一种：海军蓝（接近 `#0e2f66`），不随物品颜色变化；浅色物件也不用灰描边。

### 2.3 剪影优先

一件装备先得在纯黑剪影下被认出来，再谈颜色。头饰、道具、眼镜现在基本做到了（≥0.80 重合度的对子分别是 8/171、2/36、0/10），衣服图标没有做到（90/276，平均 0.69，开衫 vs 安保夹克 0.95，相机衬衫 vs 背带裤 0.95）。原因是 24 件衣服图标全部用了同一个"平铺 T 恤"姿态。修复方案见 F2，核心思路：**图标的姿态可以和穿戴层不同（挂起、折叠、展开、打结），颜色和标识必须相同。**

### 2.4 稀有度是材质，不是闪光

数据说明现在的稀有度没有视觉语言：细节密度普通 0.0101、稀有 0.0135、史诗 0.0126、传说 0.0127，饱和度也没有单调关系，只有颜色数在涨（63→81→87→102）。玩家从画面上看不出传说比稀有"贵"。

定义四级材质，只约束**质感和一处点睛**，不加任何边框、角标、放射光（那些是 UI 的事）：

| 稀有度 | 材质与上色 | 点睛 | 禁止 |
| --- | --- | --- | --- |
| 普通 | 哑光，1 主色 + 1 阴影色，最多 1 点高光 | 无 | 金属、宝石、图案 |
| 稀有 | 2 色搭配，1 条高光，允许条纹/格纹 | 1 个小件（扣子、徽章、口袋） | 金色 |
| 史诗 | 材质暗示（针织、呢料、皮革各用 2–3 笔纹理），金属件用黄铜（`#c98a3a` 系） | 1 处二级高光（如镜片反光、皮革亮面） | 发光 |
| 传说 | 金属 / 宝石 / 发光部件（金 `#f0c35a` + 纯白高光），刺绣或图案 | 1 处微光（素材内，很小），配合特效层 | 大面积金色、彩虹 |

史诗、传说共 19 件的逐件修饰清单见 F3。普通、稀有不动。

### 2.5 暗色主题是一等公民

应用深色主题的卡片底是 `#2c2c2c`，海军蓝描边（亮度 ≈0.02）在它上面几乎没有对比。21/57 个图标超过 40% 像素低对比，黑卫衣 86%、相机 82%、安保夹克 82%、方框和长方框眼镜 75%。这不是重画能解决的（描边颜色不能改），是**底板**的事：所有图标在两个主题下都要落在"中间调"底板上，并由 UI 给出一圈极淡的亮边。方案见 F1，不改素材。

同样的问题在浅色主题是镜像的：米色衬衫、长袍、米色围巾、开衫在纯白底上 68–78% 低对比。现在的浅色格子底不是纯白而是 `#f4f6f9` 的径向渐变，勉强可以；规范里把底板亮度定死，两边都不出问题。

### 2.6 为 24 / 34 / 48px 诚实地设计

聊天里 90% 的时间头像是 34px 的脸部裁切。在这个尺寸只有三样东西能传达身份：帽檐（颜色 + 形状）、眼镜（颜色 + 形状）、羽色。道具 0–9% 进框、衣服 9–26% 进框，不要指望它们。所以：

- 每顶帽子的帽檐或下沿必须进入裁切框 ≥45%（有小尺寸版的 4 顶已做到 49–66%，但原版 19 顶里有 15 顶不足，巫师帽 13%、毛线帽 20%、耳机 26%、安全帽 28%、厨师帽 29%、贝雷帽 30%，见 F8）。
- 眼镜小尺寸版继续保留；镜框都是接近黑的海军蓝，与四种羽色的对比度实测 ≥9，不需要改色，身份靠镜框形状和镜片颜色区分。
- 24px 以下允许"只认颜色"：巫师帽 = 深蓝带星，毛线帽 = 红带白边，这是合理的终点，不再追求形状。

### 2.7 情绪只在眼睛里

原角色没有眉毛。新表情"惊喜、认真、困"都加了一道粗眉毛，和默认、眯眼笑、眨眼放在一起像两套人设，戴帽子时眉毛还会顶到帽檐。情绪全部用眼睛和喙表达：眼睛大小、眼皮位置、瞳孔大小与方向、喙的开合、腮红深浅。具体画法见 F5。

### 2.8 四个羽色是同一只鸟

实测身体主色色相：天空蓝 206°、蓝紫 222°、薄荷青 179°、青绿 174°。薄荷青和青绿只差 5°，24px 下不可分；蓝紫离天空蓝也只有 16°。羽色是玩法里的解锁物（随角色卡解锁），四个必须一眼可分。目标色相：天空蓝 206°（不动）、蓝紫 236°（偏薰衣草）、薄荷青 188°（偏青）、青绿 152°（真正的薄荷绿）；饱和度保持 0.38–0.44，明度 0.86–0.98，保住手绘感。做法见 F7，和 v1 的 I 任务合并。

### 2.9 柔和的游戏感

这是写代码工具里的陪伴功能，不是抽卡大厅。所有仪式感都要"短、轻、不挡事"：换装的"噗"是 400ms 的一次弹跳 + 三颗星；揭晓是淡淡的稀有度光晕，不是放射线和震屏；特效素材不做动画帧，由 UI 做 1–2 个属性的缓动。素材层面：特效层永远半透明、永远不进 faceBox、永远不超过角色外轮廓 20% 的宽度。

## 3. 修复项

按优先级排列。每项标明"改素材 / 改代码 / 两者"，并给出可测的验收标准。

### F1 暗色主题图标可读性（改代码）

- 数据：见 2.5。暗色修复预览中，四种做法（原样 / 中间调底板 / 1.5px 亮边 / 底板 + 亮边）里底板 + 亮边最清楚，单独底板次之。
- 方案：
  1. 图标格子的"井"（`.rooms-avatar-option-art`、装备槽）在暗色主题用 `color-mix(in srgb, var(--ds-text) 12%, var(--ds-surface-card))`（约 `#4a4a4a`），浅色主题用 `#eceff4`，不再用纯白或纯卡片色；稀有度底色按原有 `--avatar-rarity` 14% 混入。
  2. 暗色主题给图标 `<img>` 加 `filter: drop-shadow(0 0 1px rgba(255, 255, 255, 0.5))`，形成 1px 柔和亮边；浅色主题不加。只作用于图标，不作用于舞台合成图。
  3. 不出"暗色版图标"素材；只有在真机验证仍不达标时，才为最差的 8 件（黑卫衣、相机、安保夹克、方框眼镜、长方框眼镜、魔法师披风、巫师帽、月亮围巾）烘焙 2px 亮边变体 `icon/{类别}/{id}.dark.png`。
- 验收：暗色主题冒烟截图里，57 件图标在 58px 格子内轮廓完整可辨；低对比占比指标在 `#4a4a4a` 底上全部 <40%。

### F4 稀有度特效层重做（两者）

- 数据：两层覆盖率 0.85%（alpha >64），0% 在 faceBox 内，颜色偏淡（史诗均值 193,170,224；传说 230,198,136）。270px 浅色舞台上几乎不可见。
- 结构改为两层：
  1. **背光层** `fx/{rarity}.back.png`：画在身体之下，中心 (512, 560)、半径约 420 的柔和径向光晕，峰值 alpha 0.45，边缘归零；外加 2–3 个柔焦光斑。史诗紫（`#7a68e8`）、传说金（`#f0c35a`）。任何尺寸都能读到"有光环"。

- 代码：合成器图层顺序增加 `fx/*.back` 在 `outfit/*.back` 之前；特效仍只在舞台和揭晓请求，≥96px；UI 不再对特效层整体着色。
- 验收：270px 浅色与深色舞台截图里，史诗和传说一眼可分；24/34/48px 不叠特效；特效像素 0% 落在 faceBox。

### 10.1 口径冲突与未通过项

- F1 的柔光边改善轮廓，不会改变 `alpha>=200` 的内部颜色与底板对比。因此没有将截图清晰等同于“全部低对比占比 <40%”，也没有通过任意改底板或烘焙白边掩盖指标。
- 第 0 节逐行宽度和 F6 距离变换不是同一量：斜边逐行穿过的长度会更大；指定海军蓝 `#0e2f66` 的 WCAG 亮度约 0.030857，已略高于 `<0.03` 的深色分类阈值。脚本分别报告两者，并保留原严格门限；当前 96 个阻断全部来自距离变换。阈值和是否扩大重画范围仍待确认。
- F3 按本次明确的相邻像素求和算法，稀有组基线不等于原临时脚本的 0.0135/81。报告同时保留固定阈值与同算法稀有组比较，不用两种口径混算。固定阈值仍未通过：侦探帽穿戴/图标、宇航头盔穿戴/图标、兜帽穿戴/图标、实验服图标、放大镜穿戴、烧瓶穿戴；不为凑颜色数添加无意义杂色。
- F4 中心径向背光和“特效完全不进 faceBox”存在文字冲突。本轮采用层次语义：身体后的背光可经过 faceBox，但顶层星屑连抗锯齿像素也不得进入 faceBox。两层分别检验，不把背光混入星屑覆盖率。
