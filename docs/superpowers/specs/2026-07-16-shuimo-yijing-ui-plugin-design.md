# 水墨易经 UI 插件设计

日期：2026-07-16
状态：已批准

## 目标

为 Kun 新增一个可在“设置 → 形象工坊”启用的预装 UI 插件 `shuimo-yijing`。插件以清雅文人画为浅色主题，并提供对应的深色墨夜主题。应用每次启动时按梅花易数的年月日时规则起一卦，将该卦在《周易本义》中的卦名、卦辞、本义注、动爻及其本义注，以低对比度行楷书法铺陈在整个窗口背景。

主题必须保持前景内容清晰、应用离线可用，并继续遵守 UI 插件不执行代码的安全模型。

## 非目标

- 不允许第三方 UI 插件执行 JavaScript、HTML 或 CSS。
- 不把梅花易数或动态背景配方加入通用 `manifest.json` 协议。
- 不提供占卜解释、吉凶建议、历史卦象或手动重新起卦功能。
- 不在运行时联网获取历法、经文、字体或图片。
- 不新增独立于现有 `system`、`light`、`dark` 的主题模式。

## 用户体验

### 形象工坊

`shuimo-yijing` 与 `ikun` 一样作为预装 UI 插件出现，提供标准插件卡片、预览图、启用、停用和删除行为。老用户升级后能够收到该插件；用户主动删除后，后续启动不再自动恢复。

插件启用后，浅色和深色由现有应用主题设置决定。切换明暗主题只改变色板和墨迹颜色，不重新起卦。停用插件后立即移除书法背景、插件 token、形象和文案。

### 浅色主题

浅色主题采用宣纸白、松墨灰、灰绿和克制朱砂。主背景避免纯白，边框和阴影保持柔和，强调色用于选择状态、焦点和必要操作，不让界面被单一灰色主导。

### 深色主题

深色主题使用墨夜黑、暖灰白、暗灰绿和低亮度朱砂。它与浅色主题保持相同的信息层级和表面结构，不使用纯黑、纯白或高饱和红色。

### 书法背景

背景覆盖整个应用窗口，以从右向左的竖排书法展示当前启动卦。显示内容依次为：

1. 卦名
2. 卦辞
3. 卦辞对应的本义注
4. 动爻爻辞
5. 动爻对应的本义注

浅色墨迹目标透明度为 5%–7%，深色墨迹为 4%–6%。侧栏、顶栏、卡片、代码块、编辑器和输入框使用 88%–98% 的实底或等效不透明表面，保证书法不会穿透并干扰前景内容。

背景层固定在应用壳层，设置 `pointer-events: none`、`user-select: none` 和 `aria-hidden="true"`。它不参与搜索、复制、键盘导航或屏幕阅读。窗口变窄时减少可见字列并增大列间距，不缩小前景字体。背景在插件数据就绪后短暂淡入；系统启用减少动态效果时不执行过渡。

## 架构

### 预装插件

在 `src/main/ui-plugin-bundled.ts` 中新增 `shuimo-yijing` 的 manifest 和形象资源。manifest 继续使用 UI 插件 v1 的既有字段：

- `figures`：水墨 Kun 的通用槽位图片
- `labels`：中英文进行中文案
- `tokens.light`：浅色完整色板
- `tokens.dark`：深色完整色板
- `features.cameos`：设为 `false`，不启用通用彩蛋，以保持安静的文人画氛围

预装标记从单一全局标记改为每个插件独立的版本标记。播种逻辑必须做到：新插件可以进入已有安装；成功播种后写标记；播种失败允许下次重试；用户删除已有插件后不因后续普通启动而复活。

### 宿主效果

`shuimo-yijing` 的动态背景采用与 `ikun` 专属动画相同的可信宿主特例，但不把逻辑写入插件目录。共享加载结果新增可选、带判别字段的只读宿主效果：

```ts
type UiPluginHostEffect = {
  kind: 'shuimo-yijing'
  hexagram: {
    ordinal: number
    name: string
    statement: string
    statementCommentary: string
    movingLine: number
    movingLineText: string
    movingLineCommentary: string
  }
}
```

只有主进程在加载内置 `shuimo-yijing` 时能够构造该字段。磁盘 manifest 的标准化、第三方插件安装和第三方插件加载都不能声明或注入 `hostEffect`。

主进程在应用启动时捕获一次本地时间，并惰性生成一次宿主效果。重复加载插件、切换路由、打开设置和切换浅色/深色均复用同一结果。重新启动应用才重新起卦。

### 渲染层

`ui-plugin-store` 将可选 `hostEffect` 保存到激活插件运行时状态，并维持现有 `data-ui-plugin` 和 token 样式注入机制。`AppShell` 挂载专用的 `ShuimoYijingBackdrop`，使背景覆盖 Workbench、Settings 和其他应用内路由，同时保持窗口标题栏和交互表面位于其上方。

组件只消费已经校验的结构化文字，不拼接 HTML。书法字体通过应用包内的字体资源加载；背景内容以 React 文本节点渲染。

## 起卦规则

使用 MIT 许可的 `lunar-typescript` 将系统本地启动时间转换为农历日期、年支和时支。序数规定如下：

- 十二地支：子一、丑二、寅三、卯四、辰五、巳六、午七、未八、申九、酉十、戌十一、亥十二。
- 八卦：乾一、兑二、离三、震四、巽五、坎六、艮七、坤八。
- 六爻：初爻为一，上爻为六。

计算公式：

```text
基础数 = 年支序数 + 农历月 + 农历日
上卦 = 基础数 mod 8
下卦 = (基础数 + 时支序数) mod 8
动爻 = (基础数 + 时支序数) mod 6
```

八卦余数为 `0` 时映射为 `8`，动爻余数为 `0` 时映射为 `6`。闰月使用对应月份的数字，不增加额外偏移。子时定义为本地时间 `23:00–00:59`，不执行晚子时换日；农历日以系统民用日期转换结果为准。

起卦逻辑实现为无副作用纯函数，输入为显式时间与时区上下文，输出为上下卦、六十四卦序和动爻，便于边界测试。

## 文本与字体来源

《周易本义》采用中文维基文库的《周易本義（四庫全書本）》分卷文本作为校勘来源：

- 入口：`https://zh.wikisource.org/wiki/周易本義_(四庫全書本)`
- 作者：朱熹
- 站点文本许可：Creative Commons Attribution-ShareAlike 4.0

开发期生成并人工抽查离线结构化数据，运行时不抓取网页。仓库中保存来源 URL、抓取或校勘日期、许可说明和必要的归属文本。数据集覆盖 64 卦，每卦包含卦名、卦辞、本义注和六条爻辞及其本义注。

背景字体使用 `@fontsource/ma-shan-zheng` 提供的 Ma Shan Zheng 字体，许可为 SIL Open Font License 1.1。应用包保留字体许可。该字体仅用于背景书法；加载失败时回退 `STXingkai`、`KaiTi` 和系统衬线字体。

## 失败处理

- 历法转换、起卦计算或经文匹配失败：保留水墨配色和形象，隐藏书法背景，并记录不含用户数据的警告。
- 字体加载失败：使用系统字体回退，不隐藏背景。
- 插件资源播种失败：不写成功标记，下次启动重试；不阻塞主窗口。
- 插件加载失败：沿用现有行为回退默认 UI 模式并展示现有错误状态。
- `hostEffect` 缺失或类型不匹配：渲染层不显示背景，不接受未校验的替代对象。

## 安全与隐私

- 起卦仅使用本地启动时间，不持久化精确启动时间，也不发送网络请求。
- 宿主效果由可信主进程生成，插件 manifest 无法声明动态代码或背景内容。
- 经文通过文本节点渲染，不使用 `innerHTML`。
- 插件安装仍只复制白名单 manifest 和图片；字体与经文属于应用内置资源，不从插件目录读取。
- 背景不会捕获输入、鼠标事件或辅助技术焦点。

## 测试与验证

### 单元测试

- 起卦纯函数覆盖固定已知时间、八卦余数为零、动爻余数为零、子时两端、月日边界和闰月。
- 八卦组合到六十四卦的映射覆盖 64 个唯一结果。
- 经文数据断言恰有 64 卦、每卦六条爻、序号唯一且所有必填文字非空。
- manifest 标准化继续拒绝 `hostEffect`；普通插件加载结果不含宿主效果。
- 预装播种测试覆盖已有 iKun 用户、新插件首次播种、失败重试和删除后不复活。
- IPC 测试使用固定启动时间，验证多次加载返回同一启动卦。
- Zustand 和组件测试覆盖插件启停、明暗切换不重新起卦、无宿主效果时降级，以及背景的 `aria-hidden` 和无指针事件属性。

### 视觉验证

使用 Playwright 对 Code、Design、Write、Settings 截取浅色和深色截图，并覆盖常用桌面窗口与窄窗口。检查：

- 背景非空且当前卦文字可辨认但不抢占注意力。
- 侧栏、顶栏、输入框、代码块、编辑器和模态框内容不被背景遮挡。
- 长文、长文件名、工具提示和错误状态无重叠。
- 切换主题和停用插件后不存在旧墨迹或旧 token 残留。

### 工程检查

至少运行：

```bash
npm run typecheck
npm run test
npm run build:kun
npm run build
```

提交前运行 `git diff --check`，并区分本次引入的失败与已有基线失败。
