## 本次已处理

| 复审问题 | 处理结果 |
|---|---|
| 新研究会话在首条消息前刷新后丢失入口 | 按文献库在当前手机标签页保存未发送研究会话列表。刷新后会话选择器继续列出草稿；发送成功后移除待发送标记。 |
| 阅读页码写入失败被主进程吞掉 | `paperLocalStateWrite` 改为明确返回成功或错误。手机保留失败页码并提供重试；页内返回先等待写入，失败时给出重试或明确选择不同步离开。 |
| 拒绝浏览器后退会改写目标历史项 | 给手机历史项标记位置；拒绝时用浏览器历史移动回原项，保留 Back/Forward 两个方向的目标。异步检查期间的新导航不会被旧结果覆盖。 |
| NOTES.md 不存在时创建失败没有反馈 | 捕获 Remote/文件错误，在原界面显示原因并保留重试按钮。 |
| 嵌套文件夹的「返回上一级」回到根目录 | 根据当前路径生成真正的父目录路由，根目录下才返回 Work 首页。 |
| 「最近打开」刷新后消失 | 在手机会话中按工作区保存最近文件；刷新恢复，改名/删除或文件失效后移除旧记录。 |
| 打开已知论文时扫描所有文献库 | 同一手机标签页保存经过 key 校验的论文路由；已知论文只读所属库。未知链接仍采用全库扫描与碰撞保护。 |

## 验证要点

- 研究草稿：新建多个未发送会话，切换、刷新、回到原草稿并发送；不同文献库之间不可串用。
- 阅读进度：模拟主机磁盘写入失败与重试；失败不能显示为已同步，快速返回不能丢掉待写入页码。
- 导航：未保存编辑阻止浏览器后退或前进后，保存并再次操作仍能到原目标；嵌套三层文件夹逐层返回。
- 最近文件与论文链接：手机刷新后最近文件可重新打开；已知 B 库论文在 A 库暂时不可用时仍可打开 B，未知链接继续保守校验。

## 后续体验验证

- 真实 iOS Safari 与 Android Chrome 的 PDF 文本选择、下载、键盘、安全区、文件上传和屏幕阅读器仍以设备清单为准；此前的真机验收豁免不代表这些路径已验证。
- 长 PDF 搜索目前逐页扫描并只定位到匹配页；导入在网络中断且响应丢失时仍需用户核对文献库最终结果。若要自动给出确定结论，需要持久任务回执与更完整的 PDF 文本索引。
- 现有手机文案覆盖简体中文和英文，其他语言使用英文回退。
