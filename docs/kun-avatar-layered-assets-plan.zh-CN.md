# Kun 头像分层素材制作计划（自定义换装）

> 状态：计划，尚未实施（2026-10-07）。本文只讲两件事：一是怎么做出和现有 30 张头像画风完全一致的分层素材，二是素材到位后怎么接进应用。

## 1. 结论

- 想要像游戏一样自由换颜色、头饰、眼镜、衣服，又要和现有头像一模一样，就必须按原画风格重新制作分层素材：
  - 一张无配件的底图，附带几种颜色变体；
  - 每一件头饰、眼镜、衣服、道具单独一张透明图层；
  - 所有图层都在同一张画布、按同一套对齐基准绘制。
- 不能从现有 30 张里直接抠配件。它们是整张生成的位图，配件和小鸟画在同一层；而且每张图里小鸟的位置和比例都不一样（实测见 2.2），抠出来的帽子叠到别的底图上会错位。
- 也不建议用矢量重画。我们试了 3 版，比例和光影都能接近，但始终是另一种画风（见 2.3）。
- 推荐做法：底图只生成或绘制一次，并锁定。之后所有配件都在这张底图上局部绘制或局部重绘，再导出成透明图层，这样坐标天然对齐。这一步可以交给画师（方案 A），也可以走「AI 局部重绘 + 像素差分抠层 + 人工清理」（方案 B），见第 4 节。

### 2.2 为什么不能直接拆现有图

从 30 张里挑出五官检测可靠的 18 张，测量结果如下（单位为 px，每格 229）：

| 指标 | 范围 | 最大偏差 |
| --- | --- | --- |
| 喙中心 x | 91–113 | 22（9.6%） |
| 喙中心 y | 139–157 | 18（7.9%） |
| 左眼中心 y | 122–138 | 16（7.0%） |
| 右眼中心 y | 123–140 | 17（7.4%） |
| 两眼间距 | 77–89 | 12 |

同一部位在不同图里差了 7%–10%。另外配件和身体、翅膀之间的遮挡边缘已经合在一起，抠下来以后，被挡住的那部分身体还得重画。所以「从现有图里拆」的工作量和效果，都不如重新分层制作。

### 2.3 矢量重画的结论

我们用 SVG 画了 3 版：

- v1：平涂；
- v2：加光影；
- v3：调整头身比例和腮红。

头身比例、配色、光影方向都能接近，但描边质感、柔和渐变和手绘细节始终不同，和原图放在一起能明显看出是两套画风。矢量版只适合作对齐草图，或者以后需要超轻量占位时再用，不作为正式素材。

## 3. 素材规格

### 3.1 画布与导出

- 母版：2048×2048 的 PSD（Procreate 也可），所有图层共用一张画布，不裁切。
- 交付：每个图层导出整张画布的透明 PNG，1024×1024，RGBA，sRGB，不要裁掉空白边。只有这样，叠起来才会自动对齐。
- 应用内另外生成 512 / 256 / 128 三档 WebP。
- 背景不画进任何图层，应用里单独铺背景色。原图背景色约为 `#f7f5ef`。

### 3.2 构图基准

以下按 1024 画布计。先画底图，底图定稿后的实际坐标就是所有配件的对齐标准；下面这些数是按现有 30 张的平均值换算出来的起点。

| 部位 | 位置 | 说明 |
| --- | --- | --- |
| 水平中线 | x = 512 | 现有图集平均偏左约 6%，新底图要居中 |
| 两眼中心 | y ≈ 584（57%） | 两眼中心距 ≈ 376（37%） |
| 喙中心 | (512, 666)（65%） | — |
| 头顶（不含羽冠） | y ≈ 190（约 19%） | 羽冠最高点不高于 y = 40，留 4% 安全边 |
| 肩线 | y ≈ 880 | 翅膀从左右下角出画，构图和现有头像一样是半身 |
| 脸部框 `faceBox` | (232, 300)–(792, 860) | 列表小头像（≤48px）按它裁到脸部，记录在 manifest 里 |

### 3.3 图层结构（从下到上）

| 顺序 | 图层 | 内容 |
| --- | --- | --- |
| 0 | `background` | 应用绘制，纯色或透明 |
| 1 | `back`（后片） | 绕到头或身体后面的部分：兜帽后片、披风后摆、宇航头盔后半球 |
| 2 | `crest` 羽冠 | 单独一层，方便帽子把它藏起来 |
| 3 | `base` 底图 | 不戴任何配件的小鸟：身体、奶油色肚子、翅膀、描边、光影 |
| 4 | `face` 表情 | 眼睛、喙、腮红：默认 / 眯眼笑 / 眨眼…… |
| 5 | `outfit` 衣服 | 盖住肩部，自带描边和阴影 |
| 6 | `glasses` 眼镜 | 镜片半透明（alpha 约 15%–30%），要能透出眼睛 |
| 7 | `headwear` 头饰 | 帽子、耳机、发带、桂冠…… |
| 8 | `prop` 手持道具 | 道具，加上抓着它的那只翅膀尖 |

`face` 也可以先和 `base` 合成一张，但要做表情就必须拆开。

### 3.4 遮挡与互斥规则（写进 manifest）

- `hidesCrest`：帽子是否把羽冠完全盖住。
  - 毛线帽、厨师帽、巫师帽、安全帽：`true`。
  - 耳机、桂冠：`false`。
  - 侦探帽、贝雷帽：按原图来，原图里羽冠会从帽子后面露出来。如果需要，可以多交一张压低的羽冠 `crest/tucked.png`。
- `excludes`：互斥关系。
  - 宇航头盔和其他头饰、眼镜都互斥；兜帽和帽子互斥。
  - 飞行员、创客戴在额头上的护目镜算头饰，不算眼镜。
- 道具会挡住右下角的翅膀，所以道具图层自带「抓握的翅膀尖」。这块翅膀要跟着身体变色，处理方式见 3.5。

### 3.5 颜色

- **身体颜色**：首批 4 种，色值取自现有图的中间调（实际画面有渐变）：

  | id | 名称 | 参考色 | 现有角色举例 |
  | --- | --- | --- | --- |
  | `sky` | 天空蓝 | `#95cbf6` | 协调员、侦探、作家 |
  | `teal` | 薄荷青 | `#7cdadb` | 程序员、科学家、医生 |
  | `periwinkle` | 蓝紫 | `#a6c1fc` | 评审员、数据分析师、摄影师 |
  | `mint` | 青绿 | `#79d1cb` | 设计师、园丁 |

  推荐做法：画师在 PSD 里用「色相/饱和度」调整层，导出 4 张底图变体，质量最好。同时交一张 `base.mask.png`（白色 = 可换色的羽毛区域，不含肚子、眼睛、喙、腮红、描边），为以后支持任意颜色留余地。羽冠和道具里的翅膀尖也照此出变体或蒙版。
- **配件颜色**：首批每件只交原色。需要可换色的配件（帽子、卫衣、围巾）另交 `*.mask.png` 标出可着色区域，应用里用「颜色 × 明暗」着色，保留原有的高光和阴影。
- **统一色**（取自原图，所有图层都要对齐）：

  | 部位 | 色值 |
  | --- | --- |
  | 描边 | `#071836` |
  | 喙 | `#fba83a` |
  | 腮红 | `#fd9182` |
  | 肚子 | `#fdf4e2` |

## 4. 怎么做出「一模一样」

两种方案的共同原则：**底图只做一次，所有配件都在这张底图上画或重绘**。永远不要让人或模型重画整张图，否则位置和比例又会漂。

### 方案 A：画师分层重绘（质量最稳）

1. 以现有 30 张为风格参考，先画标准底图：无配件、居中、符合 3.2 的基准。确认后锁定。
2. 在同一个 PSD 里，每件配件一个图层组，画在底图上方。被配件挡住的身体不用擦，盖住就行；绕到后面的部分单独放在 `back` 组。
3. 用第 5 节的合成检查脚本出图，把每件配件叠到底图上，和对应的原角色并排对比。
4. 工作量估算：
   - 底图、羽冠和 4 个颜色变体：约 2 天；
   - 每件配件：1–3 小时；
   - 首批 12 件（见第 7 节）：约 3–4 天；
   - 补齐全部配件：再加 5–7 天。

### 方案 B：AI 局部重绘 + 差分抠层 + 人工清理（原图本来就是 AI 生成的，画风最容易贴近）

1. **底图**：选一张配件最少的原图，比如「协调员」，只戴了耳机、没穿衣服。
   - 用带蒙版的局部重绘去掉耳机，补全头部和羽冠。
   - 人工修线，统一描边粗细，把小鸟缩放、平移到 3.2 的基准位置。
   - 定稿后导出无背景的 1024 图。
2. **配件**：以底图为输入，按配件类型画蒙版，在蒙版内做局部重绘。
   - 蒙版区域：头饰 = 头顶，眼镜 = 眼部，衣服 = 肩部，道具 = 右下角。
   - 提示词：描述这件配件，并要求「画风、描边、光照与原图一致」。
   - 参考图：用原 30 张里对应的角色，比如侦探帽就参考「侦探」。
3. **抠层**：把重绘结果和底图逐像素对比，**只保留蒙版内**变化超过阈值的像素。
   - 根据差值和颜色距离生成 alpha，边缘羽化 1–2px。
   - 人工清理半透明边缘、描边断口和溢出的阴影。
   - 镜片这类半透明部件要手动设定 alpha。
4. **透明背景**：如果模型不支持透明输出，就在纯色背景上生成（比如品红 `#ff00ff`），再抠色。
5. **工具支持**：
   - Kun 现有的 `generate_image`（`kun/src/adapters/tool/image-gen-tool-provider.ts`）支持参考图和整图编辑，可走 OpenAI 兼容的 `/images/edits`、Codex 和火山方舟。
   - 但它还不能传蒙版，也不能要求透明背景。走这条路要先给工具加上 `mask_path` 和 `background` 参数，或者直接在支持局部重绘的工具里做（例如 Photoshop 的生成式填充）。
6. **工作量和成本**：每件配件大约生成 3–8 次，再清理 20–40 分钟；费用按所用图像接口计费。用哪个服务、预算多少，需要先确认。
7. **风险和对策**：

   | 风险 | 对策 |
   | --- | --- |
   | 模型改动了蒙版外的像素 | 抠层只看蒙版内的差分 |
   | 描边粗细、颜色不一致 | 抠完统一做一次描边校色 |
   | 同一配件多次生成风格不一 | 每件配件只选一次结果，锁定后不再重生成 |

### 方案对比

| | 方案 A：画师 | 方案 B：AI + 人工清理 |
| --- | --- | --- |
| 和原图一致程度 | 高，取决于画师 | 高，本来就是同一类模型生成的；需要清理 |
| 对齐 | 同一 PSD，天然对齐 | 局部重绘 + 差分，天然对齐 |
| 首批周期 | 约 5–6 天 | 约 3–5 天 |
| 成本 | 画师费用 | 图像接口费用 + 清理工时 |
| 前置工作 | 无 | 给 `generate_image` 加 mask 和透明背景参数，或改用外部工具 |

## 5. 质量检查（验收）

- 写一个合成检查脚本 `scripts/kun-avatar-compose-check.mjs`：
  - 读取 manifest，把每件部件叠到每种底色上，导出总览图；
  - 按 30 个原角色的组合合成一遍，和原图同尺寸并排，方便逐个比对。
- 检查项：
  - **对齐**：眼睛、喙、羽冠和底图完全重合，误差 ≤ 2px（以 1024 画布计）。
  - **边缘**：没有白边、锯齿或半透明残渣。
  - **遮挡**：羽冠、眼镜、翅膀、道具之间的前后关系正确。
  - **小尺寸**：24 / 34 / 48 / 96px 下都能看清。
  - **暗色背景**：边缘不露底色。
- **颜色**：描边色、腮红色与 3.5 的取样色差 ΔE ≤ 5。

## 6. 应用接入（素材到位后再做）

- **数据**：`RoomAvatarReference` 新增 `composed` 类型（`kun/src/contracts/room-content.ts`）。
  - 结构：`{ kind: 'composed', parts: { color, face, headwear, glasses, outfit, prop, bg } }`。
  - zod 严格校验每个 id 都在 manifest 里。
  - 旧的 `builtin` 和 `uploaded` 继续有效，用户资料和 Agent 身份都不需要迁移。
- **预设**：把 30 个原角色写成 30 个 `composed` 预设，比如「侦探」= 侦探帽 + 放大镜。用户可以从预设开始改。新素材覆盖全部角色之前，预设缩略图先沿用原图。
- **渲染**：`RoomAvatar` 按图层顺序合成。
  - 列表里一屏可能有几十个头像，所以按「部件组合 + 尺寸」把合成结果缓存成位图（OffscreenCanvas → ImageBitmap / objectURL），而不是每个头像叠 6–8 张图。
  - ≤48px 时按 manifest 的 `faceBox` 裁到脸部，沿用现在的规则。
- **编辑器**：桌面「我的头像」、Agent 设置和手机头像编辑器，统一成游戏式面板：
  - 分类标签：颜色 / 表情 / 头饰 / 眼镜 / 衣服 / 道具 / 背景；
  - 每个选项显示缩略图，选中即预览；
  - 支持随机、恢复默认，以及从 30 个角色预设一键换装。
- **体积**：首批约 60 张 512px WebP，大约 3–6MB。缩略图按需懒加载。
- **测试**：schema 单测、合成结果快照、`--workbench-only` 和手机端冒烟截图。
