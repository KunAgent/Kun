# Codex 历史引用分支

在设置的实验室中开启“Codex 历史分支”后，Code 侧边栏会出现“从历史创建分支”入口，选择 Codex 来源。
该功能默认关闭；关闭时不会扫描 Codex 目录，也不能创建分支或读取外部历史。
已经创建的 Kun 分支及其新消息不会被删除。

## 创建与浏览

- 从本机 Codex 会话列表选择，也可以手动选择 `.jsonl` / `.jsonl.zst`。
- 默认从最后一个完整回合继续，也可以在预览中选择较早的完整回合。
- 默认工作目录跟随选定回合的有效目录；手动选择的目录保持优先。
- 同一段源历史可以建立多个独立 Kun 分支。每个分支只保存自己的新对话。
- 旧历史以只读消息展示。查看和滚动不会调用模型，也不会执行原工具或恢复旧审批。
- 图片等附件按需从原日志或允许的本地文件读取，不会自动复制到 Kun 附件库。

## 模型上下文与存储

Kun 保存来源引用、固定截止位置和内容指纹，不另存完整 Codex 日志或 Markdown。
默认不会生成交接摘要，也不会把最后几轮自动放进模型请求。

模型开始时只看到历史引用及新的用户请求。需要旧背景时，它可以通过
`read_source_history` 搜索或读取相应回合。实际读取的片段属于新工具结果，
会正常保存，所以重启后仍能使用已经读过的内容。

“查看历史片段”定位具体原始记录，长回合支持向前和向后分页。
补载历史和跳转片段按固定来源顺序合并，不用相同时间戳猜测消息位置。

## 原文件变化

创建分支后，Codex 继续追加的内容不会进入该分支。原文件改名、归档或重新压缩后，
可以重新关联；Kun 会验证固定范围内的内容仍然相同。

如果原文件被删除或原有内容被改写，旧历史会显示不可用。Kun 新消息和已经读取的
片段仍保留，但未读取的历史无法恢复。来源引用不是备份。

工作目录不存在时可以浏览历史，发送新消息前需要选择有效的工作目录。
删除或归档 Kun 分支不会删除 Codex 原文件。

再次分支沿用当前会话的工作目录，分支标记按 Kun 回合定位。
实验室开关变化会刷新引用历史的显示和缓存，不清除 Kun 新消息或中断当前执行。
后台事件触发的 Codex 自主回合与用户回合使用各自的分支边界；长记录读完后仍可继续向前翻页。

最后一个关联线程删除后，Kun 会回收不再使用的引用元数据。共享引用和未完成创建仍保留；
删除请求只留下不含原路径、标题和工作目录的精简标记，防止重试重新创建已删除的线程。
内存索引缓存最多保留 8 份、估算 8 MiB 的位置元数据，不缓存正文；来源文件发生变化后失效，
返回正文前仍校验固定范围的内容指纹。

会话恢复使用宿主保存的结构化引用信息，不从用户消息正文猜引用。
线程元数据丢失但 Kun 会话仍可恢复时，引用回收会保留它所需的描述。
内部数据迁移也携带引用描述，共享描述只导出一次，不包含 Codex 原日志；
目标机器暂时没有源文件时仍可恢复 Kun 新消息，并在之后重新关联原文件。

## 实现边界

该功能是同一 Kun Runtime 内的只读数据源，不启动 Codex、不读取账号令牌、
不使用云端会话接口，也不增加第二个 Agent。来源投影只进入 HTTP 时间线响应；
Kun 原生事件序号、活动回合、审批和用量只记录新分支的执行。

实验室设置为 `agents.kun.lab.codexReferenceBranches.enabled`，缺失按 `false` 处理。

## Claude Code 来源

同一入口也支持 Claude Code。设置 -> 实验室 -> 历史引用分支中有独立的
“Claude Code 历史分支”开关，默认关闭，不跟随 Codex 开关自动开启。
弹窗只显示已经开启的来源，切换来源会清空当前选择和预览。

Claude Code 从 `CLAUDE_CONFIG_DIR/projects` 或默认 `~/.claude/projects` 发现
本机主会话；支持项目、关键词、日期筛选，以及手动选择 `.jsonl` / `.jsonl.zst`。
首轮扫描逐文件读取元数据，后续列表使用有数量上限、按文件变化失效的摘要缓存。
不调用 Claude 云端 API、不启动 Claude Code、不读取账号凭证。

解析器按 UUID 父链恢复最新主分支，区分真实用户输入与工具结果，并展示文本、
可用 thinking、工具参数和结果及声明的附件。完整回合可创建分支；未完成的尾部
可以预览，但不能作为分支点。压缩、缺失父记录和不支持的内容会显式提示。
第一版只展示主会话已有的子代理调用和结果，不展开子代理独立日志。

引用仍固定在选定回合，旧消息不自动进入模型上下文。`read_source_history` 共用于
两个来源，实际读取片段作为新工具结果保存。分页、精确定位、附件、重新关联、
恢复、迁移与引用回收采用相同机制，不复制完整历史或自动生成交接摘要。
原文件被清理后，未读取的历史不可恢复；Kun 新消息和已读取片段保留。

运行时新增 `/v1/history-sources/claude-code/sessions` 和 `/preview`；创建引用分支
使用 `sourceProvider: "claude-code"`，与模型的 `providerId` 不同。旧请求省略来源
继续按 Codex 处理；再次分支以已有引用的来源为准。

## OpenCode 来源

“OpenCode 历史分支”是独立且默认关闭的实验室开关，开启后进入同一个
“从历史创建分支”弹窗选择 OpenCode。支持本机 SQLite 数据库、旧 JSON 存储目录，
以及 OpenCode 导出的 `{ info, messages }` 会话 JSON。

默认查找 `$XDG_DATA_HOME/opencode`，未设置时查找 `~/.local/share/opencode`。
数据库优先于同 ID 的旧目录记录。旧目录包括 `storage/session/<project>/<session>.json`
及更早的 `project/<project>/storage/session/info` 布局。列表支持项目、关键词、日期和
归档筛选，每次最多返回 200 条，隐藏子代理会话。手动选择数据库或目录后先选择
其中的会话；手动选择单个导出 JSON 会直接预览。

数据库使用只读连接和短事务，读取 WAL，不执行 OpenCode 初始化或迁移。
引用保存消息/内容块的 ID、固定顺序和规范化内容指纹，不复制数据库、JSON 或旧正文。
记录按 OpenCode 的二进制 ID 顺序排列，不依赖操作系统区域设置。
新增消息、其他会话更新、checkpoint 和 VACUUM 不影响已有引用；固定记录被修改、
删除或压缩清理后会显示不可用，Kun 新消息和已读取片段继续保留。

创建时排除撤销边界后的记录，只有已完成且工具结果齐全的回合允许创建分支。
保留文本、reasoning、工具参数/结果、声明的附件和压缩标记；不展开子代理独立日志。
模型仍通过 `read_source_history` 按需读取，浏览与预览不自动加入模型上下文。

OpenCode 引用使用 parserVersion 2 和记录清单，旧 JSONL 引用格式保持兼容。
一次来源快照最多读取 10,000 条消息/内容块记录及 64 MiB 原始数据；导出 JSON 单文件也限制为 64 MiB，
超出时明确报错，不生成截断后冒充完整的分支。重新关联要求来源格式、会话身份和
固定记录指纹匹配；不自动在 SQLite、旧目录与导出文件之间转换。
恢复、内部迁移与垃圾回收保留完整引用清单，不携带原始正文。

新增 `/v1/history-sources/opencode/sessions` 与 `/preview`；创建请求指定
`sourceProvider: "opencode"`，可携带 `sourceKind: "sqlite" | "legacy" | "export"`。
数据库和目录必须同时指定 `sessionId`。记录清单只在 Kun 管理的数据目录保存。
