# Kun 衣橱：对话掉落与换装设计

> 更新：2026-10-09。状态：M1、M2 已实现，M3、M4 大部分实现；第三轮加入瓶架、十连开和开瓶特效（见第 9、10、11 节）。对话主题加成、手机端衣橱面板待做。
> 设计稿画布：https://claude.ai/artifact/MfduEGkMqoLaQGovrUYNRz （私有，需在画布的 Share 菜单里共享后他人才能打开）。
> 美术配套：`docs/kun-avatar-art-polish-plan.zh-CN.md`。素材与合成基础：`docs/kun-avatar-layered-assets-plan.zh-CN.md`。

## 1. 目标

现有换装工作室（`RoomAvatarComposer` + `RoomAvatarStage`）已经能用79个手绘图层自由组合，但所有装备一开始就全部可用，没有“得到”的过程，像设置页而不像游戏。本设计把它改成一个收集型衣橱：

- 换装本身要像游戏：大舞台、纸娃娃式装备槽、悬停试穿、稀有度、套装称号。
- 装备和角色要“挣来”：和 Agent 正常对话时随机捡到漂流瓶，开瓶获得装备或角色卡。
- 收集有方向：重复装备变成羽毛，可兑换指定装备；集齐套装自动点亮角色卡；角色卡可分配给自己或任意 Agent。
- 不打扰工作：掉落只在回合结束后出现，Agent 执行中不弹窗、不出声，可整体关闭。

非目标：不涉及付费、不联网、不调用模型或图像服务；掉落和换装全部在本地 Kun 运行时完成。

## 2. 核心循环

```text
和 Agent 对话（回合正常完成）
  → 掉落判定（概率 + 保底 + 每日上限）
  → 消息流里出现漂流瓶卡片 / 侧栏头像角标
  → 开瓶揭晓：新装备 / 重复转羽毛 / 角色卡
  → 立即穿上，或收进衣橱
  → 集齐套装 → 点亮角色卡 → 分配给自己或 Agent
  → 继续对话
```

### 3.2 羽色、表情、背景

- 羽色：天空蓝、薄荷青默认拥有；蓝紫、青绿随“点亮任意一张该羽色的角色卡”解锁。
- 表情：默认、眯眼笑默认拥有；新增表情（见美术计划）随对话解锁。
- 背景：6个纯色免费；手绘场景作为后续收集物，美术完成前在衣橱里显示为“即将推出”。

### 3.3 角色卡（30张，沿用 `KUN_AVATAR_PRESETS`）

- 一张角色卡 = 一套装备 + 羽色/表情 + 称号 + 一句台词 + 卡面。
- 点亮方式：①集齐该卡的全部配件（羽色、表情不计）自动点亮；②掉落时有8%概率直接掉一张未点亮的卡，同时补齐缺少的配件。
- 卡的稀有度取其配件中的最高稀有度。
- 已点亮的卡可一键换上，也可分配给任意 Agent；一张卡可以同时被多位使用。
- 穿戴完整套装时，舞台名牌显示“套装 · 侦探”等称号。

## 4. 掉落规则（初版数值）

| 项 | 值 |
| --- | --- |
| 计入条件 | 任一对话的 Agent 回合以 `turn_completed` 结束，且距离上一个计入回合至少60秒 |
| 不计入 | `turn_failed`、`turn_aborted`、仅有用户输入请求的回合、定时任务与 IM 无人值守回合 |
| 单回合掉落率 | 12% |
| 保底 | 连续12个计入回合未掉落，下一回合必掉 |
| 每日上限 | 5个漂流瓶，按本地时区0点重置；到上限后保底计数暂停 |
| 首次 | 用户第一次完成对话必掉1个普通或稀有装备 |
| 角色卡直掉 | 每次掉落8%，只从未点亮的卡中抽 |
| 稀有度权重 | 普通55% / 稀有30% / 史诗12% / 传说3% |
| 史诗保底 | 每10个漂流瓶至少1个史诗或以上 |
| 重复转羽毛 | 普通5 / 稀有15 / 史诗40 / 传说100 |
| 羽毛兑换 | 普通30 / 稀有80 / 史诗200 / 传说500，只能兑换未拥有的装备 |

补充规则：

- 抽装备时优先未拥有的：未拥有装备的权重是已拥有的3倍，降低重复带来的挫败感。
- 对话主题加成（可选，M4）：当前对话 Agent 的形象所属套装，其部件权重×1.5。
- 漂流瓶在开瓶前不确定内容，但发光颜色提示稀有度（卡片里写“可能是史诗”）。开瓶结果在掉落时已确定并持久化，避免反复刷新重抽。
- 所有判定在 Kun 运行时完成，renderer 只展示；手机端和多窗口看到同一份结果。

## 5. 界面（对应画布画板）

原则：在现有换装弹窗（`RoomModal size="wide"` + `RoomAvatarComposer` + `RoomAvatarStage`）上加游戏层，不另起一套页面。布局、页签、格子、按钮、字号沿用现有组件，新增的只有稀有度、锁定剪影、漂流瓶、角色卡状态和进度条。

| 画板 | 场景 | 关键行为 |
| --- | --- | --- |
| 1 换装弹窗（衣橱） | 现有 880px 换装弹窗 | 标题栏加“给谁换装”切换（我 / 各 Agent）和羽毛数；标题下一条进度栏：待开启漂流瓶、装备与角色卡收集进度、保底提示；左侧沿用舞台、四个装备槽（边框按稀有度着色）、随机搭配；右侧沿用八个图标页签（“套装”改为“角色卡”），格子增加菱形稀有度、底色光晕、“新”、重复数量和未拥有剪影；“只看已拥有”；底部按钮不变 |
| 2 对话中捡到漂流瓶 | Code 私聊、群聊、Agent 对话 | 回合结束后在 Agent 回复下方挂一张小卡片（稍后 / 打开）；稍后则收起为一行提示；侧栏左下角头像红点 + “漂流瓶 1”入口 |
| 3 开瓶揭晓 | 点“打开”后的标准对话框（520px） | 顶部稀有度光晕、物品大图、名称与稀有度、台词；“穿上后”预览与套装进度；三种变体：新装备、重复转羽毛、角色卡 |
| 4 角色卡页签 | 换装弹窗里的“角色卡”页签 | 30张卡网格，按已点亮/进度排序；选中后舞台显示该卡的完整形象和部件，已点亮可“换上这套”，未点亮可用羽毛兑换缺的部件 |
| 5 手机端换装 | Connect 手机端 | 顶部返回/保存；漂流瓶入口；舞台 + 四个装备槽；横滑页签；四列格子；底部随机搭配 |
| 6 组件与状态规范 | 实现参考 | 稀有度浅色/深色取值、格子五种状态（浅色与深色）、掉落提示四种形态、装备槽与页签角标、小尺寸头像 |

画板1–4、手机端都提供浅色/深色切换（画布 Tweaks 里的 `theme`）。

掉落提示四种形态（画板6）：

- A 默认：回合结束后挂在 Agent 回复下面的小卡片。
- B 回合还在执行（排队的后续回合、长任务）：不插卡，只在运行状态旁显示“漂流瓶 +1”，结束后再出现卡片。
- C 侧栏左下角头像红点 + “漂流瓶 N”入口，随时进入换装弹窗开启。
- D 今日上限已满：只在换装弹窗里提示一次，当天不再出现卡片。

视觉规则：

- 只用现有令牌：底色 `--bg-app #fcfcfd`、侧栏 `#f5f6f8`、卡片 `#ffffff`、浅底 `--ds-surface-subtle #f4f6f9`、边框 `#e7e9ee`、文字 `#20242d / #687083 / #9299a8`、强调色 `--ds-accent #5b78ff`。深色主题对应 `#181818 / #2c2c2c`、强调色 `#78a3ea`。
- 稀有度复用现有语义色，不新增颜色：普通 = `--ds-text-faint`，稀有 = `--ds-accent`，史诗 = `--ds-skill #7a68e8`，传说 = `--ds-warning #d97706`；浅底与文字色见画板6。
- 稀有度不只靠颜色：同时有1–4颗菱形点和文字标签。
- 字体沿用系统字体，标题 17px/600、正文 13px、格子名 11.5px；不引入网络字体。
- 未拥有物品显示为“未知装备”：问号占位，不显示图和名字，也不能悬停试穿；只保留稀有度菱形。（2026-10-09 起替代最初的剪影方案。）
- 衣服在格子里必须穿在“人台”上展示（当前羽色的身体），单独的领口条看不懂；物品图标完成后替换为图标（见美术计划A）。
- 打包后的样式文件、类名和注释里不得出现参考产品的名字。

## 6. 数据与接口

### 6.1 状态存储

沿用房间存储（`rooms.service.store`），新增一行 `room_wardrobe` / `self`：

```ts
type KunWardrobe = {
  version: 1
  items: Record<string, number>        // 'headwear/detective-hat' -> 拥有数量（重复也记数，方便显示 ×3）
  seen: string[]                       // 已看过的“新”标记
  colors: KunAvatarColor[]
  faces: KunAvatarFace[]
  roles: string[]                      // 已点亮的角色卡 id
  roleAssignments: Record<string, string[]> // 角色卡 -> ['user', memberId...]
  feathers: number
  looks: Array<{ id: string; name: string; parts: KunAvatarParts }> // 我的搭配，最多8套
  pending: KunWardrobeDrop[]           // 待开启的漂流瓶（内容已确定）
  pity: { sinceDrop: number; sinceEpic: number; lastCountedAt: string | null }
  daily: { date: string; drops: number }
  rngState: string                     // 本地种子，保证结果可复现且不被刷新重抽
}
```

掉落记录写入独立的追加日志（图鉴的“掉落记录”页签读取），不放进上面这一行，避免它无限增长。

### 6.2 HTTP 与事件

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/v1/rooms/wardrobe` | 读取衣橱状态（含 revision） |
| POST | `/v1/rooms/wardrobe/open` | 开启一个待开启的漂流瓶，返回揭晓结果 |
| POST | `/v1/rooms/wardrobe/exchange` | 用羽毛兑换指定装备 |
| POST | `/v1/rooms/wardrobe/seen` | 清除“新”标记 |
| PUT | `/v1/rooms/wardrobe/looks` | 保存/删除我的搭配 |
| PUT | `/v1/rooms/wardrobe/assignments` | 角色卡分配给自己或 Agent（同时写对应头像） |

运行时在 `runtime-factory.ts` 里订阅事件总线的 `turn_completed`，调用纯函数 `rollWardrobeDrop(state, context, rng)`；掉落成功后持久化，再发布 `wardrobe_drop` 事件（遵守先持久化后发布的约束），renderer 据此在对应线程的回合尾部插入卡片。

所有写操作沿用现有用户资料接口的模式：`clientRequestId` 幂等、`expectedRevision` 冲突检测、更新事件广播。

### 6.3 与头像保存的关系

- 渲染永远不受拥有状态限制：任何已保存的组合头像照常显示。
- 编辑时只能穿已拥有的装备；服务端在保存用户/Agent/成员头像时校验新出现的配件已拥有，旧头像里已有的配件不追溯。
- 迁移：首次创建衣橱时，自动授予①当前所有已保存组合头像（用户、Agent、群、成员）里出现的配件和羽色；②默认 Agent 预设（协调员、程序员、评审员、侦探）的配件；③新手包：带麦耳机、方框眼镜、蓝围巾、笔记本。旧内置头像和上传照片不受影响。
- 开发者开关 `KUN_WARDROBE_UNLOCK_ALL=1`：本地调试时视为全部拥有，便于冒烟测试。

### 6.4 设置

设置 → 外观 新增两项：“对话中掉落装备”（默认开）、“掉落提示样式”（消息流卡片 / 仅侧栏角标）。关闭掉落不影响已拥有的装备和衣橱使用。

## 8. 验收

- 纯函数单测：掉落率统计（10万次模拟误差±1%）、保底、每日上限跨午夜、史诗保底、未拥有优先权重、角色卡直掉只抽未点亮、重复转羽毛、兑换余额不足。
- 运行时测试：`turn_completed` 计入、失败/中断/IM 回合不计入、60秒间隔、先持久化后发布、重启后 pending 与 rng 状态恢复、多窗口同时开瓶的幂等。
- 迁移测试：现有组合头像的配件全部授予，旧头像可继续保存。
- 界面：Electron 冒烟（`--avatar-only` 扩展为衣橱流程）截图覆盖画板1–6的主要状态，浅色/深色/窄屏各一张；手机端冒烟。
- 常规门禁：相关 Vitest、`npm run typecheck`、`npm run build`、`npm run check:file-lines`、`git diff --check`。

## 11. 第三轮：瓶架、十连开与开瓶特效（2026-10-09）

目标：开瓶要有抽奖的感觉；捡到的瓶子可以先攒着，攒满 10 个十连开。设计稿见画布画板 9（单抽特效）、10（十连）、11（瓶架与开瓶规范），画板 7 的面板组件也换成了瓶架。

| 项 | 规则 |
| --- | --- |
| 先攒后开 | 对话或 Code 任务里捡到的瓶子默认放在瓶架上。消息下方卡片只有“收进瓶架”和“现在打开”两个按钮，不再提示“可能是史诗”，稀有度留到开瓶时揭晓。收进瓶架后卡片不再出现（`stashedAt`）。 |
| 瓶架上限 | 最多 99 个；满了以后回合不计数，直到开掉一些。 |
| 开瓶 | `POST /v1/rooms/wardrobe/open` 接受 `dropIds`（1–10 个，按瓶架从旧到新取）。瓶子内容在掉落时已确定，开瓶时只判定两件事：是否已经重复（两个瓶子里是同一件、或期间已兑换，第二个就变羽毛；已点亮的角色卡同样变羽毛），以及十连保底。 |
| 十连保底 | 一次开 10 个且全部是普通时，最后一个升级为稀有装备，优先选还没有的，卡片标“保底”，记录里同样标注。随机数用衣橱持久化的种子，接口幂等，刷新不会重抽。 |
| 收进瓶架 | `POST /v1/rooms/wardrobe/stash`。 |
| 调试 | `KUN_WARDROBE_SEED_BOTTLES=N`（最多 30）在衣橱首次创建时预放 N 个已收起的瓶子，不占当天掉落；只用于本地调试和冒烟测试。 |

开瓶舞台（`RoomWardrobeOpening`，全屏模态）：

- 单抽：瓶子摇晃至少 0.7 秒，接着透出稀有度颜色（传说多停 0.4 秒），然后白光爆开。之后光柱展开、粒子飞散，结果卡翻转落定。卡上显示 NEW、保底角标或“+N 羽毛”印章。完成后可以穿上（直接存到我的头像，在换装弹窗里则穿到草稿上）、收下或再开一个。
- 十连：10 个瓶子一起晃、依次冲开，卡片每 0.14 秒翻一张，史诗以上带光柱。完成后顶部横幅提示“出了传说/史诗”或“十连保底生效”，下方汇总新装备、重复转羽毛、点亮角色卡。
- 跳过动画随时可用，结果不变；Esc 在动画中先跳过，结束后关闭。系统开启“减少动态效果”时直接显示结果。
- 应用给 `body` 设置了缩放，舞台用 `inset: 0` 撑满窗口，不用 `100vw/100vh`。

瓶架入口：衣橱面板“今天”卡片下方的瓶架（10 格进度、开 1 个、十连开）、换装弹窗顶部进度条、侧栏底部“瓶架 N”（外圈是攒向十连的进度，点开是舞台的待开状态）、右侧栏衣橱图标角标。原来的开瓶揭晓对话框已移除。

检查：kun 新增 `kun-wardrobe-open.test.ts`（十连顺序与记录、全普通保底、开瓶时判重、收进瓶架、瓶架满停计数、调试预放）；渲染器新增 `RoomWardrobeOpening.test.ts`（十连阶段推进与汇总、跳过与保底、开瓶请求取最旧 10 个、穿上、待开状态与瓶架文案）；Electron 冒烟 `--wardrobe-only` 用 11 个预放瓶子跑真实十连与单抽，并断言舞台铺满窗口。
