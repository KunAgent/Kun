# Code 工作台融合 Agent 与协作能力

- 决策日期：2026-09-30。
- 来源：用户明确要求 ADE 与 Code 深度融合为同一页面，以复用 Code UI 和降低心智负担为首要原则。
- 状态：主链路已实现；本文保留目标设计，实际完成范围与验证限制见 [实现状态](./impl/p7-workbench-configuration/implementation-status.md)。
- 优先级：本文取代 `00-ade-mode.md` 的独立模式决策和 P7 中单独 ADE 页面/配置中心的设计。单运行时、权限、工作区和进程生命周期约束继续有效。
- 当前代码基线：`1f7b48968`；早先记录的草稿/发送改动已进入后续基线，实施前重新核对，不再假设仍未提交。

## 1 产品定位与默认体验

用户只进入 Code 工作台：选择项目、输入目标、看结果。换 Agent 是现有输入框的执行选项，协作是当前任务按需开启的能力，审查是现有改动视图的扩展。

常规用户不需要理解 ADE、harness、总管、dispatch、执行单元等词。内部目录、设置 key 和历史字段可以继续保留这些名称，避免无收益的大范围重命名。

首屏必须保留 Code 的现有骨架：项目侧栏、会话标题栏、空状态、原模式按钮的位置、项目/分支控制、浮动输入框、右侧工具栏和底部终端。

## 2 保留、合并与移除

| 当前表面 | 融合后的处理 |
| --- | --- |
| Code 模式和工作台 | 唯一代码工作入口 |
| ADE 模式切换项 | 移除；旧路由重定向到 Code |
| AdeStage/AdeSidebar 的独立展示职责 | 逐步归并进现有 Code 组件；稳定的数据/选择器可复用 |
| Code 与 ADE 两份任务列表 | 服务端统一列表、搜索、归档视图，worker 仍挂父任务 |
| 新建总管 / 新建一对一 | 合成现有“新建任务”，不先让用户选择组织形式 |
| ADE 配置侧栏入口 | 移除；使用现有设置入口 |
| Agent 选择器 | 输入框原 Code/设计入口：Kun 分组内选 Code/设计，其他 Agent 直接选择 |
| Workers / 子代理 / 侧边对话多个同层入口 | 一个“协作”入口，按对象关系分组，保留各自数据语义 |
| 改动 / ADE 审查 | 复用现有“改动”入口，增加目标、检查和批注操作 |
| Mission Control 首页 | 不再作为默认首页；任务状态先以项目列表筛选/摘要呈现 |
| 项目看板、Graph、计划 | 保留已有语义与入口，按需使用，不增加新的顶层模式 |

## 3 常规工作页面

```text
Code                          项目 / 分支 / 当前任务              原有工具栏
＋ 新建任务
项目                          普通对话或原有 Code 空状态
  Kun
    登录重构                  项目 ▾   分支 / 当前目录 ▾
    导出修复                  ┌────────────────────────────────┐
                              │ 描述你想完成的工作……             │
                              │ ＋ Kun·Code ▾ 权限 … 模型 ▾ 发送│
设置                          └────────────────────────────────┘
```

- 默认不展开团队、看板、配置检查和空的审查面板。
- 保留输入框现有布局，Agent 不再另占一个常驻工具按钮。
- 只用 Kun 的用户继续沿用原有操作次数；Agent 进入原模式菜单，协作进入“＋”菜单。
- 项目/分支控件始终描述实际工作位置，切 Agent 不清空这些选择。
- Code/Design 作为 Kun 的工作表面，不能把“协作”插成第三个顶层模式。

## 4 Agent 与 Kun 模式共用原模式入口

2026-09-30 用户后续修订取代前版“Agent 放进模型菜单”：使用输入框现有 Code/设计按钮切换执行者。
外层 Code 工作台继续承载所有开发会话；这里的 Code/设计是 Kun 的产品能力，不是对外部 Agent 编程能力的限制。

```text
[＋] [Kun · Code ▾] [权限 ▾] … [供应商 · 模型 ▾]

Kun
  ✓ Code
    设计
其他 Agent
    Claude Code
    Codex
    Devin
    …
管理 Agents…
```

- 触发器显示 `Kun · Code`、`Kun · 设计` 或选中的外部 Agent 名称和品牌图标。
- 右侧模型菜单保留原供应商、模型、搜索与推理选项结构；不再包含 Agent 列表。
- Kun 只列出兼容自身模型调用的来源，外部 Agent 只列出它实际支持的账号/模型路径。
- 切到外部 Agent 使用其普通会话，收起 Kun 设计、需求、计划、Graph 等专属入口；宿主拒绝不支持的专属执行意图。
- 外部 Agent 仍可作为 Kun 协作流程的通用执行者，保留已有 capability/权限边界；不将内部 `agentSurface=code` 当成禁止外部编码的理由。
- 选择改变保留草稿、附件和项目；Kun Code/设计之间切换保留模型。切换已有会话的执行 Agent 仍须明确交接。
- 已接纳/排队消息保留冻结路由与表面，不因当前选择被改派。
- Devin 使用官方原生 ACP (`devin acp`) 接入同一个 `kun serve`；参考 Orca 的 Agent 发现与交互，采用准确的已支持协议，不照搬终端 bypass 默认值。

## 5 协作按需出现

默认路径不要求用户选择“一对一/总管”。持久 worker 团队能力通过输入框“＋ → 协作处理”或任务设置开启；已开启时菜单显示相应状态。

- 已有 Code 任务和新任务默认保持既有行为，不因页面融合自动创建团队或扩大委派权限。
- 项目可以保存允许协作的默认值；开启只表示允许，实际是否派工由 Kun 按目标判断，不强制凑满人数。
- 用户自然语言明确要求多 Agent 协作时，可由既有结构化设置动作进入同一开启流程；不得用 renderer 关键词正则静默改策略。
- 普通 Kun 子代理继续按原规则工作，不把现有临时子任务强制迁成持久 worker。
- 当前主 Agent 为外部引擎时，“协作处理”说明由 Kun 协调并使用已有交接流程；不能悄悄换掉主 Agent。
- 已有团队运行中切换主 Agent，必须先明确团队的管理/接管安排，不能留下无人管理却显示正常的团队。

未派工前只保留紧凑的“允许协作”状态，实际派工后才在输入框上方出现一行摘要：

```text
协作 3 · 2 执行中 · 1 待回答     改动 8 文件
```

摘要能打开右面板，但新 worker 到达不能抢焦点、自动展开右栏或挤掉用户正在看的文件。

## 6 协作面板复用现有侧边能力

右侧沿用 Code 面板宿主和 tabs，仅新增/收敛一个用户入口“协作”。

- 团队成员、临时子任务、旁支讨论可以分组呈现，不修改底层对象类型或生命周期。
- 默认只显示与当前任务相关的对象；数量增加时提供列表，不横排无限 Agent 标签。
- 点成员在右侧查看，主对话仍停在当前任务；显式“完整打开”才切主会话。
- 用户可查看任务、消息和改动；接管、停止和交还分别是明确动作。
- 右侧输入明确显示收件人。预览选择不能改变主输入框的发送对象。
- 关闭面板只关闭视图。真实协作状态和未处理问题仍在摘要、父任务行显示。

临时子代理、Graph 节点、持久 worker 的按钮按实际能力决定；不把所有对象都伪装为可接管会话。

## 7 结果继续从“改动”进入

保留 Code 现有改动按钮/标签，逐步增强同一视图：

1. 普通任务默认显示当前目录的现有 diff。
2. 有多个任务工作区时显示“查看对象”选择，默认根据用户打开的目标决定。
3. 有检查/验收时显示证据摘要，没有时不占空白区域。
4. 行批注、批量返工、重新检查和合入使用已经规划的版本化协议。

普通用户不需要选择“旧改动”或“ADE 审查”。内部可以保留不同 diff 数据适配器，使用统一 `ChangeTarget` 选择准确范围，不能把当前目录改动与某 worker 的补丁混在一起。

合入目标、审查版本、源目录未提交修改保护继续保留；界面融合不能压缩掉对用户决策必要的信息。

## 8 侧栏与历史

- 沿用 Code 的按项目分组、固定项、搜索和归档，不新增一套“协作任务”根列表。
- 旧 ADE 根线程和 Code 根线程按原 ID 显示在一起，worker 保留父子关系。
- 状态提示沿用现有行组件，未读与必须处理分开；父任务显示子问题计数。
- “待处理”先做项目列表的状态筛选，任务总览作为已有看板的可选视图，不能抢占无任务首页。
- 旧 ADE 链接、通知、恢复记录都打开 Code 中相同线程；不复制线程、不变更消息 ID。
- 合并排序和分页必须由服务端/明确的联合游标完成，不能简单拼接两份第一页。

## 9 配置进入已有设置

取消上一版新增的“ADE 配置”导航类别和左下入口。

| 配置对象 | 最终入口 |
| --- | --- |
| Kun 原生助手能力 | 现有 设置 → 助手 → 常规/权限/工具 |
| 添加、连接和 Agent 默认值 | 现有 设置 → 助手 → Agent 接入 |
| 团队规模、预算等默认值 | 设置 → 助手 → 协作，低频项折叠 |
| 账号、API Key、模型目录 | 现有 设置 → 模型来源 |
| 通用工作区偏好 | 现有 Worktrees 设置；用户文案可按既有术语统一 |
| 本机项目默认与仓库声明 | 项目行菜单 → 项目设置，复用已有项目配置 |
| 当前任务覆盖 | 标题栏“…” → 任务设置，复用右面板 |

助手设置已有较多 tabs，实施时复用其分组/溢出机制；窄屏不挤成八九个不可读小标签。

先前计划中的列表详情、连接向导、来源分组、显式保存、revision/generation 和任务快照继续有效，只改变入口和容器。内部 `agents.kun.ade` key 不为 UI 改名而立即迁移。

## 10 页面归属与执行授权解耦

`workspaceMode` 暂保留为历史元数据；旧 `code/ade` 记录原样读取，新 Code 任务写 `code`。不能批量重写历史来实现页面合并。

新增明确的协作策略进入任务设置快照，例如 `collaboration.enabled`（提案名）。Manager 工具广告与执行共享相同准入判断：

- 当前工作表面允许该能力。
- 当前有效主 harness 是 Kun。
- 任务已允许持久协作，且不是被管理 worker 或 Rooms agent。
- 项目策略、宿主权限、功能可用性通过校验。

不能把 `workspaceMode === 'ade'` 简单改成 `workspaceMode === 'code'`。历史 ADE 的协作权按既有角色/team 及原准入语义兼容解析；历史 Code 不自动获得新增委派能力。

已有 `agentSurface` 和 client surface 约束保持：Design 的能力门控不因线程位于 Code 页面被解除，Work/IM/Rooms 不因列表统一获得 GUI 工具。

## 11 工作区只有一个归属者

UI 复用现有项目/分支选择器，后端每个执行单元的工作区仍明确由原机制持有：

- 普通当前目录任务：保持原目录绑定。
- 已有 Code Direct 计划的 agent-managed worktree：保持原生命周期和用户未提交文件约束。
- 宿主创建的任务 worktree：复用 TaskWorkspaceService，并记录实际 workspace ID。
- Graph 节点：保持 Graph 原有隔离策略。

创建/构建时解析一个明确 workspace intent；同一执行单元不能既进入 Code worktree pool 又创建 TaskWorkspace，也不能在已有宿主工作区里再次注入计划工作区创建协议。

开启协作不搬动主任务目录。写入 worker 独立准备工作区，主任务与 worker 的 source/execution path 分别显示。需要切换工作区策略时走独立明确操作，不在打开设置或切 Agent 时执行。

## 12 兼容与功能开关

- 旧 `ade` route 作为 alias 解析到 Code；旧独立 stage/sidebar 在所有消费者迁走后删除。
- 保留旧 API `workspace_mode=code|ade` 的含义；新增可协商的联合工作台查询范围，不把旧参数语义偷偷扩大。
- 列表、搜索、归档、fork、通知、最后打开线程、分页必须同一分类规则；Work/Rooms 不混入。
- 联合列表能力先随 runtime 上线，再切 UI；与旧 runtime 混用时通过兼容读取层保留历史可达，不能展示不完整列表冒充完整。未支持的新写能力说明版本要求。
- 旧 ADE 开关迁为高级协作能力门控的兼容输入，不能再控制旧会话是否可见。
- 关闭新派工后允许查看历史、停止在途执行、处理已产生的审批/问题，不强杀团队或隐藏任务。
- 回退新 UI 保留相同线程 ID、原 `workspaceMode` 和新快照；不能回滚为另建第二份任务。

## 14 具体验收任务

1. 用户直接进入 Code、选项目、输入、发送，路径与常规 Code 一致。
2. 用户从原模式入口改用 Claude/Codex/Devin，不离开页面，不重复配置项目；Kun Code/设计与外部 Agent 清晰分组。
3. Kun 任务从“＋”允许协作，未派工时没有空团队面板，派工后出现摘要。
4. 查看 worker 时主输入/滚动保持，关闭右栏继续正常对话。
5. 打开“改动”可查看当前目录或指定 worker，不能混淆成果版本。
6. 原 Code 与原 ADE 会话都能搜索、归档、恢复、fork 和从通知打开。
7. 关闭高级协作后旧任务仍可见，已发请求可处理，新任务不自动派工。
8. 同一任务不会因页面融合创建两套 worktree 或扩大权限。
9. Agent 接入和品牌问题仍需 B01-B04 全部验证，不能因融合隐藏这些缺陷。
