# Code 融合后的配置与交互实施规格

本文件把配置入口、容器、字段和状态定到可实现程度。行为约束见 `specs/`，字段正本与生效边界见 [contracts.md](contracts.md)。所有尺寸是初始布局目标，需通过验收矩阵校正；不能以硬编码宽度牺牲窄屏可用性。

2026-09-30 用户要求融合到 Code：不再新增 ADE 配置中心。本文使用现有助手、模型来源、Worktrees 和项目配置入口，页面设计以 [14](../../14-code-workbench-integration.md) 为准。

## 1 入口和返回位置

| 用户位置 | 可见入口 | 目标 | 返回行为 |
| --- | --- | --- | --- |
| Code 侧栏底部 | 设置 | 现有设置壳 | 回原 Code 任务 |
| 现有助手设置 | Agent 接入 / 协作 | 对应默认值配置 | 沿用设置返回机制 |
| composer 原 Code/设计模式菜单底部 | 管理 Agents… | 当前 Agent 详情 | 回原输入框，保留草稿、附件 |
| Agent 不可用行 | 完成登录 / 安装 / 修复连接 | 该对象对应向导步骤 | 回原选择器，可继续选择 |
| 项目行菜单 | 项目设置 | 该项目本机默认值 | 回原任务和项目分组位置 |
| 任务标题栏 | 任务设置 | 当前任务侧边抽屉 | 关闭后恢复原工具面板 |
| Agent 模型区域 | 管理模型来源 | 全局来源管理，携带 return target | 回原 Agent 和未保存草稿 |
| 旧 Harnesses 深链 | 无新增按钮 | 重定向到 ADE/Agents | 原返回目标继续有效 |

独立 ADE 侧栏及“Agent 中心/ADE 配置”主入口移除。项目设置必须可从菜单和键盘进入，不能仅有 hover 图标。

复用已有助手设置的 Agent 接入页签，并归入协作默认值；模型来源和 Worktrees 不复制。内部路由和交接开关不扩大曝光，高级协作开关只限制新派工，旧会话仍在 Code 中可见。

## 2 页面容器

### 2.1 完整配置页

```text
设置 / 助手 / Agent 接入          这台电脑 · 全局默认
沿用已有设置导航，低频项收起
-------------------------------------------------
已添加             Claude Code       [测试连接]
Kun                可用 · 本机账号
Claude Code
Codex              模型与来源
                   [当前模型 · 来源]
＋ 添加 Agent       管理模型来源…

                   使用默认值
                   默认权限       [跟随任务]
                   自动选择       [允许]

                   ▸ 高级连接设置
                   ▸ 停用与移除
-------------------------------------------------
新任务生效          [恢复继承] [保存更改]
```

- 外层沿用 SettingsView，不新增独立 ADE 分类或设置壳。
- 页签始终表示内容类别，作用域写在标题下，不能通过同名页签猜作用域。
- Agent 对象栏目标 180-220px，详情区域至少能容纳 320px 表单；空间不足时改为对象列表进入详情并提供返回。
- 不同时常驻应用项目侧栏、设置分类栏、Agent 列表和右工具栏四套导航。进入完整设置时复用现有设置壳的导航替换行为。
- 保存区域在内容末尾或容器内 sticky；不能遮住错误和最后一个字段。

### 2.2 项目页

标题 `项目名 · 项目设置`，次行完整路径可复制。两个明确区域：

- 本机默认值：模型、可选择 Agent、worker 规模/预算覆盖、一对一起点偏好。
- 仓库环境配置：`.kun/project.json` 的 setup、checks、共享声明及其有效/未批准/已变更状态。

两区独立草稿、独立保存。仓库区有单独“编辑仓库配置”动作，提交前显示目标文件和差异；本机保存不隐式改仓库。

已有 MCP/Skills 声明不得因编辑 worktree 区域被丢弃。整个文件 digest 改变后既有信任状态如何更新，由现有 project-config 流程决定并在页面反馈。

### 2.3 当前任务抽屉

- 宽屏目标宽 360-420px；窄屏使用全宽 sheet，保留返回控件。
- 与 Workers、文件等共用右面板宿主；打开前记录原面板，关闭后恢复。
- 标题带任务名，副标题“只影响此任务”。正在查看 worker 时明确是主任务还是该 worker，不能复用错误 activeThreadId。
- 展示实际生效值、待生效值、来源和生效时机；不把 runtime 当前值提前改成草稿值。
- 工作区身份只读，换工作区进入已有独立准备/交接流程。

## 3 Agents 页字段

| 区域 | 字段/操作 | 默认展示 | 编辑要求 |
| --- | --- | --- | --- |
| 标题 | 名称、图标 | 常驻 | 名称来自可信目录或用户保存值 |
| 身份 | 版本 | 次级文本 | unknown 不显示伪版本 |
| 状态 | 已安装/需登录/未确认/可用/失败 | 一条摘要 | 详情展开显示分阶段结果 |
| 模型 | 当前模型与来源 | 常驻 | 按来源分组，完整 route 原子保存 |
| 权限 | Agent 默认权限 | 常驻 | 只列当前能力支持值，显示有效上限 |
| 派工 | 允许总管自动选择 | 常驻 | 仅影响后续选择，不中断已派任务 |
| 高级 | 路径、参数、环境变量引用 | 折叠 | 修改标记连接测试过期 |
| 能力 | 插话、附件、续接、审批等 | 需要时展开 | 从 runtime capability 读取 |
| 停用/移除 | 当前及后续影响 | 更多菜单/独立区 | 显示引用任务，保留历史 |

主操作状态表：

| 状态 | 主操作 | 次操作 | 不允许的误导 |
| --- | --- | --- | --- |
| 检测中 | 显示检测进度 | 取消/稍后 | 无限转圈无超时反馈 |
| 程序缺失 | 在终端准备安装 | 指定路径、重新检测 | 宣称已安装 |
| 明确未登录 | 完成登录 | 选择兼容模型来源 | 把所有 Agent 都要求网关 |
| 登录未确认 | 检查连接 | 查看登录方法 | 把 unknown 当 signed-out 或 signed-in |
| 连接失败 | 重试连接 | 修改连接、诊断详情 | 只给灰按钮 |
| 可用 | 测试连接 | 可选试运行、默认值 | 把握手通过称为模型可用已验证 |
| 已停用 | 启用 | 查看影响 | 自动启动已有任务 |

状态变化预留一行高度；正在编辑字段不会因后台检测重置。停止/取消检测只取消该操作，不停止任务中的 agent。

## 4 模型选择

- Agent 切换进入 Code 现有模式按钮；Kun 组内为 Code/设计，其他 Agent 直接选择，不另加常驻按钮。
- 模式按钮显示 `Kun · Code`、`Kun · 设计` 或外部 Agent 品牌和名称；右侧供应商/模型区域继续以模型为主。
- 旧 provider-kind 推断继续有效，不能强行设 `harnessId=kun` 改变已有订阅路径。
- 模型菜单按“本机 Agent 账号”和已配置供应商分组；只展示当前 Agent 支持的 route。
- 同名模型不同来源必须分别列出，选中摘要常驻显示来源；长名称截断时能通过焦点或悬停读完整值。
- 下方“管理模型来源”跳转全局 Providers，无第二份 API Key 输入框。
- 一个来源没有模型时显示加载/失败/重新获取，允许已有契约支持的手动模型路径；不填入猜测的模型。原生账号模型列表为空时显示“Agent 默认模型”，不误导用户去配置 HTTP 供应商。
- 来源切换影响原生会话时，使用已有交接确认，只对实际变化执行一次。
- 凭据不进入设置草稿缓存。CLI 登录交给既有认证操作，provider key 走现有凭据服务。

## 5 添加 Agent 向导

宽屏为约 560px 的模态流程，窄屏为全宽独立步骤。步骤状态由独立 controller 持有；临时切到终端/Providers 后可返回，不靠弹窗 DOM 是否挂载保存进度。

### 第一步 选择

- 推荐只含有依据的候选：已发现且差一步的内置 Agent 优先。
- 其次为内置目录；已添加对象直接提供“打开设置”。
- 自定义 ACP、终端 Agent、导入配置有固定入口。
- 没有已接入 Registry 时不展示伪在线目录；已实现的本地快照可作为候选来源。

### 第二步 连接

- 安装与登录命令来自既有内置定义或用户明确填写的配置。
- 沿用当前终端预填语义，按钮写清“在终端准备安装/登录”，不把预填完成视为操作成功。
- 已实现协议登录的 Agent 才使用该分支；不凭通用 UI 假设所有 Agent 能浏览器授权。
- 等待期间可取消，迟到成功回执不能把取消后的向导跳到另一个 Agent。
- 自定义表单：名称、命令、参数列表、环境变量列表；密钥行使用凭据引用，保存后值隐藏。
- 终端 Agent 明示终端交互及状态来源；不能作为结构化聊天/审批能力完整的 worker 自动准入。

### 第三步 检查与完成

- 显示程序检测、连接握手和可选模型试运行各自结果及耗时。
- 检查结果绑定连接配置指纹；编辑后标为过期。
- 选择默认来源/模型、权限，完成后列表聚焦新对象。
- 握手成功不自动发付费测试消息；“试运行”独立触发。
- 可保存未就绪配置时按钮明确为“保存，稍后连接”；保存后仍不可错误显示可执行。
- 自定义 ID 稳定，重复完成按 requestId/ID 去重；重名只需可区分，不能按名称覆盖旧对象。

## 6 协作页

| 字段 | 产品文案 | 说明 |
| --- | --- | --- |
| managerModel | 总管模型 | 跟随 Kun 默认或选择兼容来源模型 |
| softWorkers | 建议 worker 数量 | 是选择建议，不强制补足 |
| hardWorkers | 活跃 worker 数量上限 | 不是同时运行上限；降低后不删除现有 worker |
| managerMayApprove | 总管可处理授权范围内的审批 | 不能代批超出已有权限的请求 |
| budget.softTokens | 团队 Token 提醒阈值 | 预算区域，默认折叠 |
| budget.hardTokens | 团队 Token 上限 | 显示实际拒绝操作边界 |
| hibernation | 空闲资源释放 | 高级区域，沿用既有生效规则 |
| stall | 无进度提示阈值 | 高级区域，不把“可能卡住”显示成失败 |

数字输入允许临时空值作为编辑草稿；保存时验证范围及软硬阈值关系，不能输入一半就 clamp 并保存。任何字段的单位常驻显示。

允许自动选择的 Agent 从详情页的同一配置读取；协作页可以展示摘要和跳转，不维护另一套相互矛盾的勾选结果。

## 7 工作区页与任务开始

- 通用页放一对一隔离默认、默认起点策略，以及项目设置入口。
- 共享路径按项目配置，不通过全局当前 `workspaceRoot` 隐式确定修改对象。
- 新任务开始前显示项目、当前目录/worktree、起点；已有派工型写入 worker 使用既定宿主隔离策略。
- 普通目录允许本地工作，Git 起点控件隐藏或给出原因。
- 准备中可编辑后续输入，首条消息保持排队；状态为解析起点、创建、环境准备、就绪。
- 创建失败可重试原意图或修改草稿；取消不假称删除所有已经产生的文件，宿主返回实际保留结果。
- 已有线程切换项目不能静默重绑定；调用已实现的工作区切换/新建线程流程，并明确结果。

## 8 保存、返回与错误

表单状态：`clean → dirty → saving → saved + applying → applied`。持久化和应用分开：保存失败返回 dirty；应用失败保留 saved 意图并提供“重试应用”。

- clean 时主保存按钮禁用；dirty 时显示未保存计数或简短提示。
- 对象切换保留草稿；真正关闭含未保存编辑的配置工作区时提供保存、放弃、继续编辑。
- 进入模型来源/终端等内部子流程不询问丢弃，保留草稿与返回 target。
- 校验错误放字段下并让首个错误可聚焦；页面级错误放页面顶部；无需每次错误都弹窗。
- 并发冲突显示当前值与本地修改，允许重读后有意识地重新应用，不能隐式 force。
- 普通保存不追加审批；涉及既有保护字段、项目命令批准的动作继续原授权流程，不重复再问。
- 成功只在匹配 revision/generation 的回执到达后显示；不以按钮点击或 HTTP 200 泛化为 runtime 已应用。

## 9 工作台配套交互

- 新建任务沿用 Code 入口和草稿，不先选择一对一/总管；协作从“＋”或任务设置按需允许。
- 无团队时不常驻空协作栏或看板；派工后出现一行摘要，不能自动挤掉正在查看的工具。
- 主任务固定，右侧单击 worker 预览；完整打开有明确返回父任务。
- worker 详情分任务、对话、改动；嵌入输入可见“发送给：worker 名称”。
- 主任务输入默认发给总管；选择右侧 worker 不自动改变主输入接收者。
- 接管不隐式停止；执行中支持插话时显示单独动作，否则排队或显式停止。
- “待我处理”是统一待办数据的筛选视图，复用审批/问题表单，不另存处理结果。
- 现有“改动”入口扩展审查，明确 workspace/dispatch/revision；无任务工作区时仍用原当前目录 diff。

## 10 视觉、键盘和响应式

- 使用 Kun 现有语义 token、图标、标题栏和表单 primitives；不引入第二套主题。
- 常用正文/字段约 13-14px，辅助文本约 12px；中文层级不依赖极细字重差。
- 一个操作区域保留一个强调主按钮，安装/登录与保存同时出现时用步骤分开。
- 图标不能单独表达权限或失败；颜色不能成为唯一状态信号。
- 菜单使用 portal 与真实碰撞定位，保留 Esc、外部点击、键盘焦点返回。
- 桌面 1280/1440/1920 宽度验证；窄屏 960、375、320 验证重排。不得把整个 desktop 按比例缩小。
- 长模型名、分支名、路径、英文错误都可折行/截断后查看；主操作始终可见。
- 触摸点击区约 44px；键盘顺序与视觉顺序一致；IME 输入不误发送。
- 动画尊重 reduced motion，状态切换保持布局稳定；检测结果不得抢走编辑焦点。

## 11 第一批可见收益

先完成统一 Code 的路由、历史与协作准入，再在现有设置和模型菜单中接入列表详情、来源选择、保存与应用回执。项目/任务编辑在契约落地后出现，不能在数据仍依赖全局设置时开放看似独立的表单。

交互原型用于评审布局，实际文案、字段默认值、能力与流程以本文件和 contracts 为准。

## 12 应用内确认与工具审批

- 工具审批、执行权限变更以及通用确认/提示使用 Kun 自有窗口，复用现有 Rooms 受控窗口实现。
- 按应用语言和明暗主题呈现，常规宽度 560px；工具/权限首选 500px 高，普通确认 360px，单按钮提示 320px，并限制在当前屏幕工作区域内。
- 工具审批显示操作标题、会话/工具、完整目标、作用目录和“仅本次”说明。已知写入操作明确为“修改文件”；命令和路径保持可选择、可滚动的完整文本。
- 参数 JSON 放在折叠详情内，并说明可能经过缩略；不能用参数预览替代真正的授权目标。哈希编号和框架安全实现只留日志。
- 权限设置按实际变化列“字段：旧值 → 新值”；完全访问有明确说明和克制的图标强调，未变化字段不重复堆叠。
- 取消、关闭、Escape 均保留待处理请求；确认按钮名称对应“允许一次”“拒绝执行”或具体业务动作。普通通知只显示一个“知道了”按钮。
- 默认焦点为取消，通知默认焦点为知道了；Tab 在窗口内循环，长标题/内容可滚动，底部按钮持续可见，重复提交被禁用。
- 视觉层变化不改变授权边界：独立临时 session、专用 preload、主 frame 与 nonce 校验，Main 读取真实请求并在提交前重验同一运行时/动作快照。
- 请求已处理、来源导航或窗口关闭时取消旧确认。受控窗口不接入扩展脚本，不向 Remote 广播其内容或事件。
