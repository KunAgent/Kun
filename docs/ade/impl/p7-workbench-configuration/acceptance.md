# ADE 实施验收矩阵

本文是未来实施的验收合同，所有结果初始均为待执行。计划文档通过校验只证明计划格式和引用有效，不证明下面的功能通过。

## 1 证据层级

| 层级 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 单元测试 | 解析、状态机、映射、版本比较、错误分类 | 真实布局、Agent 协议兼容 |
| 服务集成 fixture | 保存链、SSE、并发、故障注入、幂等 | 第三方程序真实启动/账号 |
| Electron 离线 smoke | 实际 renderer/preload/main/runtime 与布局命中 | 真实模型请求成功 |
| 真实 Agent E2E | 已记录版本/来源的完整执行能力 | 未测试版本、平台或来源 |
| 人工视觉和操作 | 可读性、焦点、布局、工作流程 | 自动化状态/权限保证 |

已有 `smoke-development-ade.cjs` 使用 stub/离线模型，报告必须标注 fixture；不能将其通过写成所有 Agent 已接入。

每个支持的来源单独一行，不写“该 Agent 全部通过”泛化到未测试 route。

| Codex | 原生 app-server；兼容 ACP 单列 | 无 ACP 包的新建、原生恢复、停止、审批/问题、模型来源 |
| Cursor | 当前 SDK/provider | 连接、模型、执行、停止；CLI 状态不冒充 SDK 状态 |

| OpenCode | ACP/native-login；支持时 gateway | 真实启动环境、session、模型、prompt、取消 |
| Antigravity | 当前受支持 CLI 路径 | 真程序/参数、输出、取消；限制按能力呈现 |

每行记录 app commit/实际包路径、CLI 版本、transport、来源、步骤、结果与证据。缺安装/账号写未执行并列出补测条件；保持相应能力未验证状态。真实试运行由用户主动进入测试，不因打开设置触发。

## 8 恢复、兼容和生命周期

- runtime 重连：恢复游标和摘要；未确认的 restored row 不显示仍活跃。
- 主窗口退出：沿用应用退出屏障和受管进程清理；关闭面板不走该屏障。
- 旧客户端/旧 runtime：新写能力按协商隐藏，原操作仍可使用。
- 旧设置：4/8 默认、权限、模型、预算不被示例数据覆盖；normalize/save/normalize 幂等。
- 旧线程：无新快照可读，显式编辑后再迁移；无全库扫描。
- 旧 verdict：未知版本显示历史，不赋予当前通过。
- 关闭高级协作：Code 新建、发送、图片、审批、队列、计划/Graph 保持，旧 ADE 历史仍可见且在途请求可收尾。
- 同版本 UI 回退：数据和草稿可恢复；旧二进制回退单独验证字段保留与备份策略。

## 9 性能和布局目标

以下为待量测的目标，不是已验证结果。记录机器、构建类型、样本量和 p50/p95，和 A01 基线比较。

- fixture：100 个任务摘要、跨团队 20 个活跃执行单元、长时间线 10,000 项。
- 侧栏不加载所有 transcript；非选中任务不轮询完整 diff。
- 缓存内 worker 切换目标 p95 小于 200ms；输入反馈目标 p95 小于 100ms。
- 可见状态在收到本地事件后目标 1s 内更新，后台摘要按已有节流预算；不将网络延迟计作 renderer 处理延迟。
- 反复切换 50 次后 watcher/订阅数回到稳定值，关闭后无持续增长；记录内存而非只看一次堆大小。
- 1280x800、1440x900、1920x1080、960x780、375/320 窄屏，明暗主题，中英文、长路径、长模型名。
- 弹层中心 `elementFromPoint` 命中真实菜单，滚动/缩放后不被裁剪；错误、保存、修复入口可达。

## 10 自动化与执行命令

```bash
git diff --check
npm run typecheck
npm run build:kun
npm run build
npm run smoke:development-ade
npm run test
npm run lint
npm run check:file-lines
```

各批先跑相关 vitest 文件；完整 test/lint 在最终交付运行。跨层修改按仓库要求运行最小必要检查，不反复重跑无关全套。所有失败注明新引入或已存在，未执行项目写原因。

新的 smoke 场景沿用现有脚本分模块，单文件不超过 700 行；输出放 ignored `dist/`，不提交截图日志或用户凭据。

真实应用验证使用隔离 profile，不覆盖用户配置、不关闭用户已有实例。macOS packaged 验证确认实际 app 路径与进程身份；Windows/Linux 的进程、路径和安装差异不能用 macOS 通过替代。

## 11 发布退出条件

1. 八个能力规格的必做场景均有结果和证据，所有功能 blocker 清零。
2. 所有公开宣称支持的 Agent/来源完成对应真实验证，未知项明确列出，不用“界面可选”代替成功。
3. 旧配置/线程/批注/worktree/凭据保持，迁移和回退演练通过。
4. 设置、选择器、worker 和 review 完成中英文、明暗及窄屏检查。
5. 变更文件不超过 700 行，基线失败和未测平台如实列出。
6. 页面融合不自动放宽协作/权限默认；高级功能关闭不隐藏历史或阻断安全收尾。
