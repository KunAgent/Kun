## 已落地的用户路径

1. 代码任务统一进入 Code。旧 ADE 链接打开原任务；列表和搜索由宿主统一分页，保留原任务 ID、父子关系及历史字段。
2. 按用户后续修订，输入框原 Code/设计入口统一选择 Agent：Kun 分组内是 Code 和设计，其他 Agent 直接选择。原供应商/模型菜单继续只管理来源和模型。品牌图标、未就绪原因与修复操作保留；Cursor SDK 来源与普通 HTTP 来源分开，原生登录不继承无关的 API 账号。
3. 原“设置 → 助手”承载 Agent 接入、协作默认值和项目设置；没有增加独立 ADE 配置页。任务标题栏的设置抽屉只修改当前任务，显示来源与生效时机。保存配置不会重写已接纳的队列或在途回合。
4. “＋ → 协作处理”是显式开启动作。新任务不预建空团队；派工后才出现协作信息。宿主对工具调用和 HTTP 派工使用相同的全局/任务/角色/Agent 准入；关闭协作后已有停止、回答和接管操作仍可用。
5. Code 首发和显式新建使用同一个任务工作区所有者。准备失败保留输入，重试复用已有工作区；非 Git 不静默改为源目录。准备期间切换任务后可恢复正确绑定。
6. worker 在右侧预览，主任务及草稿保持不变。完整打开和返回是独立动作；人工输入先确认接管，只发给目标 worker。隐藏预览释放自己的订阅，不停止其他线程。
7. 原“改动”入口同时承载对话补丁和明确选择的任务工作区。审查、检查和裁决绑定成果版本；变更后旧结果显示过期，无法完成的指纹不会被当成通过。批注返工带幂等标识，未知发送结果的重试保留原版本。

## 配置与兼容边界

- 全局、项目和任务使用不同的对象 revision；保存时检测冲突，保留草稿，不覆盖其他窗口的新值。
- 项目身份由宿主解析真实路径与 Git common directory；项目覆盖不包含凭据或执行程序路径。
- 当前配置与待生效配置分开。改变路由影响下一条新输入，协作上限和预算影响后续受控准入。
- 当前任务工作目录只读；隔离目录变更走工作区准备流程。
- 旧运行时没有新能力时降级为只读或明确错误；不猜测任务成功或静默改派其他 Agent。
- 外部 Agent 仍由同一个 `kun serve` 调用；没有恢复旧运行时切换器。

## 父任务与 worker 的工作区边界

实际桌面派工发现：worker 工作区事件中的 owner 是主任务，unit 是 worker。
旧投影把该 ready 当成主任务绑定，宿主正确拒绝重复绑定后，GUI 却将父准备状态标为失败。
现在事件/REST 结果按执行单元过滤，已绑定任务不会被另一个工作区的迟到 ready 改写；
返回任务时也可修复旧的错误 failed 投影。真实 wire event 到 normalizer、sink 和恢复测试
共 13 项通过，并验证源项目 registry 不变、父任务发送门禁保持可用。

标题栏显示源项目名，分支和悬停路径继续描述实际工作目录，不把生成的 `tws_*` 目录 ID 当作项目名称。

## 网络出口复查

本机系统 HTTP/HTTPS/SOCKS 代理均已启用，而原生进程的代理环境变量为空。
使用无认证 HEAD 请求对照：OpenAI 模型入口直连 5 秒超时，系统代理约 0.76 秒返回 401；
ChatGPT 入口直连超时，系统代理约 0.72 秒返回 HTTP 响应；Anthropic 入口的直连/代理状态也不同。
这些检查没有发送 API key、提示词、会话或代码，证明网络出口影响连通性，不证明账号或模型可用。
因此，此前独立 CLI 同样超时的证据只能证明直连失败，不能排除 Kun 未继承系统代理的问题。

同时确认 Claude SDK 的安全环境白名单剥掉了用户明确配置的代理变量。
修复范围保持在原生 Agent 启动环境，普通 shell 工具白名单不扩大，Kun 网关的 loopback 地址绕过代理。
系统代理桥接仅针对具有明确原生出口的 Codex/Claude；代理地址与凭据留在宿主内存，
Agent 接入高级区只展示连接来源并复用重新检测动作。复杂或不一致的系统策略要求显式配置，不猜测目标出口。

## worker 实际文件写入

桌面审批通过后发现安全检查将 Manager 给定的绝对 worker 写入根误作相对路径，
导致真实文件写入被拒。路径检查现在接受宿主给定的根内绝对路径或相对路径，并仍要求
scope 本身和目标均位于当前 worker 根内。祖先目录、兄弟目录、`../`、符号链接逃逸
继续拒绝，既有 shell 限制保持有效。
实际文件写入与负向路径测试连同现有内置工具测试共 65 项通过。

原生网络桥接已落地：Main 独立 Electron 系统 resolver 实测确认 Codex/Claude 已知出口均使用系统代理；
检测、握手、模型探测与实际进程共享私有策略。启动环境中的私有快照读取后删除，
热更新只在内存，持久化配置拒绝该字段。系统策略冲突按 credential mode 拒绝原生准入，
不阻断可用的 Kun 网关来源。Main 57 项、原生接线 134 项、准入 115 项针对性测试通过；
没有继续发送付费模型请求，真实回合可用性仍与网络可达性分别记录。

worker 写入根还保留父任务的目录上限：父若只允许 `src/generated`，子工作树只获得对应目录；
父的空写入集合保持为空。该映射与 Manager/实际写入相关的 29 项回归通过。

## 脱离父回合的后台事件

后台 worker 完成、审批和活动投影原先继承了已结束父回合的写入 fence，导致 Manager 409 和未处理异常。
已授权的 detached 生命周期现在使用宿主作用域；child 镜像保留原父回合关联，外层作为线程级事件写入。
真实 Manager HTTP 回归覆盖父回合结束、父下一回合同时运行，以及旧工具仍被同一 stale fence 拒绝。
相关 5 个测试文件、21 项测试通过，通用 Manager/Recorder 防线未放宽。

## Devin 终端命令与流异常反馈（2026-10-01）

Devin 的 exec 工具可通过 ACP `terminal/create` 发送完整 shell 命令且没有独立 argv。
原实现把整个字符串作为可执行文件名，带参数或管道的命令因此创建失败，Agent 随后反复重试。
参考 Paseo 的 `resolveTerminalCommand`，现保留显式 executable/argv，完整命令使用明确的系统 shell。
真实存在且名称含空格或符号的可执行文件仍直接启动；原有审批、目录边界和 owned-process 管理均保留。

流解析或时间线写入异常原先可能等到 `session/prompt` 结束才反馈，现立即结束等待、请求取消并回收异常连接，
避免界面长期显示运行中而 Agent 继续工作。第二轮恢复测试增加真实回复断言，加载时的历史重放仍不进入新一轮。
